# 知识内容质量标准字段模型设计

## 背景

当前知识仓库已经具备从原材料到知识产物的处理链路，但“什么样的知识内容才算达到入库质量要求”仍然主要散落在代码、测试和治理脚本中，缺少一套产品意义上的统一模型。

本设计聚焦的是：

1. 最终产出的知识内容本身是否合格
2. 这套质量标准是否可以配置、组合、版本化
3. 后续是否能够在不推翻整个系统的前提下持续演进

本设计不直接解决：

1. 原材料如何被解析
2. 中间链路如何可视化
3. 工具和模型如何执行

这些内容仍然重要，但应属于“过程可信度”和“过程可视化”模型，而不是“入库内容质量标准”本身。

## 核心原则

### 1. 内容中心化

入库质量标准只判断知识对象内容质量，不直接以解析器、模型、分块器等处理方法作为准入标准。

### 2. 可配置而非写死

质量标准必须允许字段启停、阈值调整、策略组合和版本迭代。

### 3. 分层判断

内容质量标准至少拆成三个层级：

1. 知识项级
2. 关系级
3. 发布批次级

### 4. 可解释

每个字段都必须能够回答以下问题：

1. 它评估什么
2. 它为什么存在
3. 它的值如何取
4. 不满足时会产生什么结果

### 5. 可演进

质量标准不追求一开始就绝对正确，而是要支持“先建立基线，再逐步修订”。

## 与其他标准体系的边界

本项目后续建议区分三套并行模型：

1. 内容质量标准
   - 判断“知识对象本身能不能入库、能不能发布”

2. 过程可信度标准
   - 判断“这条知识是用什么方法生产出来的、可信度需要怎么调整”

3. 过程可视与审计标准
   - 判断“生产过程是否被完整记录、能否前端可视、能否回放”

本次文档只定义第一套，即内容质量标准。

## 三层内容质量标准

### 一、知识项级

知识项级字段用于判断单个实体、事件、流程等知识对象本身是否足够好，是否值得进入工作态知识库，是否具备继续治理和发布的价值。

主要关注：

1. 名称是否清晰
2. 类别是否准确
3. 定义是否完整
4. 证据是否充分
5. 来源支撑是否可靠
6. 是否存在明显歧义、重复、噪声或语义冲突

### 二、关系级

关系级字段用于判断知识对象之间的关系是否成立，是否语义清晰，是否有足够证据支持，是否能进入图谱结构。

主要关注：

1. 关系类型是否合法
2. 端点是否存在且兼容
3. 方向是否正确
4. 关系证据是否充分
5. 是否存在重复、孤立、自环或矛盾关系

### 三、发布批次级

发布批次级字段用于判断某一批工作态知识是否整体达到发布条件。

主要关注：

1. 审核是否完成
2. 结构是否完整
3. 证据覆盖率是否达标
4. 低质量项比例是否可接受
5. 是否还存在未解决冲突

## 统一字段模型

每一个内容质量字段都建议使用统一元数据结构进行定义。无论该字段最终对应配置文件、数据库还是页面配置，都应满足以下属性语义。

### 通用属性

- `field_key`
  - 字段唯一标识
  - 例如：`item.definition_present`

- `field_label`
  - 前端展示名称
  - 例如：`定义是否存在`

- `quality_level`
  - 字段作用层级
  - 允许值：`item`、`relation`、`publication_batch`

- `quality_dimension`
  - 质量维度
  - 例如：`identity`、`definition`、`evidence`、`support`、`consistency`

- `value_type`
  - 字段期望值类型
  - 允许值：`boolean`、`integer`、`float`、`enum`、`enum[]`

- `allowed_range`
  - 取值范围
  - 例如：`0.0-1.0`、`0-999`、枚举集合

- `recommended_baseline`
  - 当前推荐基线值
  - 用于形成第一版策略模板

- `evaluation_meaning`
  - 这条规则具体在判断什么

- `business_rationale`
  - 这条规则为什么存在

- `failure_interpretation`
  - 不满足时代表什么质量问题

- `typical_decision`
  - 常见处理动作
  - 例如：`block`、`manual_review`、`warning`

## 各层级关注范围

### 知识项级字段应覆盖

1. 标识与命名质量
2. 类别与归类质量
3. 定义与语义清晰度
4. 证据充分性
5. 来源支撑充分性
6. 语义一致性与歧义控制

### 关系级字段应覆盖

1. 关系合法性
2. 关系端点正确性
3. 关系证据充分性
4. 关系支持广度
5. 图谱结构合理性

### 发布批次级字段应覆盖

1. 审核完成度
2. 结构完整性
3. 证据覆盖率
4. 支撑多样性
5. 风险项占比
6. 冲突和残缺项阈值

## 不纳入内容质量字段的内容

以下内容不应进入“内容质量标准字段字典”，应在未来单独归入“过程可信度”或“过程可视化”模型：

1. 解析器名称和版本
2. 模型名称和模型版本
3. 分块策略名称
4. prompt 名称和 prompt 版本
5. 工具执行耗时
6. 中间步骤日志
7. 任务运行状态
8. 具体处理链路中的技术实现方式

这些信息仍然必须可见，但它们不应该直接决定知识内容是否达标。

## 使用建议

### 1. 先建立“字段字典”，再建立“策略模板”

先明确有哪些字段、每个字段是什么意思，再讨论不同知识库如何组合这些字段。

### 2. 先把字段定义清楚，再讨论阈值高低

当前阶段重点不是争论每个阈值到底该取 0.6 还是 0.8，而是先把“评估维度”建立起来。

### 3. 每次策略调整必须有版本号和原因

后续任何质量策略变化，都应至少记录：

1. 调整了哪些字段
2. 为什么调整
3. 对哪些知识库生效
4. 从何时生效

## 后续衔接

在本设计之后，后续建议按以下顺序继续推进：

1. 先使用字段字典形成第一版完整字段集合
2. 再从字段集合中抽出第一版策略模板
3. 再讨论哪些字段是硬底线、哪些字段允许按知识库覆盖
4. 最后再映射到前端展示、配置保存和评估结果展示
