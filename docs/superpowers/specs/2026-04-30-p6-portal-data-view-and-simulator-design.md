# P6 五阶段精确数据视图与统一模拟发生器设计

## 背景

当前 `/portal` 语义画布效果已经确认，后续不应把它扩展成密集报表页。新增能力应作为补充页面存在：

- `/portal-data`：同一套 P6 数据源的精确表格 / 图表视图。
- `/xx-p6-sim`：统一五阶段展示合同模拟发生器。

基础事实源仍然是 `P6DisplayExportContract.v2`。图表页不得编造模拟器或未来真实源没有产生的数据。

## 已确认决策

1. `/portal` 保持语义画布定位，只在低干扰位置提供 `/portal-data` 和 `/xx-p6-sim` 入口。
2. `/portal-data` 默认展示五阶段全局表格，不默认进入单阶段详情页。
3. `/portal-data` 的跨阶段流量折线来自模拟发生器记录的历史样本。
4. `/xx-p6-sim` 每次推送一组完整 `P1 ~ P5` 五阶段合同。
5. 每次模拟器推送都在后端内存中记录一条历史样本，供图表页绘制趋势。
6. 首版历史样本不持久化，后端重启后允许清空。

## `/portal-data` 页面结构

首屏包含四个区域：

1. 标题与动作区
   - 标题：五阶段同源数据精确观察
   - 动作：返回 `/portal`、打开 `/xx-p6-sim`
2. 场景摘要
   - 阶段数量
   - 跨阶段流数量
   - 接入用户数量
   - 队列对象数量
   - 历史样本数量
3. 跨阶段流量图
   - `P1 -> P2` 知识
   - `P2 -> P3` 需求规格
   - `P3 -> P4` 模块工单包
   - `P3 -> P5` 设计基线
   - `P4 -> P5` 工具供给
   - `P5 -> 交付目录`
4. 五阶段合同总表
   - 行：`P1` 到 `P5`
   - 列：阶段、总体状态、实时输入 / 处理、输出流、接入用户、队列

点击某一阶段行后，才打开下钻区，展示合同 JSON 摘要、端口明细、`source_trace`、队列项、接入用户和历史样本。

## 模拟历史样本

`P6SimulatorHistorySample` 只在模拟器提交五阶段合同时创建。

最小字段：

- `sample_id`
- `scenario_id`
- `captured_at`
- `stage_contracts`
- `flow_points`
- `source_label`

首版样本保存在后端内存中。没有样本时，`/portal-data` 必须显示空态，不得由前端临时生成趋势。

## 验收标准

实现完成后至少满足：

- `/portal` 可以跳转到两个补充页面，但不改变语义画布主体。
- `/portal-data` 首屏展示 `P1 ~ P5` 五阶段总表。
- 折线图使用历史样本，不使用前端临时推演趋势。
- `/xx-p6-sim` 可以生成五阶段合同，并同步创建历史样本。
- 测试覆盖新增路由、数据派生、无历史样本空态和模拟器推送行为。
