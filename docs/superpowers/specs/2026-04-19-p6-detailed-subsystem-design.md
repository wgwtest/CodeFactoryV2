# P6 分层详细设计落版说明

## 1. 背景

`2026-04-19` 已经完成 `P6` 阶段定位重排，正式确认：

- `P6` 不是“登录 / 权限优先”阶段
- `P6` 的当前主线是：
  - `P6.1` 首屏观察门户
  - `P6.2` 跨阶段只读集成与状态投影
  - `P6.3` 设计语言与前端展示基线
  - `P6.4` 前端展示工具化实验场

上一轮已经把这些结论收敛进 `P6` 总设计与阶段计划，但仍然停留在“总口径成立”的层面，还不足以作为后续实现、验收和 `JB_DOC` 投影的细化来源。因此需要继续拆成可实施的正式专项设计。

## 2. 本轮目标

本轮不写代码，只做三件事：

1. 把 `P6` 总设计继续拆成四份正式专项设计。
2. 修正 `CODEX_DOC` 中仍然残留的旧 `P6` 口径。
3. 为后续 `P6` 实现、`JB_DOC` 投影和 GitHub WBS 同步提供稳定入口。

## 3. 设计拆解结论

### 3.1 `P6.1` 首屏观察门户

`P6.1` 负责独立路由 `/portal` 的全屏蓝图画布。

本轮要把以下内容从总设计中拆成独立正式文档：

- 门户页面的角色定位
- 固定节点集合与元素分层
- 世界坐标、锚点、连线与布局边界
- 单击高亮、双击进入、拖拽、缩放、推荐/个人布局切换
- 门户投影数据模型与首版验收口径

### 3.2 `P6.2` 跨阶段只读集成与状态投影

`P6.2` 不是一个普通页面，而是 `P6` 的读侧集成底座。

本轮要把以下内容拆成独立正式文档：

- `P6` 对 `P1 ~ P5` 的只读边界
- 阶段级标准查询 / 订阅输入契约
- 投影归一、缓存、时效、降级和来源标记规则
- 门户页与串行观察页如何消费投影数据
- 首版按“先查询、后订阅”推进的实施顺序

### 3.3 `P6.3` 设计语言与前端展示基线

`P6.3` 的职责不是抹平所有业务模块，而是统一平台级表达语言。

本轮要把以下内容拆成独立正式文档：

- 跨阶段命名、状态、动作文案基线
- 平台级颜色、层级、间距、动效和信息密度规则
- 总览条、筛选条、卡片、抽屉、图谱视图等共享展示基元
- 哪些地方必须统一，哪些地方允许阶段保留个性
- 渐进式改造的落地规则

### 3.4 `P6.4` 前端展示工具化实验场

`P6.4` 是探索性能力，但不是可有可无的边角料。

本轮要把以下内容拆成独立正式文档：

- 为什么前端展示工具化值得单独立项验证
- 实验对象模型
  - `DisplayWidgetTemplate`
  - `DisplayWidgetBinding`
  - `DisplayWidgetLayout`
  - `DisplayWidgetPreset`
  - `DisplayExperimentRecord`
- 实验流程、记录机制和准入/晋升规则
- 与 `P3 / P4 / P5` 的反哺关系

## 4. 旧口径修正要求

本轮还必须同步修正以下旧口径：

- `P6` 在总纲中仍被写成“门户与平台入口”
- `00-工程总体分析` 里仍把 `P6` 描述成“首页、导航、权限和入口承载”
- `CODEX_DOC 到 JB_DOC` 缺口矩阵里，仍把 `P6.2 / P6.3 / P6.4` 写成登录、权限和导航治理

这些内容如果不一起修正，会导致正式文档根内部自相矛盾。

## 5. 正式文档落点

本轮正式文档落点应为：

- `DOC/CODEX_DOC/02_设计说明/10-P6-门户与平台入口设计.md`
- `DOC/CODEX_DOC/02_设计说明/11-P6.1-首屏观察门户设计.md`
- `DOC/CODEX_DOC/02_设计说明/12-P6.2-跨阶段只读集成与状态投影设计.md`
- `DOC/CODEX_DOC/02_设计说明/13-P6.3-设计语言与前端展示基线设计.md`
- `DOC/CODEX_DOC/02_设计说明/14-P6.4-前端展示工具化实验场设计.md`
- `DOC/CODEX_DOC/04_研制计划/06-WBS-P6-门户与平台入口-研制计划.md`

## 6. 结论

`P6` 的下一轮推进不该再停留在“门户概念”层，而应进入“四个稳定专项设计 + 两个预留能力占位”的结构。

其中：

- `P6.1 ~ P6.4` 要写成正式可实施设计
- `P6.R1 / P6.R2` 继续保留为后置预留能力

只有这样，`P6` 才能既保持当前阶段的实现聚焦，又不把后续平台能力演进写乱。
