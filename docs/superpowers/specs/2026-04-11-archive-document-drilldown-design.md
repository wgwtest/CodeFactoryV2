# 档案文档检索与知识钻取设计

## 背景

当前“已建库档案文档”页面只能展示文档清单和汇总指标，存在两个直接影响检查效率的问题：

1. 用户无法在已建库文档中快速检索目标文件。
2. 用户点击文档后无法看到该文档实际关联了哪些知识，只能看到“4 项知识”这类汇总数字。

这导致文档页只能用于确认“是否入库”，不能用于确认“这篇文档讲了什么、抽到了什么知识、证据是什么”。

## 目标

本次改动的目标是把文档页从“文档台账”提升为“文档知识入口”：

1. 支持按文档标题、来源档案、文件类型快速检索已建库文档。
2. 支持点击文档标题或“查看”按钮，在右侧抽屉中查看该文档关联的知识内容。
3. 在抽屉中按实体、事件、流程分组展示知识，并显示中文释义和当前文档内的证据摘录。
4. 保持现有页面结构稳定，不引入新的独立详情页，不扩展到跨文档联动。

## 非目标

本次不包含以下内容：

1. 不引入文档全文预览。
2. 不新增后端文档搜索接口，文档检索先基于当前清单做前端本地过滤。
3. 不在本次把文档详情与图谱详情做双向联动。
4. 不做 Neo4j 或独立图谱可视化扩展。

## 用户体验设计

### 文档列表

在“已建库档案文档”区域增加搜索框，支持按以下字段做本地模糊过滤：

1. 文档标题
2. 来源档案
3. 文件类型

文档表格做以下调整：

1. “文档标题”列改为可点击操作，点击后打开右侧抽屉。
2. 新增“操作”列，提供统一的“查看”按钮。
3. 原有汇总列保留，包括字符数和关联知识总数。

### 文档详情抽屉

抽屉从右侧展开，默认展示四个信息块：

1. 文档概览
2. 实体
3. 事件
4. 流程

文档概览展示：

1. 文档标题
2. 文件类型
3. 来源档案
4. 字符数
5. 实体数
6. 事件数
7. 流程数
8. 知识总数

知识分组展示规则：

1. 每个分组显示数量。
2. 每条知识至少展示名称、类型标签、中文解释、证据摘录。
3. 如果是架构工件，优先展示解释层中的中文释义和标准名称。
4. 如果某个分组为空，显示“该文档未关联此类知识”。

- `GET /api/knowledge/archive/{archive_id}/documents`

## 后端设计

### 服务层

在 `ArchiveKnowledgeService` 中新增 `get_document_detail(archive_id, document_id)`：

1. 读取档案知识 JSON。
2. 定位目标文档。
3. 统计该文档的实体、事件、流程数量。
4. 扫描实体、事件、流程集合，筛选 `document_ids` 包含当前文档的知识条目。
5. 为每个知识条目附加：
   - `item_type`
   - `interpretation`
   - 仅属于当前文档的 `evidence`
6. 返回文档概览对象和知识条目列表。

### 路由层

在知识路由中新增：

- `GET /api/knowledge/archive/{archive_id}/documents/{document_id}`

如果文档不存在，返回 `404`。

## 前端设计

`DocumentsPage` 保持页面入口不变，新增以下状态：

1. 文档搜索关键字
2. 当前选中的文档 ID
3. 文档详情数据
4. 文档详情加载状态
5. 文档详情错误信息

交互流程：

1. 页面初始化时继续并行加载 summary 和 documents。
2. 用户在搜索框输入时，对已加载文档列表做本地过滤。
3. 用户点击文档标题或“查看”按钮时，发起文档详情请求。
4. 详情加载成功后，在右侧抽屉展示文档概览和知识分组。
5. 详情加载失败时，只在抽屉区域显示错误，不影响主列表继续使用。

## 数据展示规则

知识分组按 `item_type` 拆分为：

1. 实体
2. 事件
3. 流程

每条知识展示优先级：

1. 主标题使用 `name`
2. 次级说明优先使用 `interpretation.display_name`
3. 解释文本使用 `interpretation.summary`
4. 如果存在别名，则展示别名
5. 证据只展示当前文档的摘录

## 错误处理

1. 文档清单加载失败：保持现有整页错误提示。
2. 文档详情加载失败：抽屉内展示错误提示，保留关闭能力。
3. 文档无关联知识：抽屉概览正常显示，三个分组均展示空态说明。
4. 文档不存在：前端显示“文档详情暂不可用”。

## 测试策略

### 后端

新增或扩展 API 测试，覆盖：

1. 文档详情接口可返回文档概览。
2. 文档详情接口只返回当前文档关联的知识。
3. 文档详情接口中的证据摘录仅来自当前文档。
4. 文档不存在时返回 `404`。

### 前端

扩展 `DocumentsPage` 测试，覆盖：

1. 文档清单可正常渲染。
2. 搜索关键字可过滤文档。
3. 点击文档标题可打开详情抽屉。
4. 点击“查看”按钮可打开同一详情抽屉。
5. 抽屉中能看到文档概览、知识解释和证据摘录。

### 端到端

本轮不强制新增 E2E 用例。待文档抽屉交互稳定后，再补充浏览器级验证。

## 风险与约束

1. 当前文档搜索是前端本地过滤，适用于当前演示数据量；未来数据量扩大后需要改为后端分页检索。
2. 当前详情抽屉展示的是“文档关联知识”，不是文档全文语义阅读器，避免本轮范围膨胀。
3. 当前证据质量依赖已有知识构建结果；若部分条目没有摘录，前端应显示空态而不是伪造说明。

## 验收标准

满足以下条件即可视为本轮完成：

1. 用户可在“已建库档案文档”区域通过关键字快速定位目标文档。
2. 用户点击文档标题或“查看”后，可在右侧抽屉看到该文档关联的知识详情。
3. 抽屉中的知识内容至少能回答“这篇文档提到了什么”和“证据在哪里”。
4. 后端和前端测试全部通过，现有页面功能无回归。
