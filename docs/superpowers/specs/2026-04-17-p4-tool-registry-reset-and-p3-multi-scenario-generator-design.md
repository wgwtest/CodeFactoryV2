# P4 工具仓库测试管理与 P3 多场景模拟发生器设计

**日期：** 2026-04-17

**对应节点：**
- `P4.1.2` 工具仓库 CRUD
- `P4.2.2` `P3-sim` 模拟发生器页
- `P4.2.5` 三段联调与回归验证

## 1. 问题定义

当前 `P4` 与 `P3-sim` 已具备最小闭环，但仍有 3 个明显缺口：

- `工具仓库` 页只能新建和编辑工具，不能移除单个工具
- 当前阶段缺少一个临时的“一键移除全部工具”入口，演示与回归时难以快速重置工具池
- `P3-sim` 只能生成固定的 `模拟蓝军` 工单，无法覆盖其他典型业务方向

这三个问题都会直接降低闭环演示效率，并增加测试路径的重复性。

## 2. 设计目标

- 为 `工具仓库` 补齐单个工具移除能力
- 为当前阶段提供临时性的“一键移除全部工具”能力
- 把 `P3-sim` 升级为“典型工单发生器”，支持至少 3 种预置场景
- 保持 `P3 / P4 / P5` 页面解耦，只共享协议对象和 API 契约

## 3. 设计边界

### 3.1 本轮要做

- 新增单工具删除接口与前端按钮
- 新增临时测试接口，用于一键清空工具定义与相关运行记录
- 新增 `模拟蓝军 / 导航规划 / 数据治理` 三类模拟工单预置
- `P3-sim` 页面增加场景选择，再按所选场景生成工单

### 3.2 本轮不做

- 不做工具软删除、回收站、版本回滚
- 不做真实 `P3` 业务建模器
- 不做动态配置化的场景模板管理后台
- 不做工具引用关系的全图治理

## 4. 工具移除语义

### 4.1 单个工具删除

单个工具删除采用 `安全删除` 语义。

后端在删除前必须检查该工具是否仍被当前运行态对象引用，包括但不限于：

- 需求项上的 `recommended_tool_id`
- 需求项 `supply_result.tool_ref`
- 研制计划 `manufactured_tool_id`

若存在引用，则拒绝删除，并返回可解释的错误消息。

### 4.2 一键移除全部工具

该能力明确是 `当前阶段的测试接口`，不是正式业务能力。

执行范围：

- 清空全部工具定义
- 清空工具匹配运行记录
- 清空自演进巡检运行记录

该操作不自动清理工单与工单生命周期数据；工单重置仍由既有测试接口负责。

## 5. P3 多场景模拟发生器

### 5.1 页面职责

`/xx-p3-sim` 继续只负责“按标准对象向 P4 发出工单”，不承担 `P4` 内部处理逻辑。

### 5.2 预置场景

本轮固定增加 3 个预置场景：

- `simulated_blue_force`：模拟蓝军
- `navigation_planning`：导航规划
- `data_governance`：数据治理

### 5.3 生成方式

页面先选场景，再调用对应的模拟生成接口。

后端按场景返回独立的 `ToolDemandSheetCreateRequest` 模板，再走与现有工单完全一致的受理逻辑。

## 6. 数据与接口

本轮建议新增或补齐：

- `DELETE /api/tool-hub/tools/{tool_id}`
- `POST /api/tool-hub/testing/clear-tools`
- `POST /api/tool-hub/mock-generators/demand-sheets/{scenario_id}`

兼容性要求：

- 现有 `blue-force` 专用模拟接口可保留为兼容别名
- 现有 `tools` 读模型、`demand_sheets` 读模型、`P5` 查询协议不变

## 7. 页面影响

### 7.1 `P4`

在 `工具仓库` 页：

- 工具列表增加“移除工具”操作列
- 顶部操作区增加“测试清空全部工具”按钮
- 关键按钮补充稳定 DOM id

### 7.2 `P3-sim`

页面从“模拟蓝军需求发生器”升级为“典型工单发生器”：

- 新增场景选择器
- 生成按钮名称与说明文案改为通用表述
- 已生成工单列表与撤销能力保持不变

## 8. 验收标准

- 用户可以在 `工具仓库` 删除未被引用的工具
- 删除已被引用工具时，页面收到明确失败原因
- 用户可以一键清空当前工具池和相关运行记录
- `P3-sim` 可以在 3 个典型场景间切换并生成对应工单
- 生成后的工单仍可被 `P4` 受理、被 `P5` 查询
