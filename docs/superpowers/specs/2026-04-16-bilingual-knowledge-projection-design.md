# 双语知识投影设计

**日期：** 2026-04-16

**设计目标：** 在不改变正式知识抽取主链的前提下，为已抽取的知识对象补充双语标准化字段和中文解释视图，使知识治理与图谱浏览更直观、更可追溯。

## 1. 背景

当前正式知识抽取链路已经明确固定为：

`Docling -> 结构化大模型抽取 -> 分块归并 -> 治理 -> 发布`

这条链路的目标是保证知识抽取准确性和证据可追溯性。对于英文为主的原始资料，如果在抽取前做全文翻译，会引入术语漂移、缩写误译、表格语义丢失等问题，因此不适合作为正式建库主链。

但在治理和展示阶段，用户确实需要更直观的中文解释，否则会出现如下问题：

- 看到 `SV-8`、`OV-1`、`NAS` 等对象时无法立刻判断其含义
- 看到英文对象时不知道中文对应概念
- 知识图谱详情里只有原名和关系，缺少“中文解释 / 英文原名 / 缩写 / 当前中文化状态”

因此需要在 `P1.3` 与 `P1.5` 之间增加一层“**双语知识投影**”，作为治理与展示增强层，而不是抽取主链替代层。

## 2. 节点归属

该能力挂载到 `P1.3 候选知识抽取` 下，新增子节点：

- `P1.3.6` 双语术语标准化与中文映射

原因：

- 该层的输入是 `P1.3` 已产生的结构化知识对象
- 该层输出的是标准化后的双语元数据视图
- `P1.4` 治理和 `P1.5` 图谱展示都消费这层结果，但不依赖其内部实现方式

## 3. 设计原则

- 正式知识库抽取主链不变，不采用“全文先翻译再抽取”
- 双语结果必须保留原文对象、原文别名和原文证据
- 编号类对象、架构工件号、缩写不做硬翻译，只补中文解释
- 双语字段属于增强元数据，不能覆盖正式抽取原值
- 所有中文化结果必须可追溯到原对象和证据
- 后续可由规则、词典、人工治理、结构化大模型共同增强，但对外契约保持稳定

## 4. 数据模型

为知识对象新增 `language_projection` 字段，结构如下：

- `display_name_zh`
- `display_name_en`
- `acronym`
- `aliases_zh`
- `aliases_en`
- `description_zh`
- `evidence_summary_zh`
- `translation_status`
- `translation_confidence`

字段语义说明：

- `display_name_zh`：默认展示中文名。若对象本身是中文对象，可直接复用对象名或中文释义
- `display_name_en`：英文原名或标准英文名
- `acronym`：如 `NAS`、`FAA`、`ATCT`
- `aliases_zh / aliases_en`：按语言拆分的别名集合
- `description_zh`：面向阅读与治理的中文解释，不替代原文定义
- `evidence_summary_zh`：从原文证据中提炼的中文摘要
- `translation_status`：`none | derived | generated | curated`
- `translation_confidence`：当前中文化结果可信度

## 5. 最小实现范围

本轮不做全文机器翻译，也不新增批量翻译任务。

本轮只完成：

1. 后端为已发布知识对象生成 `language_projection`
2. 图谱详情、治理详情、流程详情可以展示双语字段
3. 列表/详情检索后续可消费这些字段
4. 当前状态明确标记为“推导生成”还是“人工治理”

最小生成策略：

- 优先复用现有 `interpretation` 中的中文释义和标准名
- 从对象名与别名中识别英文名、中文名和缩写
- 从证据摘录中提炼简短中文摘要
- 无法可靠识别时返回空值，并将 `translation_status` 标记为 `none`

## 6. 与后续能力的关系

本轮只是建立“双语投影契约”和“前端可见性”。

后续增强可以继续演进为：

- 术语词典驱动的标准翻译
- 人工治理覆写双语字段
- 大模型辅助生成 `description_zh / evidence_summary_zh`
- 中文、英文、缩写三路统一检索

这些增强都属于对 `P1.3.6` 内部实现的升级，不应影响 `P1.4 / P1.5` 的消费接口。

## 7. 当前页面呈现方案

针对当前“知识图谱 -> 列表视图”页面，双语投影不只放在详情抽屉中，也需要直接进入主表，降低用户逐条点开详情的成本。

主表列顺序调整为：

`名称 | 类型 | 类别 | 投影 | 释义 | 别名 | 覆盖文档 | 操作`

其中“投影”列固定放在“类别”后、“释义”前。

“投影”列的展示规则如下：

- 第一行：`display_name_zh`，作为中文主名
- 第二行：`display_name_en / acronym`，用于展示英文原名和缩写
- 第三行：`translation_status`，必要时可配合轻量标签显示

“释义”列继续承担较长的解释性文本，不与“投影”列混排，避免主表信息层级混乱。

这样可以形成稳定分工：

- “投影”列回答“它中文叫什么 / 英文叫什么 / 缩写是什么”
- “释义”列回答“它到底是干什么的”
- 详情抽屉继续承载完整双语投影、证据、关系结构和关系邻域

该布局属于当前页面的正式设计约束，后续实现不采用“把投影内容混入释义列”的压缩方案。
