# 慢速抽取验收源

## 目的

这份文档用于固定一套“慢速抽取”验收流程，专门验证单知识库 / 单文档运行页的实时表现。

它不是新的抽取业务逻辑，也不是正式评测集；它的作用是把抽取过程故意拉慢，让页面可以被肉眼观察和自动脚本监控：

- 当前阶段是否真实随后端推进
- runtime stream 是否优先连接
- stream 断线时是否回退轮询
- 页面实时更新时是否没有整页刷新
- 图谱、流程导航、观察窗是否跟随阶段变化
- 质量门禁和发布候选状态是否能解释清楚

慢速配置内容：

```json
{
  "enabled": true,
  "stage_delay_ms": 3000,

```

`.data` 是本地运行数据目录，按仓库规则不提交到 Git。若换机器或清理 `.data`，可以用任意一组 DOCX / PDF 文档重新创建同名目录，并补上上面的 `.cfv2-runtime-slow.json`。

## 创建验收知识库

1. 启动后端与前端服务。
2. 打开 `http://127.0.0.1:5173/archives`。
3. 新建知识库，源目录选择慢速验收源目录。
4. 创建后立即点击开始抽取。
5. 进入该知识库的单文档运行页，选择当前正在处理的文档。

推荐命名：

```text
semantic-slow-YYYYMMDD-HHMMSS
```

这样可以和 `.data/knowledge_output` 里的运行产物对应起来。`.logs` 只用于本地截图、调试日志和验收矩阵，不提交到 Git。

## 页面验收点

### 不允许整页刷新

实时抽取过程中，页面应该只做局部状态更新，不应发生整页刷新、路由重载或白屏重建。

通过标准：

- 当前 URL 不应在运行中跳回 `/archives` 首页
- 浏览器不应触发 `beforeunload`
- 页面头部、左侧知识库选择、单文档页布局应保持稳定
- 阶段变化、图谱变化和观察窗变化应在当前页面内完成

失败信号：

- 页面整体闪烁或回到列表页
- 当前选择的知识库 / 文档丢失
- 运行中阶段重新从初始态开始渲染

### 实时连接状态

运行中优先显示 stream 连接状态。

通过标准：

- 正常情况下显示类似“已连接 stream”的运行提示
- stream 不可用时，显示“已回退轮询”
- 抽取完成后可以切回静态快照状态

失败信号：

- 运行中只显示静态快照
- stream 失败后没有明确回退提示
- 回退轮询后状态不再推进

### 当前阶段

流程导航中的“当前阶段”必须来自真实后端运行状态，而不是用户点击。

通过标准：

- 未到达阶段保持未进入 / 灰色状态
- 已完成阶段可点击查看历史快照
- 点击历史阶段只切换查看快照，不改变真实当前阶段
- 正在执行的阶段始终保持当前态

失败信号：

- 点击任意阶段后，该阶段被误标为当前阶段
- 后端已经推进，但页面仍停留在旧阶段
- 运行完成后无法回看已完成阶段快照

### 图谱语义表达

图谱应表达“阶段输入对象 -> 策略 / 动作依据 -> 输出对象”，而不是只堆叠对象节点。

通过标准：

- 默认是语义聚合视图，不一上来铺满所有明细节点
- 主链节点之间保持可读间距
- 节点文字在节点内，不应大面积外溢
- 节点入场和状态变化有可感知动画
- 密集阶段通过集合节点和局部展开降低线海
- 选中节点 / 边后，高亮层级和右侧观察窗内容同步变化
- 质量门禁阶段能看出哪组策略和规则命中导致放行、警告或阻断发布候选

失败信号：

- 节点挤在同一区域，无法阅读
- 边线折叠或起终点明显错误
- 图谱只显示抽象阶段节点，没有显示阶段内对象转换
- 选中图谱对象后，观察窗内容不跟随变化

### 发布候选状态

`indexes_snapshots_apis` 阶段展示的是机器发布候选，不是正式入库完成。

通过标准：

- 能看到“机器已发布候选”
- 能看到“等待治理确认”
- 能区分“尚未正式入库”和“已正式入库”
- `/governance` 读取的是发布候选知识，而不是抽取中的临时节点

失败信号：

- 质量门禁后被误表达为已经正式入库
- `/governance` 看不到发布候选
- 人工治理确认前就生成正式入库版本

## 后端验收点

慢速验收不是只看前端动画，后端也必须提供真实运行支撑。

需要确认：

- runtime stream 事件包含当前阶段、阶段状态、策略快照、质量门禁结果
- 单文档 runtime API 能返回 13 阶段快照
- 质量门禁结果包含 `policy`、`metrics`、`rule_hits`、`decision`
- 发布阶段包含门禁决策、发布快照、索引 / API 暴露范围、治理确认状态
- `/governance` 只消费发布候选，不消费抽取过程临时节点

## 下一步使用方式

后续每次修改以下能力，都至少跑一次慢速验收源：

- runtime stream / fallback polling
- 单文档流程导航
- 单文档图谱布局与交互
- 阶段策略执行
- 质量门禁
- 发布候选与治理确认衔接

如果慢速验收失败，优先修复真实运行链路和 runtime 事件字段，再修前端展示。不要用前端假状态掩盖后端没有提供的数据。
