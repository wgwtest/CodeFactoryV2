# P6 阶段定位重排设计

## 背景

现有 `P6` 正式文档已经完成了 `P6.1 门户蓝图画布` 的归档，但阶段定位仍偏向“门户 / 登录 / 权限入口层”。

结合本轮讨论，`P6` 的真实职责需要重新收敛：

- 它首先是一个首屏观察与平台观察层
- 它其次是一个跨阶段只读集成层
- 它还承担一个前端展示工具化实验层

这里最关键的变化是：

- `P6` 不再以登录 / 权限为当前主线
- `P6` 不对 `P1 ~ P5` 反写数据
- `P6` 只消费 `P1 ~ P5` 暴露出的规范化查询 / 订阅接口
- `P6.4` 的实验结果要能反哺 `P3 / P4 / P5`

## 对应节点

- `P6` 平台门户、观察与前端展示实验层
- `P6.1` 首屏观察门户
- `P6.2` 跨阶段只读集成与状态投影
- `P6.3` 设计语言与前端展示基线
- `P6.4` 前端展示工具化实验场

后置预留能力：

- `P6.R1` 统一登录接入
- `P6.R2` 权限与角色控制

## 核心设计结论

### 1. P6 采用“两层结构”

第一层是稳定平台层：

- `P6.1` 首屏观察门户
- `P6.2` 跨阶段只读集成与状态投影
- `P6.3` 设计语言与前端展示基线

第二层是探索验证层：

- `P6.4` 前端展示工具化实验场

这样划分的好处是：

- 平台入口与观察能力保持稳定
- 前端展示工具化实验可以快速试错
- `P6` 不会因为探索功能不断膨胀成大杂烩

### 2. P6 对 P1 ~ P5 保持只读边界

`P6` 的关键边界必须明确固定为：

- 只读查询
- 可选订阅
- 不反写
- 不驱动业务推进

`P6` 可以做的事：

- 读取 `P1 ~ P5` 的阶段状态
- 读取各阶段概览、摘要、指标和入口状态
- 订阅阶段状态变化并刷新显示
- 把这些数据投影成门户、总览卡片和串行观察页

`P6` 不能做的事：

- 修改 `P1 ~ P5` 内部事实状态
- 代替任一阶段触发业务命令
- 回写设计语义、工具语义或构建状态

### 3. P1 ~ P5 必须面向 P6 提供规范化读接口

为了支撑 `P6`，各阶段应当暴露标准化读接口或投影接口。

首版优先支持两类：

- 查询接口：概览、详情、健康度、入口可用性
- 订阅接口：阶段状态变更、关键指标更新、运行告警

首版不强制各阶段立即实现真实订阅总线，但必须在设计上明确：

- `P6` 消费的是标准状态投影
- 不是页面私有状态
- 更不是数据库直连

### 4. P6 承担平台级设计语言统一职责

因为 `P1 ~ P5` 已被定义成五个可独立运行、可独立打开的工具，所以它们不要求业务耦合，但需要：

- 统一命名口径
- 统一状态表达
- 统一指标卡、总览条、抽屉、列表、图形和入口按钮的语言
- 统一平台级视觉 token、节奏、层级与交互反馈

`P6` 在这里不是替各阶段重做页面，而是沉淀：

- 一套可复用的设计语言规则
- 一套平台级前端展示基线

### 5. P6.4 是前端展示工具化实验场

`P6.4` 是本轮最重要的新定位之一。

它的职责不是做一个普通首页，而是验证：

- 页面中的展示卡片能否被工具化
- 展示单元能否模块化、可绑定、可替换、可组合
- 同一张串行观察页能否通过配置快速变成不同的展示形态

因此 `P6.4` 本质上是在用平台首屏和串行观察页，验证“前端展示层如何工具化”。

这个实验层的成果，要反哺：

- `P3`：软件设计阶段对前端展示模块的表达方式
- `P4`：前端展示工具 / 组件的生产方式
- `P5`：最终软件构建时的前端装配方式

### 6. 登录 / 权限属于后置预留能力

`P6.R1 / P6.R2` 不是不重要，而是：

- 它们对最终平台是必要的
- 但对当前原型验证不是主矛盾
- 过早强化权限流会显著增加演示阻力和验证噪声

因此当前建议是：

- 文档中保留其预留地位
- 不把它们当作 `P6` 当前主线
- 仅在后续从原型验证转向正式平台化时再拉起

## 首版实现指向

### P6.1 首屏观察门户

- 路由：`/portal`
- 提供首屏平台蓝图
- 串起 `P1 ~ P5` 主链节点与主数据流
- 双击进入阶段页面
- 不承担业务编辑

### P6.2 跨阶段只读集成与状态投影

- 统一读取 `P1 ~ P5` 的概览接口
- 汇总阶段状态、入口状态、指标摘要、健康信息
- 为门户和串行观察页提供只读投影源

### P6.3 设计语言与前端展示基线

- 定义卡片、总览条、状态徽标、图谱节点、抽屉、表格和工作台容器的统一语言
- 明确哪些组件属于平台共性展示基元
- 明确哪些组件仍保留阶段个性

### P6.4 前端展示工具化实验场

- 支持卡片模板化
- 支持卡片数据绑定
- 支持可切换布局与组合
- 形成可回写到 `P3 / P4 / P5` 的实验记录

## 非目标

- 不把 `P6` 做成新的业务中台
- 不让 `P6` 承担跨阶段写操作协调
- 不在当前轮次实现完整登录体系
- 不在当前轮次实现严格权限系统
- 不在当前轮次把 `P6.4` 直接宣告为正式产品能力
