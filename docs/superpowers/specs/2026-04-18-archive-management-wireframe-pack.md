# 知识库管理页低保真线稿包

## 文档目的

本文件是“知识库管理页重构蓝图”的 `Pencil-ready` 低保真线稿方案。

本轮目标仅限于：

1. 固定页面级结构
2. 固定信息层次
3. 固定主场景下的用户操作路径
4. 深入设计“抽取运行中心”

本轮不涉及：

1. 最终视觉风格
2. 组件库选择
3. 实际前端实现
4. 高保真视觉稿

本文件应作为 `Pencil` 线稿制作前的直接依据，并在人工评审通过后再进入实现阶段。

## 当前轮次的设计方向

本轮采用单一路线：

- `Calm Operations Console`

其含义是：

1. 先强调结构、监控和层次
2. 先用清晰的台面分区表达“发现问题 -> 定位问题 -> 解释问题”
3. 暂不引入复杂视觉修饰

反例方向：

- 花哨大屏式监控面板
- 大量炫技图表压过处理链信息
- 把文档级细节默认铺满首页

## 全局导航模型

```text
+--------------------------------------------------------------------------------------+
| Logo / 产品名 | 知识库总览 | 抽取运行中心 | 策略 / 质量 | 当前知识库切换 | 用户区 |
+--------------------------------------------------------------------------------------+
| 面包屑 / 页面标题 / 状态标签 / 主操作按钮                                               |
+--------------------------------------------------------------------------------------+
| 页面主体                                                                              |
+--------------------------------------------------------------------------------------+
```

导航原则：

1. 一级导航固定三页
2. 当前知识库切换器始终在顶栏
3. “发起新运行”只在总览和运行中心出现
4. “策略 / 质量”不承担运行操作按钮

## 页面一：知识库总览

### 屏幕信息卡

- `screen_name`: `01-archive-overview-v1`
- `user_goal`: 快速判断当前有哪些知识库、哪个最需要关注、下一步进入哪里
- `page_role`: 发现问题与导航入口
- `main_cta`: 进入抽取运行中心
- `secondary_actions`: 切换知识库、进入策略/质量、发起新运行
- `what_to_borrow`: 清晰控制台首页、风险优先排序、摘要卡 + 列表组合
- `what_to_avoid`: 把运行明细和文档细节铺到首页

### 页面级线稿

```text
+--------------------------------------------------------------------------------------------------+
| 顶栏：全局导航 / 当前知识库切换 / 发起新运行                                                    |
+--------------------------------------------------------------------------------------------------+
| 页面标题：知识库总览                                      [状态说明] [进入运行中心] [发起新运行] |
+--------------------------------------------------------------------------------------------------+
| A. 当前知识库卡                                                                                  |
| 名称 | archive_id | 激活状态 | 来源目录 | 当前状态 | 最近更新时间                                |
| 最近一次运行摘要：成功 X / 跳过 X / 失败 X / 告警 X                                               |
+--------------------------------------------------------------------------------------------------+
| B. 全局状态摘要条                                                                                |
| 总知识库数 | 运行中 | 异常中 | 需要人工关注 | 已可用                                            |
+--------------------------------------------------------------------------------------------------+
| C. 重点关注区                                                                                    |
| [最值得关注的知识库卡 1] [最值得关注的知识库卡 2] [最近异常摘要]                                  |
+--------------------------------------------------------------------------------------------------+
| D. 知识库列表                                                                                    |
| 名称 | 当前状态 | 最近一次运行时间 | 最近运行结果 | 是否异常 | 下一步入口                                |
| ----------------------------------------------------------------------------------------------  |
| nas-a | ready | ... | 成功/跳过/告警摘要 | 否 | [进入运行中心] [查看策略]                      |
| ...                                                                                        ...   |
+--------------------------------------------------------------------------------------------------+
| E. 最近运行摘要                                                                                  |
| 最近运行 1 | 知识库 | 状态 | 结果摘要 | [查看运行]                                               |
| 最近运行 2 | 知识库 | 状态 | 结果摘要 | [查看运行]                                               |
+--------------------------------------------------------------------------------------------------+
```

### 这页要证明什么

1. 用户不进运行中心也能知道哪里有风险
2. 用户能自然从“库”切到“运行”
3. 首页不被细节淹没

### 关键状态

1. 正常态：大部分知识库正常
2. 异常态：一个或多个知识库异常，高风险卡片置顶
3. 空态：还没有知识库

## 页面二：抽取运行中心总入口

### 屏幕信息卡

- `screen_name`: `02-run-center-global-v1`
- `user_goal`: 在多库并行运行时先看整体，再决定聚焦哪个知识库
- `page_role`: 全局运行监控入口
- `main_cta`: 聚焦某个知识库运行
- `secondary_actions`: 查看最近异常、按状态过滤、进入策略解释
- `what_to_borrow`: 运维控制台首页的“全局 -> 单对象”过渡方式
- `what_to_avoid`: 一上来就打开单文档详情

### 页面级线稿

```text
+--------------------------------------------------------------------------------------------------+
| 顶栏：全局导航 / 当前知识库切换 / 发起新运行                                                    |
+--------------------------------------------------------------------------------------------------+
| 页面标题：抽取运行中心                                [运行过滤器] [只看异常] [发起新运行]        |
+--------------------------------------------------------------------------------------------------+
| A. 全局并行运行总览                                                                              |
| 并行运行总数 | 正常 | 阻断 | 异常 | 等待中 | 最值得关注运行                                      |
+--------------------------------------------------------------------------------------------------+
| B. 当前运行矩阵                                                                                  |
| 知识库 | run_id | 当前阶段 | 当前状态 | 最近告警/阻断 | 处理中文档数 | [聚焦查看]                    |
| ----------------------------------------------------------------------------------------------  |
| nas-a | run-... | Evidence Pack | blocked | 质量门禁命中 2 | 24/68 | [进入单库视图]              |
| ...                                                                                        ...   |
+--------------------------------------------------------------------------------------------------+
| C. 全局告警与阻断摘要                                                                            |
| 告警列表摘要 | 失败列表摘要 | 阻断列表摘要                                                        |
+--------------------------------------------------------------------------------------------------+
| D. 快速解释入口                                                                                  |
| [查看本次最常见阻断规则] [查看质量门禁说明] [查看某库策略]                                       |
+--------------------------------------------------------------------------------------------------+
```

### 这页要证明什么

1. 运行中心默认先看“整体运行态”
2. 用户能先定位到哪一个知识库出问题
3. 告警、失败、阻断是三个不同层次

### 关键状态

1. 并行运行态
2. 全局空闲态
3. 多库异常态

## 页面三：抽取运行中心单知识库视图

### 屏幕信息卡

- `screen_name`: `03-run-center-archive-v1`
- `user_goal`: 在选定知识库后，看清这次 run 卡在哪、各阶段发生了什么、文档分布如何
- `page_role`: 单知识库运行详情页
- `main_cta`: 下钻某篇文档
- `secondary_actions`: 查看规则解释、切换到其他 run、重新运行
- `what_to_borrow`: 产品工作台的“主时间线 + 队列 + 侧边摘要”布局
- `what_to_avoid`: 把所有文档都展开成长列表细节页

### 页面级线稿

```text
+--------------------------------------------------------------------------------------------------+
| 顶栏：全局导航 / 当前知识库切换 / 返回全局运行中心 / 发起新运行                                 |
+--------------------------------------------------------------------------------------------------+
| 页面标题：nas-a / 当前运行详情                           [切换 run] [查看策略] [重新运行]         |
+--------------------------------------------------------------------------------------------------+
| A. 运行头部卡                                                                                   |
| run_id | 运行类型 | 开始时间 | 当前阶段 | 总体状态 | 最近更新时间                                 |
+--------------------------------------------------------------------------------------------------+
| B. 阶段流水主区                                                                                 |
| [01 Asset Intake] -> [02 Parser Router] -> [03 Parser Execution] -> ... -> [12 Gate] -> [13 Publish] |
| 每阶段卡：状态 / 输入摘要 / 输出摘要 / 工具摘要 / 用时 / 可展开                                   |
+--------------------------------------------------------------------------------------------------+
| C. 主体双栏                                                                                     |
| 左：文档处理队列                                                                                 |
| - 待处理 / 进行中 / 成功 / 跳过 / 失败 切换                                                      |
| - 文档表：名称 | 当前阶段 | 状态 | 结果 | 最新原因 | [查看详情]                                   |
|                                                                                                  |
| 右：运行结果与风险摘要                                                                           |
| - 质量命中结果摘要                                                                               |
| - 阻断命中摘要                                                                                   |
| - 人工复核摘要                                                                                   |
| - 告警与失败摘要                                                                                 |
+--------------------------------------------------------------------------------------------------+
| D. 底部辅助区                                                                                   |
| 最近阻断事件时间线 | 最近失败文档 | 最近跳过文档                                                  |
+--------------------------------------------------------------------------------------------------+
```

### 这页要证明什么

1. 单知识库运行视图不是文档页，而是“阶段 + 队列 + 风险”的组合页
2. 质量命中结果属于运行侧，不属于策略配置侧
3. 用户可以在不进入文档详情的情况下完成大部分定位

### 关键状态

1. 正在运行
2. 阻断中
3. 完成待治理
4. 完成可发布

## 页面四：抽取运行中心文档下钻

### 屏幕信息卡

- `screen_name`: `04-run-center-document-drilldown-v1`
- `user_goal`: 看清某篇文档在整条处理链里的具体经历，以及为什么被纳入、跳过或阻断
- `page_role`: 文档级处理轨迹页或抽屉
- `main_cta`: 返回单库运行视图
- `secondary_actions`: 查看命中规则、查看原文证据、切换上下文文档
- `what_to_borrow`: 分阶段审计视图
- `what_to_avoid`: 用一个超长结果表替代阶段结构

### 页面级线稿

```text
+--------------------------------------------------------------------------------------------------+
| 文档详情抽屉 / 独立详情页                                                                        |
+--------------------------------------------------------------------------------------------------+
| 头部：文档名称 | 文档类型 | 当前状态 | 当前阶段 | 最终结果 | [查看规则] [查看原文]                       |
+--------------------------------------------------------------------------------------------------+
| A. 文档处理阶段时间线                                                                            |
| Asset Intake -> Parser Router -> Parser Execution -> Unified Document -> Evidence -> Chunk -> ... |
+--------------------------------------------------------------------------------------------------+
| B. 分阶段折叠区                                                                                  |
| 1. 原始文件信息                                                                                  |
| 2. 解析摘要                                                                                      |
| 3. 证据构造摘要                                                                                  |
| 4. chunk / evidence pack 摘要                                                                    |
| 5. 候选知识摘要                                                                                  |
| 6. 关系 / 家族归一摘要                                                                           |
| 7. 定义 / 冲突整合摘要                                                                           |
| 8. Canonical 归并结果                                                                            |
| 9. Quality Gate 结果                                                                             |
+--------------------------------------------------------------------------------------------------+
| C. 底部结论区                                                                                    |
| 最终结论：纳入 / 跳过 / 失败 / 人工复核                                                          |
| 原因摘要：内容问题 / 规则问题 / 实现问题                                                         |
| 下一步：返回运行中心 / 查看策略定义                                                              |
+--------------------------------------------------------------------------------------------------+
```

### 这页要证明什么

1. 文档详情必须按阶段组织
2. 质量 gate 结果必须和文档处理链在同一视图里
3. 用户能区分“内容没过”和“策略拦住了”

### 关键状态

1. 成功纳入
2. 被跳过
3. 解析失败
4. 质量门禁阻断
5. 待人工复核

## 关键用户流

### 流一：发现异常库

```text
知识库总览
  -> 看“重点关注区”与“知识库列表”
  -> 选择异常库
  -> 进入抽取运行中心全局视图
  -> 聚焦单知识库运行视图
```

### 流二：解释为什么没入库

```text
抽取运行中心单知识库视图
  -> 在文档队列或阻断摘要中找到目标对象
  -> 打开文档下钻视图
  -> 查看 Quality Gate 结果
  -> 跳到策略 / 质量查看对应规则
  -> 返回运行中心做判断
```

## 关键状态覆盖

本轮线稿至少需要在 `Pencil` 中补出以下状态：

1. 总览页空态
2. 总览页异常态
3. 运行中心全局并行运行态
4. 单知识库运行阻断态
5. 文档详情中的“质量门禁阻断”态

## 本轮评审重点

在进入实现前，评审者至少需要确认：

1. 三个页面拆分是否合理
2. 运行中心默认先看全局、再聚焦单库的结构是否正确
3. 质量命中结果放在运行中心是否正确
4. 文档详情是否应该继续保持抽屉，还是升级为独立页面
5. 策略 / 质量页是否已经足够纯粹，没有混入运行态内容

## 本轮开放问题

1. 单文档下钻更适合抽屉还是独立路由页
2. 单知识库运行视图的右侧“运行结果与风险摘要”是否需要固定侧栏
3. 全局并行运行视图是否需要默认展示历史运行切换

## 抽取运行中心的线稿约束补充

这部分用于覆盖当前已有线稿中的默认进入关系。如果现有线稿与下面规则冲突，以这里为准。

### 一、三张页面分别对应三种颗粒度

1. `02-run-center-global-v1`  
   对应第一颗粒度：全局并行运行视图。

2. `03-run-center-archive-v1`  
   对应第二颗粒度：单知识库运行视图。

3. `04-run-center-document-drilldown-v1`  
   对应第三颗粒度：单文档处理下钻视图。

### 二、默认跳转规则

1. 从“知识库总览”点击某个知识库  
   默认进入 `03-run-center-archive-v1`，而不是 `02-run-center-global-v1`。

2. `02-run-center-global-v1`  
   只作为抽取运行中心的总入口、顶层导航入口或返回入口，不作为从总览进入具体知识库时的默认着陆页。

3. `04-run-center-document-drilldown-v1`  
   只能从 `03-run-center-archive-v1` 的文档队列进入。

### 三、后续线稿调整原则

1. `02-run-center-global-v1` 要强调“多库并行监控”。
2. `03-run-center-archive-v1` 要强调“阶段 + 队列 + 风险”。
3. `04-run-center-document-drilldown-v1` 要强调“单文档处理轨迹”。
4. 后续如果重构抽取运行中心，优先保证 `03-run-center-archive-v1` 成为知识库总览的默认落点。

## 详情面板的线稿约束补充

### 一、详情面板必须支持流输出主区

后续重画抽取运行中心时，右侧详情面板不能只画成静态字段卡。需要预留一块明显更大的“流输出主区”，用于承接：

- 持续分析文本
- 处理中间说明
- 规则评估输出
- 阻断与告警形成过程
- 人工复核提示

### 二、详情面板的视觉层级

线稿中应按以下顺序组织：

1. 顶部：阶段标题 + 状态 + 当前对象
2. 中部主区：流输出区域
3. 底部或侧下区：结构化字段摘要
4. 末尾：动作入口与下钻入口

### 三、降级规则

如果当前阶段没有流输出，则详情面板退回静态结构化视图；但线稿仍需保留这块区域，以保证后续支持流式展示时无需重构整体布局。
