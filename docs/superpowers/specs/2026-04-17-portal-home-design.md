# P6.1 门户蓝图画布设计

## 背景

当前系统已经具备 `P1` 知识库链路、`P2` 需求分析、`P3` 设计表达、`P4` 工具中台与 `P5` 构建入口的业务页面，但缺少一个能够从平台层统一表达这些模块关系、运行态势和入口路径的顶层门户。

上一版门户试验稿属于“页面化门户”路线：顶部大表头 + 绝对定位 DOM 卡片 + 中心点连线。这种实现适合验证概念，不适合承载用户期待的“蓝图式、全屏、可缩放、可拖拽、强流动感”的平台门户，因此需要重新归档并升级到 `P6.1`。

## 对应节点

- `P6` 门户、登录与权限平台层
- `P6.1` 门户蓝图画布
- `P6.2` 登录接入（占位）
- `P6.3` 权限与角色控制（占位）
- `P6.4` 平台级入口与导航治理（占位）

## 目标

- 在独立路由 `/portal` 提供一个真正的全屏门户蓝图画布，不进入现有 `MainShell`
- 用统一蓝图视口表达 `P1 ~ P5` 与“行业用户”之间的空间关系和数据流动
- 交互上采用 `单击高亮 / 双击进入`，不再使用信息遮挡型弹窗
- 画布支持拖拽节点、本地记忆布局、背景平移与缩放
- 门户本身明确归属于 `P6.1`，与 `P1 ~ P5` 的业务页面解耦
- 在画布右下角使用小型图例表达 `P6` 平台层身份，以及 `P6.2 ~ P6.4` 的后续占位

## 非目标

- 本轮不实现真正登录页
- 本轮不实现角色权限校验
- 本轮不把业务编辑能力搬进门户
- 本轮不支持多人协同编辑蓝图
- 本轮不做后端持久化视口和布局

## 技术路线

### 路线选择

采用“**蓝图画布混合实现**”路线，而不是普通页面式门户：

- 视口层：统一的世界坐标、平移、缩放能力
- 节点层：React/DOM 节点卡片，承载丰富文本与状态
- 连线层：与视口同坐标系的图形层，基于锚点 / pin 计算连线
- 特效层：流光、脉冲、网格和氛围光

之所以不用纯 `Canvas/WebGL`，是因为门户节点需要承载较多文字、指标与交互，纯画布会让可维护性和可读性明显变差。

### 明确放弃的旧路线

以下能力属于上一版试验稿，当前已被明确放弃：

- 顶部大表头 + 说明区
- “点击节点打开摘要卡片”交互
- 以节点中心点作为连线起止点
- 把门户视为普通页面，而不是平台蓝图画布

## 信息架构

### 路由

- 独立路由：`/portal`
- 不进入当前顶栏导航壳层
- 仅作为平台入口页，不替换各业务模块页

### 节点集合

门户画布中固定展示以下节点：

- `行业用户`
- `业务知识库（P1）`
- `需求分析系统（P2）`
- `软件设计系统（P3）`
- `工具仓库 / 工具中台（P4）`
- `软件构建系统（P5）`

`P6` 本身不作为一块和 `P1 ~ P5` 并列的大节点出现，而作为画布的**所属平台层**，通过右下角图例表达。

### 连线集合

初版固定表达以下主路径：

- 行业用户 -> 需求分析系统
- 业务知识库 -> 需求分析系统
- 需求分析系统 -> 软件设计系统
- 软件设计系统 -> 工具中台
- 工具中台 -> 软件构建系统
- 软件设计系统 -> 软件构建系统

## 画布模型

### 世界坐标与视口

- 节点位置保存在统一世界坐标中
- 画布提供视口平移与缩放能力
- 节点拖拽时更新的是世界坐标，而不是页面像素位置
- 连线与节点共同处于同一世界坐标系下，避免缩放和尺寸变化造成错位

### 锚点 / Pin 模型

每个模块节点必须至少有以下锚点：

- 输入锚点（左侧）
- 输出锚点（右侧）

必要时允许：

- 顶部锚点
- 底部锚点

连线必须从锚点出发，而不是从节点中心点出发。这是蓝图感的核心约束之一。

## 交互设计

### 单击节点

- 只做高亮，不弹出摘要卡片
- 高亮当前节点及其关联连线

### 双击节点

- 直接进入对应模块页面

默认映射：

- `P1 -> /graph`
- `P2 -> /requirements`
- `P3 -> /modeling`
- `P4 -> /xx-p4`
- `P5 -> /build`

### 拖拽节点

- 支持自由拖拽
- 拖拽结果写入本地存储
- 刷新后保持个人布局

### 拖动画布

- 支持背景拖拽平移
- 支持滚轮缩放

### 右下角图例

图例必须是小体量、低干扰的信息层，包含：

- `P6.1 门户蓝图画布`
- 当前知识库
- 交互提示
- `P6.2 登录接入`
- `P6.3 权限与角色控制`
- `P6.4 平台级入口与导航治理`

图例存在的目的不是抢占视觉焦点，而是说明“这个页面属于平台层，而不是业务层”。

## 视觉原则

- 全屏、沉浸式、浅底蓝图，不采用页面头图式结构
- 网格、连线、pin、流光和轻量脉冲形成运行感
- 颜色按阶段区分，但整体属于同一张工程蓝图
- 门户是“高密度结构表达 + 受控动态”，不是数字大屏

明确避免：

- 大表头
- 大段说明文字
- 点击后遮挡画面的弹窗
- 节点中心点连线
- 普通后台首页式卡片排版

## P6 占位约束

### P6.2 登录接入

当前只做占位，不编码。后续将负责：

- 统一登录入口
- 平台身份识别
- 单点接入或本地认证壳

### P6.3 权限与角色控制

当前只做占位，不编码。后续将负责：

- 平台角色模型
- 路由级权限
- 模块访问控制
- 审计归属

### P6.4 平台级入口与导航治理

当前只做占位，不编码。后续将负责：

- 默认首页策略
- 平台级导航组织
- 平台入口编排

## 验收标准

1. `/portal` 打开后直接进入全屏蓝图画布，而不是普通页面头图
2. 单击节点不再出现弹窗
3. 双击节点可直接进入模块
4. 连线从锚点 / pin 出发，并在缩放、拖拽后仍与节点对齐
5. 右下角图例明确展示 `P6.1` 与 `P6.2 ~ P6.4` 占位
6. 门户从职责上明确归档到 `P6`，不再作为 `P1 ~ P5` 页面附属试验稿
