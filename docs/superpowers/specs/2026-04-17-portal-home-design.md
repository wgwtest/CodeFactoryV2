# P6.1 门户蓝图画布设计

## 背景

当前系统已经具备 `P1` 知识库链路、`P2` 需求分析、`P3` 设计表达、`P4` 工具中台与 `P5` 构建入口的业务页面，但缺少一个能够从平台层统一表达这些模块关系、运行态势和入口路径的顶层门户。

上一版门户试验稿属于“页面化门户”路线：顶部大表头 + 绝对定位 DOM 卡片 + 中心点连线。这种实现适合验证概念，不适合承载用户期待的“蓝图式、全屏、可缩放、可拖拽、强流动感”的平台门户，因此需要重新归档并升级到 `P6.1`。

## 对应节点

- `P6` 门户、登录与权限平台层
- `P6.1` 门户蓝图画布
- `P6.2` 登录接入（占位）
- `P6.3` 权限与角色控制（占位）
- `P6.4` 平台级入口与导航治理（占位）

围绕 `P6.1`，补充拆解以下子节点：

- `P6.1.1` 门户图形语言与元素表达体系
- `P6.1.2` 连线语义、流向编码与拥塞表达
- `P6.1.3` 画布交互边界、布局约束与拖拽规则
- `P6.1.4` 门户投影数据模型与自动生成规则

## 目标

- 在独立路由 `/portal` 提供一个真正的全屏门户蓝图画布，不进入现有 `MainShell`
- 用统一蓝图视口表达 `P1 ~ P5` 与“行业用户”之间的空间关系和数据流动
- 交互上采用 `单击高亮 / 双击进入`，不再使用信息遮挡型弹窗
- 画布支持拖拽节点、本地记忆布局、背景平移与缩放
- 门户本身明确归属于 `P6.1`，与 `P1 ~ P5` 的业务页面解耦
- 在画布右下角使用小型图例表达 `P6` 平台层身份，以及 `P6.2 ~ P6.4` 的后续占位

## 非目标

- 本轮不实现真正登录页
- 本轮不实现角色权限校验
- 本轮不把业务编辑能力搬进门户
- 本轮不支持多人协同编辑蓝图
- 本轮不做后端持久化视口和布局

## 技术路线

### 路线选择

采用“**蓝图画布混合实现**”路线，而不是普通页面式门户：

- 视口层：统一的世界坐标、平移、缩放能力
- 节点层：React/DOM 节点卡片，承载丰富文本与状态
- 连线层：与视口同坐标系的图形层，基于锚点 / pin 计算连线
- 特效层：流光、脉冲、网格和氛围光

之所以不用纯 `Canvas/WebGL`，是因为门户节点需要承载较多文字、指标与交互，纯画布会让可维护性和可读性明显变差。

### 明确放弃的旧路线

以下能力属于上一版试验稿，当前已被明确放弃：

- 顶部大表头 + 说明区
- “点击节点打开摘要卡片”交互
- 以节点中心点作为连线起止点
- 把门户视为普通页面，而不是平台蓝图画布

## 信息架构

### 路由

- 独立路由：`/portal`
- 不进入当前顶栏导航壳层
- 仅作为平台入口页，不替换各业务模块页

### 节点集合

门户画布中固定展示以下节点：

- `行业用户`
- `业务知识库（P1）`
- `需求分析系统（P2）`
- `软件设计系统（P3）`
- `工具仓库 / 工具中台（P4）`
- `软件构建系统（P5）`

`P6` 本身不作为一块和 `P1 ~ P5` 并列的大节点出现，而作为画布的**所属平台层**，通过右下角图例表达。

### 元素分层

门户画布允许出现的元素必须被限定在以下四类：

- **系统节点**：`P1 ~ P5` 这类可进入的业务模块，使用主节点卡片表达
- **用户节点**：如“行业用户”“技术专家”等外部参与者，使用与系统节点不同的视觉形态，避免误判为系统模块
- **数据/产物节点**：需求规格说明、软件设计说明、工具化描述等中间成果，使用轻量胶囊或标签表达
- **状态/注释节点**：运行中、待建模、知识库名、占位说明等辅助信息，只能作为附属信息层，不能替代主节点

当前不允许直接把日志、长文本说明、编辑控件塞进门户画布。

### 连线集合

初版固定表达以下主路径：

- 行业用户 -> 需求分析系统
- 业务知识库 -> 需求分析系统
- 需求分析系统 -> 软件设计系统
- 软件设计系统 -> 工具中台
- 工具中台 -> 软件构建系统
- 软件设计系统 -> 软件构建系统

这些只是主干链路。后续新增连线时，必须先归入 `P6.1.2` 定义的语义类型，再进入画布。

## 画布模型

### 世界坐标与视口

- 节点位置保存在统一世界坐标中
- 画布提供视口平移与缩放能力
- 节点拖拽时更新的是世界坐标，而不是页面像素位置
- 连线与节点共同处于同一世界坐标系下，避免缩放和尺寸变化造成错位

### 锚点 / Pin 模型

每个模块节点必须至少有以下锚点：

- 输入锚点（左侧）
- 输出锚点（右侧）

必要时允许：

- 顶部锚点
- 底部锚点

连线必须从锚点出发，而不是从节点中心点出发。这是蓝图感的核心约束之一。

## 图形语言

### P6.1.1 元素表达体系

门户不是“把所有对象都画成圆角矩形”的自由画布，而是一个有图形语言约束的系统视图。

元素表达基线如下：

- **系统节点**：圆角矩形主卡片，可进入业务页，必须带阶段编号、名称、摘要和少量指标
- **用户节点**：椭圆或胶囊型节点，只表达角色和目标，不伪装成系统模块
- **数据/产物节点**：小尺寸胶囊，用于表达“规格说明”“工具化描述”等传递对象
- **状态投影**：作为节点角标、徽标、色条或边框变化出现，不单独占据大面积空间
- **平台层注释**：仅出现在右下角图例，不与业务主节点竞争视觉中心

任何新元素在进入门户前，都必须先回答三个问题：

1. 它是系统、用户、数据产物还是状态投影
2. 它是否可点击进入某个稳定页面
3. 它是自动生成还是人工配置

### P6.1.2 连线语义与流向编码

连线不能只表示“有关系”，必须明确其语义类型。当前阶段定义如下：

- **主生产链连线**：表示 `P1 ~ P5` 的主链传递，使用最稳定、最粗的路径
- **知识供给连线**：表示知识仓对需求分析或设计阶段的支撑，强调来源属性
- **设计转化连线**：表示需求规格向设计说明、设计说明向工具化描述的转化
- **工具匹配连线**：表示软件设计与工具中台之间的匹配/回填
- **构建执行连线**：表示工具调用进入软件构建

编码规则：

- 颜色表达语义类型，不直接拿颜色表达“重要程度”
- 箭头或流动粒子表达方向
- 同一对节点间存在多条不同语义链路时，优先合并为“一条主线 + 若干中间产物节点”，而不是无限并排堆线
- 连线过多时，允许切换为聚合路径、折叠标签或摘要模式，不能让门户退化成毛线团

## 交互与布局约束

### P6.1.3 交互边界与拖拽规则

当前门户交互要从“能拖”提升为“有明确约束地拖”。

规则如下：

- 节点拖拽必须存在明确世界边界，禁止无限拖到不可见区域
- 视口平移与节点拖拽要共享同一坐标约束，不能一个有限、一个无限
- 系统主节点允许人工拖拽微调，但数据产物节点优先由系统自动布局
- 自动生成的锚点、连线和产物节点默认不可直接随意拖散，避免破坏语义
- 手工修改布局后，要能区分“默认布局”和“个人覆盖布局”
- 节点存在吸附、碰撞规避和最小间距规则，避免拖动后压线、重叠和遮挡

门户需要至少定义以下边界：

- 世界坐标的最小/最大范围
- 默认视口与重置视图规则
- 哪些元素可拖，哪些只能被系统重排
- 何时触发自动回流布局

## 数据投影

### P6.1.4 门户投影数据模型与自动生成规则

门户不是手工摆图工具，而是平台结构、运行状态和阶段产物的投影视图。

因此需要明确输入数据模型：

- **节点主数据**：节点类型、标题、阶段、入口路由、摘要、状态、指标
- **关系主数据**：起点、终点、语义类型、方向、强度、是否聚合
- **产物主数据**：规格说明、设计说明、工具化描述等中间对象及其挂接位置
- **布局主数据**：默认布局、系统推荐布局、个人覆盖布局

自动生成与人工配置的分工如下：

- `P1 ~ P5` 主节点、主链路和阶段摘要由系统自动生成
- 当前知识库名、运行指标、入口可用性等信息由实时状态投影生成
- 图例、平台注释和极少数展示开关由人工配置
- 个人拖拽布局只覆盖位置，不允许篡改节点语义和链路语义

只有在这套投影规则稳定后，门户才适合接入真实运行态数据。

### 当前实现落位

当前版本已将上述规则落实为以下交互与视图能力：

- 图例中提供 `推荐布局 / 个人布局` 切换，区分系统推荐布局与个人覆盖布局
- 图例中提供 `语义线 / 投影聚合` 切换，区分逐条关系表达与节点级聚合表达
- 门户展示 `投影摘要`，把系统节点、角色节点、数据产物、连线数量与自动/人工投影数量显式化
- 节点在投影聚合模式下展示 `入 / 出 / 产物` 结构徽标，用于应对关系增多时的拥塞表达

## 交互设计

### 单击节点

- 只做高亮，不弹出摘要卡片
- 高亮当前节点及其关联连线

### 双击节点

- 直接进入对应模块页面

默认映射：

- `P1 -> /graph`
- `P2 -> /requirements`
- `P3 -> /modeling`
- `P4 -> /xx-p4`
- `P5 -> /build`

### 拖拽节点

- 支持自由拖拽
- 拖拽结果写入本地存储
- 刷新后保持个人布局
- 拖拽必须受世界边界与最小间距约束

### 拖动画布

- 支持背景拖拽平移
- 支持滚轮缩放
- 平移范围与重置视图规则必须可解释

### 右下角图例

图例必须是小体量、低干扰的信息层，包含：

- `P6.1 门户蓝图画布`
- 当前知识库
- 交互提示
- `P6.2 登录接入`
- `P6.3 权限与角色控制`
- `P6.4 平台级入口与导航治理`

图例存在的目的不是抢占视觉焦点，而是说明“这个页面属于平台层，而不是业务层”。

## 视觉原则

- 全屏、沉浸式、浅底蓝图，不采用页面头图式结构
- 网格、连线、pin、流光和轻量脉冲形成运行感
- 颜色按阶段区分，但整体属于同一张工程蓝图
- 门户是“高密度结构表达 + 受控动态”，不是数字大屏

明确避免：

- 大表头
- 大段说明文字
- 点击后遮挡画面的弹窗
- 节点中心点连线
- 普通后台首页式卡片排版

## P6 占位约束

### P6.2 登录接入

当前只做占位，不编码。后续将负责：

- 统一登录入口
- 平台身份识别
- 单点接入或本地认证壳

### P6.3 权限与角色控制

当前只做占位，不编码。后续将负责：

- 平台角色模型
- 路由级权限
- 模块访问控制
- 审计归属

### P6.4 平台级入口与导航治理

当前只做占位，不编码。后续将负责：

- 默认首页策略
- 平台级导航组织
- 平台入口编排

## 验收标准

1. `/portal` 打开后直接进入全屏蓝图画布，而不是普通页面头图
2. 单击节点不再出现弹窗
3. 双击节点可直接进入模块
4. 连线从锚点 / pin 出发，并在缩放、拖拽后仍与节点对齐
5. 右下角图例明确展示 `P6.1` 与 `P6.2 ~ P6.4` 占位
6. 门户从职责上明确归档到 `P6`，不再作为 `P1 ~ P5` 页面附属试验稿
7. 门户元素、连线、状态与产物至少有一套清晰可讲述的图形语言，不再是随意摆放的卡片集合
8. 拖拽、缩放、自动布局和边界限制具有成体系约束，而不是各自独立的试验能力
