# P3 Analysis-Lab-Style Workbench Redesign

## 目标

P3 Design Lab 下一版界面以 `/p2-requirement-analysis-lab` 为主要参考对象，不再沿用当前“顶部卡片 + 左侧上下分栏 + 右侧文档卡片”的静态原型感布局。

目标界面应是“产物中心的 Lab 工作台”：

- 像 P2 Lab 一样，有清晰的顶部阶段身份、左侧导航和右侧任务工作区。
- 能观察 P3 从虚规输入到软设生成、设计基线、检查评审、P4 投影的全过程。
- 默认视图仍围绕正式 P3 产物组织，不退化成纯调试台。

## 设计基准

参考页面：`/p2-requirement-analysis-lab`

需要继承的体验：

1. 顶部身份区清晰说明当前 Lab 的阶段、目的、约束和运行状态。
2. 左侧导航把复杂阶段拆成多个可切换视图，而不是把所有信息堆在同一屏。
3. 右侧工作区按当前任务展示配置、会话、当前 Turn、状态对象和日志。
4. 每个视图都应有明确的数据对象，不出现只有静态排版、没有业务含义的模块。

不应继承的部分：

1. P2 Lab 的业务对象名称不能直接搬到 P3。
2. P3 不能变成只看组织器和日志的调试台。
3. 软件设计说明不能被弱化为附件；它仍是 P3 的首要主产物。

## 信息架构

P3 新界面采用三层结构。

### 顶部阶段身份区

顶部区域展示：

- 标识：`P3 Software Design Lab`
- 副标题：`从 P2 需求规格冻结包生成软件设计说明、设计基线和 P4 投影`
- 状态标签：
  - 输入包状态
  - 设计会话状态
  - 设计基线状态
  - 检查评审状态
  - P4 投影状态
- 主动作：
  - 选择 P2 冻结包
  - 生成 / 重新生成
  - 运行检查
  - 冻结候选

顶部不再展示“布局：左 38% / 右 62%”这类实现细节。

### 左侧导航

左侧采用 P2 Lab 风格的纵向导航。建议导航项如下：

1. 输入包
2. 软设工作区
3. 当前 Turn
4. 设计基线
5. 检查评审
6. P4 投影
7. 运行日志

每个导航项显示：

- 标题
- 简短说明
- 当前状态
- 数量或关键指标，如模块数、阻断项、投影工单数

默认选中 `软设工作区`。

### 右侧主工作区

右侧根据左侧导航切换内容。

工作区必须保持 P2 Lab 的密度和产品感：边界清晰、信息紧凑、操作靠近对象，不使用大面积装饰背景。

## 各视图设计

### 输入包

用途：解释 P3 当前消费的 P2 冻结包。

内容：

- 冻结包标题、来源文档、冻结时间
- P3 可消费状态
- 需求规格说明摘要
- 结构化字段摘要
- 标注、知识绑定和待确认项

空态：

- 显示“没有可用的 P2 新版冻结包”
- 保留选择输入包动作
- 不显示大片空白文档纸面

### 软设工作区

用途：P3 默认主视图，承载正式软件设计说明。

布局：

- 上方：当前输入包、生成策略、会话状态、主操作
- 中部：A4 软件设计说明正文
- 侧边或下方：设计基线摘要、检查状态、P4 投影状态

软设正文仍应保留 A4 文档质感，但整体工作区外壳参考 P2 Lab，而不是当前 P3 的三块静态面板。

正文 Tab 建议：

- 正文
- 目录
- 追溯
- 版本

### 当前 Turn

用途：展示本轮自然语言配置和系统解释结果。

内容：

- 用户输入
- 系统解释出的设计意图
- 影响范围
- 对设计基线的变更摘要
- 对软件设计说明正文的变更摘要
- 下一步建议
- CLI 输入框

CLI 不再挤在左下角，而是当前 Turn 视图的一等对象。

### 设计基线

用途：展示软件设计说明背后的结构化设计状态。

内容：

- 架构模式
- 模块清单
- 模块职责
- 接口草案
- 数据对象
- 状态机或关键流程
- P2 需求条款追溯关系

设计基线是系统消费对象，不是正文的重复展示。

### 检查评审

用途：展示 P3 是否可冻结、是否能交给后续阶段。

内容：

- 阻断项数量
- 警告项数量
- 通过项数量
- 检查规则列表
- 每条问题的作用范围、证据、建议动作

检查评审回答：当前软设为什么能或不能进入下一阶段。

### P4 投影

用途：展示 P3 成果如何转换为 P4 可接收的任务包。

内容：

- 投影包名称
- 下游目标阶段
- 工单列表
- 每个工单对应的模块、接口、数据对象和需求条款
- 工单就绪状态

P4 投影回答：这份软设后面怎么变成可执行工作。

### 运行日志

用途：保留 Lab 的可观测性。

内容：

- API 调用记录
- 生成器 / Provider 调用记录
- 检查器调用记录
- 状态迁移记录
- 错误和重试记录

运行日志不作为默认视图，只作为诊断入口。

## 视觉方向

整体视觉参考 P2 Lab：

- 浅灰蓝背景
- 紧凑顶部栏
- 左侧深浅分明的导航
- 白色工作区面板
- 小半径边角，最多 8px
- 标签、状态、指标紧凑排列
- 不使用网格背景、装饰渐变和大块静态卡片

P3 的正式产物区可以保留 A4 文档纸面，但 A4 纸面应该嵌入 Lab 工作区，而不是让整页都围绕 A4 做三栏静态布局。

## 数据与组件边界

已有 `StageDocumentWorkbenchViewModel`、`StandardDocumentViewModel`、`StageQualityGateViewModel`、`StageOutputProjectionViewModel` 和 `p3DesignLabWorkbenchAdapter` 可继续使用，但界面组织需要重排。

建议新增或调整组件：

- `StageLabShell`：参考 P2 Lab 的顶部 + 左侧导航 + 右侧工作区外壳。
- `StageLabNavigation`：左侧导航列表。
- `P3InputPackageView`：输入包视图。
- `P3SoftwareDesignWorkspaceView`：软设工作区。
- `P3CurrentTurnView`：当前 Turn 视图。
- `P3DesignBaselineView`：设计基线视图。
- `P3QualityReviewView`：检查评审视图。
- `P3ProjectionView`：P4 投影视图。
- `P3RuntimeLogView`：运行日志视图。

共性组件只接受 ViewModel，不直接读取 P3 API DTO。P3 Adapter 继续负责 DTO 到 ViewModel 的转换。

## 状态设计

### 没有输入包

- 顶部显示待输入状态。
- 左侧导航仍可见，但除“输入包”外大部分视图为禁用或空态。
- 右侧默认显示输入包空态和选择动作。

### 已选择输入包，未生成

- 默认进入软设工作区。
- A4 软设区域显示正式空态。
- 当前 Turn 显示可输入的生成策略。
- 设计基线、检查评审、P4 投影显示等待生成。

### 已生成软设

- 软设工作区显示 A4 正文。
- 设计基线显示模块、接口、数据对象摘要。
- 检查评审可运行。
- P4 投影显示工单预览。

### 检查存在阻断项

- 顶部状态显示阻断。
- 检查评审视图成为建议跳转项。
- 冻结候选动作禁用。

### 可冻结

- 顶部状态显示候选就绪。
- 软设、设计基线、P4 投影均显示可下发状态。

## 验收口径

设计实现后至少满足：

1. 页面第一眼像 P2 Lab 的同类产品，而不是当前 P3 的静态原型页。
2. 左侧导航能覆盖输入包、软设工作区、当前 Turn、设计基线、检查评审、P4 投影和运行日志。
3. 默认视图能突出软件设计说明这一主产物。
4. 当前 Turn 能承载自然语言 CLI、解释结果和影响范围。
5. 设计基线、检查评审、P4 投影三个对象有独立视图。
6. 空输入包状态不出现大片无意义空白。
7. 桌面和移动视口不出现文字互相遮挡或按钮不可见。
8. 旧 `/xx-p3` 页面不受影响。

## 不在本轮设计内

本轮只定义界面重设计，不要求新增后端生成能力。

暂不处理：

- 真正的多轮设计生成算法。
- 冻结版本持久化策略。
- P4 真实工单下发。
- P2 页面回迁。

这些能力可以在界面结构稳定后分阶段实现。
