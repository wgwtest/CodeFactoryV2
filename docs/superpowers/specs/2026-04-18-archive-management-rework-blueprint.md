# 知识库管理页重构蓝图

## 文档目的

本文件用于将现有“知识库管理”页重构为围绕目标抽取蓝图运作的前端工作台。

重构目标不是简单优化当前页面，而是将页面从“操作页”升级为：

1. 知识库总览台
2. 抽取运行中心
3. 策略 / 质量台

本蓝图与 [知识抽取目标流程蓝图](/E:/project/Web/智能软件生成/CodeFactoryV2/docs/superpowers/specs/2026-04-18-knowledge-extraction-target-blueprint.md) 配套使用。

配套线稿见：

- [知识库管理页低保真线稿包](/E:/project/Web/智能软件生成/CodeFactoryV2/docs/superpowers/specs/2026-04-18-archive-management-wireframe-pack.md)

## 重构原则

### 1. 页面按职责拆，不按接口拆

页面结构应围绕用户问题组织，而不是围绕当前已有接口和组件组织。

### 2. 默认看全局，按需下钻

用户进入管理工作台时应先看到全局状态，再逐步下钻到：

1. 某次运行
2. 某个阶段
3. 某篇文档
4. 某个 chunk / 证据包

### 3. 可视比可操作优先

当前阶段优先保证用户能看清楚整个链条，而不是优先堆更多操作按钮。

### 4. 总览、运行、策略分离

“知识库是什么”“这次运行发生了什么”“系统按什么标准在判断”必须分开。

## 页面职责合同

### 一、知识库总览回答什么

知识库总览负责回答“现在整体怎么样”，包括：

1. 当前有哪些知识库
2. 当前激活的是哪个知识库
3. 每个知识库当前状态如何
4. 当前知识库最近一次运行结果如何
5. 当前知识库是否异常、是否需要人工关注
6. 接下来应该进入哪个页面继续处理

知识库总览不负责回答：

1. 当前运行具体卡在哪个阶段
2. 某篇文档为什么失败或被跳过
3. 某个质量规则为什么命中
4. 某条知识为什么被阻断入库

一句话定义：总览页负责发现问题和提供入口，不负责深度解释。

### 二、抽取运行中心回答什么

抽取运行中心负责回答“当前和最近的运行过程发生了什么”，包括：

1. 当前有哪些知识库运行正在并行执行
2. 每个知识库当前运行到哪个阶段
3. 哪些知识库运行正常、阻断、异常或等待中
4. 某个知识库本次运行的阶段流水是什么
5. 某个知识库哪些文档成功、失败、跳过、待处理
6. 某篇文档在本次运行中经历了哪些处理阶段
7. 本次运行命中了哪些质量规则、哪些规则导致阻断或人工复核
8. 如果要排查问题，应该先看哪个知识库、哪个阶段、哪篇文档

抽取运行中心不负责回答：

1. 全量质量字段的定义和维护方式
2. 策略版本为什么这样设计
3. 所有质量规则的长期演进历史

一句话定义：运行中心负责运行监控、问题定位和执行结果解释。

### 三、策略 / 质量回答什么

策略 / 质量页负责回答“系统按什么标准在判断”，包括：

1. 当前知识库采用的是哪套抽取蓝图
2. 当前知识库绑定的是哪套质量策略
3. 质量标准按哪些层级组织
4. 哪些规则是硬底线
5. 哪些规则只触发人工复核
6. 哪些规则只触发告警
7. 当前策略版本、适用范围和变更语义是什么
8. 如果要调整标准，应该调整哪一类字段

策略 / 质量页不负责回答：

1. 当前实时运行到哪一步
2. 某个知识库当前有哪些文档在排队
3. 本次运行命中了哪些规则以及命中数量
4. 当前阻断具体发生在哪个对象上

一句话定义：策略 / 质量页负责规则说明和判断依据，不负责实时运行监控。

建议将当前知识库管理能力拆为三个子页面。

### 一、知识库总览

#### 页面目标

回答：

1. 当前有哪些知识库
2. 当前激活的是哪个
3. 每个知识库最近状态如何
4. 最近一次运行结果如何

#### 核心职责

- 知识库列表
- 当前知识库基本信息
- 当前知识库运行摘要
- 最近运行记录摘要
- 快速操作入口

#### 典型模块

1. 当前知识库卡片
2. 知识库列表表格
3. 最近运行摘要卡
4. 快速入口区
   - 进入运行中心
   - 进入策略 / 质量

## 主场景与用户操作路径

在进入线稿前，优先围绕两个高频且高价值场景来组织页面。

### 场景一：整库或多库运行中，我要快速知道哪里卡住了

#### 用户目标

用户希望在后台并行运行多个知识库时，快速发现异常运行、判断问题严重度，并定位到具体的知识库和阶段。

#### 页面路径

1. 从“知识库总览”进入
2. 观察所有知识库当前状态与最近运行摘要
3. 点击异常或高风险的知识库，进入“抽取运行中心”
4. 先看全局并行运行视图，确认当前有哪些运行在执行
5. 聚焦目标知识库，查看其阶段流水、文档队列、告警和阻断
6. 如有必要，再下钻到单文档查看具体处理详情
7. 如阻断原因与规则有关，再跳转“策略 / 质量”查看对应规则定义

#### 页面需要支撑的关键判断

1. 哪个知识库需要我优先关注
2. 它卡在运行链的哪一层
3. 是阶段级问题、文档级问题，还是质量门禁问题
4. 这是不是一个需要调整策略的问题

#### 线稿上的关键要求

1. “知识库总览”必须能一眼看出异常库
2. “抽取运行中心”必须默认先看到全局并行运行，再聚焦单库
3. 运行中心中的告警、失败、阻断必须能区分层级
4. 从运行结果跳到规则解释的路径必须直接可达

### 场景二：某篇文档或某批知识没有最终入库，我要知道为什么

#### 用户目标

用户希望从最终结果反查处理链路，确认某篇文档为什么被跳过、失败、阻断，或者某批知识为什么没有通过质量门禁进入发布态。

#### 页面路径

1. 从“知识库总览”进入目标知识库
2. 打开“抽取运行中心”，聚焦最近一次相关运行
3. 在文档队列或运行结果摘要中找到目标文档或目标问题对象
4. 下钻到单文档处理详情，查看其解析、证据、候选、归并和 gate 结果
5. 如发现阻断来自质量规则命中，再进入“策略 / 质量”
6. 在“策略 / 质量”中查看命中规则的定义、阈值、动作和适用范围
7. 回到运行中心，判断问题属于内容质量、规则配置，还是流程实现问题

#### 页面需要支撑的关键判断

1. 这篇文档是在什么阶段被拦住的
2. 是解析失败、证据不足、归并冲突，还是质量 gate 未通过
3. 最终没入库是内容质量问题还是策略设置问题
4. 如果要改，应该改处理流程还是改质量标准

#### 线稿上的关键要求

1. 运行中心必须支持从知识库级快速下钻到文档级
2. 文档详情必须按阶段组织，而不是堆一堆结果字段
3. 质量命中结果必须贴着运行结果展示，而不是埋在策略页里
4. 从具体阻断点跳到规则定义时，必须保留上下文

### 两个场景对页面职责的反向约束

如果后续线稿无法同时自然支撑这两个场景，则说明页面边界或信息层次仍未收好。

1. 如果场景一无法快速发现异常运行，说明“知识库总览”或“运行中心”的整体视图不够强
2. 如果场景二无法快速解释为什么没入库，说明“运行中心”和“策略 / 质量”的衔接不够清楚

## 抽取运行中心的硬规则

这条规则优先级高于当前已有线稿表达，后续如果线稿与这条规则冲突，以这条规则为准。

### 一、抽取运行中心必须拆成三个子页面

抽取运行中心不是一个页面里的三个模块，而是三个明确的子页面，分别对应三种颗粒度：

1. 全局并行运行视图  
   用来回答“当前有哪些知识库在并行运行、哪些阻断、哪些异常、整体最值得关注什么”。

2. 单知识库运行视图  
   用来回答“某一个知识库的这次运行现在处于哪个阶段、文档队列如何、风险和质量命中结果如何”。

3. 单文档处理下钻视图  
   用来回答“某一篇文档在整条处理链中的经历，以及为什么被纳入、跳过、失败或阻断”。

### 二、三个子页面的默认进入关系

必须固定成下面这条关系：

1. 从“知识库总览”点击某个具体知识库  
   默认直接进入“单知识库运行视图”，不能先落到全局并行运行视图。

2. 全局并行运行视图  
   只作为抽取运行中心的总入口、顶部导航入口或返回入口使用。

3. 单文档处理下钻视图  
   只能从“单知识库运行视图”的文档队列中进入，不应从知识库总览直接跳入。

### 三、导航语义

后续无论是页面标题、路由命名还是 Pencil 线稿，都要遵循这套语义：

1. 抽取运行中心 / 全局并行运行
2. 抽取运行中心 / 单知识库运行
3. 抽取运行中心 / 单文档下钻

### 四、由此带来的设计约束

1. “知识库总览”页上的主入口按钮，不应写成笼统的“进入抽取运行中心”，而应明确表达为“查看该知识库运行”或同义语义。
2. “抽取运行中心”的全局页，不应默认承担从总览页进入后的首屏职责。
3. “单知识库运行视图”才是知识库级问题定位的默认工作页。
4. “单文档下钻视图”是第三层，不应与单知识库运行页混成同一层。

## 详情面板的流输出优先规则

这条规则适用于抽取运行中心的三个颗粒度视图。

### 一、详情面板不应只做静态信息卡

详情面板除了展示状态、输入、输出、告警、阻断原因等结构化字段外，还必须支持“流输出可视化”。

这里的流输出，是指某一阶段在运行中持续产生的分析文本、处理中间说明、判断过程摘录、规则评估过程、人工复核提示等连续更新内容。

### 二、如果某个阶段存在流输出，它应占据详情面板的主位置

详情面板的优先级应固定为：

1. 流输出主区  
   如果当前阶段有持续文本输出，这一块应成为详情面板最主要的显示区域。

2. 结构化摘要区  
   显示当前状态、当前对象、输入输出摘要、告警数、阻断原因、下一步动作等。

3. 辅助字段区  
   显示规则命中、关联对象、时间戳、来源锚点、跳转入口等。

也就是说：流输出不是附属字段，而是“当前阶段正在发生什么”的主视图。

### 三、流输出可视化的产品意义

详情面板中的流输出，主要用来回答：

1. 当前阶段正在分析什么
2. 当前阶段为什么得出这个判断
3. 当前阶段是否仍在继续
4. 当前阶段停在了哪里
5. 当前阶段的阻断、告警、待复核提示是如何产生的

### 四、没有流输出时的降级规则

如果某个阶段没有流输出，则详情面板退回为静态结构化视图，使用：

1. 状态摘要
2. 输入输出摘要
3. 风险与告警
4. 相关动作

### 五、由此带来的线稿约束

1. 详情面板必须预留“流输出主区”。
2. 结构化字段不能占满详情面板全部空间。
3. 当阶段有实时流输出时，流输出区域必须明显大于普通字段区。
4. 右侧详情面板的默认设计，不应再是纯静态表单式信息堆叠。
