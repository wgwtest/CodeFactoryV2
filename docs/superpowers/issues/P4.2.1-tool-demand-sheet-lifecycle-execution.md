# `P4.2.1` 工具需求单生命周期与协议对象

## 工作目标

把 `P4` 工具需求单从“只有处理状态”提升为“具备完整业务生命周期约束”的正式对象，明确 `P3` 撤销、`P4` 驳回、`P5` 消费查询的角色边界，并固定留痕规则。该对象同时是 `P3 / P4 / P5` 串联的主干交付流之一。

## 工作内容

- 为 `P4.2.1` 单独建立生命周期与协议约束设计文档
- 区分 `lifecycle_status / review_status / delivery_status / processing_status`
- 固定 `撤销 / 驳回 / 关闭` 的动作归属与状态迁移
- 固定“待审定 / 已审定 / 已交付 / P4 闭环完成”的判定规则
- 定义生命周期事件日志与终态留痕字段
- 约束 `ToolDemandSheet / ToolDemandItem / ToolManufacturePlan` 在终态下的冻结规则
- 为后续 API 与前端页面动作提供稳定契约

## 潜在难点

- 当前实现已经把处理态写入 `ToolDemandSheet.status`，后续改造会涉及模型兼容
- 需要避免把“开发态清理数据”继续误当成业务撤销
- `P3/P4/P5` 的页面边界已经拆开，生命周期动作必须与页面边界同步收敛

## 验收方法

- 人工审阅生命周期设计，确认以下结论明确且不冲突：
- `撤销` 属于 `P3`
- `驳回` 属于 `P4`
- 二者都不是物理删除
- `已审定` 与 `已交付` 不是同一状态
- `P5` 查询时能区分 `withdrawn / rejected / ready`
- 叶子项与制造计划在终态下存在冻结规则
- 后续进入编码前，必须据此补充模型、路由、测试与页面动作设计
