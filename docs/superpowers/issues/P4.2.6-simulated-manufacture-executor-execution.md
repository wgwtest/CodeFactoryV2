# `P4.2.6` 模拟研制执行器

> 工作层执行工单说明：本文件属于 `docs/superpowers/issues/` 下的执行工单镜像与过程证据，不是当前 WBS 树事实源，也不替代正式设计、正式计划或远端 GitHub Issue 正文。
>
> 当前节点状态、WBS 结构与正式约束，优先以 GitHub `Issues + sub-issues` 和仓库主工作树中的 `DOC/CODEX_DOC/` 为准。

## 工作目标

为 `P4` 增加一个内部后台模拟执行器，把“未命中后进入研制”的路径从“查询驱动推进”改造成“后台自动推进，前台只读查询”。

## 工作内容

- 为 `P4.2.6` 建立专属设计文档
- 扩展 `ToolManufacturePlan` 的模拟执行字段
- 新增后台模拟执行器，支持多个工具并行推进
- 新增研制计划查询接口，供 `P4` 工具仓库消费
- 把 `progress` 查询从“推进 + 查询”改为纯查询
- 更新 `P4/P5` 页面展示与回归测试

## 潜在难点

- 当前 `ToolHubService` 是按请求创建的，后台执行器不能简单挂在单次请求对象上
- 本地 JSON 仓库需要处理并发写入与原子落盘
- 需要避免把 `P5` 的轮询继续变成推进动作
