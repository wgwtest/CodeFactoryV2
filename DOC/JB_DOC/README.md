# CodeFactoryV2 标准化副本文档根

本目录用于承接 `CodeFactoryV2` 的标准化副本文档体系。

它不是当前项目唯一正式文档根，也不替代 `DOC/CODEX_DOC/`。它的职责是：

- 将适合纳入美军 / DoD 软件文种规划的内容，按标准对象重新组织
- 形成“平台自身标准文档”“软件工厂产物模板中心”“项目实例样例”的独立表达层
- 为后续对标、审查、模板中心建设和正式交付样例提供稳定目录

## 1. 与 `CODEX_DOC` 的关系

- `DOC/CODEX_DOC/`
  - 当前平台研发层正式文档根
  - 承担工程治理、阶段设计、WBS、测试与过程归档职责
- `DOC/JB_DOC/`
  - 标准化副本层
  - 承担标准对象映射、候选标准文档、模板中心和样例组织职责

因此：

- `CODEX_DOC` 不是 `JB_DOC` 的镜像来源目录
- `JB_DOC` 也不是 `CODEX_DOC` 的替代根目录
- 二者是“研发文档根”和“标准化投影根”的关系

## 2. 目录结构

- `00-总说明/`
  - 说明 `JB_DOC` 的定位、状态、边界和同步规则
- `01-平台自身标准文档/`
  - 软件工厂平台自身的标准化候选文档
- `02-软件工厂产物模板中心/`
  - 软件工厂未来生成软件交付物时使用的模板组说明
- `03-项目实例与样例/`
  - 未来具体项目的标准化输出实例目录
- `04-映射与追溯/`
  - `CODEX_DOC -> JB_DOC` 来源映射、覆盖缺口和路线图
- `99-标准来源库/`
  - 官方标准详情页、原始影像与元数据本地库

## 3. 阅读顺序

1. `DOC/JB_DOC/README.md`
2. `DOC/JB_DOC/00-总说明/00-JB_DOC-体系说明与使用边界.md`
3. `DOC/JB_DOC/00-总说明/01-JB_DOC-文档状态与同步规则.md`
4. `DOC/JB_DOC/04-映射与追溯/00-CODEX_DOC到JB_DOC来源映射总表.md`
5. `DOC/JB_DOC/01-平台自身标准文档/*`
6. `DOC/JB_DOC/02-软件工厂产物模板中心/*`

## 4. 使用原则

- 只有明确声明“对应标准文种”的文档，才要求尽量按标准章节和控制点表达
- 没有直接标准对象对应的桥接文档，必须明确标注为“本地桥接文档”或“标准化辅助文档”
- 不允许把本地发挥型文档伪装成军标文种原件
- `JB_DOC` 的每一份关键文档，都应能追溯到其主要来源材料
