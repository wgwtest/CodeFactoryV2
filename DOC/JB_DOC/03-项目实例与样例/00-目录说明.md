# 项目实例与样例目录说明

## 1. 文档定位

**文档类别：** 标准化辅助文档  
**标准依据：** 无直接单一军标文种对应  
**当前状态：** 生效

本目录用于承接具体项目实例的标准化输出样例，并与模板中心、测试验证和组织器评估活动保持边界清晰。

## 2. 当前职责

当前阶段本目录承接 P2 需求分析 Lab 样例，以及 P2/P3 需求规格与软件设计主链验证样例。模板仍放在模板中心，样例文档放在本目录。

## 3. 后续使用方式

每个实例项目建议单独建目录，例如：

- `P2-需求分析Lab样例-态势分析系统/`
- `P2-P3主链样例-SX-DataStore/`
- `01-某项目样例/`

每个项目样例目录中可按实际需要放入：

- 需求规格实例
- 设计说明实例
- 测试文档实例
- 发布与移交实例

## 4. 当前原则

- 实例文档不应与模板文档混放
- 需求规格基础模板和自定义模板实例统一放入 `DOC/JB_DOC/02-软件工厂产物模板中心/`，不放入本目录
- 实例文档必须注明所使用的模板来源
- 实例文档应与 `JB_DOC/04-映射与追溯/` 建立回链
- 面向组织器的测试辅助文档不得把完整样例一次性暴露给被测组织器
- 需求规格说明范本应聚焦用户需求、业务流程、功能、数据、非功能和验收，不应混入实现结构
- 软件设计说明范本应聚焦架构、模块、对象、API、流程、约束和验证，不应反向改写需求
- 项目样例命名采用“文档类型-样例对象”，例如 `需求规格说明样例-态势分析系统`、`软件设计说明范本-SX-DataStore`
