# 组织器评估清单-态势分析系统

## 1. 文档定位

本文档用于评估 P2 需求分析组织器在态势分析系统样例上的交互质量和最终需求规格产物质量。评估对象是组织器能力，不是测试者是否按固定脚本输入。

## 2. 交互过程评估

| 评估项 | 合格标准 |
| --- | --- |
| 意图理解 | 能识别用户要建设的是软件级态势分析系统，而不是通用模板或上级大系统 |
| 澄清能力 | 能围绕用户、流程、功能、数据、边界和验收提出具体问题 |
| 节奏控制 | 不在关键缺口未闭合前直接生成完整定稿 |
| 事实管理 | 能区分已确认事实、暂定假设、待确认问题和推断结论 |
| 纠偏响应 | 被指出误解后能修正结构化状态和后续正文 |
| 模板纪律 | 不把样例业务内容污染到通用需求规格模板 |

## 3. 规格说明覆盖评估

| 需求域 | 必须覆盖的内容 |
| --- | --- |
| 编写目的 | 文档用途、软件对象、后续设计开发测试验收用途 |
| 适用范围 | 第一阶段范围、主要用户、排除范围和上级系统边界 |
| 软件定位 | 科研分析和业务验证场景下的态势编辑、展示与分析工具 |
| 建设目标 | 态势管理、地图展示、分析工具、结果管理、权限日志 |
| 用户角色 | 科研分析人员、业务专家、数据管理员、系统管理员 |
| 核心流程 | 态势创建编辑、分析工具使用、成果导出复核 |
| 功能分解 | 至少覆盖态势工程管理、展示浏览、编辑标绘、量算、地形、通视、光照、结果管理、数据图层、权限日志 |
| 行为级功能 | 关键功能具备角色、触发条件、输入、处理、输出、异常和验收要点 |
| 数据需求 | 输入数据、输出数据、参数记录、数据版本和结果追溯 |
| 接口边界 | 第一阶段以文件导入导出和内网数据加载为主，不做实时数据总线 |
| 非功能 | 性能、可靠性、安全权限、部署环境、精度质量约束 |
| 验收准则 | 覆盖核心流程闭环、P0 功能、结果追溯、权限日志和异常提示 |
| 待确认事项 | 明确多人协作、文件格式、障碍物数据、光照精度、报告格式等未闭合问题 |

## 4. 严重问题判定

出现以下任一情况，应判定为需要整改：

- 把完整样例内容当作用户输入直接复述，没有体现交互澄清。
- 把态势分析业务功能写入通用需求规格模板。
- 把辅助分析系统扩展成自动决策或正式指挥系统。
- 功能需求只停留在名称清单，没有输入、处理、输出和验收要点。
- 未记录数据精度、结果限制和责任边界。
- 未区分已确认事实、暂定假设和待确认事项。

## 5. 推荐评分口径

| 等级 | 判定标准 |
| --- | --- |
| A | 交互自然，追问有效，产物可直接进入 P3 设计准备 |
| B | 覆盖主要需求域，但部分功能行为、数据或验收细节需要补充 |
| C | 能生成基本结构，但依赖测试者大量纠偏，功能仍偏清单化 |
| D | 混淆模板和样例，关键角色、流程、边界或非功能缺失 |
| E | 直接虚构需求或无法形成可用需求规格结构 |
