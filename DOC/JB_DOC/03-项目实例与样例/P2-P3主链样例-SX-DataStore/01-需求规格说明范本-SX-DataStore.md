## 2 项目概述

### 2.1 软件定位

`SX-DataStore` 是面向仿真资源的三门户资源平台原型系统。系统的业务中心不是单个商店首页，也不是页面壳层，而是受控资源体系。商店首页、工作台、资源工作区和治理驾驶舱均是资源对象、资源实例、申请审批、交付授权、组织责任和治理规则的不同页面投影。

系统通过三类门户承接不同角色的业务活动：

- 消费者门户面向资源发现、选型、申请和使用。
- 生产者门户面向资源创建、维护、发布、审批和交付准备。
- 管理者门户面向全局治理、审计、纠偏和异常接管。

### 2.2 建设目标

系统建设目标如下：

1. 建立统一资源目录，集中展示数据资源、模型资源、工具包和工具服务。
2. 支持资源按类型、领域、标签、组织、交付方式和业务场景进行浏览、检索和筛选。
3. 支持资源详情展示，说明资源能力、版本、产物、样例输出、关系图谱和申请条件。
4. 支持消费者通过资源篮提交资源申请，并跟踪审批和交付状态。
5. 支持生产者维护资源对象、版本、能力产物、发布状态、审批任务和交付处理。
6. 支持管理者查看全局治理驾驶舱、资源分布、用户分析、风险摘要和异常接管信息。
7. 支持公共页面、个人页面和资源级页面的配置、发布和运行时解析。
8. 支持普通检索、高级检索和对话式智能检索，帮助用户发现合适资源。
9. 通过清晰的角色、对象、流程和验收场景，为后续工程化实现提供需求基线。

### 2.3 使用场景

#### 2.3.1 消费者发现并申请资源

科研人员或业务分析人员进入资源商店，通过首页推荐、分类树、频道页、关键词搜索或高级筛选发现资源。用户查看资源详情、比较资源能力、确认申请条件，将资源加入资源篮，填写用途、范围和合规承诺后提交申请。系统展示申请进度，审批通过并完成交付后，用户在“我的资源”中进入已获得的资源实例。

#### 2.3.2 生产者维护并交付资源

资源负责人或生产者进入生产者门户，查看自己负责或协作的资源。生产者维护资源基础信息、资源版本、能力产物、示例输出、接口说明、发布状态和上下线状态。生产者处理责任链内的申请审批任务，审批通过后准备交付，完成下载包、接口凭据、在线入口或服务开通信息。

#### 2.3.3 管理者开展资源治理

平台管理者进入治理驾驶舱，查看资源数量、类型分布、组织分布、活跃使用、审批积压、异常风险和用户行为。管理者可查看全资源列表、用户分析和用户注册信息，对异常审批、违规资源、超时交付、风险资源进行接管、冻结、恢复或审计追踪。

#### 2.3.4 页面配置和运行时装配

运营人员或具备权限的角色可对公共页面、个人页面或资源级页面进行编辑。系统应保留关键锚定区域，例如顶部搜索区和左侧分类树；普通运营模块可进行拖拽、删除、缩放、配置和样式调整。页面发布后，运行时根据页面、用户、资源和配置范围解析最终展示结构。

### 2.4 范围边界

#### 2.4.1 首版负责

首版系统负责：

- 资源目录、资源详情、资源图谱和资源类型化展示。
- 消费者资源商店、资源检索、资源申请、我的申请和我的资源实例。
- 生产者资源维护、审批处理、交付处理和生产者工作台。
- 管理者治理驾驶舱、资源治理清单、用户分析和用户列表。
- 资源申请、审批、交付和实例获得的核心闭环。
- 页面配置、页面发布、运行时解析和页面编辑的基本闭环。
- 原型阶段需要的模拟数据、运行态页面和冒烟验证入口。

#### 2.4.2 首版不负责

首版系统不负责：

- 复杂多级审批、跨组织会签和真实电子签章。
- 大规模资源存储、真实数据下载、真实模型运行和真实工具服务编排。
- 完整低代码页面平台和任意页面自由搭建。
- 生产级计费、订单、合同、采购、结算和商业运营闭环。
- 真实统一身份认证、组织目录同步和生产级权限策略引擎。
- 面向第三方系统的正式开放平台生态。

## 3 功能需求

### 3.1 用户与角色

系统采用“单账号、多职责”模型。用户可在不同上下文中承担消费者、生产者或管理者职责。

| 角色 | 主要目标 | 典型能力 |
| --- | --- | --- |
| 消费者 | 发现、申请并使用资源 | 浏览资源、检索筛选、查看详情、加入资源篮、提交申请、查看申请、进入资源实例。 |
| 生产者 | 创建、维护、发布并交付资源 | 维护资源对象、维护版本和能力产物、发布上线、处理审批、准备交付。 |
| 管理者 | 治理资源、组织、用户和异常流程 | 查看治理驾驶舱、审计资源和用户、接管异常审批、冻结或恢复资源。 |
| 审批职责 | 处理某次申请中的决策节点 | 批准、拒绝、退回补充、填写审批意见。该职责可附着在生产者、资源负责人、协作者或管理者身上，不作为第四类总体角色。 |

### 3.2 核心业务流程

#### 3.2.1 资源发现与申请流程

1. 用户进入资源商店首页、频道页、资源列表页或搜索结果页。
2. 系统展示资源分类、资源推荐、资源卡片、筛选条件和搜索入口。
3. 用户查看资源详情，了解资源类型、交付方式、版本、能力产物、适用场景、申请条件和关系图谱。
4. 用户将资源加入资源篮，填写申请类型、目标实例名称、使用范围、合规承诺和补充材料。
5. 用户提交申请，系统生成资源申请并进入审批流程。
6. 用户在“我的申请”中查看当前状态、审批意见、退回原因或通过结果。
7. 审批通过并交付完成后，用户在“我的资源实例”中进入使用。

#### 3.2.2 资源维护与发布流程

1. 生产者进入生产者门户，查看自己负责或协作的资源。
2. 生产者创建或维护资源基础信息、分类、标签、版本、交付方式和申请策略。
3. 生产者维护资源能力产物，包括说明文档、示例输出、评估摘要、接口说明或安装说明。
4. 生产者发布资源版本，必要时执行上线或下线操作。
5. 系统在资源详情、资源列表、资源图谱和治理页中反映资源最新状态。

#### 3.2.3 审批与交付流程

1. 用户提交申请后，系统生成资源申请和审批任务。
2. 具备审批职责的用户查看审批任务，阅读申请用途、资源上下文和合规承诺。
3. 审批人可批准、拒绝或退回补充。
4. 审批通过后，系统进入交付准备或实例开通阶段。
5. 生产者或系统完成下载包、接口凭据、在线入口或服务环境配置。
6. 系统生成资源实例，用户可进入使用；审批、交付和实例变化应留下审计记录。

#### 3.2.4 治理与异常接管流程

1. 管理者查看治理驾驶舱，识别异常资源、审批积压、交付失败、权限风险和用户异常行为。
2. 管理者进入资源治理清单或用户分析页面查看详情。
3. 对异常审批、违规资源、超时交付等情况，管理者可发起接管。
4. 管理者可执行冻结、恢复、强制下线、撤销实例或审计追踪等治理动作。
5. 所有治理动作应保留操作者、对象、原因、时间和结果。

#### 3.2.5 页面配置与发布流程

1. 具备权限的用户进入页面编辑态。
2. 系统展示锚定区域和可编辑编排区。
3. 用户调整可编辑模块的位置、尺寸、配置或样式。
4. 用户保存草稿，系统保留页面配置版本。
5. 用户发布配置，系统在运行时解析公共版、个人版或资源级页面配置。

### 3.4 核心功能项说明

#### FR-01 资源目录与分类管理

系统应支持统一资源目录，资源至少包括数据资源、模型资源、工具包和工具服务。每个资源应包含名称、类型、标签、所属组织、负责人、更新日期、状态、交付方式和摘要说明。

输入包括：资源基础信息、资源分类、资源标签、所属组织、负责人、交付方式和状态。输出包括：资源列表、资源摘要、资源详情入口和资源统计信息。

验收口径：用户能够按资源类型和关键词查看资源列表；不同资源类型应能在列表和详情中被清晰区分。

#### FR-02 资源商店首页与频道浏览

系统应提供消费者资源商店首页，包含搜索入口、分类导航、推荐资源、频道入口和资源卡片。系统应支持至少一个模型资源频道，并具备扩展到数据、工具包、工具服务频道的能力。

首页应体现商店化浏览体验，但不应把商店首页作为业务事实源。资源状态、申请资格和交付状态应来自资源对象和用户资源关系。

验收口径：用户可通过首页、频道页和分类入口进入资源详情或资源列表；关键资源卡片应包含资源名称、类型、标签、组织和入口动作。

#### FR-03 资源检索与筛选

系统应支持普通关键词检索、高级筛选和对话式智能检索。普通检索应支持按名称、标签、场景或接口能力检索；高级筛选应支持按类型、领域、组织、交付方式和状态过滤；对话式智能检索应能根据用户自然语言意图推荐候选资源并说明理由。

检索结果应受用户可见性和权限规则约束，不应返回用户无权观察的敏感资源详情。

验收口径：用户输入关键词后能获得相关资源；筛选条件能影响结果；智能检索入口能返回候选资源和推荐理由，原型阶段可使用模拟结果。

#### FR-04 资源详情与能力产物展示

系统应为每个资源提供详情页，展示资源基础信息、适用场景、交付方式、版本信息、能力产物、示例输出、申请条件、关系图谱和当前用户申请状态。

不同资源类型的详情页应展示差异化功能区：数据资源可展示字段、质量摘要、血缘和范围；模型资源可展示模型格式、输入输出示例、评估摘要和运行环境；工具包可展示安装脚本、依赖、示例命令和校验信息；工具服务可展示接口、SLA、配额、依赖服务和健康状态。

验收口径：至少能查看数据、模型、工具包和工具服务四类资源详情示例；详情页应能展示申请入口、资源关系和类型化能力产物。

#### FR-05 资源篮与申请提交

系统应支持消费者将资源加入资源篮，并在提交申请前填写申请类型、目标实例名称、使用范围、合规承诺和补充材料。申请类型至少包括试用、正式使用和合作。

提交申请后，系统应生成资源申请对象，并将申请状态置为待审批。申请不得直接改变资源对象本体，也不得直接生成已获得资源实例。

验收口径：用户能够从详情页发起申请；提交后可在我的申请中看到新申请及其状态。

#### FR-06 申请审批与退回补充

系统应支持审批职责用户查看待处理审批任务。审批任务应展示申请人、资源、申请类型、用途说明、提交时间、当前状态和历史意见。审批人可批准、拒绝或退回补充。

审批职责由资源责任链、组织规则、申请类型和治理策略决定。审批者不是独立的第四类总体角色，而是附着在生产者、资源负责人、协作者或管理者身上的职责身份。

验收口径：审批人能够筛选待审批任务并做出决定；审批结果能回写申请状态并在申请人侧可见。

#### FR-07 资源交付与实例开通

审批通过后，系统应进入交付或开通阶段。交付方式可包括在线访问、下载、API 调用或服务环境开通。交付完成后，系统生成资源实例，并在消费者“我的资源”中展示入口、状态、有效期和使用范围。

资源实例应与资源对象区分。资源对象回答“资源是什么”，资源实例回答“用户这一次获得了什么、能否使用、流程走到哪一步”。

验收口径：审批通过后能形成交付记录或交付任务；交付完成后消费者能看到资源实例并进入使用入口。

#### FR-08 我的申请与我的资源

系统应提供消费者资源中心，支持查看我的申请和我的资源实例。我的申请以资源申请为主对象，展示提交、审批、退回、拒绝、通过和交付状态；我的资源以资源实例为主对象，展示可使用资源、有效期、状态和入口。

“我的资源”在消费者和生产者上下文中含义不同。消费者侧指已获得或正在使用的资源实例，生产者侧指自己创建、负责或维护的资源对象。

验收口径：消费者能够在不同页签查看申请和资源实例；状态文案不应混淆资源对象、申请和资源实例。

#### FR-09 生产者资源维护工作区

系统应提供生产者资源维护工作区，支持资源基础信息维护、归属和责任链维护、版本管理、能力产物维护、发布上线、下线、申请审批上下文、交付处理和历史记录查看。

资源工作区应围绕单个资源对象组织，不应替代个人审批主入口和全局治理入口。

验收口径：生产者能够查看资源列表并进入资源工作区；工作区至少覆盖基础信息、版本、能力、发布、审批或交付等关键页签。

#### FR-10 管理者治理驾驶舱

系统应提供管理者治理驾驶舱，展示资源总量、资源类型分布、组织分布、用户行为、审批积压、风险摘要和异常事项。管理者应能进入全资源列表、用户分析和全用户列表，并对异常资源、异常申请或异常实例进行接管和审计。

治理动作应与普通生产者动作区分。管理者可执行治理特权动作，但必须留下审计记录。

验收口径：管理者能够查看治理聚合数据、资源分布和用户分析；异常处理入口应能明确区分接管、冻结、恢复、撤销等动作。

#### FR-11 页面配置与运行时装配

系统应支持页面配置能力，包括公共页面、个人页面和资源级页面。页面配置应支持模块、插槽、布局、样式和编辑策略。关键锚定区域不得作为普通模块随意移除或拖离，例如顶部搜索区和左侧分类树。

系统应在运行时根据页面标识、用户、资源和配置范围解析最终页面结构。页面不得直接定义业务事实，页面展示应通过 ViewModel、领域对象、聚合对象和接口获得。

验收口径：系统能保存草稿、发布配置并解析页面；公共版、个人版和资源级配置应能被区分。

#### FR-12 审计、权限与异常处理

系统应对关键动作进行审计，包括资源创建、维护、发布、上线、下线、申请提交、审批决策、交付、实例撤销、治理接管、冻结和恢复。系统应根据角色、职责、资源关系、组织规则和状态展示能力入口。

异常状态应可被用户理解，包括接口失败、资源不可用、无权限、审批退回、交付失败、页面配置解析失败等。原型阶段允许通过模拟数据表达异常状态。

验收口径：关键动作具备状态反馈和审计事实；用户无法看到与当前角色上下文不匹配的核心动作入口。

### 3.5 业务规则与处理逻辑

1. 页面只投影业务事实，不直接创造资源、申请、审批、实例或治理事实。
2. 消费者提交申请后生成资源申请，审批通过并完成交付后才生成资源实例。
3. 生产者默认只能维护自己负责、协作或被授权的资源。
4. 管理者具备治理特权，但治理特权必须进入审计和异常接管链路。
5. 审批职责由资源归属、责任链、组织规则、申请类型和治理策略共同决定。
6. 上线、下线、冻结、撤销和恢复应区分常规生产者动作和管理者治理动作。
7. 公共页面和个人页面配置应分版本管理，个人配置不能破坏公共页面基线。
8. 检索结果应经过可见性、脱敏和权限过滤。
9. 锚定骨架区域不得被普通页面编辑操作破坏。
10. 资源对象、资源申请、审批任务、交付订单和资源实例应保持对象边界清晰。

### 3.6 结果输出与共享

系统应输出以下结果：

- 资源目录、资源详情和资源图谱。
- 消费者申请记录、审批状态和资源实例列表。
- 生产者资源工作区数据、审批任务和交付处理信息。
- 管理者治理聚合、资源分布、用户分析和审计记录。
- 页面配置摘要、页面配置版本和运行时解析结果。
- 原型阶段的冒烟验证结果、页面截图和接口响应证据。

### 3.7 异常与补偿

系统应处理以下异常：

- 后端接口不可用时，前端应展示明确的不可用或降级状态。
- 资源不存在或已下线时，详情页应提示不可访问或资源状态变化。
- 用户无权限时，应隐藏或禁用对应动作入口，并给出合理说明。
- 审批退回时，申请人应能看到退回原因和补充要求。
- 交付失败时，生产者和管理者应能看到失败状态并进行处理。
- 页面配置解析失败时，应回退到安全默认配置或展示运行时错误提示。

## 4 数据与接口需求

### 4.1 输入数据

系统输入数据包括：

- 资源基础数据：名称、类型、标签、领域、组织、负责人、状态、交付方式、更新时间。
- 资源详情数据：版本、能力产物、说明文档、示例输出、接口说明、依赖关系、申请条件。
- 申请数据：申请人、资源、申请类型、用途说明、使用范围、合规承诺、补充材料。
- 审批数据：审批任务、审批人、审批意见、审批结论、处理时间。
- 交付数据：交付方式、目标实例名称、凭据或入口、有效期、交付状态。
- 治理数据：资源分布、用户行为、异常事项、接管原因、治理动作和审计记录。
- 页面配置数据：页面标识、配置范围、模块、插槽、布局、编辑策略、版本和发布状态。

### 4.2 输出数据与报表

系统输出数据包括：

- 资源列表、资源详情、资源图谱和推荐结果。
- 搜索结果、筛选结果和智能检索推荐说明。
- 我的申请、申请进度、审批意见和申请结果。
- 我的资源实例、实例状态、有效期和使用入口。
- 审批任务列表、审批历史和交付任务列表。
- 治理驾驶舱指标、资源分布、用户分析、异常事项和审计记录。
- 页面配置摘要、页面解析结果和页面运行时状态。

### 4.3 外部接口需求

原型阶段系统应至少提供以下接口能力：

| 接口能力 | 需求说明 |
| --- | --- |
| 健康检查 | 用于确认后端 API 可用。 |
| 资源目录 | 支持按类型、领域和关键词查询资源。 |
| 资源详情 | 支持按资源标识获取详情和当前用户上下文。 |
| 资源图谱 | 支持获取资源节点和资源关系快照。 |
| 申请查询与创建 | 支持查询用户申请和提交资源申请。 |
| 审批查询与决策 | 支持审批任务列表和审批决策提交。 |
| 消费者工作台聚合 | 支持我的申请和我的资源实例聚合。 |
| 生产者工作台聚合 | 支持生产者资源、审批和交付聚合。 |
| 管理者治理聚合 | 支持治理驾驶舱和治理摘要。 |
| 页面配置与解析 | 支持页面配置查询、草稿保存、发布和运行时解析。 |

接口设计的字段、路径和模块边界不在本文展开，应在软件设计说明和接口规范中定义。

## 5 非功能需求

### 5.1 性能与可靠性

- 资源列表、搜索结果和工作台聚合在原型数据规模下应满足交互流畅性要求。
- 关键页面应在后端不可用时提供明确错误提示或降级展示。
- 页面配置解析失败时应可回退到安全默认配置，避免整体白屏。
- 冒烟验证应覆盖关键页面和接口，检查主要入口是否可访问。

### 5.2 安全与权限

- 系统应根据角色、职责、资源关系和状态控制动作入口。
- 管理者治理特权动作必须进入审计链路。
- 用户侧不得通过页面按钮绕过后端权限决策。
- 检索和详情展示应考虑可见性和脱敏规则。
- 原型阶段可使用模拟用户和模拟权限，但需求口径应保留正式权限扩展空间。

### 5.3 部署与运行环境

原型阶段系统按本地 monorepo 运行，至少包括：

- 后端 API 服务。
- 消费者门户 Web 应用。
- 生产者/管理者门户 Web 应用。
- 可选智能检索服务。

系统应提供清晰的本地启动说明、端口说明、环境变量说明和冒烟验证命令。

### 5.4 可维护性与扩展性

- 资源类型应可扩展，不应把某一类资源特性写死为全局规则。
- 页面配置应区分公共、个人和资源级范围。
- 资源对象、申请对象、审批任务、交付对象和资源实例应保持边界清晰。
- 需求、设计、代码和测试应能相互追溯。

### 5.5 易用性与可理解性

- 消费者应能理解“资源是什么、是否适合申请、如何申请、申请进度如何、在哪里使用”。
- 生产者应能理解“我负责哪些资源、哪些要维护、哪些要审批、哪些要交付”。
- 管理者应能理解“系统资源和用户是否健康、哪里有风险、哪些需要接管”。
- 状态文案应避免混淆资源对象、申请、审批和资源实例。

## 6 验收准则

### 6.1 验收场景

| 场景 | 验收内容 |
| --- | --- |
| 消费者资源发现 | 从商店首页、频道页或搜索页进入资源详情。 |
| 消费者申请闭环 | 查看详情、提交申请、查看我的申请、审批后查看资源实例。 |
| 生产者维护资源 | 查看生产者资源列表，进入资源工作区维护资源信息和版本。 |
| 生产者审批交付 | 查看审批任务，处理审批，进入交付处理。 |
| 管理者治理 | 查看治理驾驶舱、资源分布、用户分析和异常事项。 |
| 页面配置运行时 | 查询页面配置摘要，保存草稿，发布配置，解析运行时页面。 |
| 资源图谱 | 查看资源节点、资源关系和图谱入口。 |
| 异常与降级 | 后端不可用、无权限、资源不存在或页面解析失败时有明确提示。 |

### 6.2 验收准则

1. 系统主要入口可访问，且消费者、生产者、管理者上下文明确。
2. 资源目录和资源详情能覆盖数据、模型、工具包和工具服务四类资源。
3. 资源申请、审批、交付和资源实例的业务对象边界清晰。
4. 消费者“我的资源”与生产者“我的资源”语义不混淆。
5. 审批职责不被误建模为第四类总体业务角色。
6. 管理者治理动作与生产者常规动作可区分，并有审计口径。
7. 页面配置能力不被扩展为无限制通用低代码平台。
8. 检索、筛选和智能检索入口能服务资源发现目标。
9. 文档、页面、接口和测试证据能够互相追溯。

### 6.3 待确认事项

以下事项在原型阶段可采用模拟数据或预留接口，但进入生产化前需要进一步确认：

- 真实组织、用户、角色和职责来源。
- 资源可见性、脱敏、审批路由和权限策略的正式规则。
- 智能检索所使用的大模型、索引、知识库和安全过滤策略。
- 真实资源交付方式、凭据管理和资源实例生命周期。
- 页面配置发布审批、回滚和版本治理策略。
- 生产级审计、日志留存、合规和安全要求。
