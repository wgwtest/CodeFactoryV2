# 需求规格模板组说明

## 1. 文档定位

**文档类别：** 标准文种候选文档  
**标准依据：**

- `DI-IPSC-81433 Software Requirements Specification`
- `DI-IPSC-82259 System/Subsystem Specification`

**当前状态：** 基线

## 2. 模板组目标

本模板组用于说明软件工厂在需求分析阶段形成正式需求规格时，应如何选择标准模板。

## 3. 当前模板分流规则

### 3.1 软件级对象

当产物边界清晰、对象主要是单体应用或纯软件服务时，优先采用：

- `81433`

### 3.2 平台级 / 系统级对象

当产物边界接近平台、系统或子系统，且具有更强的跨模块能力包特征时，优先采用：

- `82259`

## 4. 对应 `P2` 的关系

`P2` 的核心输出是：

- 结构化 `RequirementSpec`

需求规格说明模板不是 `P2` 的唯一权威成果，但它是 `RequirementSpec` 的重要文档投影。

## 5. 当前应覆盖的最小章节

### 5.1 软件级模板最小章节

- 范围
- 对象与用户
- 功能需求
- 接口需求
- 非功能需求
- 验证考虑

### 5.2 平台级模板最小章节

- 范围
- 系统 / 子系统概述
- 需求分组
- 接口与约束
- 验证基线

## 6. 当前结论

需求规格模板组已经具备明确的双路线：

- 软件级走 `81433`
- 平台 / 系统级走 `82259`
