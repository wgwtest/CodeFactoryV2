# JB_DOC 文档状态与同步规则

## 1. 文档定位

**文档类别：** 标准化辅助文档  
**标准依据：** 吸收 `SDP / SEMP / 配置与基线管理` 控制思路  
**当前状态：** 生效

本文件用于规定 `JB_DOC` 的文档状态、同步关系和维护规则。

## 2. 文档状态分层

`JB_DOC` 中的文档统一采用以下状态：

### 2.1 骨架

含义：

- 只建立目录、章节和对象边界
- 尚未形成完整内容

适用：

- 后续待补文种
- 初步矩阵文档

### 2.2 候选

含义：

- 已经根据现有来源文档完成首版复写
- 已具备较完整结构
- 但尚未经过进一步标准对齐校核

适用：

- 平台规格说明候选
- 平台设计说明候选
- `SDP / SEMP` 候选

### 2.3 基线

含义：

- 已经过人工确认
- 已明确标准依据、章节边界和来源映射
- 可作为当前稳定引用对象

适用：

- 已冻结的模板组说明
- 已冻结的标准化平台文档

### 2.4 样例

含义：

- 面向某个具体项目实例输出的文档
- 用于验证模板在真实项目中的适配性

适用：

- 未来项目交付实例

## 3. `CODEX_DOC` 与 `JB_DOC` 的同步规则

### 3.1 权责边界

- `CODEX_DOC`
  - 研发正式文档根
- `JB_DOC`
  - 标准化投影与副本文档根

因此：

- `CODEX_DOC` 不是 `JB_DOC` 的附录
- `JB_DOC` 也不是 `CODEX_DOC` 的替代品

### 3.2 同步原则

当以下对象发生变化时，应评估是否同步到 `JB_DOC`：

- 平台总体边界变化
- 阶段接口契约变化
- 模板中心适用范围变化
- 新增标准模板族
- 关键映射关系变化

### 3.3 不要求实时逐字同步

`JB_DOC` 不是逐字镜像层，因此：

- 不要求每次 `CODEX_DOC` 小改动都立即同步
- 允许按版本或里程碑进行批量更新

### 3.4 必须同步的情况

以下情况必须同步：

- 影响标准对象边界的修改
- 影响模板选择规则的修改
- 影响来源映射关系的修改
- 新增已确认的标准候选文档

## 4. 每份文档必须声明的最小信息

`JB_DOC` 中的关键文档必须在开头明确：

- 文档类别
- 标准依据
- 当前状态

必要时还应补充：

- 主要来源文档
- 适用范围

## 5. 标准依据声明规则

### 5.1 有明确标准对象的文档

必须写明：

- 对应标准编号
- 标准名称
- 是“严格对应”还是“候选对齐”

### 5.2 无明确标准对象的文档

必须写明：

- 无直接单一军标文种对应
- 本文档属于“桥接文档”或“辅助文档”

## 6. 版本维护规则

当前阶段先采用“单文件当前版”方式维护，不立即引入复杂版本号体系。

后续如果出现以下情况，可升级版本管理：

- 同一标准候选文档多轮冻结
- 模板中心开始对外提供正式版本
- 项目实例样例数量显著增加

## 7. 目录维护规则

### 7.1 不允许空建目录长期无文档

目录一旦创建，应至少有一份说明性文档，避免后续无法理解用途。

### 7.2 不允许把所有桥接内容堆到一个文件里

映射、缺口、路线图应分别成文，防止后续维护困难。

### 7.3 不允许把本地自由发挥文档包装成标准原件

这是 `JB_DOC` 最重要的规则之一。

凡是没有直接标准对象支撑的文档，都必须明确标注其桥接或辅助性质。
