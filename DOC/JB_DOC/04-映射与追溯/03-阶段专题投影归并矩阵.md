# 阶段专题投影归并矩阵

## 1. 文档定位

**文档类别：** 本地桥接文档  
**标准依据：** 参考 `DID` 文种组合交付与本地标准化投影规则  
**当前状态：** 基线

本文件用于回答一个容易被误解的问题：

- 当前新增的 `10 ~ 21` 这些阶段 / 专题投影稿，是否就是 `JB_DOC` 的最终正式文种形态

本文件给出的正式答案是：

- 不是

这些投影稿当前只承担：

- 来源拆解
- 审阅分流
- 细节保真
- 追溯锚点

它们的后续命运不是长期与平台规格说明、平台设计说明平级并存，而是按真实文种边界逐步并回主文种，并在必要时以附录、补充件或专题补卷形式保留。

本轮执行状态补充如下：

- 第一轮主文种归并已经启动。
- `01-软件工厂平台规格说明-候选.md` 与 `02-软件工厂平台设计说明-候选.md` 已吸收 `P1 / P2 / P3 / P4 / P6` 的阶段级正文。
- 投影稿当前仍保留，并已统一移入 `01-平台自身标准文档/90-阶段专题投影附件/`，用作追溯附件与后续精细归并锚点。

## 2. 归并原则

### 2.1 主文种优先

平台自身标准文档包的真实主文种当前仍是：

- `01-软件工厂平台规格说明-候选.md`
- `02-软件工厂平台设计说明-候选.md`
- `03-系统工程管理计划-候选.md`
- `04-软件开发计划-候选.md`
- `05-需求追溯验证矩阵-骨架.md`
- `06-配置管理计划-候选.md`
- `07-质量保证计划-候选.md`
- `08-技术评审与阶段门控说明.md`
- `09-验证与发布策略-候选.md`

阶段 / 专题投影稿不是对这些主文种的替代。

### 2.2 规格与设计分流

归并时按以下边界处理：

- 回答“平台要实现什么、边界是什么、对外暴露什么、验收关心什么”的内容，优先并入规格说明
- 回答“平台内部如何组织、对象如何协作、运行如何闭环、数据如何落地”的内容，优先并入设计说明
- 回答“暂时不适合压缩进主文种，但必须保留的细节”的内容，可保留为附录、补充件或专题补卷

### 2.3 投影稿先保留、后降级

在主文种完成吸收前，投影稿必须保留，以防细节丢失。

当以下条件满足后，投影稿可从“主阅读对象”降级为“追溯附件”：

- 主文种已吸收对应章节
- 来源映射已改为指向主文种章节
- 缺口声明已同步到主文种或缺口清单

## 4. 归并顺序

当前建议按以下顺序推进：

1. 已完成本矩阵与总说明、路线图、来源映射的一致化
2. 已完成 `P1 / P2 / P3 / P4 总体 / P6` 的阶段级首轮正文归并
3. 持续细化 `P4` 四个专题向平台设计说明及其补充件的吸收深度
4. 并行补 `B1` 契约级源文
5. `B1` 补齐后，再二次增强主文种中的接口、schema、状态机章节

## 5. 当前不做的事

本轮不做以下动作：

- 不删除任何已写投影稿
- 不宣称当前投影稿已经等同于真实军标最终文种结构
- 不在 `B1 / B2` 缺口未补齐时伪造完整终版编号体系

## 6. 当前结论

当前 `10 ~ 21` 这些文档的正确身份是：

- 阶段 / 专题来源投影稿
- 主文种归并前的过渡层
- 追溯层与审阅层

它们不是长期的正式终态。  
后续 `JB_DOC` 必须沿“主文种吸收 + 附件保留 + 缺口显式标记”的路径继续收敛。
