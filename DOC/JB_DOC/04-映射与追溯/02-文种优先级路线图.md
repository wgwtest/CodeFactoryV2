# 文种优先级路线图

## 1. 文档定位

**文档类别：** 标准化辅助文档  
**标准依据：** 结合当前标准对象与平台阶段主链  
**当前状态：** 基线

本文件用于说明 `JB_DOC` 后续文种建设的优先级顺序。

## 2. 排序原则

- 优先服务当前主链
- 优先补齐闭环能力
- 优先建设对验证价值最高的对象

## 3. 优先级分层

### 第一优先级：需求与设计主链

- `81433`
- `81435`
- `82259`
- `82284`

理由：

- 这是当前 `P2 / P3` 的直接主链
- 当前系统已具备主链验证基础

### 第二优先级：追溯与测试闭环

- `RTVM`
- `STP`
- `STD`
- `STR`

理由：

- 这是从“能生成文档”走向“能验证文档”的关键跃迁

### 第三优先级：发布与交接闭环

- `SPS`
- `SVD`
- `STrP`

理由：

- 这是从“能验证”走向“能正式交付”的关键补齐

### 第四优先级：接口与数据库扩展

- `IRS`
- `IDD`
- `DBDD`

理由：

- 重要，但不应先于主链和闭环链建设

## 4. 当前推荐推进法

当前推荐顺序为：

1. 巩固 `P2 / P3` 主链模板中心
2. 将 `RTVM` 从骨架推进为正式矩阵
3. 建立测试文档模板章节骨架
4. 建立发布与移交模板章节骨架
5. 视具体项目需求扩展接口与数据库模板

## 5. 当前结论

`JB_DOC` 后续建设不应追求“文种数量越多越好”，而应追求：

- 主链优先
- 闭环优先
- 实例可落地优先
