# CODEX_DOC 到 JB_DOC 来源映射总表

## 1. 文档定位

**文档类别：** 本地桥接文档  
**标准依据：** 无直接单一军标文种对应  
**当前状态：** 基线

本文件用于说明：`JB_DOC` 当前各关键文档分别吸收了哪些 `CODEX_DOC` 正式来源，以及它们当前主要承接哪些对象。

## 2. 映射原则

- 以 `CODEX_DOC` 为研发权威根
- `JB_DOC` 允许多来源合成，不追求逐文件复制
- 只有正式文档层内容，才作为 `JB_DOC` 的稳定来源
- `superpowers` 草稿若已被回写进 `CODEX_DOC`，则通过 `CODEX_DOC` 间接进入 `JB_DOC`
- 阶段 / 专题投影稿当前属于过渡追溯层，不等同于最终主文种终态

## 2.1 当前平台文档包标准基线说明

当前平台自身标准文档包采用的不是“同编号族全包”，而是彼此可适配的 current baseline 组合：

- 产品定义主文种：`DI-IPSC-82259 + DI-IPSC-82284`
- 过程管理主文种：`DI-SESS-81785 + DI-IPSC-81427B`
- 控制保障主文种：`DI-SESS-80858D + DI-QCIC-81794A`
- 追溯矩阵主文种：`DI-MGMT-82133`
- `08 / 09` 明确作为桥接或组合文档管理

当前仍有一个来源库层面的事实缺口：

- `99-标准来源库/` 已补齐 `DI-IPSC-81427B / DI-SESS-81785B / DI-SESS-80858D / DI-QCIC-81794A` 的 revision 级官方证据；其中 `DI-SESS-80858D / DI-QCIC-81794A` 当前采用 `WMX` PDF / `NOTICE` 直证据，旧主号页只保留为历史或异常留档

## 7. 当前结论

当前 `JB_DOC` 采用的是：

- 多来源合成
- 按标准对象重组
- 先拆出阶段 / 专题投影，再按主文种归并
- 对当前缺失对象明确保留缺口

这也是现阶段唯一合理、且与新版 `CODEX_DOC` 相一致的映射方式。
