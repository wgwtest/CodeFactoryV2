# 软件工厂平台规格说明（候选）

## 1. 文档定位

**文档类别：** 标准文种候选文档  
**标准依据：** 主要对齐 `DI-IPSC-82259 System/Subsystem Specification`  
**当前状态：** 候选  
**主要来源文档：**

- `DOC/CODEX_DOC/01_需求分析/00-工程总体分析.md`
- `DOC/CODEX_DOC/02_设计说明/00-软件工厂平台总体设计.md`
- `DOC/CODEX_DOC/03_研制计划/00-WBS-0-CodeFactoryV2-研发总纲-研制计划.md`

本文件面向软件工厂平台自身，目标是形成平台级 / 系统级规格说明候选稿，而不是描述某个单一业务软件。

## 2. 适用范围

本规格说明适用于 `CodeFactoryV2` 平台自身，覆盖：

- `P1` 业务知识库
- `P2` 需求分析系统
- `P3` 软件设计系统
- `P4` 工具仓库
- `P5` 软件构建系统
- `P6` 门户与平台入口

不覆盖：

- 某个具体业务项目的交付实例文档
- 某个单阶段的实现细节设计

## 3. 平台概述

`CodeFactoryV2` 的目标是构建一个“知识驱动的软件工厂平台”，使行业专家与研发团队可以围绕统一平台完成：

- 领域知识沉淀
- 交互式需求建模
- 软件设计编制
- 工具 / 组件资产匹配
- 目标软件装配与生成

平台主链为：

`P1 -> P2 -> P3 -> P4 -> P5`

`P6` 作为平台入口和观察层，不改变主链依赖顺序。

## 4. 平台级需求

### 4.1 知识处理需求

平台应支持基于资料文档形成结构化知识仓，并对外提供：

- 实体、事件、流程、规则、指标查询能力
- 来源文档与证据回溯能力
- 向 `P2` 输出可选业务元素的能力

### 4.2 需求建模需求

平台应支持面向非技术行业专家的交互式建模，并满足：

- 从对象出发进行建模
- 允许引用领域知识元素
- 允许创建临时元素并标记待入库
- 输出结构化 `RequirementSpec`

### 4.3 设计编制需求

平台应支持对冻结的需求规格进行设计分析与设计说明编制，并满足：

- 形成结构化设计基线
- 生成“软件设计说明”投影
- 允许人工评审、修订与冻结
- 形成面向 `P4` 的模块级 / 子模块级工具化描述

### 4.4 工具资产需求

平台应支持：

- 工具、组件、执行器资产登记与管理
- 对 `P3` 输出的工具化描述进行匹配
- 输出可复用资产命中结果与未命中项推进结果

### 4.5 构建与交付需求

平台应支持：

- 基于设计结果和工具资产生成目标软件或元数据应用
- 沉淀新形成的构建资产

### 4.6 平台入口需求

平台应提供统一入口，支持：

- 模块访问
- 状态观察
- 首页导航与可视化入口

## 5. 外部接口与阶段接口

### 5.1 阶段接口

- `P1 -> P2`
  - 已发布知识对象、元素筛选和来源回溯能力
- `P2 -> P3`
  - 冻结的 `RequirementSpec`
- `P3 -> P4`
  - 模块级 / 子模块级工具化描述与设计冻结投影
- `P4 -> P5`
  - 资产命中结果、执行资产清单、校验结果

### 5.2 管理接口

平台应允许对知识库、订单、资产、样例和配置进行管理，但各模块不得直接依赖上游内部工作态。

## 6. 约束条件

平台研发与运行应满足以下约束：

- 结构化对象优先于文档投影
- 下游阶段只消费上游标准成果物
- 组件 / 工具闭环发生在应用生成过程中
- 平台研发文档与平台产物模板文档应分层管理

## 7. 验证考虑

平台级验证至少应覆盖：

- 主链模块是否按既定顺序协作
- 标准成果物是否能够作为阶段输入输出
- 模板中心是否能支撑 `P2 / P3` 标准产物生成
- 知识、设计、资产和构建之间是否存在可追溯链路

## 8. 当前结论

本文件可作为 `CodeFactoryV2` 平台自身向系统 / 子系统规格说明方向演进的首版候选稿，后续仍需继续补齐：

- 需求编号体系
- 更细化的非功能需求
- 更正式的验证章节
