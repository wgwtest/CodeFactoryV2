# 软件工厂平台设计说明（候选）

## 1. 文档定位

**文档类别：** 标准文种候选文档  
**标准依据：** 主要对齐 `DI-IPSC-82284 Software/Hardware Design Description`  
**当前状态：** 候选  
**主要来源文档：**

- `DOC/CODEX_DOC/02_设计说明/00-软件工厂平台总体设计.md`
- `DOC/CODEX_DOC/02_设计说明/06-P3-软件设计系统设计.md`
- `DOC/CODEX_DOC/02_设计说明/02-P4-核心业务循环设计.md`
- `DOC/CODEX_DOC/02_设计说明/04-P4-Backend服务边界设计.md`

本文件描述的是软件工厂平台自身的总体设计候选稿，而不是某个被平台生产出来的软件设计说明。

## 2. 设计对象与范围

本设计说明覆盖 `CodeFactoryV2` 平台自身的：

- 总体架构
- 六阶段模块边界
- 阶段接口
- 关键设计原则

不下钻到：

- 各模块的全部实现细节
- 前端页面的具体视觉方案
- 某个实例项目的业务设计

## 3. 总体设计原则

### 3.1 结构化对象优先

平台各关键阶段优先输出结构化对象，再按需要投影为说明文档、图谱视图或执行描述。

### 3.2 标准成果物驱动

下游阶段只依赖上游标准成果物，不依赖其内部工作态。

### 3.3 对象优先于流程

在需求分析侧，优先从对象出发，再组织流程，以支持：

- 多对象跨流程应用
- 新流程探索
- 既有流程与新流程并存

### 3.4 闭环在生成过程中发生

组件 / 工具资产闭环发生在应用生成过程中，而不是应用完成后再补做沉淀。

## 4. 平台架构

### 4.1 主链架构

平台主链为：

`P1 业务知识库 -> P2 需求分析系统 -> P3 软件设计系统 -> P4 工具仓库 -> P5 软件构建系统`

`P6` 独立承担入口、导航与观察职责。

### 4.2 分层视角

从设计角度，平台可理解为三层：

- 研发平台层
  - 负责平台自身研发与治理
- 产物模板层
  - 负责生成标准化需求、设计及后续交付模板
- 项目实例层
  - 负责承接具体项目的实际输出

### 4.3 模块职责

- `P1`
  - 知识资料接入、知识治理、知识查询
- `P2`
  - 交互式需求建模、形成 `RequirementSpec`
- `P3`
  - 形成结构化设计基线、设计说明投影与工具化描述
- `P4`
  - 工具 / 组件资产匹配、供给与演进
- `P5`
  - 目标软件装配与生成
- `P6`
  - 统一入口与运行态观察

## 5. 接口设计

### 5.1 `P1 -> P2`

接口语义：

- 已发布知识对象
- 元素筛选能力
- 来源与证据回溯

### 5.2 `P2 -> P3`

接口语义：

- 冻结的 `RequirementSpec`

### 5.3 `P3 -> P4`

接口语义：

- 模块级 / 子模块级工具化描述
- 冻结后的设计投影

### 5.4 `P4 -> P5`

接口语义：

- 命中资产清单
- 供给结果
- 校验与约束结果

## 6. 关键子系统设计说明

### 6.1 `P3` 子系统设计要点

`P3` 的设计要点在于：

- 输入是冻结的需求规格
- 内部权威层是结构化设计基线
- 文档层是软件设计说明投影
- 交接层是批次模块工单包

### 6.2 `P4` 子系统设计要点

`P4` 的设计要点在于：

- 它不是单纯工具列表管理器
- 它是工具资产运行中台
- 其核心循环是：
  - 命令接入
  - 写入事实
  - 投递任务
  - 调度执行
  - 刷新投影
  - 供给查询

## 7. 设计追溯考虑

平台总体设计应能够向下追溯到：

- 阶段设计说明
- 模板中心设计说明
- 关键接口约束

平台总体设计也应能够向上回溯到：

- 平台规格说明
- 工程总体分析
- 研发总纲

## 8. 当前结论

本文件可作为 `CodeFactoryV2` 平台自身向系统级设计说明方向演进的首版候选稿。后续还需补齐：

- 更细化的接口分解
- 设计决策记录
- 设计与验证的明确追溯关系
