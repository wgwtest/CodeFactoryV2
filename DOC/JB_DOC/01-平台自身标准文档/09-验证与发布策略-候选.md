# 验证与发布策略（候选）

## 1. 文档定位

**文档类别：** 标准文种候选文档  
**标准依据：** 组合参考 `RTVM / STP / STD / STR / SPS / SVD / STrP`  
**当前状态：** 候选  
**主要来源文档：**

- `DOC/JB_DOC/01-平台自身标准文档/05-需求追溯验证矩阵-骨架.md`
- `DOC/JB_DOC/02-软件工厂产物模板中心/03-测试文档模板组说明.md`
- `DOC/JB_DOC/02-软件工厂产物模板中心/04-发布与移交模板组说明.md`
- `DOC/CODEX_DOC/06_测试文档/*`
- `DOC/CODEX_DOC/07_过程文档/*`

本文件用于定义 `CodeFactoryV2` 平台如何从“已有需求与设计主链”继续走向“可验证、可发布、可交接”的完整闭环。

## 2. 当前验证对象

当前验证对象分为三层：

### 2.1 平台研发层

验证：

- 平台边界
- 阶段设计
- 阶段计划
- 自测、验收和交接记录

### 2.2 标准化副本层

验证：

- 平台自身标准文档包
- 模板中心
- 映射、缺口与路线图

### 2.3 项目实例层

未来验证：

- 某个真实项目的正式 `SRS / SDD / RTVM / STP / STR / SVD` 样例链

## 3. 当前验证主线

平台当前推荐验证主线为：

`需求边界 -> 设计归档 -> 追溯矩阵 -> 自测 / 验收 -> 标准副本同步 -> 模板中心补齐 -> 项目实例样例`

其中当前已较稳定的部分是：

- 平台边界与阶段设计
- 文档迁移、自测、验收和交接记录
- `JB_DOC` 平台文档包候选稿

## 4. 当前发布主线

平台当前发布主线至少应回答：

- 当前发布对象是什么
- 发布基线是什么
- 哪些内容属于工程正式交付物
- 哪些内容属于外接资料或本地运行态，不纳入正式发布包

当前推荐的平台发布包至少包括：

- 当前代码基线
- `CODEX_DOC` 正式文档根
- `JB_DOC` 标准化副本根
- 必要的模板中心文档
- 必要的测试、自测、验收和交接记录

不应默认纳入：

- 外接知识源资料
- 本地抽取结果
- 本地运行数据

## 5. 当前证据链

### 5.1 已有证据

当前可沉淀的证据主要来自：

- 阶段设计正式归档记录
- 阶段自测报告
- 验收清单
- 会话交接记录

### 5.2 仍待补齐的证据

后续仍需补齐：

- 平台级 `RTVM` 的更严格证据字段
- `STP / STD / STR` 的平台样例或模板应用证据
- `SPS / SVD / STrP` 的平台发布与交接样例

## 6. 当前后续优先级

当前验证与发布链的优先级顺序建议为：

1. 巩固平台级 `RTVM`
2. 形成测试链模板与应用证据
3. 形成发布与移交模板及样例
4. 推进项目实例层验证

## 7. 当前结论

本文件可作为 `CodeFactoryV2` 走向测试链、发布链和交接链的总体策略候选稿。

它当前不声称这些链路已经全部落地，但已经明确：

- 验证对象
- 发布对象
- 当前证据
- 后续优先级
