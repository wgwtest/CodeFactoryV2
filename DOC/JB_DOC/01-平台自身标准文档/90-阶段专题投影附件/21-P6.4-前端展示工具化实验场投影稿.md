# P6.4 前端展示工具化实验场投影稿

## 1. 文档定位

**文档类别：** 标准化投影文档  
**标准依据：** 主要服务平台入口与观察层专题补充，不直接对应单一军标原件  
**当前状态：** 候选  
**主要来源文档：**

- `DOC/CODEX_DOC/02_设计说明/P6_门户与平台入口/P6.4-前端展示工具化实验场设计.md`
- `DOC/CODEX_DOC/02_设计说明/P6_门户与平台入口/P6-门户与平台入口设计.md`

## 2. 投影目标

`P6.4` 是 `P6` 探索验证层中的核心节点，负责验证“前端展示是否可以像工具一样被配置、绑定、组合和复用”。

它不是正式业务模块，也不是与 `P4` 重复的工具仓库页面。它的职责是为平台前端展示工具化提供实验场、样板和反馈证据。

## 3. 设计边界投影

### 3.1 当前负责

- 定义展示工具化的最小对象模型
- 提供展示模板、数据绑定、布局组合和预设的实验框架
- 记录实验结果与反馈结论
- 将可复用结论回传给 `P3 / P4 / P5`

### 3.2 当前不负责

- 替代正式业务页
- 反写业务数据
- 替代 `P4` 工具仓库
- 在当前阶段冻结为正式生产能力

### 3.3 实验场硬约束

`P6.4` 首版固定遵守以下硬约束：

- 实验数据只允许来自 `P6.2` 的只读投影
- 实验样式必须先继承 `P6.3` 基线，再声明实验性例外
- 实验通过只能形成晋升候选，不自动升级为正式资产
- 模板、绑定、布局和预设都必须能独立命名和被复用

## 4. 最小对象模型投影

首版固定：

- `DisplayWidgetTemplate`
- `DisplayWidgetBinding`
- `DisplayWidgetLayout`
- `DisplayWidgetPreset`
- `DisplayExperimentRecord`

这些对象共同回答：

- 展示模板本体是什么
- 数据如何绑定
- 多组件如何组合
- 哪些结果值得晋升为正式复用能力

### 4.1 晋升候选输出

当实验结果稳定时，至少输出：

- `promotion_candidate_id`
- `candidate_kind`
- `target_stage`
- `adoption_reason`
- `evidence_refs`

## 5. 实验流程投影

`P6.4` 首版建议采用如下实验流程：

1. 选择阶段数据源
2. 选择或创建展示模板
3. 建立字段绑定
4. 组合布局
5. 在平台观察页或实验页预览
6. 记录实验结果
7. 判断是否可进入正式复用链

这条链路的目标不是现场改页面，而是把展示能力对象化、证据化。

## 6. 与 `P3 / P4 / P5` 的关系

### 6.1 对 `P3`

为 `P3` 提供“哪些展示对象适合结构化表达”的反馈。

### 6.2 对 `P4`

为 `P4` 提供“哪些展示能力值得做成正式工具或组件资产”的依据。

### 6.3 对 `P5`

为 `P5` 提供可直接装配的展示预设候选。

这意味着 `P6.4` 的产出是反哺，不是替代。

## 7. 当前未纳入投影的缺口声明

本投影稿当前**不补写**以下内容：

- 正式生产级展示资产规范
- 展示组件契约与版本兼容规则
- 可直接发布的前端资产清单

这些内容当前仍属探索后续项，不应在本轮被伪装成已冻结正式能力。

## 8. 当前结论

`P6.4` 当前已具备明确的最小对象模型、实验流程和反哺关系，可作为 `P6` 探索验证层专题进入 `JB_DOC`。
