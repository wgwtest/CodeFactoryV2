# P4 工具仓库总体投影稿

## 1. 文档定位

**文档类别：** 标准化投影文档  
**标准依据：** 主要服务平台设计主链中的工具中台阶段表达，不直接对应单一军标原件  
**当前状态：** 候选  
**主要来源文档：**

- `DOC/CODEX_DOC/02_设计说明/05-P4-工具仓库设计.md`
- `DOC/CODEX_DOC/02_设计说明/00-软件工厂平台总体设计.md`

本文件用于把 `P4` 的总体角色、核心对象、双闭环和对外边界从平台总设计中独立投影出来。

## 2. 投影目标

`P4` 不是“工具列表管理页”，而是软件工厂中的工具资产运行中台。

其首版最小闭环包括：

- 工具描述模型
- 工具仓库 CRUD
- 分类与标签体系
- 工具需求单与匹配规则 MVP
- 自演进巡检闭环
- 对 `P5` 可查询、可获取的结果出口

## 3. 阶段职责重组

### 3.1 当前负责

- 工具、组件、执行器资产的结构化登记
- 工具需求单与叶子需求项的受理、匹配、审定与供给
- 工具池自演进巡检、发现项处置、内部任务推进与回退
- 统一数据快照与驾驶舱验证工作台

### 3.2 当前不负责

- 替代 `P3` 的软件设计对象生成
- 承担最终软件装配与运行
- 成为跨全厂通用调度中心

## 4. 双闭环与公共运行骨架

`P4` 同时承担两条业务闭环和一条公共运行骨架。

### 4.1 外部输入闭环

面向 `P3 / P3-sim`：

`工具需求单 -> 拆叶子工具项 -> 匹配 -> 审定 -> 直接交付或进入研制 -> 对 P5 提供查询与获取`

### 4.2 内部自演进闭环

面向工具池自身：

`工具仓快照 -> 巡检 -> 发现项 -> 采纳/忽略 -> 内部任务 -> 自动改写或人工跟进 -> 回退`

### 4.3 公共运行闭环

为上述两条业务链统一提供：

`命令接入 -> 事实写入 -> 任务投递 -> 调度 -> 分域执行 -> 查询投影刷新 -> 审计与回退`

## 5. 核心对象投影

### 5.1 `ToolDefinition`

`ToolDefinition` 是当前首版核心资产对象，用于表达：

- 工具身份
- 所属域
- 形态
- 输入输出
- 平台与生命周期阶段
- 标签
- 验证信息

### 5.2 `ToolDemandSheet / ToolDemandItem`

它们共同承载：

- 外部输入受理
- 叶子需求拆解
- 生命周期推进
- 匹配与审定过程

### 5.3 自演进对象

`P4` 内部还应显式承载：

- 工具仓快照
- 巡检发现项
- 内部任务
- 自动改写或人工跟进结果

## 6. 对外边界

### 6.1 上游边界

`P4` 通过标准契约与上游耦合，不直接依赖：

- `P1` 治理工作态
- `P1 / P2 / P3` 内部表结构
- 临时脚本输出
- 未发布中间 JSON

### 6.2 下游边界

`P4 -> P5` 当前只提供：

- 资产命中结果
- 供给结果
- 运行约束
- 查询与获取出口

### 6.3 非直接修订语义

`P4` 不直接接受来自 `P5` 的业务不匹配修订命令。

更准确的边界是：

- `P5` 上报问题
- `P3` 仲裁问题归属
- 若属于供给缺口，由 `P3` 向 `P4` 下发新供给任务 / 派生任务 / 组件拆分任务
- `P4` 自主决定复用、派生、拆分或新建

这保证：

- 平台级资产语义不被单次装配临时改写
- `P4` 自循环能独立演进
- `P3` 保持业务目标和设计语义的唯一解释权
