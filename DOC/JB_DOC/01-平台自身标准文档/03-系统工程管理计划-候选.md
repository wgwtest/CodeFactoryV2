# 系统工程管理计划（候选）

## 1. 文档定位

**文档类别：** 标准文种候选文档  
**标准依据：** 主要参考 `DI-SESS-81785 Systems Engineering Management Plan`  
**当前状态：** 候选  
**主要来源文档：**

- `DOC/CODEX_DOC/00-本地工程策略映射.md`
- `docs/development-policy.md`
- `DOC/CODEX_DOC/03_研制计划/00-WBS-0-CodeFactoryV2-研发总纲-研制计划.md`
- `DOC/CODEX_DOC/02_设计说明/00-软件工厂平台总体设计.md`

本文件不是标准原件复写，而是平台自身研发活动吸收 `SEMP` 控制思路后的首版候选稿。

## 2. 计划目标

本计划用于说明 `CodeFactoryV2` 平台研发过程中：

- 系统工程如何组织
- 各阶段边界如何定义
- 上下游接口如何冻结
- 需求、设计、实现、验证如何逐步建立追溯关系

## 3. 系统工程对象

本计划关注的平台对象是：

- 软件工厂平台本身
- 平台内六个一级阶段系统

不直接管理：

- 某个具体项目实例的交付文档内容
- 某个阶段的局部实现细节

## 4. 工程组织原则

- 采用 WBS 组织阶段边界
- 采用正式成果物驱动上下游协作
- 采用本地文档根与工作文档层协同方式
- 优先冻结边界、接口和对象模型，再展开局部实现

## 5. 阶段工程主线

当前平台按以下主线推进：

- `P1`
  - 业务知识库
- `P2`
  - 需求分析系统
- `P3`
  - 软件设计系统
- `P4`
  - 工具仓库
- `P5`
  - 软件构建系统
- `P6`
  - 门户与平台入口

工程管理要求：

- 各阶段对下游只暴露标准成果物
- 低耦合准备工作可以前移
- 正式核心实施以稳定上游结果为前提

## 6. 关键控制点

### 6.1 边界控制

必须持续控制：

- 阶段边界
- 输入输出契约
- 模板中心边界
- 实例文档与模板文档边界

### 6.2 追溯控制

后续应逐步建立：

- 需求编号体系
- 设计编号体系
- 交付模板编号体系
- 验证证据回链关系

### 6.3 文档控制

必须区分：

- 平台研发文档根
- 标准化副本文档根
- 工作层临时文档

## 7. 当前阶段重点

当前阶段系统工程重点为：

- 巩固 `P1 ~ P3` 的标准主链
- 明确 `P4` 的中台边界
- 为后续 `RTVM / STP / STR / SVD` 等对象预留位置

本候选稿后续还需补齐：

- 更正式的工程评审节点
- 风险管理表述
- 验证闭环与里程碑控制项
