# 平台自身标准文档包总说明

## 1. 文档定位

**文档类别：** 标准化辅助文档  
**标准依据：** 采用 current baseline 组合：`DI-IPSC-82259 / DI-IPSC-82284 / DI-SESS-81785 / DI-IPSC-81427B / DI-MGMT-82133 / DI-SESS-80858D / DI-QCIC-81794A`，其中 `08 / 09` 为桥接或组合文档  
**当前状态：** 基线

本文件用于说明 `01-平台自身标准文档/` 的内部结构、对象边界、当前版本深度和后续深化方式。

## 1.1 当前采用的标准基线

平台自身标准文档包当前按如下口径统一标准依据：

这里的“统一”指的是：

- 统一到一组彼此可适配的 current baseline，而不是要求所有文档来自同一个编号族
- `01 / 02` 当前作为成对的产品定义主文种使用，不再出现“一个偏旧、一个偏新”的混搭表达
- `05 / 08 / 09` 明确属于桥接或组合对象，不伪装成单一标准原件

当前仍保留一个需要诚实声明的缺口：

- `99-标准来源库/` 已补齐 `04 / 06 / 07` 对应的 current baseline revision 证据；其中 `DI-SESS-80858D / DI-QCIC-81794A` 当前采用官方 `WMX` PDF / `NOTICE` 直证据而非稳定详情页，这会影响证据形态一致性，但不改变本包的文种定位和结构判断

## 2. 文档包服务的对象

本目录服务的是：

- 软件工厂平台自身

而不是：

- 平台未来生成的某个具体业务项目交付物

因此，本目录中的“规格说明”“设计说明”“计划”“配置”“质量”“验证发布”文档，描述的都是 `CodeFactoryV2` 平台自身，而不是由平台生成出来的业务系统实例。

## 4. 与 `P1 ~ P6` 的关系

### 4.1 覆盖关系

本目录已吸收的平台阶段如下：

- `P1` 业务知识库
- `P2` 需求分析系统
- `P3` 软件设计系统
- `P4` 工具仓库
- `P6` 门户与平台入口

其中，`P1 / P2 / P3 / P4 / P6` 的 `A` 类阶段与专题设计，现已形成独立投影稿，不再只停留在平台规格 / 平台设计总包中。

但这并不意味着这些独立投影稿将长期作为与规格说明、设计说明平级的正式主文种存在。

当前更准确的理解应是：

- 它们是归并前置层
- 是主文种吸收前的审阅与追溯锚点
- 其最终归并去向由 `03-阶段专题投影归并矩阵.md` 约束

### 4.2 当前仍处边界定义层的对象

- `P5` 软件构建系统

原因不是忽略 `P5`，而是当前正式来源仍主要停留在总纲与边界层。本目录已保留其平台级职责与约束，但不会伪造独立详细设计。

## 7. 当前最小可用链

当前推荐把平台自身的标准文档推进链理解为：

`平台规格说明 -> 平台设计说明 -> 系统工程管理计划 -> 软件开发计划 -> 技术评审与阶段门控 -> 配置管理 / 质量保证 -> 追溯矩阵 -> 验证与发布策略`

这条链的含义不是“必须串行写完才开发”，而是：

- 每一类控制对象都必须存在
- 平台不能只有产品定义文档，而没有过程、控制和验证文档

## 8. 当前结论

`01-平台自身标准文档/` 当前已经形成：

- 一套基于新版 `CODEX_DOC` 深化过的首版标准文档包
- 一套已收敛到 current baseline 口径、且已区分主文种与桥接文档的标准对象组合

其后续主要任务不是再扩目录，而是：

- 按归并矩阵把阶段 / 专题投影稿吸收到主文种
- 继续提高章节质量
- 补齐 `B1` 契约级源文对应的后续投影
- 补齐编号、证据与实例
- 与模板中心、样例层形成稳定衔接
