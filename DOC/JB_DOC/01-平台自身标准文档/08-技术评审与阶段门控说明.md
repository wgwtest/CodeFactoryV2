# 技术评审与阶段门控说明

## 1. 文档定位

**文档类别：** 本地桥接文档  
**标准依据：** 吸收 `SEMP` 与 DoD 技术评审思路，无单一军标文种一一对应  
**当前状态：** 基线

本文件用于回答一个 `SRS / SDD` 本身不会展开回答的问题：

- 从平台需求、平台设计到模板、实现、验证，中间到底通过哪些评审与门控步骤推进

## 2. 为什么需要本文件

即使拥有完整的需求、设计、测试和交付文档族，也仍然需要说明：

- 何时进入下一阶段
- 何时冻结基线
- 哪些结果必须人工评审

这类内容通常散落在系统工程管理、开发计划、评审制度和验证制度中，而不会全部放在一份产品定义文档里。

## 3. 当前推荐评审链

### 3.1 平台对象澄清评审

目标：

- 澄清平台边界
- 明确主链阶段职责
- 确认哪些对象属于平台研发层，哪些属于模板层

主要输入：

- 平台总体分析
- 平台总体设计

### 3.2 标准对象映射评审

目标：

- 确认某类对象该对应哪种标准文种
- 确认哪些内容只能做桥接文档

主要输入：

- 文种映射分析
- 模板中心说明

### 3.3 模板可执行性评审

目标：

- 判断模板是不是能真正支持后续实例输出

主要输入：

- 标准模板文档
- 来源映射和缺口清单

### 3.4 阶段实现就绪评审

目标：

- 判断是否可以从文档与模板进入具体实现或联调

主要输入：

- 需求规格
- 设计说明
- 追溯矩阵
- 测试计划

### 3.5 阶段关闭评审

目标：

- 判断阶段是否已达到可验收、可冻结、可交接状态

## 4. 当前门控规则

- 没有对象边界，不进入模板细化
- 没有模板边界，不进入实例化输出
- 没有追溯与测试计划，不宣称形成闭环
- 没有人工确认，不宣称阶段关闭

## 5. 当前结论

平台的“研发过程步骤”并不是不存在，而是：

- 分散在管理、评审、验证和配置控制活动中

本文件就是为这些步骤提供统一桥接表达。
