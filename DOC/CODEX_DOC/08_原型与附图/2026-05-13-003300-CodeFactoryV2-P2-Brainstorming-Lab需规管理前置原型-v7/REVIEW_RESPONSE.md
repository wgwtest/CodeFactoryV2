# v7 评审响应

## 1. 评审背景

用户确认 v6 对齐真实系统的方向，但进一步指出：真实用户工作流应先有“需求规格说明本身”的对象管理。用户需要先新建、打开或编辑一份需求规格说明，然后再进入组织器配置、会话、Turn 和日志。

## 2. 已吸收的批注

### 批注 1：最上面应先有需规管理

处理结果：

- v7 新增第一个 Tab：`需求规格说明管理`。
- 左侧导航顺序调整为：需求规格说明管理、组织器配置、会话管理、当前 Turn、调用日志。

### 批注 2：新建需规后再进入配置

处理结果：

- 管理页左侧提供需规列表、新建入口和最小输入。
- 管理页右侧提供当前需规对象详情和 `进入组织器配置` 主动作。
- 组织器配置页顶部增加当前需规对象上下文，说明配置作用于当前对象。

### 批注 3：暂不讨论是否合并

处理结果：

- v7 只做原型设计，不改代码，不回写主文档。
- README 中把“是否合并为 P2 首页或并入 Lab”列为后续确认问题。

## 3. 本版结论

v7 的核心结论是：

```text
需求规格说明是用户首先管理的业务对象；组织器配置、会话、Turn 和调用日志是选中该对象后的运行层视图。
```

本版当前仍需用户确认。
