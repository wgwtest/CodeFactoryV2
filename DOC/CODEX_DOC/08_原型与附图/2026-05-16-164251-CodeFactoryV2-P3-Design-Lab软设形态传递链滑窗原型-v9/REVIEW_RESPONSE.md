# v9 评审响应记录

## 1. 来源

用户对 v8 的核心批注是：从软设文档到功能树、分层架构、技术实现、展示形态，不应只是一个页面一个页面的普通 Tab，而应能直观看出上一个形态与下一个形态之间的传递关系。

## 2. 处理结果

| 批注 / 诉求 | v9 处理 |
| --- | --- |
| 希望看到软设文档到功能树到架构图的递进关系 | 增加顶部完整形态链，固定展示 `需规 -> 文档 -> 功能树 -> 架构 -> 技术实现 -> 展示形态 -> P4` |
| 希望探索长画卷 / 横向拖动 / 滑窗 | 主工作区改成三形态滑窗，并用底部缩略滑窗表示长卷位置 |
| 希望下方可以拖拽或动态编辑 | 原型中用底部“长卷滑窗”和当前对象追溯轨表达交互入口；实现时可升级为真实拖拽 |
| 希望看到当前对象上下游关系 | 增加底部当前选中对象追溯链 |
| 不确定普通 Tab 是否有实际意义 | v9 将普通 Tab 降级为 Lab 主导航层，软设工作区内部不再使用普通五 Tab 作为主组织方式 |

## 3. 仍待用户确认

- 三形态滑窗是否比完整七形态同屏更适合审阅和编辑。
- 顶部完整链条与底部追溯轨是否足够表达传递关系。
- 后续实现是否需要支持真实横向拖拽，还是先用分段切换实现。
