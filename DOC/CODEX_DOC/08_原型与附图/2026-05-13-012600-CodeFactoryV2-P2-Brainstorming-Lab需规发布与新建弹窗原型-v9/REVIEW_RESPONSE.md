# v9 评审响应

## 1. 评审背景

v8 已将 4.1 收敛为单栏需求规格说明列表，但列表右侧仍保留 `打开 / 编辑 / 进入配置` 三个按钮。用户指出这三个动作语义上基本都是进入配置，不应并列出现。

用户同时要求：右上角 `新建需规` 按钮需要弹出一个模态窗口，并补充该窗口设计。

## 2. 已吸收的批注

### 批注 1：行内动作改为进入配置和发布

处理结果：

- 删除 `打开 / 编辑 / 进入配置` 三连按钮。
- 每条未发布需规改为 `进入配置` 与 `发布` 两个动作。
- 已发布对象显示 `已发布`，发布状态列显示 `P3 可接收`。

### 批注 2：发布是 P2 到 P3 的边界动作

处理结果：

- README 明确发布会冻结当前需求规格说明版本。
- 发布后该版本可以被 P3 接收。
- 后续修改应通过配置生成修订草稿或新版本，不直接把已发布版本当普通草稿编辑。

### 批注 3：新建需规需要模态窗口

处理结果：

- 新增 `#spec-new` 原型状态。
- 补充 `新建需求规格说明` 模态窗口图。
- 模态窗口收集标题、初始说明、默认模板和创建后动作。
- 默认主动作是 `创建并进入配置`。

## 3. 本版结论

v9 的核心结论是：

```text
4.1 列表行只保留“进入配置 / 发布”；新建需规通过模态窗口创建业务对象，再进入 4.2 配置。
```

本版当前仍需用户确认。
