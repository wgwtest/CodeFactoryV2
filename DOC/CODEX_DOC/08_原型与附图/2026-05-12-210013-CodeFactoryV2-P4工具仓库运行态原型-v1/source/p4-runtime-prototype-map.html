P3 输入侧

P3 不直接生产最终工具，而是把软件设计里的组件级缺口拆成 P4 可处理的叶子需求项。

需求单 业务场景、系统树、组件叶子项、输入输出类型、验收说明。
提交状态 submitted -> accepted，P4 成为供给工序的责任阶段。
代表路由 /xx-p3-sim

P4 工具资产运营中台

Tool Demand Chain

受理 P3 工具需求单，按叶子项形成审批、匹配、制造或交付决策。

Tool Registry

维护工具资产、形态、领域覆盖、运行平台、校验状态与可获取接口。

Manufacture & Delivery

未命中工具时进入制造计划；命中工具时生成供给结果和 fetch interface。

Runtime Coordination

制造队列、运行进度、内部循环与快照投影共同形成运行态事实。

Evolution Inspection

周期性巡检重复工具、覆盖缺口、停滞任务和优化建议。

Real Tool Delivery

真实工具构建、交付清单、依赖策略、导入规范与 P5 查询保持一致。

/xx-p4 总览指标、监控、风险、覆盖
输入工序链需求单、叶子项、审批
自演进巡检发现项、任务队列、回滚
工具仓库资产表、制造队列、真实交付

P5 消费侧

P5 只消费 P4 暴露的查询结果、进度状态和交付清单，不绕开 P4 直接读取制造内部过程。

整单查询 sheet review/delivery status 与叶子项清单。
叶子项进度 直接交付、制造中、ready for fetch、失败等状态。
代表路由 /xx-p5-sim
核心闭环： P3 demand sheet -> P4 leaf item review -> existing tool delivery or manufacture plan -> runtime progression -> P5 query / delivery manifest -> P6 projection.
本版边界： 原型用于解释当前 P4 已实现界面与逻辑，不替代后续 UI 改版设计；截图中的数据为运行态取证数据。
