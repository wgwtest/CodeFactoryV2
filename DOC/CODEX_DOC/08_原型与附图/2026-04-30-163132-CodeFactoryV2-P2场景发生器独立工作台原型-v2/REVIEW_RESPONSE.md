# v1 评审响应

## 用户批注

用户指出 v1 的整体思路有问题：

1. 模拟数据或新造数据不应影响需求规格编辑器本体。
2. 需求规格编辑器理论上不知道数据来源是真还是假的。
3. 发生器应有自己独立的界面，是独立新功能，不是当前需求规格编辑器的设置扩展。

## 判断

批注成立。v1 将发生器放入 P2 编辑器设置弹层，并在编辑器工作面显示 `模拟 P1 知识源`、`mock-airspace-p1`、`mock_rule` 等信息，违反了来源无感边界。

## v2 处理

1. 新建独立 `P2 场景数据发生器工作台`。
2. 发生器负责场景选择、模板绑定、知识物化、问答脚本、闭环验证和交付会话。
3. P2 编辑器只接收标准 `RequirementAuthoringSession`，不显示 mock、模拟、发生器来源或 fixture id。
4. v1 保留，不覆盖；v2 作为新的送审版本。
