# P1 并行工作线 02：运行时快照与增量重算

更新时间：2026-05-06

## 工作目标

把“策略配置真正进入抽取运行过程”这件事做实。抽取启动时必须冻结当前使用的策略包版本，运行中必须持续产出可观察事件，规则变更后必须能计算影响面并触发增量重算。

这条线的核心问题是：

- 当前抽取使用的是哪一版策略。
- 每个阶段实际执行了哪些规则。
- 质量门禁、候选发布等阶段的策略命中结果有没有进入 runtime。
- 规则变化后，哪些文档、阶段、候选对象、关系、发布快照需要重算。

## 运行事件要求

runtime stream 至少要覆盖：

- stream 连接状态。
- 当前阶段真实状态。
- 阶段开始、完成、警告、阻断。
- 当前策略包版本快照。
- 阶段输入对象摘要。
- 规则命中结果。
- RuleExecutionRecord 摘要。
- 质量门禁 `policy / metrics / rule_hits / decision`。
- 发布候选快照 `candidate_snapshot / api_exposure_scope / governance_pending`。
- 增量重算任务状态。

轮询 fallback 不能只返回粗粒度状态，必须至少能返回同一份 runtime snapshot 的关键字段。

## 增量重算要求

规则变更后应计算 ImpactSet：

- `changed_rule_ids`
- `affected_stage_ids`
- `affected_document_ids`
- `affected_chunk_ids`
- `affected_candidate_ids`
- `affected_relation_ids`
- `affected_publication_snapshot_ids`
- `minimum_rebuild_stage_id`

重算任务应表达：

- 旧策略包版本。
- 新策略包版本。
- 旧运行快照。
- 新运行快照。
- 重算起点阶段。
- 每个受影响阶段的待处理数量、运行中数量、完成数量、失败数量。
- 是否需要治理重新确认。

## 可验证成果

完成后应能验证：

- 新建知识库并启动抽取后，runtime snapshot 明确显示当前策略版本。
- stream 事件里能看到规则命中、RuleExecutionRecord、质量门禁决策。
- 断开 stream 后，轮询结果仍然能补回关键运行状态。
- 修改规则合同后，系统能生成影响面并创建增量重算任务。
- 增量重算不会覆盖正式入库知识，只产生新候选或待确认结果。
