# P1 并行工作线 01：策略合同与版本主干

更新时间：2026-05-06

## 工作目标

把 P1 中“策略包版本 + 规则字段合同 + RuleExecutionRecord”这条主干收成稳定后端能力。重点不是页面视觉，而是让系统能够明确回答：

- 当前知识库使用哪一个策略包版本。
- 每条规则的输入字段、输出字段、判断条件、动作效果是什么。
- 规则变更后为什么必须生成新版本，而不是覆盖旧版本。
- 每次规则执行后留下什么可追溯记录。

## 核心设计要求

规则字段合同至少要表达：

- 字段名。
- 来源产物。
- 字段类型。
- 是否必填。
- 是否参与 `input_hash`。
- 校验规则。
- 示例值。
- 字段业务含义。
- 缺失时动作。

规则输出合同至少要表达：

- 输出字段。
- 输出归属对象。
- 生成方式。
- 是否参与 `output_hash`。
- 是否写入运行态。
- 是否写入审计日志。
- 是否用于影响面计算。
- 示例输出。

`RuleExecutionRecord` 至少要表达：

- `execution_id`
- `archive_id`
- `document_id`
- `stage_id`
- `rule_id`
- `rule_version`
- `rule_hash`
- `input_artifact_refs`
- `input_hash`
- `output_artifact_refs`
- `output_hash`
- `affected_object_ids`
- `affected_relation_ids`
- `decision`
- `metrics`
- `executed_at`

## 可验证成果

完成后应能验证：

- 加载策略包时可以看到 13 个阶段的策略配置。
- 查看某条规则时可以看到完整输入/输出字段合同。
- 保存结构性规则变更时会生成新策略包版本。
- 缺少关键字段时，合同校验能明确失败并指出字段。
- 规则执行记录能包含输入哈希、输出哈希和影响对象。
