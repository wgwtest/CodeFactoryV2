# P1 知识抽取闭环页面清单与 UI 原型提示词

## 1. 设计目标

本页面组服务于 `P1 / P0` 机器知识抽取闭环。用户需要能清楚看到：

- 一个知识库从文档接入到机器发布候选的全过程。
- 每个文档当前执行到 13 阶段中的哪一步。
- 每个阶段的输入对象、规则/策略/动作依据、输出对象。
- 每条规则的输入输出合同、版本、命中结果和影响对象。
- 用户可以把一套阶段策略沉淀为可复用策略包，后续采集同类文件时可直接选择，也可复制后创建新策略。
- 规则调整后，哪些知识会过期、需要重算、被替换、被保留、被拆分或被阻断。
- 发布/API 阶段只是生成机器发布候选，正式入库仍由 `/governance` 人工确认。

## 2. 全局 UI 约束

所有页面统一遵守以下设计约束：

- 使用中文界面，不出现乱码，不使用英文作为主要标签；必要技术字段可保留英文小字。
- 桌面端优先，画布尺寸以 `1920 x 1080` 为主，兼顾宽屏工作台。
- 视觉气质是“知识工厂控制台”：冷静、结构化、可信、可追溯，不要做成普通后台 CRUD。
- 状态颜色统一：绿色表示已完成/已生效，蓝色表示运行中/当前阶段，橙色表示警告/待确认，红色表示阻断/失败，灰色表示未进入，紫色或靛蓝表示规则版本/策略快照，淡黄色表示规则变更影响区。
- 所有图谱默认使用“语义聚合视图”，不要一上来铺满全部明细节点。
- 图谱表达必须围绕“输入对象 -> 策略/规则/动作依据 -> 输出对象”，规则节点不能隐藏在说明文字里。
- 节点文字必须在节点内部，节点和连线不能遮挡，主链节点保持间距，非主链节点围绕相关阶段局部分布。
- 图谱交互必须体现：拖动画布、缩放、选中节点/边高亮、右侧观察窗联动、局部展开明细。
- 实时运行页不能依赖整页刷新；需要明确显示“已连接 Stream / 已回退轮询”。
- 抽取启动必须明确选择策略包版本，并冻结为本次运行策略快照；不能默认偷读当前最新配置。
- 策略调整后要显示规则版本快照、影响面、重算进度和新旧差异。
- `/governance` 只处理发布后的候选知识，不审核抽取中的临时图谱节点。

## 3. 页面总览

| 编号 | 页面 | 当前入口或建议入口 | 核心用途 |
| --- | --- | --- | --- |
| 01 | 知识库总览与抽取启动页 | `/archives` | 创建知识库、查看抽取总览、启动抽取、进入单文档运行 |
| 02 | 知识库文档清单与文档选择页 | `/documents` | 管理当前知识库文档、查看纳入状态、选择文档进入运行页 |
| 03 | 文档接入与解析验证页 | `/documents/intake` | 上传、解析验证、查看统一文档前的结构化解析结果 |
| 04 | 单文档实时抽取工作台 | `/archives` 文档视图 | 实时查看 13 阶段、图谱、观察窗、策略版本和运行事件 |
| 05 | 策略库与策略模板管理页 | 建议新增 `/archives/policies` | 管理可复用策略包、策略版本、复制改造和适用知识类型 |
| 06 | 阶段策略配置页 | `/archives` 策略视图 | 在某个策略包版本下按阶段配置策略、规则、AI 适配和输出要求 |
| 07 | 规则输入输出合同编辑页 | 策略配置子页/抽屉 | 配置每条规则的输入 schema、输出 schema、影响类型和 trace 字段 |
| 08 | 策略版本与规则差异页 | 策略配置子页/抽屉 | 对比策略包版本、规则版本、阈值和动作变化 |
| 09 | 规则变更影响面与增量重算页 | 建议新增 | 显示 ImpactSet、stale 对象、重算计划、重算进度和新旧差异 |
| 10 | 质量门禁策略执行解释页 | 单文档质量门禁阶段 | 解释是哪条策略导致放行、警告、阻断或延迟发布 |
| 11 | 发布候选快照与 API 暴露页 | 单文档发布/API 阶段 | 展示机器已发布候选、API 暴露范围、等待治理确认状态 |
| 12 | 发布候选治理确认页 | `/governance` | 人工确认发布候选，生成正式入库版本 |
| 13 | 发布态知识图谱浏览页 | `/graph` | 只浏览正式发布后的知识图谱和来源文档 |

## 4. 页面 UI 原型提示词

### 01. 知识库总览与抽取启动页

```text
请生成一个 1920x1080 桌面端中文产品页面，页面名称为“知识库总览与抽取启动”。这是 CodeFactoryV2 的 P1 业务知识库控制台，不是普通后台列表。页面用于创建知识库、查看当前知识库抽取状态、启动抽取并进入单文档实时运行页。

整体风格：知识工厂控制台，浅色背景，结构化卡片，状态颜色清晰，视觉上有“运行链路”和“知识产物仓”的感觉。不要使用花哨插画，不要做成普通 Ant Design 表格堆叠。

布局：
顶部是产品级标题区，左侧标题“P1 业务知识库”，副标题“文档接入 -> 策略选择 -> 机器抽取 -> 发布候选 -> 治理确认”。右侧有当前知识库选择器、策略库按钮、创建知识库按钮、刷新按钮。
主体分三列：左侧为知识库列表，中间为当前知识库运行总览，右侧为策略与质量摘要。

左侧知识库列表：
每个知识库卡片显示名称、文档数、最近抽取时间、当前抽取状态、默认策略包、最近策略快照版本。卡片有“设为当前”“查看文档”“选择策略”“启动抽取”操作。被选中的知识库高亮。

中间运行总览：
显示 13 阶段横向微缩流程条，阶段状态包括待处理、运行中、已完成、警告、阻断、未进入。显示“当前运行文档”“已连接 Stream / 已回退轮询”“当前阶段”“最近事件”。下方是文档运行队列，列出每份文档的抽取阶段、进度、规则命中数、候选知识数、质量门禁结果，点击某文档进入单文档实时抽取工作台。

右侧策略与质量摘要：
显示默认策略包、当前策略包版本、最近运行快照、启用阶段数、规则总数、最近规则变更、是否存在 stale 对象。提供“进入策略库”“进入阶段策略配置”“查看规则变更影响面”“查看质量门禁规则”按钮。

关键交互状态：
新建知识库弹窗要有名称、业务域、默认策略包、知识内容类型、是否立即导入文档。
启动抽取时弹出确认，必须选择策略来源：使用知识库默认策略、从策略库选择已有策略包版本、复制已有策略并改造、新建空白策略、系统根据文件类型/知识类型推荐策略。确认区显示本次将冻结的策略包名称、策略包版本、运行快照 ID、文档范围和是否覆盖默认策略。
如果策略变更后有 stale 对象，页面顶部出现橙色横幅：“规则已变化，部分知识需要重算”，并提供“查看影响面”按钮。
```

### 02. 知识库文档清单与文档选择页

```text
请生成一个 1920x1080 桌面端中文页面，页面名称为“知识库文档清单与文档选择”。页面用于管理当前知识库中的文档，区分已纳入知识库、待纳入、已移出、抽取中、抽取完成、需要重算的文档。

视觉风格延续知识工厂控制台，背景干净，文档列表要像“素材进入知识工厂前后的状态板”，不是普通文件管理器。

布局：
顶部显示当前知识库名称、默认策略包、文档总数、已完成抽取数、运行中数、需要重算数、正式入库知识数。
左侧为筛选栏：文档状态、抽取状态、绑定策略包、策略快照版本、文件类型、知识内容类型、是否有 stale 对象、是否已生成发布候选。
中间为文档表格或密集卡片列表，右侧为选中文档详情预览。

文档列表字段：
文档标题、来源、文件类型、知识内容类型、字符数/页数、纳入状态、当前抽取阶段、绑定策略包、策略快照、候选知识数、规则命中数、质量门禁决策、发布候选状态、最后更新时间。

选中文档详情：
显示文档基础信息、解析摘要、推荐策略、已绑定策略、最近运行事件、13 阶段状态小图、规则变更影响提示。提供操作：进入实时抽取、选择/更换策略、复制策略后重跑、启动/重跑抽取、查看统一文档、查看发布候选、移出知识库。

重要表达：
如果某文档因规则变化需要重算，使用淡黄色状态条标记“规则版本落后于当前策略”，并显示最早需要重算的阶段。
如果文档已经完成机器发布候选但未治理确认，显示“已生成候选，等待治理确认”，不要显示“已正式入库”。
```

### 03. 文档接入与解析验证页

```text
请生成一个 1920x1080 桌面端中文页面，页面名称为“文档接入与解析验证”。页面用于上传文档、查看解析器选择、解析执行状态和统一文档前的结构化解析结果。它是抽取主链的前置验证，不代表知识已经入库。

整体视觉是“文档进入知识工厂的入口闸机”：左侧是上传与解析队列，中间是解析结构预览，右侧是解析质量与入库准备状态。

顶部：
标题“文档接入与解析验证”，副标题“上传、解析、结构化预检；通过后可纳入知识库抽取主链”。右侧有上传按钮、选择解析器、批量解析、纳入当前知识库按钮。

主体：
左侧文档接入队列显示文件名、上传时间、解析器、解析状态、错误数、片段数、是否已纳入知识库。
中间为解析结果预览，使用树状结构展示标题、章节、段落、表格、列表、图片说明、锚点编号。支持点击锚点查看原文片段。
右侧为解析质量面板，显示覆盖率、未识别段落、表格解析质量、文档语言、元数据完整性、建议动作。

底部：
显示“解析结果 -> 统一文档对象”的转换预览，包括将产生的 block、section、table、anchor 数量。提供“生成统一文档预览”和“送入知识库抽取”按钮。

重要提醒：
页面必须明确显示“当前页只做接入与解析验证，不代表正式知识入库”。如果用户选择纳入知识库，则提示会进入 13 阶段抽取链。
上传或解析完成后，需要让用户选择知识内容类型，例如行业规范、需求文档、合同条款、业务流程说明，并基于文件类型和知识类型推荐可用策略包。用户可以接受推荐策略、手动选择已有策略包，或者复制策略包创建新版本后再送入抽取。
```

### 04. 单文档实时抽取工作台

```text
请生成一个 1920x1080 桌面端中文工作台页面，页面名称为“单文档实时抽取工作台”。这是 P1 最核心页面，用于实时查看一份文档从资料接入到发布候选的 13 阶段机器抽取过程。

整体风格参考流程控制台 + 知识图谱编辑器，但不要做成普通节点堆叠。重点让用户看懂“当前真的运行到哪一步”“每个阶段输入了什么、依据什么规则、输出了什么”。

顶部：
左侧显示文档标题、所属知识库、抽取运行 ID、当前状态。右侧显示“已连接 Stream / 已回退轮询”状态徽标、策略包名称、策略包版本、当前运行快照 ID、重新连接按钮、查看规则按钮、查看原文按钮。

第一层为 13 阶段流程导航：
使用三段背景分区：摄取与统一、证据与知识生成、规范化与发布。每个阶段是圆角节点，状态颜色清晰。当前阶段只能由后端实时状态决定，用户点击不能改变当前阶段。已完成阶段可点击查看快照，未到阶段置灰不可点击。当前实时阶段始终保持蓝色高亮。

第二层为当前阶段图谱：
默认“语义聚合视图”，中心表达为三列：输入对象、规则/策略/动作依据、输出对象。主链节点横向排布，辅助节点围绕相关主链节点分布。节点文字在节点内部，连线用直线，箭头起止点根据节点位置自动调整。节点不能重叠，密集区域使用集合节点和局部展开。

图谱交互：
支持画布拖拽、缩放、适配画布、重置布局、局部展开、语义聚合/明细视图切换。选中节点或边时，高亮其上下游一跳路径，弱化其它节点；右侧观察窗同步显示对象详情、规则输入输出、事件流和原文证据。

右侧观察窗：
固定宽度，分为阶段视角、节点视角、边视角三个标签。阶段视角显示当前阶段目标、输入产物、输出产物、使用规则、执行事件。节点视角显示对象载荷、来源锚点、状态、是否 stale。边视角显示动作依据、规则命中、输入输出关系。
观察窗顶部始终显示本次运行绑定的策略包、策略版本和快照 ID，并提示“页面展示的是启动抽取时冻结的策略快照，不会被当前最新配置静默覆盖”。

底部或左下：
显示实时事件流，不刷新整页。事件包括阶段开始、对象生成、规则执行、规则命中、节点状态变化、阶段完成、stream 断线回退。

质量要求：
页面要特别强调快照语义：点击已完成阶段时展示历史快照，但流程导航中的当前实时阶段仍保持高亮。
```

### 05. 策略库与策略模板管理页

```text
请生成一个 1920x1080 桌面端中文页面，页面名称为“策略库与策略模板管理”。页面用于管理 P1 知识抽取的可复用策略包资产。用户可以把一套适用于某类知识内容采集的阶段策略保存为策略包，后续采集同类文件时直接选择，也可以复制后创建新策略。

整体视觉：策略资产库 + 模板市场 + 版本控制台。不要做成普通配置列表，要让用户感到这里管理的是“知识抽取方法资产”。

顶部：
标题“策略库与策略模板管理”，副标题“复用、复制、版本化管理 13 阶段知识抽取策略”。右侧有“新建策略包”“从现有策略复制”“导入策略模板”“查看策略差异”按钮。

主体布局：
左侧为策略包分类导航，按业务域、知识内容类型、文件类型、生命周期状态分组，例如行业规范、需求文档、合同条款、业务流程说明；状态包括草稿、已发布、已归档、推荐模板。
中间为策略包卡片或表格，每个策略包显示名称、适用知识类型、适用文件类型、最新版本、阶段覆盖数、规则数、最近使用次数、最近效果摘要、维护人、生命周期状态。
右侧为选中策略包详情，显示策略包说明、适用范围、13 阶段覆盖图、规则合同摘要、质量门禁策略、发布边界、最近版本历史和最近绑定的抽取任务。

关键交互：
点击“使用此策略”时弹出选择目标知识库和文档范围，并提示会在抽取启动时冻结运行快照。
点击“复制改造”时创建新策略包或新版本，用户可选择复制全部 13 阶段、只复制部分阶段、继承规则合同但调整阈值。
点击“设为知识库默认策略”时需要确认默认策略只影响之后的新抽取任务，不会覆盖已有运行快照。
点击“查看版本”进入策略版本与规则差异页。

重要状态：
如果某策略包有新版本但部分文档仍使用旧版本，页面显示“历史运行仍绑定旧快照”。如果新版本包含结构性规则变更，显示橙色标签“可能触发增量重算”。
```

### 06. 阶段策略配置页

```text
请生成一个 1920x1080 桌面端中文页面，页面名称为“阶段策略配置”。页面用于在某个策略包版本下，按 13 阶段配置知识抽取策略，不是 /governance 人工审核规则。配置完成后，机器抽取会在启动时选择该策略包版本并冻结运行快照，随后根据策略和 AI 自动适配策略筛选知识。

整体视觉：规则工作台、配置台、阶段蓝图。要能看出策略是按阶段组织的，每个阶段都有输入、处理目标、规则、输出、AI 适配说明。

布局：
顶部先显示当前正在编辑的策略包名称、策略包版本、生命周期状态、适用知识类型、适用文件类型，并提供“返回策略库”“另存为新策略包”“保存为新版本”“发布模板”按钮。
左侧为 13 阶段垂直导航，按三组折叠：摄取与统一、证据与知识生成、规范化与发布。每个阶段显示启用状态、规则数、最近修改版本。
中间是当前阶段配置表单，右侧是策略预览与影响提示。

中间表单内容：
```

## 5. 推荐生成顺序

1. 先生成 `04 单文档实时抽取工作台`，它决定核心信息架构。
2. 再生成 `05 策略库与策略模板管理页`，确定策略资产复用、复制和版本化语言。
