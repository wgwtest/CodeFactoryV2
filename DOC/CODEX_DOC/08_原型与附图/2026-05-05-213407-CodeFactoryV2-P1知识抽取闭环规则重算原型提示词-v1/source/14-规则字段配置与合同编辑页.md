# 14. 规则字段配置与合同编辑页 UI 原型提示词

```text
请生成一个 1920x1080 桌面端中文产品页面，页面名称为“规则字段配置与合同编辑”。这是 CodeFactoryV2 P1 业务知识库中“阶段策略配置”的下钻页面，用于编辑单条规则的字段级配置和可运行合同。它不是简单的规则组合页，也不是只读 schema 展示页；它要让用户清楚配置“这条规则读取哪些字段、用什么参数判断、输出哪些对象、如何写入追踪与重算合同”。

整体风格：
延续 P1 知识工厂控制台的浅色、结构化、可信、可追溯风格。页面要有“规则工程台 / 合同编辑器”的感觉，但不要做成纯 JSON 编辑器或普通后台表单。界面要同时服务业务人员和工程人员：业务人员能看懂字段含义和动作，工程人员能看到 input_schema、output_schema、hash、trace_fields、ImpactSet 关联。

页面定位：
上一级是“阶段策略配置页”。阶段策略配置页负责某个阶段启用哪些规则、规则顺序、AI 适配方式和阶段输出目标；本页负责单条规则的字段级详细配置。用户可以从阶段规则列表点击“字段配置 / 合同编辑”进入本页，也可以以右侧大抽屉形式打开。

顶部信息区：
左侧显示面包屑“策略库 / 合同通用抽取 v3.12 / 第 6 阶段 规则清洗 / 重复候选归并规则”。主标题为“规则字段配置与合同编辑”。标题下方显示规则摘要：rule_id 为 RL-CLEAN-006，rule_version 为 r6.4，effect_kind 为 merge，所属阶段为“规则清洗（第 6 阶段）”，启用状态为“已启用”，规则哈希为 sha256 短码。右侧提供按钮“校验合同”“保存草稿”“保存为新版本”“查看执行记录”“返回阶段配置”。

顶部警示：
如果当前规则是结构性规则，显示橙色提示：“结构性规则变更会触发影响面计算，保存新版本后不会直接覆盖已有知识。”如果合同校验失败，显示红色提示：“缺少 input_hash、affected_object_ids 或 trace_fields 时，不能发布为可运行策略版本。”

整体布局：
页面主体使用四栏或三栏组合，建议为：
左侧窄栏：规则身份与适用范围。
中间主栏上半部分：输入字段合同。
中间主栏下半部分：条件参数与输出映射。
右侧观察栏：合同校验、执行记录预览、影响面预估和示例输入输出。

左侧“规则身份与适用范围”：
以卡片表单展示：
- 规则名称、规则说明、所属策略包、所属阶段、effect_kind。
- 适用知识内容类型，例如合同条款、行业规范、需求文档。
- 适用文件类型，例如 PDF、DOCX。
- scope_selector，可用可视化条件块表达：对象类型 = 候选知识；候选类型 = 合同主体 / 金额条款 / 义务条款；来源阶段 = 候选合并前；置信度 >= 0.60。
- 依赖上游产物标签，例如“字段候选”“锚点证据”“实体候选”“关系候选”“规则候选”。
- 默认动作和异常动作，例如默认“归并并保留高置信候选”，异常“进入待复核队列 / 输出异常对象”，注意这里的“待复核”是机器异常队列，不是人工治理确认。

中间上半部分“输入字段合同 input_schema”：
用可编辑表格表达字段配置，避免只显示 JSON。表格列必须包括：
- 字段名，例如 candidate_id、semantic_similarity、anchor_ids、object_type、confidence_score、source_anchor_text。
- 来源产物，例如候选知识、锚点证据、统一文档块、上游规则命中。
- 字段类型，例如 string、float、string[]、enum、object。
- 是否必填。
- 是否参与 input_hash。
- 校验规则，例如 min、max、enum values、正则、非空。
- 示例值。
- 字段业务含义。
- 缺失时动作，例如阻断、跳过、降级为警告、输出异常对象。

输入字段区右侧或表格下方显示“Schema 预览”小面板，以伪 JSON 形式同步展示 input_schema，但视觉优先级低于字段表格。提供“新增字段”“导入字段模板”“从上游产物选择字段”“批量设置 hash 字段”按钮。

中间下半部分左侧“规则参数与判断条件”：
用条件构造器表达，不要只用文本框。需要展示：
- 相似度阈值 semantic_similarity >= 0.92。
- 置信度阈值 confidence_score >= 0.75。
- 锚点重叠条件 anchor_overlap_count >= 1。
- 对象类型约束 object_type in 合同主体、金额条款、义务条款。
- 冲突处理策略：同锚点多值时保留高置信对象，低置信对象写入 discarded_candidate_ids。
- AI 自动适配开关：允许 AI 推荐阈值 / 仅使用固定阈值 / AI 只给解释不改阈值。
条件之间用“全部满足 / 任一满足 / 自定义表达式”分组。每个条件块都要显示它读取的输入字段，并能点击高亮上方输入字段行。

中间下半部分右侧“输出字段合同 output_schema”：
用可编辑表格展示输出映射，列包括：
- 输出字段，例如 merged_object_id、discarded_candidate_ids、decision_reason、output_hash、stale_mark、affected_object_ids。
- 输出对象去向，例如统一候选知识、运行态关系、审计记录、发布候选输入包。
- 生成方式，例如归并生成、复制上游字段、规则计算、AI 解释生成。
- 是否参与 output_hash。
- 是否写入运行态。
- 是否写入审计日志。
- 是否用于影响面计算。
- 示例输出。
下方显示“动作映射”小流程：输入候选集合 -> 规则条件命中 -> 归并/过滤/拆分/阻断/发布候选 -> 输出对象集合。需要让 effect_kind 与输出字段之间的关系非常清楚。

右侧观察栏：
第一块“合同完整性检查”：
显示通过/失败项目，例如 input_schema 完整、output_schema 完整、input_hash 已配置、output_hash 已配置、affected_object_ids 已配置、trace_fields 已配置、示例用例通过。失败项用红色，警告用橙色，通过用绿色。

第二块“RuleExecutionRecord 预览”：
以小表格展示执行记录将包含的字段：execution_id、archive_id、document_id、stage_id、rule_id、rule_version、rule_hash、input_artifact_refs、input_hash、output_artifact_refs、output_hash、affected_object_ids、affected_relation_ids、decision、metrics、executed_at。突出显示哪些字段来自当前配置，哪些字段运行后回填。

第三块“影响面预估”：
显示该规则变更后可能影响的对象类型和阶段：候选知识、关系、质量门禁、发布候选快照。显示 minimum_rebuild_stage_id = 6，并提示“保存为新版本后进入策略版本差异页，再生成 ImpactSet，不直接覆盖已有正式知识”。

第四块“示例输入 -> 示例输出”：
左侧是示例输入表单或 JSON 卡片，包含 candidate_id、semantic_similarity、anchor_ids、confidence_score 等字段；右侧显示规则输出：merged_object_id、discarded_candidate_ids、decision_reason、affected_object_ids、output_hash。中间用箭头表示规则执行。示例结果需要显示“命中 / 未命中 / 警告 / 阻断”等状态。

底部区域：
显示“最近执行样本”和“版本变更记录”。最近执行样本列出最近 5 次执行的输入对象数、命中数、输出对象数、失败数、执行时间、运行快照 ID。版本变更记录显示 r6.2、r6.3、r6.4 的阈值、字段和动作变化。

交互状态：
- 点击输入字段行时，高亮所有使用该字段的条件块、输出映射和 trace_fields。
- 点击某个条件块时，高亮它依赖的输入字段和会产生的输出字段。
- 点击输出字段时，右侧显示该字段如何影响 RuleExecutionRecord 和 ImpactSet。
- 修改字段类型、必填状态、hash 参与项、条件阈值或 effect_kind 时，顶部出现“将生成新规则版本”的紫色提示。
- 如果修改 effect_kind 为 merge、split、block、publish_candidate，右侧影响面预估必须变为橙色结构性变更提示。
- 保存草稿允许合同未通过；保存为可运行新版本必须合同校验通过。

视觉重点：
页面要避免表格太像普通 CRUD。可以使用字段芯片、条件块、连线高亮、小型合同流图来表达“输入字段 -> 判断条件 -> 输出字段 -> 执行记录 -> 影响面”。状态颜色遵守 P1 全局约束：绿色已通过/已启用，蓝色当前编辑/选中，橙色警告/影响面，红色合同错误/阻断，紫色规则版本/快照。

必须出现的关键文案：
- “阶段策略配置负责编排规则，本页负责单条规则的字段级可运行合同。”
- “已有抽取运行继续使用历史规则快照，新版本只影响后续选择该版本的抽取或增量重算。”
- “没有 RuleExecutionRecord 的规则输出不得进入发布候选。”
- “正式入库知识不会被规则变更静默覆盖；结构性变更只生成修订候选并等待治理确认。”

不要出现：
- 不要把本页设计成 /governance 人工审核页。
- 不要把规则字段配置简化成只有 JSON 文本框。
- 不要出现“人工复核通过后继续抽取”作为规则执行动作。
- 不要让保存配置看起来会立即覆盖已有知识。
```
