# 前两个页面评审结论

## 结论

`01-1920x1080-知识库总览与抽取启动页.png` 与 `02-1920x1080-知识库文档清单与文档选择页.png` 可以收录为本轮 P1 知识抽取闭环的开发方向稿。

这两张图在信息架构上已经覆盖当前重点：

- 知识库总览、当前知识库切换、策略库入口、创建知识库和刷新。
- 规则变化后的重算提醒与影响面入口。
- 抽取启动确认、策略来源选择和运行快照摘要。
- 文档运行队列、当前阶段、stream/轮询状态、规则命中和质量门禁结果。
- 文档清单筛选、批量启动抽取、选中文档详情、策略绑定、复制策略后重跑。
- 发布候选与治理确认边界提示。

## 开发时需要修正

- 第一张图中的流程条把“治理确认 / 入仓完成”放进了 13 阶段主链。开发时必须修正为正式机器抽取 13 阶段；治理确认和正式入库只作为发布候选之后的边界状态展示。
- 阶段名称需要按正式 runtime 合同统一，避免出现“OCR识别 / 治理确认 / 入仓完成”等与当前 13 阶段合同不一致的标签。
- 策略摘要区需要持续强化“策略包名称 / 策略包版本 / 运行快照 ID”，避免只显示一个策略版本号。
- 文档详情侧栏里的“需要重算”应进一步关联最早受影响阶段、变更规则和 ImpactSet 入口。

## 第三页候选选择

在 `03. 文档接入与解析验证页_1.png` 和 `03. 文档接入与解析验证页_2.png` 中，选择 `_2` 版本收录为 `03-1920x1080-文档接入与解析验证页.png`。

选择 `_2` 的原因：

- 顶部明确包含当前知识库、上传文档、选择解析器、批量解析、纳入当前知识库等关键操作。
- 横幅明确说明“当前页只做接入与解析验证，不代表正式知识入库”，并补充进入 13 阶段抽取链的边界。
- 中间结构预览同时覆盖统一文档前的节点树、锚点、原文片段预览和异常节点筛选。
- 右侧同时覆盖解析质量、知识内容类型、策略推荐、推荐策略版本和“送入知识库抽取”动作。
- 底部清楚表达“解析结果 -> 统一文档对象 -> 可送入知识库抽取”的转换链。

`_1` 版本视觉更简洁，但策略选择、13 阶段链路提示和当前解析器/知识库上下文表达不如 `_2` 完整，因此不作为主开发依据。

## 第四至第六页评审结论

`04-1920x1080-单文档实时抽取工作台.png` 可以作为单文档实时抽取页面的开发方向稿。

可直接继承的方向：

- 顶部运行上下文清楚包含文档、知识库、抽取运行 ID、stream/轮询状态、策略包、策略版本和运行快照。
- 13 阶段流程条能表达已完成、运行中、未进入和历史快照语义。
- 当前阶段图谱采用“输入对象 -> 规则 / 策略 / 动作依据 -> 输出对象”的语义聚合结构，符合本轮图谱优化目标。
- 右侧观察窗能联动阶段、节点、边视角，并展示规则输入输出、执行事件和原文证据。
- 底部实时事件流具备后续 stream 增量更新的承载位置。

开发时需要修正：

- 阶段标签仍需回到正式 runtime 合同，避免出现与 13 阶段定义不一致的名称。
- 图谱开发时要确保节点可拖拽、画布可平移缩放、选中节点/边高亮路径，并避免密集区域遮挡。
- 已完成阶段点击只能查看快照，不能改变真实当前阶段。

`05-1920x1080-策略库与策略模板管理页.png` 可以作为策略库页面的开发方向稿。

可直接继承的方向：

- 左侧按业务域、知识内容类型、文件类型、生命周期状态筛选策略包。
- 中间策略资产库展示策略包、最新版本、阶段覆盖、规则数、最近使用和效果摘要。
- 右侧策略详情展示 13 阶段覆盖、规则摘要、质量门禁、发布边界、版本历史和最近绑定任务。
- “使用此策略”“复制改造”“设为知识库默认策略”“查看版本”这些入口符合策略复用设计。

开发时需要修正：

- “默认策略”必须明确只影响后续抽取任务，不覆盖历史运行快照。
- 使用策略时必须进入抽取绑定确认，生成 `PolicyRuntimeSnapshot`。

`06-1920x1080-阶段策略配置页.png` 可以作为阶段策略配置页面的开发方向稿。

可直接继承的方向：

- 左侧 13 阶段导航与启用/部分启用/未启用状态清楚。
- 中间阶段配置覆盖阶段目标、允许输入产物、期望输出产物、AI 自动适配策略、默认动作、异常动作和质量指标。
- 规则列表包含 effect kind、适用范围、阈值/条件、动作、版本、启用状态和 I/O 合同入口。
- 右侧策略预览和影响提示能解释当前配置会影响哪些阶段和历史运行。
- 保存新版本弹窗包含变更摘要、版本标签、是否设为默认策略和是否立即触发重算。

开发时需要修正：

- 保存配置必须生成策略包新版本，不能原地覆盖已发布版本。
- 对已绑定历史运行的策略版本，页面必须显示“历史运行仍绑定旧快照”。
- 若结构性规则变更影响 `merge / split / block / publish_candidate`，必须提示进入影响面计算。

## 第七至第九页评审结论

`07-1920x1080-规则输入输出合同编辑页.png` 可以作为规则合同编辑页面的开发方向稿。

可直接继承的方向：

- 顶部清楚展示规则名称、`rule_id`、`rule_version`、所属策略包、所属阶段、`effect kind`、启用状态和规则哈希。
- 页面显式展示结构性规则变更后的影响面提示，能承接后续增量重算。
- 输入合同和输出合同以字段表格 + schema 预览双视图表达，既适合业务理解，也适合工程落地。
- 合同完整性检查能直接暴露 `input_hash`、`output_hash`、`affected_object_ids`、`trace_fields` 等关键字段缺失。
- 右侧 `RuleExecutionRecord` 预览、trace fields、影响说明、示例输入输出，完整支撑规则可解释和运行追踪。

开发时需要修正：

- 合同校验失败时，保存新版本应允许保存草稿，但不能发布为可运行策略版本。
- `affected_object_ids` 和 `affected_relation_ids` 必须支持运行后回填，也要支持合同层声明影响对象类型。
- schema 编辑不能只做静态文本，需要能被后端规则执行记录和影响面计算复用。

`08-1920x1080-策略版本与规则差异页.png` 可以作为策略版本差异页面的开发方向稿。

可直接继承的方向：

- 版本 A/B、差异摘要、影响等级、13 阶段差异带、规则差异列表和右侧解释窗结构清晰。
- 明确区分新增规则、修改规则、停用规则、动作变化、阈值变化和结构性变化。
- “生成影响面”“复制为新策略包”“设为知识库默认策略”这些操作符合策略资产复用流程。
- 右侧解释窗能说明规则为何影响知识、影响哪些输入输出和是否需要重新计算。

开发时需要修正：

- 设为默认策略只能影响后续抽取任务，不能自动改变已有知识。
- 生成影响面前需要先冻结目标策略版本，否则 diff 结果不可追溯。
- 结构性变化要强制提示可能触发 `ImpactSet` 和增量重算。

`09-1920x1080-规则变更影响面与增量重算页.png` 可以作为规则变更重算页面的开发方向稿。

可直接继承的方向：

- 顶部指标覆盖变更批次、策略包版本、旧/新运行快照、变更规则数、影响文档数、最早重算阶段和治理重新确认。
- 左侧 ImpactSet 面板按 changed rules、affected stages、documents、chunks、candidates、relations、publication snapshots 分类，契合后端影响面合同。
- 中间重算计划图从 `minimum_rebuild_stage_id` 开始，清楚表达复用快照和增量重算范围。
- 右侧新旧差异观察窗能说明旧规则输出、新规则输出、规则执行记录和发布影响。
- 底部实时事件流可以承载影响面计算、stale 标记、阶段重算、候选替换、发布候选更新和 stream 状态。

开发时需要修正：

- 正式入库知识不得被重算结果静默覆盖，只能生成修订候选并等待治理确认。
- 运行过程中必须保持局部刷新，不能整页刷新。
- 若重算失败，需要保留旧候选快照和失败事件，不能让页面进入“半覆盖”状态。

## 第十至第十一页评审结论

新版 `10-1920x1080-质量门禁策略执行解释页.png` 与 `11-1920x1080-发布候选快照与API暴露页.png` 可以收录为主开发方向稿。

旧版 `candidate-10-*` 与 `candidate-11-*` 因使用深色左侧导航和独立中心外壳，已降级为 `original/` 中的结构参考，不再作为主开发方向。

`10-1920x1080-质量门禁策略执行解释页.png` 可直接继承的方向：

- 视觉外壳已回到 01-09 的浅色宽屏工作台，适合作为单文档第 10 阶段的聚焦视图。
- 顶部运行上下文覆盖当前文档、当前阶段、门禁决策、策略快照和评估时间，能承接 runtime 快照。
- 门禁决策概览明确区分自动执行、警告继续、阻断返回和延迟发布，符合机器规则自动决策边界。
- 质量指标仪表盘、规则命中图谱、规则解释观察窗和规则执行记录表能说明“哪条规则导致了通过/警告/阻断/延迟”。
- 页面明确写出“本阶段不执行人工复核动作”，符合质量门禁不需要人工参与的设计。

`10` 开发时需要保持的边界：

- 质量门禁只做机器规则执行，不出现人工复核、人工审核、人工确认等动作入口。
- 规则执行记录必须包含 actual、threshold、outcome、action、affected objects 和执行时间。
- 若门禁结果为警告继续，后续只能生成带警告标签的发布候选，不应表达为正式入库。

`11-1920x1080-发布候选快照与API暴露页.png` 可直接继承的方向：

- 视觉风格与 01-09 统一，适合作为单文档第 11 阶段的聚焦视图。
- 状态链“门禁决策 -> 机器已发布候选 -> API/索引暴露范围 -> 等待治理确认 -> 正式入库状态”表达清晰。
- 发布候选结构图区分发布候选快照、索引投影、API 暴露范围、候选知识集合、索引投影集合和只读候选 API。
- 右侧候选详情观察窗能说明候选来源阶段、规则版本、证据链、stale 状态、治理状态和候选 API 路径。
- 候选清单对新产生、修订候选、被替代、stale 等状态的表达可以直接用于后续开发。

`11` 开发时需要保持的边界：

- 发布候选是机器生成的候选快照，不代表正式入库。
- API/索引暴露只能是只读候选 API，正式 API 暴露必须等待治理确认后进入发布态版本。
- stale 或被替代候选必须显式标记，不能被静默覆盖。

## 第十二页评审结论

`12-1920x1080-发布候选治理确认页.png` 可以作为发布候选治理确认页面的开发方向稿。

可直接继承的方向：

- 页面顶部明确说明治理确认发生在机器发布候选之后，当前页只读取 `publication snapshot` 候选快照，不处理抽取中的临时图谱节点。
- 统计区覆盖当前知识库、候选快照版本、候选总数、待确认数、已通过数、已驳回数、当前正式版本。
- 左侧候选知识列表支持实体、事件、流程、关系、质量状态、规则版本、规则变更修订候选等筛选方向。
- 中间候选详情编辑区支持显示名称、类别、别名、解释、通过、驳回、合并到现有知识。
- 右侧证据与差异区覆盖原文证据、关联文档、相关关系、规则执行记录、新旧版本差异、质量与规则信息。
- 底部正式入库版本时间线能够承载治理确认后的正式版本历史。

开发时需要修正：

- 页面必须继续强调“只审核发布候选快照”，不要出现抽取中节点或运行中图谱节点。
- “确认并生成正式入库版本”需要校验待确认候选是否处理完，避免把未确认候选静默带入正式版本。
- 对规则变更修订候选，需要展示来源旧版本、新版本、变更原因和是否替代旧候选。

## 第十三页评审结论

`13-1920x1080-发布态知识图谱浏览页.png` 可以作为发布态知识图谱浏览页面的开发方向稿。

可直接继承的方向：

- 页面顶部明确说明只浏览已治理确认并正式入库的知识图谱，不包含机器验证和抽取中的临时节点。
- 统计区覆盖当前知识库、正式版本、发布时间、知识总数、关系总数和覆盖文档数。
- 左侧筛选面板支持知识类型、来源文档、版本、标签、关系类型、可信度和是否由规则变更修订产生。
- 中间图谱默认呈现正式知识地图，支持缩放、拖拽、适配布局、布局切换、按文档高亮和按版本高亮。
- 右侧对象详情包含正式入库状态、知识名称、类型、正式版本、来源候选快照、治理确认记录、证据摘要、相关关系和 API 暴露路径。
- 底部提示“当前图谱展示的是正式入库版本”，并提供返回单文档抽取运行的入口。

开发时需要修正：

- `/graph` 页面不得混入抽取过程中的 runtime 节点、规则执行节点或临时候选节点。
- 图谱对象需要能追溯到 publication snapshot 和 governance confirmation，但默认不展示运行态细节。
- 如果用户切换历史正式版本，图谱和右侧详情必须同时切换到对应版本的数据。

## 后续开发口径

后续开发可以按照已收录方向图的布局和交互方向推进，但以正式设计文档中的阶段合同、策略包合同、规则输入输出合同和发布治理边界为准。
