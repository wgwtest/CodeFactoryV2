# P2 组织器插件输入输出合同规范

> 归档说明：本文件作为 `P2` 需求分析系统组织器插件的共享输入输出合同。凡涉及本地组织器、Dify workflow 组织器、远端服务组织器与 `P2` Turn 引擎之间的数据交换，均以本文件为统一约束来源。
>
> 维护规则：新增或调整组织器能力时，必须先判断是否影响本共享合同。若影响公共字段、状态归并、过程观测或错误语义，必须先回写本文件，再同步回写对应组织器专项规范与实现。

**日期：** 2026-05-07

**适用范围：**

- `P2` 需求分析系统
- `orchestrators/xg/*` 下的可发现组织器插件
- 本地 `local_package` 组织器
- Dify workflow 型组织器
- 后续远端服务型组织器

## 1. 规范定位

本规范回答的是“任意组织器插件要和 `P2` 系统互换什么数据，最小必须遵守什么合同”。它不规定某个组织器内部如何思考，也不规定 Dify 工作台内节点怎么配置。

固定边界如下：

- 宿主系统只通过统一插件合同调用组织器。
- 组织器内部阶段、节点、Prompt、模型调用和状态策略属于插件内部。
- 插件必须返回可归一化的结构化结果，供 `P2` 页面展示、状态落库和后续阶段消费。
- 插件可以暴露不同程度的过程数据，但不能改变公共输出字段含义。

## 2. 插件包发现合同

组织器插件必须位于：

```text
orchestrators/{domain}/{plugin_dir}/
```

当前 `P2 XG` 使用：

```text
orchestrators/xg/{plugin_dir}/
```

发现规则：

- 只扫描 `orchestrators` 下的领域目录和领域目录下一层插件目录。
- 插件目录必须包含 `manifest.json`。
- 插件目录必须包含 manifest 指定的 adapter 文件。
- 插件 `plugin_id` 在全仓内必须唯一。
- 以 `.bak` 结尾或以 `.` 开头的目录不参与发现。

## 3. Manifest 最小字段

`manifest.json` 至少应具备以下字段：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `plugin_id` | 是 | 插件唯一标识，也是页面可选择的组织器 ID |
| `name` | 是 | 展示名称 |
| `plugin_type` | 是 | `local_package`、`dify_workflow` 或 `remote_service` |
| `document_type` | 是 | 当前固定为 `xg` |
| `contract` | 是 | 当前固定为 `xg-observable-orchestrator-contract@1` |
| `status` | 是 | `active` 或 `available` 表示可选 |
| `priority` | 是 | 默认排序权重，数值越小越靠前 |
| `capabilities` | 是 | 插件能力声明 |
| `requires` | 是 | 模板、知识绑定、模型提供方等依赖 |
| `adapter_entry` | 是 | adapter 类型入口，例如 `local_xg`、`dify_workflow` |
| `adapter_module` | 是 | adapter 模块路径，相对插件目录或宿主包 |
| `adapter_class` | 是 | adapter 类名 |
| `package_id` | 否 | 复用本地组织器规格策略包时填写 |
| `aliases` | 否 | 历史 ID 或快捷 ID |

## 4. 输入合同

宿主传入组织器 adapter 的对象为 `OrchestratorRunRequest`。字段如下：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `contract_version` | string | 当前合同版本 |
| `session` | object | 会话级上下文 |
| `turn` | object | 本轮用户输入和归一化结果 |
| `template` | object | 模板内容和解析结构 |
| `document_context` | object | 当前状态、工作正文、规格树和历史摘要 |
| `execution_options` | object | 输出期望、观测要求和流式设置 |

### 4.1 session

| 字段 | 含义 |
| --- | --- |
| `session_id` | 需求分析会话 ID |
| `topic` | 当前需求分析主题 |
| `template_id` | 需求规格模板 ID |
| `knowledge_package_id` | 绑定知识包 ID |
| `orchestrator_id` | 当前组织器插件 ID |
| `provider_id` | 模型提供方 ID |
| `model` | 模型名称 |
| `write_policy` | 写入策略，当前常用 `patch_suggestion_only` |

### 4.2 turn

| 字段 | 含义 |
| --- | --- |
| `turn_id` | 本轮 ID |
| `turn_index` | 本轮序号 |
| `user_input` | 用户原始输入 |
| `normalized_input` | 输入归一化结果 |
| `previous_interaction` | 上一轮交互提示 |
| `input_relation` | 本轮输入与上一轮提示之间的关系 |

### 4.3 document_context

| 字段 | 含义 |
| --- | --- |
| `state` | 会话状态快照 |
| `working_document` | Lab 临时正文 |
| `active_spec_node` | 当前活动规格树节点 |
| `spec_tree` | 需求规格完成度树 |
| `confirmed_facts` | 已确认事实 |
| `open_questions` | 未闭合问题 |
| `patches` | 历史补丁或摘要片段 |
| `history_summary` | 历史摘要 |

## 5. 输出合同

组织器必须返回 `OrchestratorRunResult`。字段如下：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `contract_version` | string | 合同版本 |
| `plugin` | object | 插件身份与观测级别 |
| `final_output` | object | 文档级最终输出或补丁输出 |
| `interaction_output` | object | 面向用户的回答和下一轮问题 |
| `process_output` | object | 过程观测、决策轨迹和风险 |
| `state_output` | object | 会话状态增量 |
| `raw_output` | object | 原始插件响应、模型响应或 workflow trace |

### 5.1 plugin

| 字段 | 含义 |
| --- | --- |
| `plugin_id` | 实际运行插件 ID |
| `plugin_type` | 插件类型 |
| `observability_level` | `full`、`limited` 或 `none` |

### 5.2 final_output

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `filled_document_text` | 是 | 整篇正文或本轮正文片段 |
| `document_patch` | 是 | 可应用到 Lab 临时正文的补丁数组 |
| `changed_sections` | 是 | 本轮影响章节 |
| `completion_status` | 是 | `partial`、`complete` 等完成状态 |
| `confidence` | 是 | 置信度 |

### 5.3 interaction_output

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `assistant_message` | 是 | 本轮助手回答 |
| `next_question` | 是 | 下一轮主问题 |
| `quick_options` | 是 | 快捷选项 |
| `suggested_focus` | 是 | 建议聚焦信息 |

### 5.4 process_output

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `stage_results` | 是 | 阶段结果，有限观测插件可为空 |
| `stage_audits` | 是 | 阶段审计，Dify 插件可为空 |
| `decision_trace` | 是 | 决策轨迹 |
| `provider_logs` | 是 | 模型调用日志 |
| `review_after_apply_result` | 是 | 应用后回看结果 |
| `annotations` | 是 | 过程注释 |
| `risks` | 是 | 风险提示 |

### 5.5 state_output

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `confirmed_facts_delta` | 是 | 新增确认事实 |
| `open_questions_delta` | 是 | 新增未闭合问题 |
| `spec_tree_update` | 是 | 规格树更新 |
| `working_document_update` | 是 | 工作正文更新 |
| `turn_path_update` | 是 | 轮次路径更新 |
| `decision_state_delta` | 否 | 决策状态增量 |
| `decision_state_change_summary` | 否 | 决策状态变化摘要 |
| `decision_state_document` | 否 | 面向 UI 展示的决策状态文档 |

## 6. 观测级别

组织器观测级别由能力声明推导。

| 级别 | 含义 |
| --- | --- |
| `full` | 插件能输出完整阶段审计、provider logs、decision trace、review 和规格树更新 |
| `limited` | 插件至少能输出正文、补丁或部分决策轨迹 |
| `none` | 插件只返回最小黑盒结果 |

Dify workflow 型组织器通常是 `limited`。这不是错误，而是边界事实：系统可以拿到工作流结果和部分 trace，但不假设能拿到每个 LLM 节点的完整内部状态。

## 7. 状态归并规则

宿主收到插件结果后，必须把结果归并到 `TurnExecutionResult`：

- `turn` 记录本轮展示所需结构。
- `state_patch` 更新会话状态。
- `provider_logs` 追加到会话 provider logs。

插件如果已经在 `raw_output.turn_execution_result` 返回完整 `TurnExecutionResult`，宿主可以直接透传。否则宿主使用统一 materializer 把 `OrchestratorRunResult` 归并为 turn 结果。

## 8. 错误语义

插件失败时不应返回半结构化随机文本。推荐处理：

- adapter 调用失败时抛出明确异常，由 API 层转为错误响应。
- 远端 workflow 返回结构不合格时，应在 `risks` 和 `raw_output` 中保留原始响应。
- 若配置了 fallback，可降级到本地 workflow，但必须在 `annotations` 中明确标注。

## 9. 版本维护

当前合同版本固定为：

```text
xg-observable-orchestrator-contract@1
```

新增字段应优先作为可选字段加入现有对象。只有字段含义发生破坏性变化时，才升级合同版本。
