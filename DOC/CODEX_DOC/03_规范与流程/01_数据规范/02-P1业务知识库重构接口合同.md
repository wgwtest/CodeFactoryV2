# P1 业务知识库重构接口合同

## 1. 文档定位

本文定义 `P1` 业务知识库重构后的内部模块调用合同、前后端 API 合同和系统间输出合同。

本文服务于并行开发，要求每条工作线只能依赖本文声明的合同，不得读取其它工作线的内部实现、缓存文件或页面状态。

关联设计：

- `DOC/CODEX_DOC/02_设计说明/P1_业务知识库/P1-业务知识库设计.md`
- `DOC/CODEX_DOC/02_设计说明/P1_业务知识库/P1-业务知识库重构设计.md`
- `DOC/CODEX_DOC/02_设计说明/P1_业务知识库/P1-知识质量与图谱质量保障设计.md`
- `DOC/CODEX_DOC/03_规范与流程/01_数据规范/01-P1-P5到P6状态输出接口规范.md`

## 2. 合同原则

- 后端 schema 是事实源，前端类型应由 schema 派生或镜像维护。
- 查询接口不得返回未声明字段作为业务依赖。
- 命令接口必须返回可追踪结果，至少包含 `operation_id`、`status`、`created_at` 或对应资源 ID。
- Stream 与 polling 返回同一运行态 payload。
- 系统间输出必须由 `external_exports` 层生成，不允许下游系统读取内部 runtime 或 candidate 文件。
- Mock / fallback / fixture 数据必须显式标记 `source_kind`。

```text

Freshness = fresh | stale | degraded | unavailable
HealthLevel = healthy | warning | critical | unknown
RuleEffectKind = filter | score | normalize | merge | split | block | publish_candidate | route | enrich

MetricScope = document | knowledge_item | relation | graph | run | archive
```

| --- | --- |

| `P1_POLICY_CONTRACT_INVALID` | 策略或规则合同不合法 |

## 12. 系统间输出合同

### 12.1 P1KnowledgeSupplyExport

`P1 -> P2` 正式业务输出。

```text
P1KnowledgeSupplyExport
- export_id: string
- contract_version: string
- archive_id: string
- published_version_id: string
- freshness: Freshness
- health_level: HealthLevel
- items: PublishedKnowledgeItem[]
- relations: PublishedRelation[]
- search_capabilities: string[]
- evidence_capabilities: string[]
- quality_summary: QualityReportSummary
- generated_at: datetime
```

必须满足：

- 只包含正式发布知识。
- 每个对象必须是库级规范对象，能追溯来源文档、文档级候选和证据。
- 每个对象带正式版本信息。
- 不包含候选态、运行态、治理任务或规则后台内部字段。
- 质量摘要只允许输出汇总分数、状态和可解释风险，不输出规则后台内部合同。

### 12.2 P6DisplayExportContract.v2

`P1 -> P6` 只读展示输出，遵循既有共享规范。

```text
P1P6DisplayExport
- contract_version: "P6DisplayExportContract.v2"
- stage_overview: StageOverview
- system_overall_metrics: StageMetricProjection[]
- live_counters: StageMetricProjection[]
- flow_ports: FlowPort[]
- connected_users: ConnectedUserProjection[]
- queue_projection: QueueProjectionItem[]
- display_binding: DisplayBinding
- source_trace: SourceTrace[]
- quality_summary: QualityReportSummary
```

P1 特定约束：

- `flow_ports` 只允许右侧输出 `发布态知识 -> P2`。
- `system_overall_metrics` 只放累计发布态资产。
- `live_counters` 可放抽取、治理、入库和供给速率。
- 不得把当前单文档运行态图谱放入 P6 展示合同。
- 质量信息只能作为 P1 健康度摘要，不作为 P6 业务决策字段。

## 14. 合同测试要求

### 14.1 后端合同测试

- `PolicyPackageVersion` 变更生成新版本。
- `RuleContract` 缺少必填字段返回 invalid。
- 抽取启动冻结 `PolicyRuntimeSnapshot`。
- `RuleExecutionRecord` 包含规则版本、哈希、输入输出引用。
- Stream / polling 返回同一 `DocumentRuntimePayload` 字段集。
- `RuntimeGraphProjection` 节点边能追溯到运行态合同。
- `ArchiveKnowledgeResolutionSnapshot` 能跨文档归并相同知识，并保留合并、修订、冲突和拆分决策。
- `CanonicalKnowledgeItem` 不被新文档静默覆盖，正式版本更新必须生成修订候选或治理确认。
- `KnowledgeQualityReport` 能追溯到候选对象、证据锚点和规则执行记录。
- `GraphQualityReport` 能识别孤立节点、无证据关系、缺少动作依据路径和布局不可读风险。
- `EvaluationRunReport` 能基于固定评测集输出概念、关系和证据指标。
- `P1KnowledgeSupplyExport` 不包含候选态和运行态字段。
- `P6DisplayExportContract.v2` 端口规则符合共享规范。

### 14.2 前端合同测试

- 前端类型字段与后端响应关键字段一致。
- 终端用户页只消费 user API 和 runtime API。
- 策略后台页只消费 policy API、impact API。
- 图谱组件只消费 `RuntimeGraphProjection`。
- 质量面板只消费 `KnowledgeQualityReport`、`GraphQualityReport` 和 `EvaluationRunReport`。
- 跨文档归并面板只消费 `ArchiveKnowledgeResolutionSnapshot`、`KnowledgeMergeDecision` 和 `CanonicalKnowledgeItem`。
- 系统间输出状态页不展示内部 runtime 细节。

## 15. 版本策略

本文初始合同版本：

```text
P1RefactorContract.v0.1
```

版本升级规则：

- 新增可选字段：patch。
- 修改字段语义：minor。
- 删除字段或改变必填性：major。
- 系统间输出合同变更必须同步更新 `P1-P5到P6状态输出接口规范` 或对应下游设计文档。
