## 7. 迁移注意事项

- 旧 API 先保留，内部逐步转调新 service。
- 旧页面先保留，新增 P1 shell 后逐步替换入口。
- 不要在迁移期删除现有抽取能力。
- 不要把运行态 runtime graph 当成发布态 graph。
- 不要把 archive policy config 直接等同于可复用 PolicyPackage，必须通过 adapter 明确转换。
- 不要把 `P6DisplayExportContract.v2` 改成 P1 内部 runtime payload。
- 不要把质量门禁决策等同于完整质量保障；质量报告必须独立计算并可被回归评测验证。
- 不要把单文档候选对象直接当成正式知识输出；必须先经过库级同知识归并与更新。

## 8. 待确认缺口

- `P1 -> P2` 的正式知识供给 API 是否已有 P2 消费侧实现。
- `PublishedKnowledgeSnapshot` 当前是否能完整覆盖实体、事件、流程、规则、指标。
- `ArchiveManagementPage` 中运行态图谱逻辑拆分的最小安全边界。
- 当前正式抽取与预览/调试链路的代码分界。
- 当前质量指标的事实源、阈值来源和评测集样本是否已经稳定。
- 当前文档级候选对象是否已有足够字段生成 `KnowledgeIdentityKey`。
- 系统间输出的正式 endpoint 是否沿用 `/api/p6/stage-snapshots` 聚合，还是由 P1 先提供 `/api/p1/system-output/p6/stage-snapshot`。
