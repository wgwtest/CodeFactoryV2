# WBS-P1 业务知识库重构并行开发计划

## 1. 计划定位

本文是 `P1` 业务知识库重构阶段的并行开发计划，服务于多线程、多工作线并行推进。

关联文档：

- `DOC/CODEX_DOC/02_设计说明/P1_业务知识库/P1-业务知识库设计.md`
- `DOC/CODEX_DOC/02_设计说明/P1_业务知识库/P1-业务知识库重构设计.md`
- `DOC/CODEX_DOC/02_设计说明/P1_业务知识库/P1-知识质量与图谱质量保障设计.md`
- `DOC/CODEX_DOC/03_规范与流程/01_数据规范/02-P1业务知识库重构接口合同.md`

原则：

- 文档和合同先行。
- 每条工作线可独立开发、独立测试、独立验收。
- 最终集成由 P1 重构主线统一收口。
- 不破坏现有抽取功能。
- 不提交本地数据和验收产物。

## 2. 总体阶段

```text
R0 现状映射与合同底座
R1 前端导航与用户入口重组
R2 后端领域模块与合同目录建立
R3 运行态合同与图谱投影收口
R4 策略包、规则合同、影响面重算闭环
R5 知识质量与图谱质量评测闭环
R6 库级同知识归并与更新闭环
R7 系统间输出接口适配
R8 兼容清理、测试与验收
```

## 3. 并行工作线总览

| 工作线 | 名称 | 可并行度 | 前置依赖 | 主要输出 |
| --- | --- | --- | --- | --- |
| A | 终端用户知识库体验 | 高 | R0 合同草案 | 用户入口、文档清单、抽取启动 |
| B | 策略包与规则合同后台 | 高 | R0 合同草案 | 策略包、版本、规则字段合同 |
| C | 运行态与规则执行主链 | 中 | R0 合同草案 | runtime payload、RuleExecutionRecord |
| D | 运行态语义图谱投影 | 中 | C 的最小 runtime fixture | RuntimeGraphProjection |
| E | 规则变更影响面与增量重算 | 中 | B、C 合同稳定 | ImpactSet、IncrementalRebuildTask |
| F | 治理发布与发布态边界适配 | 中 | publication 合同 | 候选、治理、正式入库边界 |
| G | 系统间输出接口适配 | 中 | F 的发布态事实或 fixture | P1->P2、P1->P6 输出 |
| I | 知识质量与图谱质量评测 | 中 | C、D 的运行态和图谱 fixture | KnowledgeQualityReport、GraphQualityReport、EvaluationRunReport |
| J | 库级同知识归并与更新 | 中 | C、I 的候选与质量 fixture | ArchiveKnowledgeResolutionSnapshot、CanonicalKnowledgeItem |
| H | 兼容路由与迁移清理 | 低 | A-J 初步稳定 | 旧路由 adapter、兼容测试 |

## 4. R0：现状映射与合同底座

### 4.1 目标

- 产出现有路由、页面、API、后端模块到新架构的映射表。
- 建立前后端 contracts 目录。
- 建立系统间输出的合同测试骨架。

### 4.2 任务

- `R0.1` 梳理旧路由到新路由映射。
- `R0.2` 梳理旧 API 到新 API 映射。
- `R0.3` 梳理后端文件到目标领域模块映射。
- `R0.4` 新增后端合同 schema 空壳。
- `R0.5` 新增前端合同类型空壳。
- `R0.6` 新增最小 fixture，用于并行开发。

### 4.3 验收

- 映射表能覆盖当前 P1 主要页面和 API。
- contracts 目录存在，不承载业务逻辑。
- 新旧路由和接口兼容策略明确。

## 5. 工作线 A：终端用户知识库体验

### 5.1 范围

负责普通终端用户能看懂和使用的主路径：

- 知识库总览。
- 文档清单。
- 文档状态详情。
- 抽取启动确认。
- 进入单文档实时抽取。

### 5.2 输入合同

- `ArchiveSummary`
- `ArchiveDocumentSummary`
- `ExtractionStartRequest`
- `ExtractionStartResponse`
- `PolicyRuntimeSnapshot` 摘要字段

### 5.3 输出

- `/p1/archives`
- `/p1/archives/:archiveId/documents`
- 抽取启动 UI 与状态反馈。
- 旧 `/archives`、`/documents` 兼容跳转。

### 5.4 不负责

- 规则字段合同编辑。
- 影响面计算。
- 运行态图谱内部布局算法。
- 治理确认操作。

### 5.5 验收

- 用户能创建或选择知识库。
- 用户能查看文档列表和抽取状态。
- 用户能启动抽取并进入单文档运行页。
- 页面不暴露规则 hash、合同 JSON、增量重算内部对象。

## 6. 工作线 B：策略包与规则合同后台

### 6.1 范围

- 策略库。
- 策略包版本。
- 阶段策略配置。
- 规则字段合同编辑。
- 合同校验。
- 策略版本差异。

### 6.2 输入合同

- `PolicyPackage`
- `PolicyPackageVersion`
- `StagePolicyConfig`
- `RuleContract`
- `RuleInputSchema`
- `RuleOutputSchema`
- `ContractValidationResult`

### 6.3 输出

- `/p1/policies`
- `/p1/policies/:packageId/versions/:versionId/stages`
- `/p1/policies/:packageId/rules/:ruleId/contract`
- `/p1/policies/:packageId/diff`

### 6.4 不负责

- 抽取运行。
- 单文档图谱。
- 发布态正式知识输出。
- 治理审核页面。

### 6.5 验收

- 能创建/复制策略包。
- 修改已发布策略包会生成新版本。
- 规则字段缺失时合同校验失败并说明原因。
- 能展示新旧版本差异。

## 7. 工作线 C：运行态与规则执行主链

### 7.1 范围

- 抽取启动时冻结 `PolicyRuntimeSnapshot`。
- 阶段处理器包装为 `StageExecutionContract`。
- 规则执行生成 `RuleExecutionRecord`。
- Stream / polling 返回等价 `DocumentRuntimePayload`。
- 运行事件流。

### 7.2 输入合同

- `PolicyPackageVersion`
- `PolicyRuntimeSnapshot`
- `StageExecutionContract`
- `RuleContract`

### 7.3 输出合同

- `DocumentRuntimePayload`
- `RuntimeEvent`
- `RuleExecutionRecord`

### 7.4 不负责

- 前端图谱布局。
- 策略表单编辑体验。
- 发布态图谱浏览。
- 系统间输出适配。

### 7.5 验收

- 单文档运行态能显示策略快照 ID。
- 当前阶段由后端 runtime 决定，不由用户点击决定。
- Stream 和 polling 字段一致。
- 每条规则命中有 `rule_id / rule_version / rule_hash / input_hash / output_hash`。

## 8. 工作线 D：运行态语义图谱投影

### 8.1 范围

- 生成 `RuntimeGraphProjection`。
- 支持语义聚合视图和明细视图。
- 支持节点/边观察窗 payload。
- 支持 fan-in / fan-out 集合节点。

### 8.2 输入合同

- `DocumentRuntimePayload`
- `StageExecutionContract`
- `RuleExecutionRecord`
- `DependencySelector`

### 8.3 输出合同

- `RuntimeGraphProjection`
- `RuntimeGraphNode`
- `RuntimeGraphEdge`
- `ObserverPayloadRef`

### 8.4 不负责

- 抽取算法。
- 策略编辑。
- 终端导航。
- 正式发布审核。

### 8.5 验收

- 每个阶段都能表达“输入对象 -> 规则/动作依据 -> 输出对象”。
- 密集区域默认聚合，不满屏连线。
- 选中节点/边能联动观察窗。
- 运行中更新不整页刷新。

## 9. 工作线 E：规则变更影响面与增量重算

### 9.1 范围

- 策略版本 diff。
- `ImpactSet` 计算。
- `IncrementalRebuildTask` 生成。
- stale 对象标记。
- 增量重算候选结果生成。

### 9.2 输入合同

- `PolicyPackageVersionDiff`
- `RuleExecutionRecord`
- `DependencySelector`
- `PublishedKnowledgeSnapshot`
- `PublicationCandidateSnapshot`

### 9.3 输出合同

- `ImpactSet`
- `IncrementalRebuildTask`

### 9.4 不负责

- 规则字段编辑 UI。
- 单文档图谱布局。
- 正式知识静默覆盖。

### 9.5 验收

- 修改结构性规则能计算最早重算阶段。
- 能列出影响文档、候选、关系和发布候选快照。
- 不直接覆盖正式入库知识。
- 需要治理确认时能明确标记。

## 10. 工作线 F：治理发布与发布态边界适配

### 10.1 范围

- 发布候选快照。
- 治理确认边界。
- 正式入库版本。
- 发布态知识图谱边界。

### 10.2 输入合同

- `PublicationCandidateSnapshot`
- `GovernanceConfirmation`
- `PublishedKnowledgeSnapshot`

### 10.3 输出合同

- `PublishedKnowledgeSnapshot`
- `PublishedGraphProjection`

### 10.4 不负责

- 重做治理页面视觉。
- 抽取运行态细节。
- 策略后台表单。

### 10.5 验收

- 机器候选不会被误认为正式入库。
- 治理确认后才生成正式版本。
- 发布态图谱不展示运行中临时节点。

## 11. 工作线 G：系统间输出接口适配

### 11.1 范围

- `P1 -> P2` 发布态知识供给接口。
- `P1 -> P6` 展示合同输出。
- 新鲜度、健康状态和降级原因。
- 系统间输出合同测试。

### 11.2 输入合同

- `PublishedKnowledgeSnapshot`
- `PublishedGraphProjection`
- `ArchiveSummary`
- `P1` 队列和运行摘要。

### 11.3 输出合同

- `P1KnowledgeSupplyExport`
- `P6DisplayExportContract.v2`
- `StageSnapshot`

### 11.4 不负责

- 单文档运行态页面。
- 策略后台编辑。
- 抽取算法。
- P2 / P6 消费侧页面重构。

### 11.5 验收

- `P1 -> P2` 只输出正式发布知识。
- `P1 -> P2` 支持搜索、详情、关系邻域和证据回溯。
- `P1 -> P6` 满足 `P6DisplayExportContract.v2`。
- `flow_ports` 只表达 `发布态知识 -> P2`。
- 不泄漏候选态、运行态、治理中间态。

## 12. 工作线 I：知识质量与图谱质量评测

### 12.1 范围

- 知识概念质量指标计算。
- 关系和证据质量指标计算。
- 运行态图谱与发布态图谱质量评估。
- 固定评测集回归。
- 质量报告供运行页、治理页、发布页和系统间摘要复用。

### 12.2 输入合同

- `RuleExecutionRecord`
- `RuntimeGraphProjection`
- `PublishedGraphProjection`
- `PublicationCandidateSnapshot`
- `EvaluationDataset`
- `PolicyRuntimeSnapshot`

### 12.3 输出合同

- `KnowledgeQualityReport`
- `GraphQualityReport`
- `EvaluationRunReport`
- `QualityGateDecision`

### 12.4 不负责

- 修改抽取候选对象。
- 修改正式入库知识。
- 决定治理审核结果。
- 重写图谱布局组件。

### 12.5 验收

- 能解释概念质量：类型是否合法、定义是否完整、是否有证据、是否重复或冲突。
- 能解释关系质量：端点是否合法、方向是否合理、是否有证据、是否孤立或自环。
- 能解释图谱质量：连通性、孤立节点、动作依据覆盖、证据回溯覆盖和布局可读性。
- 能基于固定评测集输出概念 precision/recall/F1、关系 precision/recall/F1 和证据 recall。
- 任一发布候选进入治理前都有质量摘要，系统间输出只能带汇总质量信息。

## 13. 工作线 J：库级同知识归并与更新

### 13.1 范围

- 同一知识库内跨文档候选知识匹配。
- 生成知识身份键和跨文档匹配候选。
- 执行新增、合并、修订、冲突、拆分、拒绝等归并决策。
- 生成库级规范知识对象和归并快照。
- 为发布候选、治理确认和系统间输出提供库级规范对象。

### 13.2 输入合同

- `DocumentKnowledgeCandidate`
- `KnowledgeQualityReport`
- `RuleExecutionRecord`
- `PublishedKnowledgeSnapshot`
- `PolicyRuntimeSnapshot`

### 13.3 输出合同

- `KnowledgeIdentityKey`
- `CrossDocumentMatchCandidate`
- `KnowledgeMergeDecision`
- `CanonicalKnowledgeItem`
- `KnowledgeUpdatePlan`
- `ArchiveKnowledgeResolutionSnapshot`

### 13.4 不负责

- 单文档抽取算法。
- 人工治理页面操作。
- 直接覆盖正式入库知识。
- P2 / P6 消费侧适配。

### 13.5 验收

- 两份文档抽取出同一知识时能合并为一个 `CanonicalKnowledgeItem`，并保留双文档证据。
- 同名异义对象不会被错误合并。
- 新文档提供更强证据或新定义时能生成 `revision_candidate`，而不是静默覆盖旧版本。
- 冲突定义或冲突关系能生成 `conflict` 决策并进入质量报告或治理确认。
- 移出文档后能重算支撑证据，无剩余证据时标记 `unsupported` 或生成撤回候选。

## 14. 工作线 H：兼容路由与迁移清理

### 14.1 范围

- 旧路由兼容。
- 旧 API adapter。
- 大文件拆分后的导出兼容。
- 删除无效 mock fallback。

### 14.2 输入

- A-J 稳定后的新页面和新服务。

### 14.3 输出

- 路由迁移表。
- API adapter。
- 兼容测试。

### 14.4 验收

- 旧入口不报错。
- 新入口可直接访问。
- Mock fallback 标记明确。
- 未删除仍被使用的旧能力。

## 15. 集成节奏

### 15.1 第一批并行

可以立即并行：

- A：终端用户知识库体验。
- B：策略包与规则合同后台。
- C：运行态与规则执行主链。
- G：系统间输出接口测试骨架。
- I：质量评测 fixture、指标定义和报告合同骨架。
- J：库级归并合同和最小同知识 fixture。

### 15.2 第二批并行

依赖第一批合同后启动：

- D：运行态语义图谱投影。
- E：规则变更影响面与增量重算。
- F：治理发布与发布态边界适配。
- I：接入 C/D/F 真实产物，替换 fixture 评测。
- J：接入 C/I/F 真实候选、质量报告和发布态知识。

### 15.3 收口批次

最后统一处理：

- H：兼容路由与迁移清理。
- 全量测试。
- 质量评测回归。
- 跨文档归并回归。
- 慢速抽取人工验收。
- 文档同步。

## 16. 合并门禁

任一工作线合并前必须满足：

- 明确改动范围。
- 不提交本地数据。
- 自动化测试通过。
- 若涉及 API，接口合同文档已更新。
- 若涉及页面，人工验收路径已写明。
- 若涉及系统间输出，`P1 -> P2` 或 `P1 -> P6` 合同测试已覆盖。
- 若涉及抽取、规则、图谱或模型配置，质量评测回归必须给出结论。
- 若涉及候选知识、发布态知识或文档并入/移出，跨文档归并回归必须给出结论。

## 17. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 拆分过程中破坏现有抽取 | 先 adapter 后迁移，旧 API 保留 |
| 前端继续堆大页面 | feature 目录和组件边界先行 |
| 规则合同和真实抽取脱节 | 运行态必须生成 `RuleExecutionRecord` |
| 图谱继续由前端猜测 | 后端输出 `RuntimeGraphProjection` |
| 质量只靠主观验收 | 固化 `KnowledgeQualityReport`、`GraphQualityReport` 和评测集回归 |
| 跨文档同知识错误合并或无法更新 | 固化 `KnowledgeMergeDecision`、`CanonicalKnowledgeItem` 和归并回归 |
| 候选态误输出给下游 | `external_exports` 合同测试硬拦截 |
| 多线程并行冲突 | 每条线只写自己的目录和合同 |

## 18. 推荐下一步

下一步优先执行 `R0`：

1. 新增现有页面和路由映射表。
2. 新增现有 API 到新 API 映射表。
3. 创建前端 `features/p1/contracts` 目录。
4. 创建后端 `archive_knowledge/contracts` 目录。
5. 新增质量评测合同与最小报告 fixture。
6. 新增库级同知识归并与更新合同 fixture。
7. 新增 `P1 -> P2` 和 `P1 -> P6` 合同测试骨架。

完成 `R0` 后，再进入 A/B/C/G/I/J 六条线并行开发。
