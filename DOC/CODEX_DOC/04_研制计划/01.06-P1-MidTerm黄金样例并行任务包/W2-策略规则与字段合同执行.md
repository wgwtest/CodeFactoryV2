你接手 CodeFactoryV2 的 P1 黄金样例 `策略规则与字段合同执行` 工作线。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。开工前先阅读本目录 `00-并行总说明.md`，然后先回复你的计划修改文件、可能影响其它工作线的合同字段和风险点，得到主线程确认后再改代码。黄金样例资料目录是 `E:\project\Web\智能软件生成\知识构建原始材料\体系结构运行测试小规模v3\Mid Term`。本工作线只负责让新 P1 的策略规则模块围绕体系结构文档生成并冻结一版可执行策略包，让规则字段合同、输入输出 Schema、动作映射和 RuleExecutionRecord 真正被抽取运行消费。不要做 git commit，不要改其它模块内部页面，不要把旧策略页面整块搬过来。

## 目标

- 为 Mid Term 样例建立一版 `architecture_midterm_default` 策略包。
- 覆盖 AV、OV、SV 文档的基础抽取规则、概念合并规则、关系抽取规则、证据覆盖规则、质量门禁规则。
- 每条规则必须具备 `rule_id`、`rule_version`、`rule_hash`、`effect_kind`、`input_schema`、`output_schema`、`trace_fields`、`action_mapping`。
- 保存策略包版本后输出稳定 `policyPackageVersionId`。
- 规则执行结果必须能生成完整 `RuleExecutionRecord`，供 W3、W4、W5 消费。

- 不修改 `modules/intake/**`、`modules/runtime/**`、`modules/qualityGraph/**`、`modules/knowledgeResults/**`、`modules/publication/**`、`modules/systemOutput/**`
- 不直接启动抽取、不写知识成果、不生成发布候选
- 不修改 `.data/**` 或样例源文件
- 不做 commit、push、reset、checkout

## 输入合同

- `archiveId`
- `documentSetId`
- Mid Term 文档类型摘要：AV-1、OV-1、OV-2、OV-5、OV-7、SV-1、SV-2、SV-4

## 输出合同

- `policyPackageVersionId`
- `policy_package_version_hash`
- `rules[]`
- `rule_id`
- `rule_version`
- `rule_hash`
- `effect_kind`
- `input_schema`
- `output_schema`
- `trace_fields`
- `action_mapping`
- `contract_status`
- `contract_errors`
- `RuleExecutionRecord` 字段定义

## 必须覆盖的规则类型

- 文档结构识别规则：章节、表格、段落、视图编号、锚点。
- 体系结构对象抽取规则：Operational Node、System、Capability、Activity、Information Exchange。
- 关系抽取规则：performs、exchanges、part_of、supports、mapped_to、depends_on。
- 跨文档合并规则：同名、别名、视图编号、证据锚点、语义相似度。
- 质量门禁规则：证据覆盖率、关系完整性、冲突数、孤立节点比例、低置信候选比例。

## 与其它工作线的边界

- W3 只消费冻结后的 `policyPackageVersionId` 和规则合同快照，不读取策略编辑表单状态。
- W4 只消费 RuleExecutionRecord 和规则输出，不修改策略包。
- W5 只展示规则命中和质量解释，不编辑规则。

## 注意事项

- 不要只做 UI 展示；策略合同必须能被运行态读取。
- 规则字段合同必须有类型或 schema 支撑，不能只写在页面文案里。
- 结构性规则变更要生成新策略包版本，不允许静默覆盖旧版本。
- `RuleExecutionRecord` 是 W3、W4、W5 的关键衔接点，字段缺失要显式报错。
- 如临时使用 fixture，要标注 `source_kind`，不要伪装成 live 策略执行结果。
