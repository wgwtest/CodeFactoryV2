# W1 资料接入与解析预检

## 初始提示词

你接手 CodeFactoryV2 的 P1 黄金样例 `资料接入与解析预检` 工作线。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。开工前先阅读本目录 `00-并行总说明.md`，然后先回复你的计划修改文件、可能影响其它工作线的合同字段和风险点，得到主线程确认后再改代码。黄金样例资料目录是 `E:\project\Web\智能软件生成\知识构建原始材料\体系结构运行测试小规模v3\Mid Term`，包含 8 个 DOCX：AV-1、OV-1、OV-2、OV-5、OV-7、SV-1、SV-2、SV-4。本工作线只负责让新 P1 的资料接入模块稳定识别、导入、解析预检这组文档，并输出可供抽取运行模块消费的 `documentSetId`。不要做 git commit，不要上传本地数据，不要把旧页面整块搬进新 P1。

## 目标

- 让 `/p1` 创建知识库时可以使用 Mid Term 文件夹作为 `source_dir`。
- 让 `/p1/archives/:archiveId/intake` 能清晰显示 8 个 DOCX 的资料集合、文件类型、解析状态、解析预检状态。
- 为每个文档生成稳定的文档标识、标题、来源路径、文件类型、解析可用性、是否可进入抽取。
- 输出稳定 `documentSetId`，供 W3 抽取运行线消费。
- 明确解析失败或未完成时的阻断原因，不伪装成功。

## 允许修改范围

- `apps/web/src/features/p1Clean/modules/intake/**`
- `apps/web/src/features/p1Clean/modules/knowledgeBaseManagement/**` 中与创建知识库 source_dir 表单直接相关的最小改动
- `apps/web/src/test/p1CleanIntakePage.test.tsx`
- `apps/web/src/test/p1CleanKnowledgeBaseManagement.test.tsx`
- 如需后端薄适配，优先新增 `apps/api/app/archive_knowledge/p1_modules/intake/**`
- 如需后端测试，新增 `apps/api/tests/test_p1_midterm_intake_api.py`

## 禁止改动范围

- 不修改 `modules/policyRules/**`、`modules/runtime/**`、`modules/qualityGraph/**`、`modules/knowledgeResults/**`、`modules/publication/**`、`modules/systemOutput/**`
- 不修改旧 `/governance`、旧发布态知识图谱、旧 P1 大页面
- 不写入 `.data/**`、`.codex-runtime/**`、本地样例源目录
- 不做 commit、push、reset、checkout

## 与其它工作线的边界

- W2 只消费文档类型和知识库类型建议，不读取本模块内部状态。
- W3 只消费 `documentSetId` 和 `documents[]` 的稳定摘要，不直接扫描本地文件夹。
- W4 只消费抽取运行后的结构化文档和候选知识，不负责解析预检。

## 注意事项

- 不要把“选择文件夹导入”重新做成第二个入口按钮；入口统一是创建知识库并填写 `source_dir`。
- 浏览器不能直接拿到本机文件夹真实路径，当前路径式创建是开发机可用方案；如要做批量上传，必须另起接口并在最终回报中标注。
- `documentSetId` 必须稳定，不能每次刷新随机变化。
- 文件状态不明时宁可显示“未解析/不可进入运行”，不要伪装解析成功。
- 如新增后端字段，必须在最终回报中声明 W3 需要如何消费。

## 验收方式

- 打开 `/p1`，创建知识库，资料文件夹路径填写 Mid Term 目录。
- 进入该知识库工作区，点击顶部导航 `资料接入`。
- 页面能看到 8 个 DOCX，且文件名、类型、导入状态、解析预检状态可读。
- 如果文档未解析完成，页面明确显示原因和下一步动作。
- 页面不出现策略编辑、运行事件、质量门禁、发布候选等其它模块职责。
