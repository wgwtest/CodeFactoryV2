## 初始提示词

你接手 CodeFactoryV2 的 P1 黄金样例 `抽取运行与实时流` 工作线。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。开工前先阅读本目录 `00-并行总说明.md`，然后先回复你的计划修改文件、可能影响其它工作线的合同字段和风险点，得到主线程确认后再改代码。黄金样例资料目录是 `E:\project\Web\智能软件生成\知识构建原始材料\体系结构运行测试小规模v3\Mid Term`。本工作线只负责让新 P1 的抽取运行模块消费 W1 输出的 `documentSetId` 和 W2 输出的 `policyPackageVersionId`，启动抽取、显示实时事件流、运行状态、运行图谱和 `runtimeSnapshotId`。不要做 git commit，不要编辑策略规则，不要生成正式发布版本。

## 目标

- 让 `/p1/archives/:archiveId/runtime` 可以选择或默认使用 Mid Term 文档集合启动抽取。
- 运行中优先使用 SSE stream，断线后自动回退 polling。
- 页面局部更新，不整页刷新。
- 实时显示当前文档、当前规则、当前事件、当前对象、当前关系、运行图谱变化。
- 输出稳定 `runtimeSnapshotId`，供 W4、W5、W6 消费。

- 不修改样例源目录和 `.data/**`。

## 与其它工作线的边界

- W1 负责资料集合，不负责运行事件。
- W2 负责策略合同，不负责运行 UI。
- W4 消费运行输出进行知识生成和跨文档合并，不直接控制 stream。
- W5 消费运行快照和质量报告，不修改运行任务。

## 注意事项

- 页面更新必须是局部 state 更新，不允许通过整页刷新模拟实时效果。
- stream 和 polling 返回字段要等价，避免断线后页面信息变少。
- 如果 W1/W2 的真实合同尚未完成，可以使用明确标注的 fallback，但 adapter 层必须保持最终字段形态。
- 运行事件要体现规则命中、对象生成和关系生成，不要只显示阶段名称。
- `runtimeSnapshotId` 必须能被 W4、W5、W6 继续使用。

## 验收方式

- 创建 Mid Term 知识库后进入 `抽取运行`。
- 点击启动或刷新运行，能看到 stream 已连接或轮询回退状态。
- 运行过程中页面不整页刷新。
- 事件流持续出现规则命中、对象生成、关系生成。
- 运行图谱能随对象和关系增加而更新。
- 完成后产生 `runtimeSnapshotId`。
