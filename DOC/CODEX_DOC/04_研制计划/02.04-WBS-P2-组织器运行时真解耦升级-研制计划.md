# P2 组织器运行时真解耦升级实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在当前 `P2` 需求分析 Lab 已完成目录插件化的基础上，进一步完成组织器运行时真解耦，使 `xg-heuristic-orchestrator` 与 `brainstorm-v1` 不再反向依赖宿主会话服务和数据库组装逻辑，而是统一通过稳定运行时端口和通用策略运行器执行。

**Architecture:** 本阶段以“端口先行、运行器收敛、插件资产显式化”为主线。宿主新增 `OrchestratorRuntimeHost` 和稳定运行时端口，adapter 不再构造 `SessionLocal` / `RequirementAnalysisSessionService`，本地 XG / Brainstorm V1 的同源阶段运行能力收敛到宿主通用 `PolicyInterpretedRuntime`。组织器差异保留在 `manifest.json`、`spec_strategy.json`、`prompts/`、`schemas/`、`adoption/` 等描述包资产中，宿主只负责装载、端口注入、合同校验、结果物化和审计。

**Tech Stack:** FastAPI, Pydantic, Python service layer, importlib, pytest, React, TypeScript, Ant Design, Vitest.

### 本阶段新增解耦判据

1. 插件 adapter 不得创建 `SessionLocal`。
2. 插件 adapter 不得构造 `RequirementAnalysisSessionService`。
3. 插件目录代码不得直接依赖宿主内部 `app.requirement_analysis.*` 服务，除稳定合同和运行时端口外。
4. 启发式组织器和 Brainstorm V1 不再各自维护复制的 XG 阶段 runtime。
5. 阶段执行按组织器描述包显式策略推进，运行时不再根据 `stage_id` 关键词推断业务阶段。
6. 宿主保留确定性基础设施，不再承担章节匹配、下一轮追问、意图识别等业务判断。

### 不进入本计划的内容

- 不接真实 `Dify` API。
- 不重做 P2 正式专家工作台。
- 不改 P2 前端主视图结构。
- 不在本阶段重写完整需求规格正文生成策略。
- 不合并本计划到主设计说明正文，待实施和复核完成后再归并。

## 12. 本轮实施记录

### 12.1 已完成内容

1. 新增 `apps/api/app/orchestrators/runtime/` 宿主运行时包，集中承载 `OrchestratorRuntimeHost`、`PolicyInterpretedRuntime`、`TurnStagePlan`、`StageRuntimeContext`、阶段执行器、阶段归约器和策略读取服务。

3. `xg-heuristic-orchestrator` 与 `brainstorm-v1` 的 adapter 删除数据库 session 和 `RequirementAnalysisSessionService` 构造逻辑，改为调用 `runtime_host.build_policy_interpreted_runtime()`。
4. 删除启发式组织器与 Brainstorm V1 插件目录中的复制运行时文件：

6. 宿主运行时调用日志不再根据 `stage_id` 字符串推断业务阶段；日志服务输出形态按阶段 `output_targets` 判断，阶段类别按 `stage_kind` 配置读取。

### 12.2 架构护栏

本轮新增并通过的护栏包括：

1. 策略解释型插件 adapter 不得引用 `SessionLocal` 或 `RequirementAnalysisSessionService`。
2. 启发式组织器和 Brainstorm V1 插件目录不得保留复制运行时文件。
3. `PolicyInterpretedRuntime._stage_kind()` 不得通过 `stage_id` 文本包含关系推断阶段类别。
