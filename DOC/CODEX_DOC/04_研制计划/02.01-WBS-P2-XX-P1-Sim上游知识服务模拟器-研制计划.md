## 1. 工作目标

实现一套确定性的 `XX-P1-Sim`，用于在真实 `P1` 尚不能稳定输出领域知识时，为 `P2` 提供可注册、可发现、可查询、可复现的上游知识服务。

本节点的闭环目标为：

`XX-P1-Sim 注册 -> P2 发现知识源 -> 用户选择领域知识 -> P2 拉取知识包 -> P2 普通编辑器继续编写需求规格`

本节点不负责：

- 模拟专家输入
- 生成需求规格正文
- 生成 P2 文档或 authoring session
- 问答补齐、自动补齐
- 缺口检查、冻结或 P3 可消费包

## 2. 实施范围

### 2.1 后端

新增或整理 `XX-P1-Sim` 上游知识模拟子系统：

- 定义服务注册对象 `P1KnowledgeProviderRegistration`
- 定义领域知识目录对象 `P1DomainKnowledgeCatalog`
- 定义发布态知识包对象 `P1DomainKnowledgeArchive`
- 定义调用日志对象 `P1SimCallLog`
- 提供固定种子、固定版本和重置能力
- 提供 `XX-P1-Sim` API 路由族

建议接口：

- `POST /api/xx-p1-sim/register`
- `GET /api/xx-p1-sim/domains`
- `GET /api/xx-p1-sim/domains/{domain_id}/knowledge`
- `POST /api/xx-p1-sim/reset`
- `GET /api/xx-p1-sim/logs`

`P2` 后端只补知识源发现和绑定接口：

- `GET /api/requirement-authoring/knowledge-providers`
- `POST /api/requirement-authoring/knowledge-bindings`

### 2.2 前端

新增独立 `XX-P1-Sim` 页面：

- 路由：`/xx-p1-sim`
- 页面对象：`XXP1SimPage`
- 展示当前模拟服务摘要
- 展示 P1 服务接口
- 展示领域知识目录
- 展示知识包预览
- 展示调用日志
- 提供重置种子和注册到 P2 操作

调整 `P2` 专家需求规格编写工作台：

- 在启动或知识绑定区域展示 P1 知识源
- 支持选择领域知识，例如 `空域规划领域知识`
- 拉取概念、规则、流程、约束和证据片段
- 进入普通编辑器后只显示来源无感状态，例如 `领域知识已绑定`

### 2.3 测试

新增后端和前端测试，覆盖：

- `XX-P1-Sim` 页面可达
- 服务注册可用
- P2 能发现该知识服务
- 领域知识目录可查询
- 领域知识包可拉取
- 知识包中包含概念、规则、流程、约束和证据
- 调用日志记录 P2 查询行为
- P2 普通编辑器不暴露 `XX-P1-Sim`、`mock`、`模拟`、`发生器` 等来源概念

## 3. 不纳入本轮

- 不生成随机数据。
- 不做 P2 样例项目包。
