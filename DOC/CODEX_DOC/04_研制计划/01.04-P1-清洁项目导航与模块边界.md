# P1 清洁项目导航与模块边界

更新时间：2026-05-10

## 1. 建设原则

本轮不再继续在旧 P1 页面上补丁式重构，而是新开一个隔离的 P1 清洁入口。

原则：

- `/p1` 是知识库管理入口，独立于单个知识库内部工作区导航。
- 进入某个知识库后，从 `/p1/archives/:archiveId/overview` 开始显示 P1 工作区导航。
- `/p1-legacy` 保留旧实验壳，仅用于对照，不作为主验收入口。
- 页面跳转只通过顶部导航完成。
- 顶部导航允许二级下拉，但页面内容区右上角不再放多级导航按钮。
- 每次只迁移一个功能模块，拒绝把旧页面的大量功能一次性堆进新页面。

## 2. 两层入口关系

| 层级 | 路由 | 职责 | 是否显示工作区导航 |
| --- | --- | --- | --- |
| 知识库管理 | `/p1` | 创建、选择、绑定资料文件夹、查看知识库运行概况 | 否 |
| 单知识库工作区 | `/p1/archives/:archiveId/overview` 及其子路由 | 资料接入、策略规则、抽取运行、质量图谱、发布输出 | 是 |

这能避免“知识库管理”和“单个知识库抽取流程”混在同一套导航里。后续如果要做面向终端用户的简洁入口，也优先从 `/p1` 这一层派生。

## 3. 工作区顶部导航

工作区导航由 `apps/web/src/features/p1Clean/registry.ts` 统一生成，不允许在页面壳中手写模块路由。

| 导航 | 路由 | 职责 |
| --- | --- | --- |
| 总览 | `/p1/archives/:archiveId/overview` | 只展示当前知识库上下文、模块状态和模块边界 |
| 资料接入 | `/p1/archives/:archiveId/intake` | 文件夹选择、文件扫描、解析预检、抽取入队 |
| 策略规则 | `/p1/archives/:archiveId/policy` | 策略包版本、规则合同、动作映射、执行记录 |
| 抽取运行 | `/p1/archives/:archiveId/runtime` | 当前阶段、事件流、语义图谱、运行状态 |
| 质量图谱 | `/p1/archives/:archiveId/quality` | 知识质量、图谱质量、门禁解释 |
| 发布输出 | `/p1/archives/:archiveId/publication` | 发布候选、治理确认状态、候选快照 |
| 系统间输出 | `/p1/archives/:archiveId/system-output` | 正式知识供应合同、系统间 API 范围 |

## 4. 模块目录约定

每个模块必须独立目录，目录内至少包含：

- `types.ts`：本模块输入输出合同。
- `api.ts`：本模块允许调用的后端 API adapter。
- `page.tsx`：本模块页面入口。
- `README.md`：职责、边界、输入输出说明。
- `testEntry.ts`：本模块可交给并行线程验收的测试入口。

当前模块目录：

- `modules/knowledgeBaseManagement`
- `modules/intake`
- `modules/policyRules`
- `modules/runtime`
- `modules/qualityGraph`
- `modules/publication`
- `modules/systemOutput`

统一工作区上下文只包含：

- `archiveId`
- `policyPackageVersionId`
- `runtimeSnapshotId`
- `documentSetId`
- `publicationSnapshotId`

## 5. 模块边界

资料接入只回答：

- 选择了哪个文件夹。
- 扫描出哪些文件。
- 解析是否可用。
- 使用哪个推荐策略进入抽取。

抽取运行只回答：

- 当前真实运行到哪一步。
- Stream / 轮询状态是否正常。
- 输入对象、规则依据、输出对象如何形成。
- 当前图谱是否能解释抽取过程。

策略规则只回答：

- 使用哪个策略包版本。
- 哪些规则参与抽取。
- 每条规则的输入、输出、动作和执行记录是否明确。

质量图谱只回答：

- 抽取出的知识是否可信。
- 图谱关系是否有参考价值。
- 哪些指标和规则导致通过、警告或阻断。

发布输出只回答：

- 机器是否生成发布候选。
- 候选 API 和正式输出 API 是否分离。
- 正式输出是否只包含治理确认后的知识。
