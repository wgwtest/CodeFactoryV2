# P3 插件式转换器落地研制计划

**日期：** 2026-05-18

## 1. 目标

把 `P3` 需规转软设从 `software_design_v2` 内部固定草稿生成，升级为可替换的插件式转换器框架。首个转换器类型为 `dify_workflow`，真实 Dify workflow 由另一个具备 Dify 接口配置的 Codex 会话创建；当前分支只实现协议、插件发现、adapter 加载、Dify API 调用边界、mock 测试和 P3 分系统接入。

## 2. 非目标

- 不登录或编辑 Dify 工作台。
- 不保存真实 Dify API Key。
- 不把 Dify 内部节点调试状态作为当前 P3 分系统事实源。
- 不改动 P3 前端页面布局。

## 3. 实施任务

### 3.1 转换器协议与插件发现

- 新增 `apps/api/app/design_converters/` 模块。
- 定义 `DesignConverterManifest`、`DesignConverterRunRequest`、`DesignConverterRunResult`。
- 定义 `ConverterDiscovery` 和 `ConverterRegistry`。
- 插件目录根为 `converters/`，首层为阶段域，例如 `converters/p3/<converter>/manifest.json`。

### 3.2 Adapter 加载与 Dify 插件

- 新增 adapter loader，按 manifest 动态加载本地 adapter。
- 新增首个插件目录 `converters/p3/requirement-to-sdd-dify-workflow/`。
- Dify adapter 调用 `/v1/workflows/run`。
- 未配置 `DIFY_API_KEY` 时明确失败，不生成伪结果。
- Dify 返回非 JSON、缺少 `data.outputs.result_json`、`result_json` 非 JSON 或缺少关键字段时明确失败。

### 3.3 `software_design_v2` 接入

- `P3DesignConversionRun` 增加 `converter_id` 与 `options`。
- `run_conversion` 构造 `DesignConverterRunRequest`，通过 adapter loader 调用转换器。
- 转换结果写入 `design_document`、`design_baseline`、`workorder_projection`、`conversion`、`check_result` 种子和 `runtime_events`。
- 保留 `strategy` 作为转换选项，兼容现有测试和页面。

### 3.4 测试与验收

- 新增转换器协议、发现和 adapter 测试。
- 新增 Dify adapter mocked HTTP 成功、缺配置、非 JSON、缺字段测试。
- 扩展 P3 API 测试，证明 P3 conversion 通过转换器 adapter loader 完成。
- 回归运行 `test_software_design_v2_api.py` 和新增测试文件。

## 4. 验收标准

- 首个转换器 manifest 可被发现并列为默认候选。
- 不支持的 `converter_id` 返回 `unsupported P3 design converter`。
- 缺少 Dify 配置时返回明确错误。
- mocked Dify 成功响应能生成软设草稿、设计包初稿、追溯、缺口和人工校核项。
- `software_design_v2` 保持现有会话、回合、保存、投影、检查、冻结流程可用。
- 代码和文档中不新增禁用旧称谓。
