## 1. 工作目标

实现一套确定性的 `P2/P1` 场景数据发生器，使首版 `P2` 专家需求规格编写工作台能够在没有真实 `P1` 发布态知识文件和真实大模型的情况下，完成可复现的端到端演示与自动化验收。

闭环目标为：

`模拟 P1 知识 -> P2 authoring 文档 -> 问答修补 -> 自动补齐 -> 缺口检查 -> 冻结 -> P3 可消费包`

## 2. 实施范围

### 2.1 后端

新增 `app.requirement_authoring` 场景子系统：

- `scenario_models.py`
  定义场景目录、物化请求、问答输入、`BrainstormingResponse` 等结构化契约。
- `scenario_fixtures.py`
  定义 `airspace-collaboration` 确定性场景包。
- `scenario_projector.py`
  将场景包物化为模拟 `P1` 发布态知识 JSON。
- `service.py`
  增加场景列表、物化、场景问答、自动补齐方法。
- `requirement_authoring.py`
  增加场景相关 API 路由。

### 2.2 前端

在现有 `P2` 专家工作台中增加小型场景入口：

- 在 `设置` 弹层中选择场景。
- 点击 `生成模拟闭环`。
- 在工作台显示模拟 `P1` 知识源。
- 对场景绑定文档调用 `scenario-turns`。
- 提供 `自动补齐` 按钮。

不得新增一个替代正式工作台的独立演示页。

### 2.3 测试

新增后端场景闭环测试和前端工作台测试，覆盖：

- 场景列表
- 模拟 `P1` 知识物化
- `P2` 文档创建
- 场景问答
- 自动补齐
- 缺口检查
- 冻结版本
- 前端显示模拟知识源和自动补齐结果

## 3. 不纳入本轮

- 不接入真实 LLM。
- 不接入 `P6` 门户状态。
- 不生成随机场景。
- 不把 `P3/P4/P5` 实现细节写入 `P2` 需求规格正文。
- 不删除或重置现有 worktree。
