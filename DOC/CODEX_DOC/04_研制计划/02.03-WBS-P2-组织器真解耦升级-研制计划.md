# P2 组织器真解耦升级实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `feat/p2-validation-workflow` 中将当前 `P2` 需求分析 Lab 组织器从“静态注册的插件化”升级为“目录可插拔的真解耦插件宿主”，使插件目录的放入、移除、重启或显式 reload 能直接决定组织器是否可用。

**Architecture:** 以 `orchestrators/<domain>/<plugin>/` 为唯一插件物理形态，宿主启动时或显式 reload 时扫描该一层目录结构，基于 `manifest.json` 和本地入口文件构建插件注册表。`TurnEngine` 与 `SessionService` 只依赖统一插件合同和 adapter 运行接口，不再依赖固定插件名、固定插件类型或静态注册表。`Dify` 在本阶段仍只作为 fake 预留插件，但其插件包也必须满足“目录存在 + 本地入口存在”这一真解耦规则。

**Tech Stack:** FastAPI, Pydantic, Python service layer, importlib, pytest, React, TypeScript, Ant Design, Vitest.

### 本阶段新增解耦判据

1. 宿主只扫描 `orchestrators/<domain>/<plugin>/` 一层结构，不做任意深度扫描。
2. 插件目录中必须同时存在 `manifest.json` 和本地可执行入口，不允许只有配置没有代码的插件包。
3. 插件放入目录后，在宿主重启或显式 reload 后可被发现。
4. 插件移出目录后，在宿主重启或显式 reload 后从列表消失，且不可再创建会话。
5. 后端主流程中不得继续手写具体组织器 ID 作为注册入口或执行分发依据。

### 不进入本计划的内容

- 不接真实 `Dify` API。
- 不增加后台定时扫描或文件系统监听。
- 不重做 `P2` 专家正式工作台。
- 不重做模板管理台。
- 不合并本补充计划到主设计说明正文。

## 11. 计划自检结果

### 11.1 本计划覆盖

1. 目录一层扫描发现插件。
2. 插件包必须带本地入口。
3. 静态插件注册表改为目录发现式注册表。
4. `SessionService` 去静态插件名依赖。
5. `TurnEngine` 去插件类型主流程分支。
6. 显式 reload 机制。
7. 真解耦插拔验收闭环。
8. 宿主 adapter 目录不再持有本地 XG 或 fake Dify 组织器实现。
9. 宿主 stage asset resolver 不再内置 XG 阶段名推断，只按插件显式 `prompt_id` / `schema_id` / `adoption_id` / `stage_id` 解析资产。
10. 宿主 Provider 层不再按 XG 阶段协议分支归一化；DeepSeek 输出按 JSON 透传并记录 raw，Mock 阶段行为由本地 XG 插件本地实现承担。

### 11.2 本计划不覆盖

1. 真实 `Dify` API 联调。
2. 后台定时扫描。
3. 文件系统热监听。
4. P2 专家正式工作台重构。

### 11.3 验收结论

完成本计划后，`feat/p2-validation-workflow` 应达到：

```text
P2 Lab 的组织器由目录可插拔插件宿主承载；
插件放入目录后，重启或显式 reload 即可被发现并运行；
插件移出目录后，重启或显式 reload 即不可再被发现或使用；
后端主流程不再依赖固定组织器名或静态插件注册表。
```

1. 新增 `apps/api/app/orchestrators/plugin_discovery.py`，按 `orchestrators/<domain>/<plugin>/manifest.json` 一层目录扫描插件。
2. `plugin_registry.py` 已改为目录发现式注册表，支持显式 reload，并保留 legacy alias 作为输入兼容，不作为注册源。
3. `manifest.json` 合同要求 `adapter_module` 和 `adapter_class`，发现阶段会校验插件目录内本地入口文件存在。
4. `xg-heuristic-orchestrator`、`xg-strong-rule-orchestrator`、`xg-dify-workflow-orchestrator` 均已具备插件目录内 `adapter.py` 本地入口。
5. `SessionService`、Lab 默认配置和前端默认选择不再手写固定组织器 ID；默认组织器来自扫描后注册表的优先级排序。
6. 新增 `POST /api/requirement-analysis/orchestrators/reload`，用于显式重新扫描插件目录。
7. 前端 P2 Lab 已提供“重新扫描组织器”入口，reload 后以服务端返回列表更新可选组织器。
8. `RequirementAnalysisTurnEngine` 已统一先按 manifest 装载 adapter，只负责构造 `OrchestratorRunRequest`、调用 `adapter.run(request)` 并接收结果；本地 XG 的四阶段高观测编排已迁入各自插件目录下的 `local_xg_turn_runtime.py`，由插件目录内 `adapter.py` 持有，不再由 `TurnEngine` 或宿主 adapter 包按阶段执行。
9. fake `Dify` 插件与本地 XG 插件走同一 adapter 装载入口；Dify 的内部阶段流转视为 workflow 黑盒，本地 XG 的内部阶段流转视为本地 adapter 黑盒，宿主只依赖统一输入输出合同。
10. 通用插件输出到 P2 `TurnExecutionResult` 的物化逻辑已迁入 `app.orchestrators.adapters.plugin_turn_result_materializer.PluginTurnResultMaterializer`；`TurnEngine` 不再兜底拼装阶段形态字段，adapter 必须返回 `raw_output.turn_execution_result`。
11. 本地 XG 阶段链专用服务 `stage_runtime_context_builder.py`、`turn_strategy_service.py`、`turn_stage_planner.py`、`turn_stage_executor.py`、`turn_stage_reducer.py` 已迁入两个本地 XG 插件目录；宿主 `app.requirement_analysis` 不再持有这些本地 XG 阶段链实现。

### 12.2 验收边界

1. 本阶段 fake `Dify` 插件只验证插件宿主、统一输入输出合同、有限观测降级和目录插拔；未接入真实 Dify API。
2. 本阶段不做定时扫描和文件系统监听；新增、移除插件后必须 reload 或重启。
3. legacy 组织器 ID 仍作为 manifest alias 接受，用于兼容历史 API 请求和测试数据；宿主注册和默认选择不再依赖这些固定 ID。

### 12.3 进一步解耦收口结果

1. fake `Dify` adapter 实现已迁入 `orchestrators/xg/xg-dify-workflow-orchestrator/adapter.py`，并删除宿主 `apps/api/app/orchestrators/adapters/dify_workflow_plugin.py`。
2. 宿主 `stage_prompt_resolver.py`、`stage_schema_resolver.py`、`stage_adoption_policy_resolver.py` 已去掉 `intent_understanding`、`review_after_apply`、`next_interaction_planning` 等 XG 阶段名推断；阶段资产选择由插件阶段计划中的显式字段决定。
3. `DeepSeekRequirementAnalysisClient` 不再按 XG 阶段名分支归一化输出；Provider 返回 JSON 由插件运行时和后续通用输出服务解释。
4. `RequirementAnalysisProviderCallService` 不再持有 XG intent/review/next planning 的 Mock 阶段输出实现；本地 XG Mock 阶段生成器迁入两个本地 XG 插件目录的 `local_xg_mock_stage_provider.py`。
5. `RequirementAnalysisLabConfigService` 的观测说明去掉具体四阶段名称枚举，保留通用过程字段说明和 P2 turn 观测结构。
6. 新增架构测试覆盖 Dify 实现插件本地化、宿主 stage resolver 去阶段名、宿主 Provider 层去 XG 阶段协议分支。
