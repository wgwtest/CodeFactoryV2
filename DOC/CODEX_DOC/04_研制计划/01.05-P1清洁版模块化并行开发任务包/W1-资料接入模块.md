# W1 资料接入模块

## 初始提示词

你接手 CodeFactoryV2 的 P1 清洁版 `资料接入` 工作线。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。本工作线只负责 `apps/web/src/features/p1Clean/modules/intake` 及必要的后端接入服务，目标是让资料接入模块围绕当前 `archiveId` 管理资料源、文档集合、解析预检和抽取入队，并输出稳定的 `documentSetId`。不要把旧 P1 页面整块搬进来，不要修改其它模块内部状态，不要做 git commit。

## 目标

把 `资料接入` 从脚手架页推进为可并行开发的真实模块：

- 读取当前知识库下的文档/资料集合。
- 展示资料源、文档集合、解析状态、解析预检结果。
- 支持上传或绑定资料后刷新文档集合。
- 输出 `documentSetId` 给抽取运行模块。

## 允许修改范围

- `apps/web/src/features/p1Clean/modules/intake/**`
- `apps/web/src/test/*intake*.test.ts?(x)`
- 如确需后端支持，优先新增：
  - `apps/api/app/archive_knowledge/p1_modules/intake/**`
  - `apps/api/tests/test_p1_clean_intake_api.py`
- 如必须挂接现有路由，只允许在 `apps/api/app/api/routes/archives.py` 增加薄路由，不允许改动其它工作线的业务逻辑。

## 禁止改动范围

- `modules/policyRules/**`
- `modules/runtime/**`
- `modules/qualityGraph/**`
- `modules/publication/**`
- `modules/systemOutput/**`
- `/governance` 页面和旧发布态知识图谱页面
- `.data/**`

## 输入合同

- `archiveId`
- 可选 `policyPackageVersionId`

## 输出合同

- `documentSetId`
- 文档集合摘要：文档数、解析完成数、解析失败数、待入队数。
- 解析预检摘要：格式可用性、结构可用性、是否可进入抽取运行。

## API adapter

只能通过 `modules/intake/api.ts` 对外调用：

- `getArchiveDocuments`
- `getArchiveSummary`
- `importArchiveDocument`
- `extractKnowledgeArchive`

新增 API 也必须先收敛到 `modules/intake/api.ts`，页面不得直接 import 全局 API。

## 验收方式

人工路径：

- 打开 `/p1`
- 进入任意知识库工作区
- 点击 `资料接入`
- 能看到当前知识库名称、资料源、文档集合、解析状态和接入动作
- 页面不出现策略编辑、质量门禁、发布确认等其它模块职责

cd E:\project\Web\智能软件生成\CodeFactoryV2\apps\web
