# W2 策略规则模块

## 初始提示词

你接手 CodeFactoryV2 的 P1 清洁版 `策略规则` 工作线。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。本工作线只负责 `apps/web/src/features/p1Clean/modules/policyRules` 及策略合同相关后端能力，目标是让策略包版本、规则字段合同、规则输入输出、动作映射、RuleExecutionRecord 和规则变更影响面成为独立模块。不要修改资料接入、抽取运行、质量图谱、发布输出和系统间输出模块，不要做 git commit。

## 目标

- 展示当前知识库可用策略包。
- 冻结或选择 `policyPackageVersionId`。
- 编辑和校验规则字段合同。
- 展示规则输入 Schema、输出 Schema、动作映射、trace fields。
- 规则变更后生成 ImpactSet，不直接覆盖正式知识。

## 允许修改范围

- `apps/web/src/features/p1Clean/modules/policyRules/**`
- `apps/web/src/test/*policy*.test.ts?(x)`
- 后端优先使用或扩展：
  - `apps/api/app/archive_knowledge/policy_config.py`
  - `apps/api/app/archive_knowledge/runtime_policy_contract.py`
  - `apps/api/app/archive_knowledge/contracts/policy.py`
  - `apps/api/app/archive_knowledge/contracts/rule.py`
  - `apps/api/tests/test_archive_policy_config_api.py`
- 如需新增清洁版服务，可放在 `apps/api/app/archive_knowledge/p1_modules/policy_rules/**`

## 禁止改动范围

- 不直接改 `modules/intake/**` 输出。
- 不直接启动抽取运行。
- 不直接写发布候选或正式知识。
- 不把旧 `P1PrototypeWorkflowPages.tsx` 大段搬入本模块。

## 输入合同

- `archiveId`

## 输出合同

- `policyPackageVersionId`
- 规则合同校验状态
- ImpactSet 摘要

## API adapter

只能通过 `modules/policyRules/api.ts` 调用：

- `getArchivePolicyConfig`
- `updateArchivePolicyConfig`
- `listArchiveIncrementalRebuildTasks`

新增 API 必须先进入本模块 `api.ts`。

## 验收方式

人工路径：

- 进入 `/p1/archives/:archiveId/policy`
- 能看到当前策略包版本、规则合同清单、字段合同状态
- 能看出规则变更不会直接覆盖正式知识，只生成影响面或候选任务
