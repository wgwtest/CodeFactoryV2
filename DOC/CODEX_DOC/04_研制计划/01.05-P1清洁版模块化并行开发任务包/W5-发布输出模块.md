# W5 发布输出模块

## 初始提示词

你接手 CodeFactoryV2 的 P1 清洁版 `发布输出` 工作线。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。本工作线只负责 `apps/web/src/features/p1Clean/modules/publication` 和发布候选快照相关后端能力，目标是消费质量决策和 `runtimeSnapshotId`，生成候选快照并输出 `publicationSnapshotId`。候选发布不等于正式入库，不要改治理确认页面，不要做 git commit。

## 目标

- 展示机器发布候选状态。
- 展示候选快照、候选 API 范围和治理确认状态投影。
- 输出 `publicationSnapshotId` 给系统间输出模块。
- 清楚区分候选态、等待治理确认、正式入库态。

## 允许修改范围

- `apps/web/src/features/p1Clean/modules/publication/**`
- `apps/web/src/test/*publication*.test.ts?(x)`
- 后端优先使用或扩展：
  - `apps/api/app/archive_knowledge/runtime_indexes_snapshots_apis.py`
  - `apps/api/app/archive_knowledge/contracts/publication.py`
  - `apps/api/tests/test_archive_document_runtime_api.py`
- 如需新增清洁版服务，可放在 `apps/api/app/archive_knowledge/p1_modules/publication/**`

## 禁止改动范围

- 不修改 `/governance` 治理确认页面。
- 不生成正式知识供应接口。
- 不直接读取抽取运行内部临时状态。
- 不覆盖正式知识。

## 输入合同

- `archiveId`
- `runtimeSnapshotId`
- 质量决策摘要

## 输出合同

- `publicationSnapshotId`
- 发布候选摘要
- 候选 API 暴露范围
- 治理确认状态投影

## API adapter

只能通过 `modules/publication/api.ts` 调用：

- `getArchivePublication`

新增发布候选 API 必须先进入本模块 `api.ts`。

## 验收方式

人工路径：

- 进入 `/p1/archives/:archiveId/publication`
- 能看出机器已发布候选，但尚未正式入库
- 能看到候选快照和等待治理确认状态
