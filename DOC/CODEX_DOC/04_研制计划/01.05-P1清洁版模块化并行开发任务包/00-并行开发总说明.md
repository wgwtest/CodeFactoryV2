# P1 清洁版模块化并行开发任务包

更新时间：2026-05-10

## 目标

本任务包服务于 P1 清洁版重构后的并行开发。核心目标不是先打通某条最短闭环，而是让每个模块在清晰合同下独立演进，最终组合成更易用、可维护、可验证、可供后续系统消费的业务知识库系统。

## 当前基座

- P1 上层入口：`/p1`
- 单知识库工作区：`/p1/archives/:archiveId/overview`
- 模块注册表：`apps/web/src/features/p1Clean/registry.ts`
- 工作区壳：`apps/web/src/features/p1Clean/P1CleanApp.tsx`
- 统一上下文：`apps/web/src/features/p1Clean/types.ts`
- 模块目录：`apps/web/src/features/p1Clean/modules/*`

## 统一上下文

所有模块只能通过以下上下文衔接，不允许跨模块读取内部状态：

- `archiveId`
- `policyPackageVersionId`
- `runtimeSnapshotId`
- `documentSetId`
- `publicationSnapshotId`

如果某条工作线认为需要新增上下文字段，必须先在自己的结论里说明原因，不要直接修改全局合同。

## 并行工作线

| 工作线 | 模块目录 | 输出 |
| --- | --- | --- |
| W1 资料接入 | `modules/intake` | `documentSetId` |
| W2 策略规则 | `modules/policyRules` | `policyPackageVersionId` |
| W3 抽取运行 | `modules/runtime` | `runtimeSnapshotId` |
| W4 质量图谱 | `modules/qualityGraph` | 质量决策与质量解释 |
| W5 发布输出 | `modules/publication` | `publicationSnapshotId` |
| W6 系统间输出 | `modules/systemOutput` | 正式知识供应接口合同 |

## 全局禁止事项

- 不要把旧 P1 页面整块复制进新模块。
- 不要让模块直接 import 其它模块的 `page.tsx`、内部 state 或私有 helper。
- 不要在页面右上角新增多级跳转按钮；导航必须来自注册表。
- 不要提交 `.data`、本地日志、临时验收截图或运行产物。
- 不要修改 `/governance`、旧发布态知识图谱等非本轮负责页面。
- 不要绕过 `registry.ts` 手写新的工作区导航。

## 交付要求

每条工作线最终回复必须包含：

- 修改了哪些文件。
- 本模块输入输出合同是否变化。
- 新增或复用的 API adapter。
- 是否触碰共享文件，为什么必须触碰。
- 跑过哪些测试。
- 人工验收路径。
