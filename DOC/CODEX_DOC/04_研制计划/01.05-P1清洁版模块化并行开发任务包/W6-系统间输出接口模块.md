# W6 系统间输出接口模块

## 初始提示词

你接手 CodeFactoryV2 的 P1 清洁版 `系统间输出接口` 工作线。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。本工作线只负责 `apps/web/src/features/p1Clean/modules/systemOutput` 和系统间正式知识供应合同，目标是消费治理确认后的 `publicationSnapshotId`，向后续系统提供严格的正式知识输出接口说明和 adapter。不要读取抽取中的临时节点，不要修改发布候选模块，不要做 git commit。

## 目标

- 定义正式知识供应接口合同。
- 明确候选 API 和正式输出 API 的边界。
- 确认输出只来自治理确认后的正式版本。
- 为 P2/P3 等后续系统提供稳定读取 adapter。

## 允许修改范围

- `apps/web/src/features/p1Clean/modules/systemOutput/**`
- `apps/web/src/test/*systemOutput*.test.ts?(x)`
- 后端优先使用或扩展：
  - `apps/api/app/archive_knowledge/contracts/system_output.py`
  - `apps/api/app/requirement_exchange/p1_knowledge_adapter.py`
  - `apps/api/app/api/routes/knowledge.py`
  - `apps/api/tests/test_requirement_specs_api.py`
- 如需新增清洁版服务，可放在 `apps/api/app/archive_knowledge/p1_modules/system_output/**`

## 禁止改动范围

- 不读取运行态临时节点。
- 不消费未治理确认的候选快照作为正式输出。
- 不修改 `modules/publication/**` 内部状态。
- 不修改 `/governance` 页面。

## 输入合同

- `archiveId`
- `publicationSnapshotId`

## 输出合同

- 正式知识供应接口列表
- 版本选择规则
- 系统间 adapter 合同
- P2/P3 消费说明

## API adapter

只能通过 `modules/systemOutput/api.ts` 调用：

- `getArchiveSummary`
- `getArchiveGraph`
- `getArchivePublication`

新增正式输出 API 必须先进入本模块 `api.ts`。

## 验收方式

人工路径：

- 进入 `/p1/archives/:archiveId/system-output`
- 能看到正式输出合同、接口清单、版本来源
- 页面明确说明正式输出不包含抽取中的临时节点

```powershell

npm run test -- p1CleanModuleRegistry.test.ts
npm run build
```
