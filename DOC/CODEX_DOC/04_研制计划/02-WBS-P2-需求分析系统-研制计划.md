# WBS-P2 需求分析系统研制计划

## 1. 节点目标

构建一个面向专业知识专家可用的可配置需求规格说明编写系统，使专家能够在标准需求规格说明正文中完成编写、校对、缺口检查和冻结，并在冻结后输出结构化 `RequirementSpec` 供 `P3` 消费。

## 2. 当前边界

`P2` 负责：

- 提供专家需求规格编写工作台
- 提供 `问答模式 / 表单模式` 两种同源输入方式
- 呈现完整标准需求规格说明正文
- 支持条款批注浮层、缺口检查和冻结版本
- 提供配置与模板管理台，配置规格模板、表单模板、字段映射、问答策略和缺口检查规则
- 消费 `P1` 的已发布知识库作为可选引用来源
- 冻结后产出标准规格说明文档和结构化 `RequirementSpec` 包

不负责：

- 直接做组件命中与复用判断
- 直接产出软件设计说明
- 直接承担工具仓库管理

## 6. 后续约束

- 专家正面工作对象必须是标准需求规格说明正文
- 结构化 `RequirementSpec` 是后台事实状态和冻结后下游包
- 规格模板、表单模板、字段映射、问答策略、缺口检查规则和知识库绑定必须可配置
- `P3` 只消费专家冻结后的正式版本
- `P2` 与组件/工具资产保持解耦，由 `P3 / P4` 在后续阶段消费

## 8. 多轮测试与样例依据

P2 组织器插件的多轮测试统一以长期测试指南为入口：

```text
DOC/CODEX_DOC/06_测试文档/00_测试指南/01-P2-组织器插件与Codex-Brainstorming对照测试指南.md
```

态势分析系统作为当前 P2 需求分析 Lab 的准真实样例，样例依据放在：

```text
DOC/JB_DOC/03-项目实例与样例/P2-需求分析Lab样例-态势分析系统/
```

该目录内文档分工如下：

- `01-需求规格说明样例-态势分析系统.md`：完整需求规格样例，只作为隐藏基准和人工复核依据。
- `02-动态考官手册-态势分析系统.md`：受控多轮交互测试策略，规定测试者如何以回答组织器问题为主，并在明显偏离时少量引导或纠偏。
- `03-组织器评估清单-态势分析系统.md`：最终产物评估依据，用于检查覆盖度、边界纪律和规格质量。

执行约束：

1. 多轮测试不得把完整样例一次性输入给组织器。
2. 固定 20 回合链路只作为历史回归链路，不作为默认测试策略。
3. 默认测试策略是受控动态考官策略：测试者先回答组织器问题，只有在明显偏离、连续空泛、遗漏已确认事实或过早收束时，才少量引导或纠偏。
4. 每轮输入最多覆盖一个主题，通常不超过 3 条事实；不得一次性释放完整角色表、功能表、流程表、数据表或验收表。
5. 测试报告必须记录本次使用的样例依据、考官动作、组织器响应和最终评估清单结论。
