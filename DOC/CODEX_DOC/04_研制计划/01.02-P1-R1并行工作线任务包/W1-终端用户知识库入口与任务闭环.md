# W1 - 终端用户知识库入口与任务闭环

## 新线程启动提示词

你正在接手 CodeFactoryV2 的 P1 业务知识库重构工作线 W1。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。本线目标是把 P1 从后台运维式原型收敛为面向终端使用者的简洁知识库入口：用户可以创建/选择知识库、上传或选择文档、选择策略包、启动抽取、看到任务运行状态，并进入单文档实时工作台。不要提交 git，不要提交本地数据内容，不要修改治理发布和发布态图谱职责页面。请先阅读 P1 重构设计、接口合同和 R0 骨架，再按本文件边界实现。

## 目标

- 面向终端用户提供“知识库总览 -> 文档清单 -> 启动抽取 -> 查看运行中状态”的闭环入口。
- 弱化 13 个固定阶段的后台感，页面语言以“知识库、文档、策略、抽取进度、结果质量”组织。
- 新建知识库和启动抽取后，不刷新整页即可看到任务进入运行态。
- 能从知识库列表和文档清单进入对应单文档实时抽取工作台。
- 对用户明确区分：机器抽取中、机器已生成发布候选、等待治理确认、正式入库。

## 边界

- 负责前端终端用户入口和必要的轻量 API adapter 对接。
- 可以调整 `/archives`、`/documents`、`/documents/intake` 中属于终端使用链路的 UI 和交互。
- 可以新增 `apps/web/src/features/p1/userFlow` 或类似独立模块。
- 可以在 `apps/web/src/features/p1/contracts` 补充用户流需要的只读类型，但不能破坏已有 R0 合同字段。
- 后端只允许补足用户入口需要的薄 adapter，不在本线重写抽取引擎。

## 输入合同

- `PolicyPackage`
- `PolicyPackageVersion`
- `PolicyRuntimeSnapshot`
- `DocumentRuntimeSnapshot`
- `PublicationCandidateSnapshot`

合同位置：

- `apps/web/src/features/p1/contracts`
- `apps/api/app/archive_knowledge/contracts`
- `DOC/CODEX_DOC/03_规范与流程/01_数据规范/02-P1业务知识库重构接口合同.md`

## 输出合同

- 用户选定的 `archive_id`
- 用户选定的 `document_id`
- 用户选定的 `policy_package_id`
- 抽取启动后冻结的 `PolicyRuntimeSnapshot`
- 可被 W3 消费的 `DocumentRuntimeSnapshot` 入口参数

## 禁止改动范围

- 不修改 `/governance` 发布候选治理确认页的业务职责。
- 不修改 `/graph` 发布态知识图谱浏览页的业务职责。
- 不把候选知识显示为正式入库知识。
- 不把运行中状态写死成前端假状态；没有真实 API 时必须显示 fixture/mock_fallback 标识。
- 不提交 git，不清理或提交 `.data`、`.npm-cache`、本地上传文件、运行产物。

## 建议实现范围

- 新增或整理终端用户视角的 P1 首页卡片：当前知识库、默认策略包、运行中文档、待处理问题、最近结果。
- 文档清单中保留策略绑定、当前运行阶段、质量状态、发布候选状态。
- 启动抽取弹窗中展示策略包版本快照，而不是只展示 13 阶段流程。
- 启动后通过 runtime adapter 进入局部状态更新，不整页刷新。
- 在页面上明确显示数据来源：live / fixture / mock_fallback。

## 验收方式

- 新建知识库后能在列表中出现，并能选择为当前知识库。
- 上传或选择文档后，用户能选择策略包并启动抽取。
- 启动抽取后，页面局部更新为运行中，不需要手动刷新页面。
- 文档清单能进入单文档实时工作台，并携带 `archive_id`、`document_id`、`run_id`。
- 用户能看懂当前状态是抽取中、发布候选待确认还是正式入库。
