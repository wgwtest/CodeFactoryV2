# W6 - 正式输出与系统间接口

## 新线程启动提示词

你正在接手 CodeFactoryV2 的 P1 业务知识库重构工作线 W6。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。本线目标是保证 P1 输出给后续系统的是严格合同化、版本化、只包含治理确认后正式知识的接口，而不是抽取中的临时节点或发布候选。不要提交 git，不要提交本地数据内容，不要重写治理发布页面 UI，不要让候选知识伪装为正式知识。请先阅读 P1 重构接口合同、R0 system output contracts 和 P2/P6 相关接口，再按本文件边界实现。

## 目标

- 明确 P1 对外输出只来自 `PublishedKnowledgeSnapshot`。
- 定义并实现 `P1KnowledgeSupplyExport.v1`，供 P2/P3/P4/P5 等后续系统稳定消费。
- 定义并实现 `P6DisplayExportContract.v2`，供 P6 门户/图谱展示稳定消费。
- 明确候选 API 与正式 API 的差异：候选只能只读预览，不进入正式供应接口。
- 输出合同必须包含版本、来源快照、治理确认信息、API 路径、图谱查询路径。

## 边界

- 负责系统间输出合同、API adapter、导出 fixture 和兼容测试。
- 可以修改：
  - `apps/api/app/archive_knowledge/contracts/system_output.py`
  - `apps/api/app/api/routes/p1_refactor.py`
  - `apps/web/src/features/p1/contracts/systemOutput.ts`
  - `app/requirement_exchange/p1_knowledge_adapter.py` 相关适配，但必须低侵入。
- 不负责治理确认页面本身的 UI 重构。

## 输入合同

- `PublicationCandidateSnapshot`
- `PublishedKnowledgeSnapshot`
- `ArchiveKnowledgeResolutionSnapshot`
- `KnowledgeQualityReport`
- `GraphQualityReport`

## 输出合同

- `P1KnowledgeSupplyExport.v1`
- `P6DisplayExportContract.v2`
- 正式知识读取 API
- 正式图谱查询 API
- 版本与来源追溯信息

## 禁止改动范围

- 不输出未治理确认的候选知识作为正式知识。
- 不直接读取抽取运行中的临时节点给后续系统。
- 不把 `/api/p1/candidates/...` 和 `/api/p1/knowledge-supply/...` 混用。
- 不修改用户入口、策略合同、运行图谱和质量算法。
- 不提交 git，不提交本地数据或导出产物。

## 建议实现范围

- 为正式输出新增 route：`/api/p1/knowledge-supply/read`、`/api/p1/knowledge-supply/graph/query`。
- 为候选输出保留只读 route：`/api/p1/candidates/...`。
- 在输出中携带 `published_snapshot_id`、`formal_version`、`governed_by`、`published_at`。
- 为 P2/P6 adapter 增加 contract_version 校验。
- 兼容旧接口时加 deprecation 标识，不直接删除旧调用。

## 验收方式

- 没有治理确认时，正式输出接口不得返回候选知识。
- 治理确认后，正式输出接口返回 `P1KnowledgeSupplyExport.v1`。
- P6 展示输出能拿到图谱摘要、实体查询、关系查询路径。
- 输出对象能追溯到发布快照和治理确认记录。
