# W4 - 知识质量与图谱质量评测

## 新线程启动提示词

你正在接手 CodeFactoryV2 的 P1 业务知识库重构工作线 W4。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。本线目标是回答“这套知识和图谱为什么可信”：建立知识质量、图谱质量、规则命中解释、质量门禁决策的最小闭环。不要提交 git，不要提交本地数据内容，不要修改终端用户入口、策略版本生成主逻辑和正式发布治理页面。请先阅读 `P1-知识质量与图谱质量保障设计.md`、R0 quality contracts 和 runtime fixtures，再按本文件边界实现。

## 目标

- 定义并实现知识质量指标：概念精度、证据覆盖率、冲突率、重复率、stale 对象数。
- 定义并实现图谱质量指标：关系可信度、孤立节点率、重复关系率、可解释覆盖率、布局可读性。
- 质量报告必须可追溯到规则、输入对象、输出对象、证据锚点。
- 质量门禁决策必须说明：哪条规则、哪个指标、哪个阈值、影响哪些对象、输出什么动作。
- 质量评测结果能被 W3 图谱观察窗和 W6 系统输出判断消费。

## 边界

- 负责后端质量评估服务、质量报告合同、质量门禁解释 adapter。
- 可以新增：
  - `apps/api/app/archive_knowledge/quality`
  - `apps/api/app/archive_knowledge/graph_quality`
  - `apps/web/src/features/p1/quality`
- 可以补充 `KnowledgeQualityReport`、`GraphQualityReport`、`EvaluationRunReport` 字段。
- 不负责大规模 UI 重绘，但要提供最小可读页面/卡片或 adapter。

## 输入合同

- `RuntimeGraphProjection`
- `RuleExecutionRecord`
- `DocumentRuntimeSnapshot`
- `PolicyRuntimeSnapshot`
- `ArchiveKnowledgeResolutionSnapshot`

## 输出合同

- `KnowledgeQualityReport`
- `GraphQualityReport`
- `EvaluationRunReport`
- `QualityGateDecision`
- 可被观察窗使用的 rule_hit/metric_hit 解释对象

## 禁止改动范围

- 不把质量门禁设计成人工复核阶段；本阶段是机器规则执行。
- 不把警告等同于阻断，必须区分 auto_pass、warn_continue、block、defer。
- 不用纯前端假指标替代后端可追溯计算。
- 不覆盖正式知识库。
- 不提交 git，不提交本地数据和评测产物。

## 建议实现范围

- 为 quality report 增加聚合函数：从 runtime graph 和 rule records 计算基础指标。
- 为每个指标提供 explanation：actual、threshold、status、affected_object_ids。
- 为质量门禁增加 decision summary：机器自动放行、警告继续、阻断返回、延迟发布。
- 在 API 中提供 `/api/p1/archives/{archive_id}/runs/{run_id}/evaluation-report` 的真实或半真实 adapter。
- 前端最少展示质量报告卡片和规则命中表。

## 验收方式

- 任一质量指标都能追溯到输入对象或规则记录。
- 质量门禁页面能看出“哪条规则导致警告/阻断/放行”。
- 质量报告能解释知识质量和图谱质量，而不是只显示分数。
- 质量报告不依赖固定 13 阶段，而依赖 runtime/graph/rule contracts。
