# W2 - 策略包版本与规则合同主干

## 新线程启动提示词

你正在接手 CodeFactoryV2 的 P1 业务知识库重构工作线 W2。仓库路径是 `E:\project\Web\智能软件生成\CodeFactoryV2`。本线目标是让策略包版本、阶段执行合同、规则字段合同和 RuleExecutionRecord 真正一一对应，支撑“规则可配置、规则可执行、运行可追溯、变更可重算”。不要提交 git，不要提交本地数据内容，不要修改终端用户 UI、运行图谱 UI、治理发布 UI。请先阅读 P1 重构接口合同和 R0 骨架，再按本文件边界实现。

## 目标

- 明确 `PolicyPackage -> PolicyPackageVersion -> StageExecutionContract -> RuleContract -> RuleExecutionRecord` 主链。
- 每条规则必须声明输入字段、输出字段、判断条件、动作映射、trace 字段、rule_version、rule_hash。
- 策略包版本发布时生成不可变版本快照。
- 规则结构性变更时生成新策略包版本，并能返回影响面所需的变更摘要。
- RuleExecutionRecord 可以被 W3 运行图谱、W4 质量评估、W5 增量重算共同消费。

## 边界

- 负责后端策略合同模型、校验、版本生成和最小 API。
- 负责前端规则字段合同编辑页的数据结构对齐，但不负责大规模 UI 美化。
- 可以修改：
  - `apps/api/app/archive_knowledge/contracts`
  - `apps/api/app/archive_knowledge/policy_config.py`
  - `apps/api/app/api/routes/p1_refactor.py`
  - `apps/web/src/features/p1/contracts`
  - `apps/web/src/features/p1/api`
- 可以补充 `apps/api/tests/test_p1_refactor_api.py` 或新增策略合同测试。

## 输入合同

- `PolicyPackage`
- `PolicyPackageVersion`
- `StageExecutionContract`
- `RuleContract`
- `RuleFieldContract`
- `RuleActionMapping`

## 输出合同

- `PolicyRuntimeSnapshot`
- `RuleExecutionRecord`
- `ImpactSet` 的规则变更摘要部分
- 合同校验结果：`contract_status`、`contract_errors`

## 禁止改动范围

- 不改真实抽取算法输出语义，除非只是接入合同字段。
- 不在规则合同里写 UI 专用字段。
- 不用前端 mock 替代后端合同校验。
- 不把规则变更直接覆盖正式知识库。
- 不提交 git，不提交本地数据、运行快照或上传文件。

## 建议实现范围

- 为 `RuleContract` 增加严格校验函数：必填 input/output/hash/trace/action 字段缺失时返回 invalid。
- 增加策略包版本生成函数：结构性字段变化时递增版本，保留 previous version。
- 增加 RuleExecutionRecord 序列化/反序列化测试。
- 在 API adapter 中暴露策略包版本详情和规则合同详情。
- 让规则字段合同编辑页读取同一份合同类型，而不是页面内重复定义字段。

## 验收方式

- 清空必要 trace 字段时，后端返回 `contract_status=invalid` 和明确错误。
- 修改规则输入/输出/条件/action_mapping 后，会生成新 `policy_package_version_id`。
- RuleExecutionRecord 中包含 `rule_id`、`rule_version`、`rule_hash`、`input_hash`、`output_hash`、`affected_object_ids`。
- 前端规则合同页展示字段与后端合同一致，不再只是规则名称组合。
