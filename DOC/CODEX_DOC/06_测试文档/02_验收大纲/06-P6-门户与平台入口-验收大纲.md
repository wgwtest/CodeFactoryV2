# `P6` 门户与平台入口验收大纲

- 节点编码：`06`
- 节点名称：`P6` 门户与平台入口

## 1. 验收目标

验证 `P6` 是否已经形成平台级入口、只读投影、展示基线和展示实验的最小正式闭环。

## 2. 验收范围

- `P6.1` 首屏观察门户
- `P6.2` 跨阶段只读集成与状态投影
- `P6.3` 设计语言与前端展示基线
- `P6.4` 前端展示工具化实验场

## 3. 前置条件

- 前后端服务可启动
- `/portal` 与 `/observation` 路由可访问
- `platform-config`、`platform-display`、`p6` 路由族可访问

## 4. 必须通过项

- `/portal` 可作为独立平台入口正常加载
- `/observation` 可作为独立串行观察入口正常加载
- 平台只读消费 `P6.2` 投影，不直接写回 `P1 ~ P5`
- 平台基线包、平台路由、平台图例、实验台对象均通过正式接口提供
- `mock` 源已正式接通，`live` 未接通时明确暴露未实现状态

## 5. 条件通过项

- `P6.4` 的实验结果可以形成记录和候选，但首版允许仍使用内存态持久化
- `/observation` 首版以消费观察投影为主，不强制承担实验台主入口

## 6. 非本轮验收范围

- `P6.R1` 统一登录接入
- `P6.R2` 权限与角色控制
- `P1 ~ P5` 真实数据源全面接通
- 全仓前端 build 清零

## 7. 验收入口

- 页面：
  - `/portal`
  - `/observation`
- 接口：
  - `/api/p6/mock-scenarios`
  - `/api/p6/portal-projection`
  - `/api/p6/observation-projection`
  - `/api/platform-config/display-baseline`
  - `/api/platform-config/routes`
  - `/api/platform-config/legend`
  - `/api/platform-display/workbench`
  - `/api/platform-display/experiments`
  - `/api/platform-display/promotion-candidates`

## 8. 判定规则

- 所有必须通过项通过，则节点可判为“通过”
- 存在必须通过项未通过，则节点不可判通过
- 条件通过项未完全满足但不影响主闭环时，可保留为“待优化项”，不阻塞节点通过
