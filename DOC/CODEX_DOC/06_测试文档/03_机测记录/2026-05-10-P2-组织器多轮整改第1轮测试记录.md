# 2026-05-10 P2 组织器多轮整改第 1 轮测试记录

## 1. 测试目的

本轮测试用于启动 `brainstorm-v1` 与 `brainstorm-v1-dify-workflow` 两个组织器的多轮自测整改闭环。测试重点不是验证接口是否能返回 `200 OK`，而是验证组织器在受控动态多轮会话中是否能形成稳定决策、减少重复追问，并在用户明确要求停止追问时交付可审阅的需求规格草案。

## 3. 测试输入

首轮基准输入为：

> 我希望创建一个态势分析系统。这个态势分析系统里面要有态势的展示，要有一系列态势分析工具，比如地理信息分析工具、通视量算、坡度分析，还有部署分析系统。但是当前用户、使用模式我都没有想清楚，希望你来一块帮我想清楚。

后续输入由受控动态考官根据组织器下一问动态生成，覆盖用户角色、软件定位、核心流程、功能项、数据接口、边界范围、非功能、异常验收、回看和强制收束。强制收束输入为：

> 强制停止追问，基于当前所有已确认信息输出完整需求规格说明草案，并列出仍需后续确认事项。

## 4. 过程记录

### 4.1 基线问题复现

第 1 轮初始测试曾复现以下问题：

| 问题 | 证据 | 判断 |
| --- | --- | --- |
| Dify 旧锚点残留 | 输出过 `REQ-3.UI`、`REQ-3.COLLAB`、`REQ-3.ERR` 等旧锚点 | 当前模板锚点未对齐 |
| 部署分析错投影 | “部署分析系统”进入 `5 非功能需求 / 部署与运行环境` | 把功能性“部署分析”误判为部署环境 |
| 边界排除错投影 | “不做自动决策推荐、不做多单位在线协同指挥”进入 `3 功能需求 / 结果输出与共享` | 协同词抢占了边界语义 |
| 混合非功能丢项 | “内网部署、角色权限、操作审计、结果可追溯”只进入安全章节 | 单句枚举未拆分到部署、安全、质量 |
| 收束草案重复堆叠 | 第 11 Turn 草案 patch 使用 `append_or_update`，最终正文出现旧正文和 bullet 草案并存 | 草案分支应替换章节当前展示版本 |

## 7. 结论

1. 第 1 轮发现的 Dify 锚点错位、部署分析错投影、边界错投影、混合非功能丢项和草案重复堆叠，均已在本轮完成整改并复测通过。
2. `brainstorm-v1` 和 `brainstorm-v1-dify-workflow` 均能在受控动态会话中进入 `draft_delivery`，本轮不再存在阻塞性接口错误或收束失败。
3. Dify 组织器仍存在产物质量偏轻的问题，例如部分章节仍为“本章节待确认”，验收准则只沉淀了首条验收事实。这属于下一轮质量提升问题，不是本轮分类投影和草案堆叠阻塞问题。
4. `brainstorm-v1` 的最终草案字数和结构更丰富，但未闭合问题仍较多，下一轮应重点比较两个组织器的“开放问题生命周期”和“成稿信息完整度”。
