## 2. 关键结论

1. 组织器插件以 `orchestrators/<domain>/<plugin>/` 为物理边界，扫描只进入一层 `domain/plugin` 目录。
2. 插件必须同时具备 `manifest.json` 和插件目录内本地 adapter 入口文件。
3. 移除插件目录后，reload 后列表消失，创建会话返回 `unsupported orchestrator`。
4. 恢复插件目录后，reload 后列表恢复，并可重新创建会话。
5. Lab 默认组织器来自发现注册表优先级排序，不再写死为具体组织器 ID。
6. fake `Dify` 仍为预留插件，本轮未接真实 Dify API。
7. 本地 XG 和 fake Dify 均先经 manifest adapter loader 装载；`TurnEngine` 不再拥有本地 XG 四阶段编排。
8. 本地 XG 的四阶段高观测流程由各自插件目录下的 `local_xg_turn_runtime.py` 持有；fake Dify 的内部流转由 workflow 黑盒持有，宿主只依赖统一输入输出合同。
9. 通用插件输出到 P2 `TurnExecutionResult` 的物化逻辑由 adapter 侧 `PluginTurnResultMaterializer` 承担；`TurnEngine` 不再兜底拼装阶段形态字段。
10. 插件 adapter loader 支持插件目录内相对导入；宿主 `apps/api/app/orchestrators/adapters/` 不再保留本地 XG adapter/runtime 实现。
11. 本地 XG 阶段链专用服务已迁入两个本地 XG 插件目录；宿主 `app.requirement_analysis` 不再保留 `turn_stage_*`、`turn_strategy_service` 和 `stage_runtime_context_builder`。
12. fake `Dify` adapter 实现已迁入 `orchestrators/xg/xg-dify-workflow-orchestrator/adapter.py`；宿主 `apps/api/app/orchestrators/adapters/` 不再保留 Dify 组织器实现。
13. 宿主 stage asset resolver 不再硬编码 XG 阶段名；阶段 prompt/schema/adoption 资产由插件阶段计划显式字段选择。
14. 宿主 Provider 层不再按 XG 阶段协议分支归一化；本地 XG 的 Mock 阶段输出生成器已迁入插件目录。

## 4. 插拔验收覆盖

- `test_requirement_analysis_orchestrator_reload_reflects_plugin_directory_changes`
  - 使用临时插件根写入 `xg-reload-test-orchestrator`。
  - reload 前可出现在组织器列表中。
  - 临时移走目录并 reload 后列表为空。
  - 移除后创建会话返回 400。
  - 恢复目录并 reload 后列表恢复。
- `test_repository_plugins_are_discoverable`
  - 验证仓库内三个插件均可被发现。
  - 验证 adapter 入口文件位于各自插件目录内。
- `test_requirement_analysis_lab_runs_local_xg_through_manifest_adapter_loader`
  - 验证本地 XG turn 执行也会经过 manifest adapter loader。
- `test_turn_engine_does_not_dispatch_by_plugin_type_or_adapter_entry`
  - 验证 TurnEngine 主入口不再按 `plugin_type` 或 `adapter_entry` 分发执行路径。
- `test_turn_engine_does_not_own_local_xg_stage_orchestration`
  - 验证 TurnEngine 主入口不包含本地 XG 阶段编排函数和阶段常量。
- `test_turn_engine_source_does_not_materialize_stage_shaped_plugin_results`
  - 验证 TurnEngine 文件中不再保留阶段形态字段兜底物化逻辑。
- `test_plugin_adapter_loader_supports_plugin_local_relative_imports`
  - 验证插件目录内 adapter 可相对导入同目录 helper/runtime。
- `test_local_xg_runtime_is_plugin_local_not_host_owned`
  - 验证本地 XG adapter/runtime 已迁入插件目录，宿主 adapter 目录不再保留本地 XG 实现。
- `test_dify_workflow_adapter_implementation_is_plugin_local`
  - 验证 fake Dify adapter 实现位于 Dify 插件目录内，宿主 adapter 目录不再保留 Dify 组织器实现。
- `test_host_stage_asset_resolvers_do_not_encode_xg_stage_names`
  - 验证宿主 stage prompt/schema/adoption resolver 不再硬编码 XG 阶段资产名。
- `test_host_provider_layers_do_not_branch_on_xg_stage_protocol`
  - 验证宿主 DeepSeek client 与 Provider call service 不再硬编码 XG 阶段协议名。

## 5. 剩余边界

- 不接真实 Dify API。
