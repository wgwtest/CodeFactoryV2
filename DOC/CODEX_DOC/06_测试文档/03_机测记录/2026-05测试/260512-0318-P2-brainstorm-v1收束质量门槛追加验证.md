# 2026-05-12 P2 Brainstorm V1 收束质量门槛追加验证

## 1. 验证背景

本轮五轮测试显示：Dify 工作流组织器五轮均稳定生成 10634 字正文，其中工程需求 6499 字；本地 `brainstorm-v1` 只有第 1 轮超过一万字，其余轮次明显偏短。

为验证本地 `brainstorm-v1` 是否能通过收束阶段 Prompt 强化达到一万字目标，本次追加执行三次单轮收束验证。

## 2. 三次验证结果

| 验证批次 | Prompt 策略 | 完成Turn | 错误数 | 正文字符 | 结果 |
| --- | --- | ---: | ---: | ---: | --- |
| `.run-logs/p2-template-engineering-qualitygate-260512-round1` | 取消 6 条/500 字限制，要求按篇幅目标加厚 | 17 | 1 | 7850 | 第 18 Turn 失败 |
| `.run-logs/p2-template-engineering-qualitygate2-260512-round1` | 要求 8-12 条 patch、单条 900-1400 字 | 17 | 1 | 8337 | 第 18 Turn 失败 |
| `.run-logs/p2-template-engineering-qualitygate3-260512-round1` | 过程累计正文为主，收束阶段只输出 4-6 条、单条 600-800 字有限补齐 | 18 | 0 | 9178 | 第 18 Turn 成功 |

前两次失败的后端错误均为：

```text
Unterminated string starting at ...
```

该错误来自 provider 返回的 JSON 字符串中途截断，不是章节锚点错误，也不是模板解析错误。

## 3. 根因判断

本地 `brainstorm-v1` 的收束阶段仍通过大模型一次性返回结构化 JSON。若要求它在单次 `document_patch.content` 中承载过长正文，模型即使理解了篇幅目标，也容易生成超出稳定 JSON 返回边界的内容，导致响应截断和后端 400。

因此，单靠“请多写、写到一万字”不是稳定方案。可行边界是：

1. 正文厚度主要靠前序多轮交互持续累计。
2. 收束阶段只做结构补齐、工程需求重点补厚、待确认事项归档。
3. 单条 `document_patch.content` 必须受控，避免产生超长 JSON 字符串。
4. 若要稳定达到一万字，应增加独立的分段成稿或扩写阶段。

## 4. 当前结论

追加验证后，本地 `brainstorm-v1` 已经能在第 18 Turn 完成收束，不再出现 400；最终正文 9178 字，接近一万字但未达到目标。

这说明当前 Prompt 调整修复了“收束阶段 JSON 截断”的问题，但没有彻底解决“本地组织器稳定一万字成稿”的问题。若下一轮继续优化，应从流程设计上新增分段成稿机制，而不是继续扩大单次 provider JSON 输出。
