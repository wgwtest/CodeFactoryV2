## 3. 最终生成正文

### 1. REQ-1.1 1.1 编写目的

本文档旨在明确态势分析系统的需求规格，为后续设计、开发和验收提供依据。软件名称待确认，背景领域待确认。

### 2. REQ-1.2 1.2 适用范围

第一阶段适用范围：本系统第一阶段不接入实时多源情报，不提供自动决策推荐，不承诺高精度测绘级或工程级计算，不实现多单位在线协同指挥。分析结果仅作为辅助判断依据。

### 3. REQ-2.1 2.1 软件定位

本软件定位为面向科研分析和业务验证的态势分析软件，兼具态势展示、地图图层管理、空间分析计算和成果输出能力。具体应用领域待确认。

### 4. REQ-2.2 2.2 建设目标

第一阶段建设目标：形成从数据加载、态势展示、分析计算、结果复核到成果导出的闭环。后续阶段目标待确认。

### 5. REQ-2.3 2.3 使用场景

系统按三类场景组织使用：
- 任务前区域研判：分析人员新建工程、选择坐标系，加载底图、DEM、影像、矢量、任务区域、禁限区和部署点位，创建或编辑标绘对象，进行地形分析和态势评估。
- 任务中态势变化辅助分析：在任务执行过程中，分析人员根据实时或近实时数据更新，选择量算、坡度坡向、高程剖面、通视或部署分析工具，输入观察点、目标点、分析半径、时间、地形数据等参数，系统执行计算并生成图层、表格、剖面图或风险提示。
- 部署方案可行性检查：分析人员利用部署分析工具，结合地形和态势数据，评估部署方案的可行性，输出风险提示和专题图件。
操作流程：用户新建工程→加载数据→选择分析工具→输入参数→系统计算→生成成果→保存工程→导出专题图件和报告→业务专家复核。
（暂定：三类场景的具体触发条件和频率待确认；各角色在流程中的具体参与环节待确认。）

### 6. REQ-2.4 2.4 范围边界

第一阶段范围边界：
- 不作为正式指挥决策系统。
- 不提供自动决策推荐、火力分配、最优部署求解或跨单位实时协同指挥。
- 不纳入实时多源情报接入。
- 不承诺高精度测绘级或工程级计算。
以上排除项不影响已确认的态势展示、地图图层管理、空间分析计算和成果输出等核心能力。

### 7. REQ-3.1 3.1 接口需求

3.1 接口需求

第一阶段接口需求以文件导入导出和内网数据加载为主，不涉及实时接口或在线服务。

输入接口：
- 底图服务或底图文件
- DEM/DSM地形数据
- 遥感影像
- 矢量图层
- 任务区域
- 禁限区
- 部署点位
- 观察点
- 目标点
- 人工标注文件

候选输入格式：GeoJSON、Shapefile、GeoPackage、GeoTIFF、CSV、XLSX、工程包（具体格式待确认）。

输出接口：
- 态势工程包
- 专题图件
- 分析结果图层
- 结果参数表
- 审计记录
- 简化研判报告

### 8. REQ-3.2 3.2 功能需求

7. 结果管理、复核和成果输出模块：由科研分析人员和参谋分析员使用。输入分析结果（结果图层、结果表、参数记录、剖面图、风险清单、说明片段）及查询条件（工程、任务、时间、工具类型、操作者、复核状态）。系统支持结果显示、隐藏、重命名、复制、删除、锁定、复核标记和版本对比；支持按多维度查询；导出成果包括PNG或PDF专题图、CSV或XLSX结果表、Markdown或PDF简要报告、GeoJSON或GeoPackage候选结果图层和审计记录。报告内容包含任务背景、输入数据来源、坐标系、参数、算法或规则说明、结果摘要、风险提示、适用限制、复核意见和导出时间。业务专家只能复核和批注意见，不能修改原始参数和历史结果。异常包括导出格式不支持、文件写入失败、查询条件不合法。验收要求：查询结果准确，导出文件格式正确可打开，报告内容完整，业务专家无法修改原始数据。

### 20. REQ-7.1 7.1 验收场景

7.1 验收场景

系统验收应覆盖以下六条任务链：

1. 安装初始化链路：管理员在内网环境完成部署、初始化账号、配置基础图层目录、配置默认算法参数、查看日志目录和备份目录。
2. 工程创建链路：分析员新建工程、加载底图、DEM、影像、矢量和业务对象，保存后重新打开。
3. 空间分析链路：完成距离面积量算、坡度坡向、高程剖面、通视分析和部署影响分析。
4. 异常链路：模拟坐标系不一致、DEM缺块、权限不足、保存失败和导出失败。
5. 成果输出链路：导出专题图、结果表和简要报告。
6. 安全审计链路：检查登录、数据导入、参数修改、分析执行、保存、删除、导出和权限调整日志。
