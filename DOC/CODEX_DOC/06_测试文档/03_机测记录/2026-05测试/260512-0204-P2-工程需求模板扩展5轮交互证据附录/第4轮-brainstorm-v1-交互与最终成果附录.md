## 3. 最终生成正文

### 1. REQ-2.1 2.1 软件定位

本软件定位为面向科研分析和业务验证的态势分析软件，兼具态势展示、地图图层管理、空间分析计算和成果输出能力。系统旨在为用户提供综合性的态势感知与空间分析能力，辅助用户进行科研分析与业务验证，不作为正式指挥决策系统。分析结果仅作为辅助判断，不构成正式决策依据。

### 2. REQ-2.2 2.2 建设目标

第一阶段建设目标为形成从数据加载、态势展示、分析计算、结果复核到成果导出的闭环。具体包括：
1. 实现多源态势数据的加载与可视化展示。
2. 提供地图图层管理功能。
3. 提供空间分析计算工具（如通视量算、坡度分析、部署分析等）。
4. 支持分析结果的复核与成果导出。

### 3. REQ-2.3 2.3 使用场景

本软件的使用场景按任务前区域研判、任务中态势变化辅助分析、部署方案可行性检查三类组织。

1. 任务前区域研判：用户新建工程并选择坐标系，加载底图、DEM、影像、矢量、任务区域、禁限区和部署点位，创建或编辑标绘对象，进行区域地形和态势的初步分析。
2. 任务中态势变化辅助分析：用户选择量算、坡度坡向、高程剖面、通视等分析工具，输入观察点、目标点、分析半径、时间、地形数据等参数，系统执行计算并生成图层、表格、剖面图或风险提示，辅助用户实时掌握态势变化。
3. 部署方案可行性检查：用户使用部署分析工具，输入部署点位和相关参数，系统评估部署方案的可行性并生成风险提示，用户保存工程、导出专题图件和简要报告，业务专家复核后形成记录。

用户角色包括：
- 科研分析人员/参谋分析员：创建态势工程、加载数据、执行空间分析、导出成果。
- 业务专家：复核结果并给出意见。
- 数据管理员：维护基础地理数据、专题图层、DEM和影像。
- 系统管理员：负责账号、角色权限、日志审计、模板、默认参数和运行配置。
- 普通查看者：只查看态势、结果摘要和报告，不允许修改工程和参数。

【待确认】具体应用领域（如军事、应急、城市规划等）待后续确认。

### 4. REQ-2.4 2.4 范围边界

本软件第一阶段的功能范围包括态势展示、地图图层管理、空间分析计算和成果输出。明确不包含以下功能：
- 自动决策推荐
- 火力分配
- 最优部署求解
- 跨单位实时协同指挥
- 实时多源情报接入
- 高精度测绘级或工程级计算

【待确认】具体应用领域和用户角色待后续确认。

### 6. REQ-3.2 3.2 功能需求

4. 基础量算模块：由科研分析人员或参谋分析员使用。输入点、线、面、坐标、数字高程模型（DEM）和地图比例尺。系统计算距离、面积、坐标、高程、坡度坡向和高程剖面结果，输出结果需附带单位、坐标系、输入对象编号和计算时间。异常处理：当输入参数不合法时提示用户修正。
5. 通视与可视域分析模块：由科研分析人员或参谋分析员使用。输入观察点、目标点、观察高度、目标高度、分析半径、地形数据和遮挡参数。系统计算两点通视、多点通视和可视域范围，输出可视或不可视结论、遮挡位置、剖面图、可视域栅格或矢量结果图层。异常处理：当DEM缺块时提示“DEM数据缺失，请补充”；当分析半径过大时提示“分析半径超出有效范围，请缩小半径”；当点位无高程时提示“所选点位缺少高程数据，请检查”；当参数不合法时提示“参数不合法，请检查输入”。
6. 部署分析模块：由科研分析人员或参谋分析员使用。输入部署点、任务区域、禁限区、影响半径、覆盖规则和冲突规则。系统计算覆盖范围、冲突位置、影响范围和可行性辅助提示，输出风险清单、冲突对象、影响范围图层和说明片段。系统不输出自动最优部署方案。异常处理：当输入参数不合法时提示用户修正。
【待确认】基础量算中“输入对象编号”的具体含义和来源待确认；通视分析中“遮挡参数”的具体内容待确认；部署分析中“覆盖规则”和“冲突规则”的具体定义待确认。
7. 结果管理、复核和成果输出模块：由科研分析人员或参谋分析员使用。分析结果保存为结果图层、结果表、参数记录、剖面图、风险清单和说明片段。支持按工程、任务、时间、工具类型、操作者和复核状态查询。支持对结果执行显示、隐藏、重命名、复制、删除、锁定、复核标记和版本对比。导出成果包括PNG或PDF专题图、CSV或XLSX结果表、Markdown或PDF简要报告、GeoJSON或GeoPackage候选结果图层和审计记录。报告需要包含任务背景、输入数据来源、坐标系、参数、算法或规则说明、结果摘要、风险提示、适用限制、复核意见和导出时间。业务专家只能复核和批注意见，不能修改原始参数和历史结果。

### 7. REQ-3.3 3.3 性能需求

3.3 性能需求

系统性能指标按场景量化如下：
- 地图浏览、缩放、平移、对象选中和图层开关：在普通数据规模下，响应时间目标小于2秒。
- 属性查询和常规坐标读取：响应时间小于2秒。
- 距离面积量算、坐标查询：响应时间小于5秒。
- 坡度坡向分析、高程剖面分析和两点通视分析：响应时间小于30秒。
- 大范围可视域分析和部署影响分析：允许1到3分钟完成，并显示进度提示。

第一阶段并发目标：支持30个并发用户，5个并发复杂分析任务；超出时任务排队或提示用户等待。

【待确认】'普通数据规模'的具体量级（如数据量、图层数、要素数）待后续定义。

### 8. REQ-3.4 3.4 安装和操作要求

3.4 安装和操作要求

系统安装和操作应满足以下要求：

1. 部署与初始化配置：
   - 提供服务器端部署包，包含前端访问入口、初始化脚本、默认管理员账号。
   - 支持基础图层目录配置、算法参数默认值配置、日志目录配置、备份目录配置和导出目录配置。

2. 管理员界面维护：
   - 管理员应能在界面中维护用户、角色、默认参数、模板、字典、系统日志和数据目录。
   - 管理员不应通过直接编辑配置文件完成上述维护操作。

3. 普通分析员操作方式：
   - 普通分析员不应直接编辑配置文件。
   - 应通过界面完成工程创建、数据加载、工具选择、参数调整、结果查看、保存和导出。

4. 升级保留策略：
   - 系统升级时应保留工程文件、用户权限、参数配置、日志和历史结果。

【待确认】部署包的具体格式或分发方式、初始化脚本的执行时机和内容、默认管理员账号的初始密码策略、升级保留的具体机制待后续明确。

### 9. REQ-3.5 3.5 业务规则与异常补偿

3.5 业务规则与异常补偿

系统应处理以下异常场景，并在异常发生时给出原因、影响范围、可恢复动作和是否需要人工复核：

1. 数据缺失：当所需数据文件或数据源缺失时，提示用户检查数据源并重新加载。
2. 坐标系不一致：当加载的数据坐标系与工程坐标系不一致时，提示用户确认坐标系转换或重新选择。
3. 计算失败：当分析计算过程中出现错误时，提示用户计算失败原因并建议重试。
4. 保存失败：当工程或结果保存失败时，提示用户检查存储空间和权限，并建议另存或重试。
5. 权限不足：当用户尝试执行无权限的操作时，提示用户权限不足并联系管理员。
6. 导出失败：当导出专题图、报告等成果失败时，提示用户检查导出路径和格式，并建议重试。
7. 实时数据中断：当实时数据源中断时，提示用户数据中断并检查网络连接。
8. DEM缺块：当DEM数据缺失时，提示用户补充DEM数据。
9. 参数不合法：当用户输入的参数不合法时，提示用户修正参数。
10. 任务超时：当分析任务执行超时时，提示用户任务超时并建议优化参数或缩小范围。
11. 外部服务不可用：当依赖的外部服务不可用时，提示用户服务不可用并等待恢复。

【待确认】各异常场景的具体触发条件和可恢复动作细节待后续细化。

### 15. REQ-6.1 6.1 安全与权限

6.1 安全与权限

系统采用基于角色的访问控制（RBAC），用户角色及权限如下：

1. 科研分析人员/参谋分析员：
   - 创建、编辑、删除态势工程
   - 加载、卸载数据（底图、DEM、影像、矢量等）
   - 执行空间分析（量算、坡度坡向、高程剖面、通视、部署分析）

   - 查看态势工程和成果

   - 不可修改工程和参数

   - 维护基础地理数据、专题图层、DEM和影像
   - 管理数据版本和更新

4. 系统管理员：
   - 管理用户账号和角色权限
   - 审计日志
   - 配置模板、默认参数和运行配置

5. 普通查看者：
   - 查看态势、结果摘要和报告
   - 不允许修改工程和参数

【待确认】具体权限粒度（如是否允许科研分析人员删除工程）待后续细化。
业务专家权限：只能复核和批注意见，不能修改原始参数和历史结果。
6.1 安全与权限

系统安全机制包括：
- 基于角色的访问控制（RBAC），用户角色及权限详见2.3使用场景。

- 操作审计：记录所有用户的关键操作，包括登录、工程操作、分析执行、导出等。

### 17. REQ-7.1 7.1 验收场景

7.1 验收场景

系统验收按以下六条任务链组织：

1. 安装初始化链路：管理员在内网环境完成部署、初始化账号、配置基础图层目录、配置默认算法参数、查看日志目录和备份目录。
2. 工程创建链路：分析员新建工程、加载底图、DEM、影像、矢量和业务对象，保存后重新打开。
3. 空间分析链路：完成距离面积量算、坡度坡向、高程剖面、通视分析和部署影响分析。
4. 异常链路：模拟坐标系不一致、DEM缺块、权限不足、保存失败和导出失败。
5. 成果输出链路：导出专题图、结果表和简要报告。
6. 安全审计链路：检查登录、数据导入、参数修改、分析执行、保存、删除、导出和权限调整日志。

### 18. REQ-7.2 7.2 验收准则

7.2 验收准则

1. 安装初始化链路：普通用户能登录并看到授权菜单，管理员能维护用户和参数。
2. 工程创建链路：图层、对象、坐标系、参数和版本说明均恢复。
3. 空间分析链路：结果带单位、参数、来源和适用限制。
4. 异常链路：系统提示原因、影响范围和可恢复动作。
5. 成果输出链路：输出物可打开、内容完整、带水印或标识、可追溯。
6. 安全审计链路：越权被阻断且关键操作可追溯。
