### 6.2 发现的问题

#### 问题一：下一问重复严重，焦点迁移不稳定

在 20 轮中，下一问高度重复：

- `核心数据接入和主要分析流程是什么？` 共出现 3 次
- `这些分析能力有哪些明确不做的范围、异常处理或验收口径？` 共出现 7 次
- `是否继续补充核心流程、边界范围、非功能要求或验收准则？` 共出现 8 次

这说明：

1. workflow 虽然能持续吸收事实，
2. 但对“当前最高价值缺口”的重新评估不稳定，
3. 容易在长轮次中回退到少数几个宽泛追问模板。

#### 问题二：回看/审计型意图处理不足

第 18 轮输入为：

```text
请回看一下，哪些关键决策已经闭合，哪些还没闭合，不要急着写全文。
```

系统返回：

- `assistant_message`：`本轮输入尚不足以稳定写入正文，我先保留为待澄清信息。`
- `document_patch`：0
- 下一问：`请继续补充一个可以写入需求规格说明的事实，例如用户、场景、流程、边界或验收口径。`

这表明当前 workflow 对“回看总结”类输入没有单独处理路径，而是退回到通用“继续补事实”逻辑。

#### 问题三：未闭合问题管理不干净

最终仍保留两条 open question：

1. `可以补齐：组织器策略问题：请先确认软件名称、背景领域和编写目的。`
2. `请继续补充一个可以写入需求规格说明的事实，例如用户、场景、流程、边界或验收口径。`

第二条实际上来自第 18 轮的兜底追问，到了第 19、20 轮仍未清理，属于**阶段性问题未被关闭或替换**。

#### 问题四：章节分类仍有漂移

最终草案虽已形成 7 个章节块，但部分事实归类仍不够稳：

1. `导出形式`、`精度口径` 被并入 `3 功能需求 / 核心业务流程`
2. `主要界面列表` 被并入 `4 非功能需求 / 性能与可靠性`
3. 协同能力的正向要求没有稳定沉淀成明确章节内容，只保留了“不做强实时多人共编”的负向边界

这说明 workflow 现在的语义映射规则能覆盖大类章节，但对子主题的落点仍偏粗。

#### 问题五：最终草案对起始目标与协同模式整合不足

最终章节内容中：

- `1 总则 / 编写目的` 只有 `待确认。`
- “中协同，支持分析结果共享、任务接力编辑和批注”没有被完整吸收

这说明：

1. workflow 对“总体目的/背景”的总结能力偏弱；
2. 对中途补充的协同模式没有形成稳定章节化表达。

## 8. 问题归因判断

本轮没有发现新的平台合同问题，问题主要集中在 **Dify workflow 内部决策质量**，而不是 `P2` 宿主侧。

归因判断如下：

| 问题 | 更可能的归因层 |
| --- | --- |
| 下一问高度重复 | Dify `next_interaction_planning` 节点 |
| 回看类意图未单独处理 | Dify `intent_understanding` / 分支策略 |
| open question 清理不干净 | Dify `decision_state_delta` / `normalize_output` |
| 子主题章节漂移 | Dify `document_projection` 规则 |
| 总则长期空白 | Dify `draft_compose` 总结策略 |

## 9. 建议整改项

### 9.1 Dify 侧

1. 为“回看/总结/哪些已闭合”增加独立意图与输出路径。
2. `next_interaction_planning` 增加去重约束，避免同一宽泛问题反复出现。
3. `decision_state_delta` 在新事实进入后要清理被替代的旧兜底问题。
4. `document_projection` 增强对子主题的映射：
   - 导出形式
   - 精度口径
   - 协同模式
   - 主要界面列表
5. `draft_compose` 增加对总则/编写目的的最低限度概括，不要长期只输出 `待确认。`

### 9.2 P2 侧

当前 P2 物化层已通过本轮验证，没有发现新的合同消费错误。短期不建议为这几个质量问题继续修改平台逻辑，应优先调整 Dify workflow。

## 10. 结论

本轮 20 turn 深测结论如下：

1. **链路层面已通过**
   真实 Dify 调用、patch 物化、working document 承载、最终收束成稿均可工作。

2. **质量层面仍有明显问题**
   长轮次下的下一问重复、回看型意图处理不足、问题清理不干净、章节分类偏粗、总则总结能力偏弱。

3. **优先整改方向明确**
   后续应优先修改 Dify workflow 内部节点和规则，而不是继续改 P2 平台。
