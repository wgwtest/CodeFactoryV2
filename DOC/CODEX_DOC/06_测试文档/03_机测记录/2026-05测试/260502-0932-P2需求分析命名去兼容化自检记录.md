## 1. 本轮目标

按当前用户要求，彻底去除 P2 需求分析模块中的早期旧称和兼容口径：

- 不保留旧路由。
- 不保留旧包路径。
- 不保留旧测试入口。
- 不保留过渡门面、过渡路由或过渡命名层表述。
- 现行代码、测试、目标设计说明统一只使用 `RequirementAnalysis` / `requirement-analysis` 命名。

## 2. 发现的问题

本轮自检先扫描当前代码、测试和现行设计文档，发现 5 类问题：

1. 前端页面 import 仍错误引用 `../lib/requirement-analysis`，与现有文件 `requirementAnalysis.ts` 不一致。
2. 强规则组织器 runner 默认模型名仍残留早期旧称。
3. 前端测试会话 id 仍使用早期旧称样例值，导致测试数据口径不统一。
4. `RequirementAnalysisTurnOutputService` 默认提示仍使用过渡协议措辞。
5. 当前目标设计文档、重构说明和 XG 组织器包规范仍把早期旧称路由、包路径、测试文件写成现行实现。

另发现 1 个真实运行问题：

6. `test_requirement_analysis_api.py` 通过 `app.requirement_analysis.deepseek_client.settings` 做 monkeypatch，但 `deepseek_client.py` 未显式暴露 `settings`，导致 2 个后端测试失败。

## 3. 修复内容

### 3.1 代码与测试修复

- 修正 `RequirementAnalysisLabPage.tsx` import，统一引用 `../lib/requirementAnalysis`。
- 将 `xg-strong-rule-orchestrator/runner.py` 的默认模型名统一为 `mock-requirement-analysis-v1`。
- 将前端测试中的会话 id 从早期旧称样例值统一改为 `ra-airspace-001`。
- 将 `RequirementAnalysisTurnOutputService` 中的过渡协议措辞改为“按当前 Turn 协议生成下一轮引导”。
- 在 `apps/api/app/db/models/__init__.py` 导出 `RequirementAnalysisSession`，保持模型边界一致。
- 在 `apps/api/app/requirement_analysis/deepseek_client.py` 显式导入 `settings`，恢复 monkeypatch 测试链。

### 3.2 现行文档口径修复

已修正文档：

- `P2-需求分析系统设计.md`
- `P2-需求分析系统设计-260502-0205-现状到目标架构重构补充.md`
- `P2-需求分析系统设计-260502-0022-XG-Orchestrator组织器包规范设计.md`
- `260502-0244-P2后端目标架构首轮重构自检记录.md`

修正内容包括：

- 现行 API 路由统一改为 `/api/requirement-analysis/*`。
- 现行后端服务路径统一改为 `apps/api/app/requirement_analysis/*`。
- 现行组织器运行时统一改为 `apps/api/app/orchestrators/*`。
- 现行测试入口统一改为 `test_requirement_analysis_api.py`。
- 删除“过渡门面”“过渡路由”“后续淡出早期旧称”等会误导实现继续保留旧层的表达。
