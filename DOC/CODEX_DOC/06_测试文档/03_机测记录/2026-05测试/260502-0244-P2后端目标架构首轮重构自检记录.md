## 1. 本轮目标

按 `P2-需求分析系统设计.md` 的目标态后端分层，推进首轮结构性重构：

- 拆分需求规格编写模块的正文渲染、批注、缺口检查和冻结包生成能力。
- 新增 `requirement_analysis` 包，承接需求分析会话、Turn 引擎、输入归一化、输入关系判断、完成度树、过程产物、审计链和 Provider 调用。
- 新增 `orchestrators` 基础包，装载组织器包并由 Host 组装 Provider prompt。
- 将强规则组织器接入本地 runner 入口，避免组织器策略继续停留在应用服务硬编码分支中。
- 删除早期旧称路由、包路径和测试入口，统一到 `requirement_analysis` 命名。

## 5. 结论

本轮完成了 P2 后端目标架构的首轮模块化重构，并完成需求分析模块的旧命名清理。

自检中发现并修复 1 个新增问题：

- `DeepSeekRequirementAnalysisClient.run_turn` 调用 `json.loads` 但缺少 `json` 导入。已补充导入，并新增无网络单元测试覆盖 JSON 响应解析和输出归一化。

后续未完成项集中在更深层的命名和接口迁移：

- `RequirementAnalysisSessionService` 仍是较大的应用服务门面，但核心职责和会话仓储已经下沉到独立服务；下一轮可继续拆分配置服务和会话编排。
- 历史设计草案和历史机测记录仍可能包含旧称，这些内容只可作为演进背景，不再代表现行接口与实现。
