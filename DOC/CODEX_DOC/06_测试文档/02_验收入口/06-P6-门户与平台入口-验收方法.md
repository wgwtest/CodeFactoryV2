## 3. 操作步骤

1. 打开 `/portal`，确认页面不是主壳层菜单页，而是独立门户页。
2. 打开 `/observation`，确认页面不是空白页，而是独立串行观察页。
3. 依次访问 `display-baseline / routes / legend`，确认三者均返回正式配置。
4. 访问 `mock-scenarios / portal-projection / observation-projection`，确认读侧投影接口均可返回。
5. 回到 `/portal`，点击小型 `卡片配置` 按钮，确认实验台可打开。
6. 在实验台中执行一次实验登记，确认它形成实验记录，而不是直接改写阶段事实。
7. 全程确认当前页面和接口都处于 `mock` 模式，不把任何结果解释为 `live` 已接通。

## 4. 通过标准

- `/portal` 与 `/observation` 都能稳定打开。
- 平台配置、读侧投影、实验台三类正式接口都能访问。
- 实验台可用，但不会直接写回 `P1 ~ P5` 阶段事实。
- `mock` / `live` 边界清楚，没有伪装。

## 5. 失败时记录

- 哪个页面或接口失败。
- 失败现象是否稳定复现。
- 是否影响 `P6.1 / P6.2 / P6.3 / P6.4` 中的某个子节点。
