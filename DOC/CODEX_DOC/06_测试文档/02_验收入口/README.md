## 0. 在当前文档体系中的位置

`02_验收入口/` 是 `CodeFactoryV2` 当前正式人工验收入口层。

相关上位入口：

1. [CODEX_DOC README](../../README.md)
2. [00-本地工程策略映射](../../00-本地工程策略映射.md)

## 1. 目录规则

`验收入口/` 后续固定按“总入口 + 节点验收方法 + 历史归档”的方式维护。

这里的“当前有效”指：

1. 有明确 `WBS` 节点或明确 `SETTING` 治理身份
2. 用户下一轮会直接打开执行或直接回查
3. 仍然代表当前项目真实验收入口

不满足以上条件的旧入口，统一移动到：

1. [99_历史归档](./99_历史归档/)

## 1.1 当前集中验收入口

如果要集中验收当前 `P6` 工作，固定从以下顺序进入：

1. [00-验收主入口](./00-验收主入口.md)
2. 直接打开对应节点的 `验收方法`
3. 完成后回写对应 `人测记录 / 验收结论`

如果当前节点尚未开始人工执行，则直接查看对应 `验收方法`、`人测记录` 和 `验收结论` 的待执行状态。

## 1.2 生成与刷新规则

`00-验收主入口.md` 不是静态说明页，而是必须按固定流程刷新的正式人工验收总入口。

当前工程固定要求：

1. 用户提出“我要验收”“更新验收入口”“给我待验收列表”时，必须先刷新或至少复核 `00-验收主入口.md`，再把路径发给用户。
2. 每个当前活跃节点都应存在一份 `*-验收方法.md`，且可直接执行。
3. `验收方法` 必须写清前置条件、测试入口、操作步骤、通过标准和回写位置。
4. 人工验收的真实执行文档不是导览页，而是 `验收方法`。

## 4. 使用约束

从现在开始：

1. `00-验收主入口.md` 只负责告诉用户从哪开始。
2. 真正承载“怎么测”的文档统一叫 `验收方法`。
3. `人测记录` 只记录事实，不能替代 `验收方法`。
4. `验收结论` 只记录判断，不能替代 `验收方法`。
