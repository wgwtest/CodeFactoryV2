- 页面：
  - `http://127.0.0.1:5182/portal`
  - `http://127.0.0.1:5182/observation`
- 接口：`http://127.0.0.1:8050/api/p6/mock-scenarios`

## 3. 操作步骤

1. 访问 `mock-scenarios`，确认存在 `baseline / review-pressure / delivery-gap` 三个场景。
2. 打开 `/portal`，确认可见当前场景或场景切换能力。
3. 打开 `/observation`，确认其消费的场景目录与 `/portal` 一致。
4. 如实验台也显示场景相关信息，确认与前两者共用同一套场景目录。
5. 全程确认页面或接口明确说明当前读源为 `mock`。

## 4. 通过标准

- 三个正式场景存在。
- 门户页、观察页和实验台共用同一套场景目录。
- `mock` 身份清楚，不伪装成 `live`。

## 5. 失败时记录

- 哪个页面与接口场景目录不一致。
- 哪个场景缺失或表现异常。
