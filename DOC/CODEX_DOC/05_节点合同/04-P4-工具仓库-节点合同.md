# `P4` 工具仓库节点合同

- 节点编码：`04`
- 节点名称：`P4` 工具仓库
- 节点类型：包节点合同

## 1. 工作目标

建设 `P4` 作为软件工厂的工具资产运行中台，使其能够：

- 管理工具、组件、执行器等资产定义与验证状态
- 承接 `P3` 工具需求单并完成匹配、审定和供给
- 运行工具池自演进巡检闭环
- 向 `P5` 提供可查询、可获取的供给结果出口

## 2. 工作内容

- 建立 `P4.1` 工具资产与验证工作台
- 建立 `P4.2` 输入工序链闭环
- 建立 `P4.3` 自演进巡检闭环
- 建立 `P4.4` 统一运行语义、数据快照与投影模型
- 建立 `P4.5` 真实最小工具交付闭环
- 固化 `P3 -> P4 -> P5` 的契约边界

## 3. 潜在难点

- 需要保证 `P4` 通过标准契约与上游耦合，而不读内部工作态
- 需要区分内部自演进修订与来自 `P5` 的业务供给缺口
- 需要保证页面查询不反向驱动后台推进
- 需要把工具池、输入链和巡检链统一到同一套运行语义

- 打开 `/xx-p4`，确认 `P4` 工作台入口可达
- 验证工具仓库、输入工具链、自演进巡检、真实工具交付和总览工作区可达
- 验证 `/api/tool-hub/*` 路由族可受理工单、返回供给结果和运行态投影
- 验证 `P4` 对 `P5` 暴露的是查询/获取接口，而不是内部写入入口
- 验证 `P4.5` 真实工具交付链能形成 manifest、产物版本和验证报告
