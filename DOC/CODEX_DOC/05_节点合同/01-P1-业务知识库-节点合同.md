# `P1` 业务知识库节点合同

- 节点编码：`01`
- 节点名称：`P1` 业务知识库
- 节点类型：包节点合同

## 1. 工作目标

建设 `P1` 作为软件工厂主链的知识入口与发布态知识底座，使其能够：

- 受控接入业务资料并形成结构化解析结果
- 生成可治理、可追溯的候选知识与正式抽取产物
- 完成人工治理、发布、版本管理与审计留痕
- 提供已发布知识查询、图谱与流程浏览能力
- 向 `P2` 暴露稳定的业务元素与证据回溯出口

## 2. 工作内容

- 建立 `P1.1` 功能验证平台底座
- 建立 `P1.2` 文档接入与结构化解析能力
- 建立 `P1.3` 候选知识抽取与文档级正式产物仓
- 建立 `P1.4` 知识治理、审核、发布与审计能力
- 建立 `P1.5` 已发布知识仓、查询与图谱展示能力
- 固化 `P1 -> P2` 标准业务元素出口

## 3. 潜在难点

- 需要严格区分正式抽取链与预览/调试链，避免隐式降级
- 需要保证候选知识、发布态知识和文档级正式产物仓之间的边界清晰
- 需要保证发布态知识可回溯到文档、章节、片段和执行元数据
- 需要保证 `P1` 对下游暴露的是标准成果物，而不是内部中间态

## 7. 验收方法

- 打开 `/p1`，确认新版业务知识库入口可达，并能进入 `/p1/archives/:archiveId/*` 工作区
- 在新版工作区检查资料接入、策略规则、抽取运行、质量图谱、知识成果、发布输出和系统间输出模块是否可达
- 打开 `/documents`，确认资料接入与解析入口可达
- 打开 `/archives`，确认知识库管理入口可达
- 打开 `/governance`，确认治理、审核与发布入口可达
- 打开 `/graph`，确认发布态知识浏览与图谱入口可达
- 验证 `P1` 对下游暴露标准业务元素，而不是未治理中间态
- 验证当前发布态知识是否具备可定位证据、定义摘要、库级归并和质量报告；若仍只有候选浏览能力，应标记为知识质量待补强
- 对照 `P1` 设计说明中的当前 API 面，确认 `/api/archives/*`、`/api/knowledge/archive/*`、`/api/p1/*` 哪些是 live 运行接口，哪些仍是 preview / fixture / deprecated 合同接口
- 对照当前前端公开类型，确认摘要和发布概览仍以 `document_count / entity_count / event_count / process_count` 为主，不把未实现的一等对象计数写入验收结论
- 对照：
  - `DOC/CODEX_DOC/06_测试文档/01_验收大纲/01-P1-业务知识库-验收大纲.md`
