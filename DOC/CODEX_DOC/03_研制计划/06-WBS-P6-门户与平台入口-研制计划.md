# WBS-P6 平台门户、观察与前端展示实验层研制计划

## 1. 节点目标

建设平台首屏观察层、跨阶段只读集成层、设计语言统一层和前端展示工具化实验层，为 `P1 ~ P5` 提供统一观察与前端表达验证环境。

## 2. 当前边界

`P6` 负责：

- 首屏观察门户
- `P1 ~ P5` 的只读状态集成与投影
- 平台级设计语言与前端展示基线
- 前端展示工具化实验与验证

不负责：

- 替代任一业务子系统
- 承担 `P1 ~ P5` 内部业务逻辑
- 对 `P1 ~ P5` 反写数据或驱动业务命令
- 在当前阶段优先实现完整登录与复杂权限体系

## 6. 子节点拆解

### 6.1 `P6.1` 首屏观察门户

负责：

- 独立路由 `/portal`
- 蓝图画布、节点图形语言、关系线和图例
- 推荐布局 / 个人布局
- 模块入口跳转

### 6.2 `P6.2` 跨阶段只读集成与状态投影

负责：

- `P1 ~ P5` 的标准读接口契约
- 状态归一化投影
- 门户页与串行观察页的读侧模型
- 新鲜度与降级机制

### 6.3 `P6.3` 设计语言与前端展示基线

负责：

- 阶段命名与状态文案基线
- 总览条、筛选条、列表 / 图谱双视图等共享展示基元
- 平台级空态、错误态和跳转语义统一

### 6.4 `P6.4` 前端展示工具化实验场

负责：

- 展示模板、绑定、布局、预设和实验记录对象
- 展示能力的配置化验证
- 面向 `P3 / P4 / P5` 的反哺结论沉淀

## 7. 后续约束

- `P6` 必须保持对业务主链的解耦
- `P6` 只消费 `P1 ~ P5` 的规范化查询 / 订阅接口，不允许直连内部实现
- `P6` 不对 `P1 ~ P5` 反写数据，不承担命令下发职责
- `P6.3` 负责平台级设计语言统一，但不强制抹平各阶段业务差异
- `P6.4` 的探索结果应反馈 `P3 / P4 / P5`，但不应直接改写其正式契约
- 登录与权限属于后置预留能力，不作为当前主线验收目标
