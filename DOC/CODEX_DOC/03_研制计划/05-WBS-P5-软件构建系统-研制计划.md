# WBS-P5 软件构建系统研制计划

## 1. 节点目标

基于需求规格、软件设计对象以及工具资产匹配结果，形成可运行的软件或元数据应用。

## 2. 当前边界

`P5` 负责：

- 软件装配
- 运行时生成
- 结果交付
- 新资产反哺

不负责：

- 业务知识抽取
- 需求建模
- 软件设计对象生成
- 工具资产治理

## 5. 后续约束

- `P5` 启动前必须明确消费对象：
  - `RequirementSpec`
  - `SoftwareDesignModel`
  - 工具/组件匹配结果
- 不应绕过 `P3 / P4` 直接从页面草稿装配系统
- `P3` 必须先冻结唯一实现路线，`P5` 不负责自行决定技术路线
- `P5` 以 `P3` 冻结设计为主输入，以 `P4` 已审定 / 已供给资产为辅输入
- `P5` 发现问题后只输出问题报告与反馈任务，`P3` 是唯一回流仲裁者
- `P4` 不直接接受 `P5` 修订回流，只接受 `P3` 发起的新供给任务 / 派生任务 / 组件拆分任务
- `P5` 首版交付物以本地独立交付目录为第一载体，并强制执行静态结构校验与本地构建校验

## 6. 首版节点拆分

当前将 `P5` 首版拆分为以下三个连续节点：

### 6.1 `P5.1` 最小构建闭环

该节点优先级最高，必须先补齐。

目标不是先做回流，而是先把从 `P3 / P4` 到 `P5` 的最小可运行循环搭起来：

- 接收 `P3` 冻结软件设计订单
- 接收 `P4` 已供给资产结果 / 工具订单结果
- 在 `P5` 内创建交付主单与装配运行单
- 提供独立 `P5` 工作台前端，而不是挂在通用知识库导航下
- 提供最小后台运行与进度监控能力
- 形成一次可观察、可导出、可复跑的模拟构建结果

`P5.1` 首版至少要有以下页面区块：

- 交付主单队列区
- 当前装配流程主视图区
- 构建运行状态 / 服务监控区
- 结果输出预览区
- 缺口与反馈区

`P5.1` 首版至少要有以下后台能力：

- `P5DeliveryOrder` 主单服务
- `P5AssemblyRun` / `P5AssemblyAttempt` 运行服务
- 构建模拟执行器
- 运行日志与进度查询
- `P3 / P4` 模拟输入接入

### 6.2 `P5.2` 运行生成与监控

在 `P5.1` 最小闭环打通后，再补齐更完整的运行态能力：

- 运行任务调度
- 执行器状态监控
- 构建日志留痕
- 失败重试
- 多次构建尝试对比
- 本地构建校验与结构校验的正式闭合

### 6.3 `P5.3` 缺口回流与追溯

`P5.3` 不应先行孤立开发，它依赖前两个节点已经形成实际构建运行事实。

该节点负责：

- 缺口分类
- 反馈任务生成
- `P3` 仲裁回流
- 订单、装配、供给、交付之间的追溯链

当前口径下，`P5.3` 的“元素回流”只是 `P5` 首版后段能力之一，不能替代 `P5.1` 的最小构建闭环。
