# P6.4 前端展示工具化实验场设计

## 1. 设计定位

`P6.4` 是 `P6` 探索验证层中的核心节点，负责验证“前端展示是否可以像工具一样被配置、绑定、组合和复用”。

它不是正式业务模块，也不是一个与 `P4` 重复的工具仓库页面。它的职责是为平台前端展示的工具化提供实验场、样板和反馈证据。

## 2. 立项原因

当前平台已经证明：

- 后端对象、流程和调用链可以被结构化
- 业务知识、需求、设计和工具资产都可以做对象化表达

但前端展示仍然容易停留在“手写页面”的状态。这会直接影响：

- `P3` 的设计表达是否足够可装配
- `P4` 的工具生产是否能覆盖展示层
- `P5` 的最终装配是否能真正做到快速构建

因此，`P6.4` 的验证价值很高。

## 3. 设计边界

### 3.1 当前负责

- 定义展示工具化的最小对象模型
- 提供展示模板、数据绑定、布局组合和预设的实验框架
- 记录实验结果与反馈结论
- 将可复用结论回传给 `P3 / P4 / P5`

### 3.2 当前不负责

- 直接替代正式业务页
- 直接反写业务数据
- 直接替代 `P4` 工具仓库
- 在当前阶段冻结为正式生产能力

## 4. 最小对象模型

`P6.4` 首版固定以下对象：

### 4.1 `DisplayWidgetTemplate`

定义展示组件模板本身，包括：

- 模板名称
- 模板类型
- 输入槽位
- 支持的字段映射
- 支持的展示状态

### 4.2 `DisplayWidgetBinding`

定义模板与数据源的绑定关系，包括：

- 绑定来源阶段
- 绑定字段
- 绑定转换规则
- 空值与错误回退规则

### 4.3 `DisplayWidgetLayout`

定义多个展示组件如何组合成一个页面片段，包括：

- 区域划分
- 排列顺序
- 尺寸策略
- 响应式约束

### 4.4 `DisplayWidgetPreset`

定义可复用的展示预设，包括：

- 预设名称
- 适用场景
- 绑定模板集合
- 布局集合

### 4.5 `DisplayExperimentRecord`

定义一次实验的记录对象，包括：

- 实验目标
- 输入数据范围
- 所用模板 / 绑定 / 布局
- 观察结果
- 问题结论
- 晋升建议

## 5. 实验流程

`P6.4` 首版建议采用如下实验流程：

1. 选择阶段数据源
2. 选择或创建展示模板
3. 建立字段绑定
4. 组合布局
5. 在平台观察页或实验页预览
6. 记录实验结果
7. 判断是否可进入正式复用链

这条链路的目标不是“现场改页面”，而是把展示能力对象化、证据化。

## 6. 与 P3 / P4 / P5 的关系

### 6.1 对 P3

`P6.4` 为 `P3` 提供“哪些展示对象适合结构化表达”的反馈。

也就是说，`P3` 需要知道：

- 哪些展示单元应在设计阶段就被建模
- 哪些展示槽位和数据绑定值得前置设计

### 6.2 对 P4

`P6.4` 为 `P4` 提供“哪些展示能力值得做成正式工具或组件资产”的依据。

注意：

- `P6.4` 自己不等于 `P4`
- `P6.4` 只负责验证和举证
- 是否沉淀为正式工具资产，仍由 `P4` 决定与承接

### 6.3 对 P5

`P6.4` 为 `P5` 提供“装配阶段可直接拿来拼装的展示预设”候选。

当某类展示模板和绑定在实验中反复成功时，它们就应逐步成为 `P5` 的可装配资产。

## 7. 承载页面

`P6.4` 首版不要求立刻拥有完整独立系统，但至少要有两个承载场景：

- 平台串行观察页
- 独立实验页或实验区

这两个场景都应只消费 `P6.2` 的读侧投影，而不直接绑定阶段内部状态。

## 8. 晋升规则

一次实验结果若满足以下条件，可考虑晋升：

- 模板边界清晰
- 数据绑定稳定
- 布局可复用
- 对多个场景有效
- 不依赖阶段私有页面实现

晋升后的承接方向：

- 进入 `P3` 作为设计模式
- 进入 `P4` 作为展示工具 / 组件生产对象
- 进入 `P5` 作为装配预设

## 9. 验收口径

1. `P6.4` 已从概念性描述提升为独立正式设计对象。
2. 展示模板、绑定、布局、预设、实验记录五类对象边界清晰。
3. 实验流程能够解释“从展示实验到正式沉淀”的路径。
4. `P6.4` 与 `P3 / P4 / P5` 的关系是反哺，不是替代。
