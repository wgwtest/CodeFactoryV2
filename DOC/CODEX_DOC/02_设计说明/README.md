# CodeFactoryV2 设计说明目录

本目录用于沉淀 `CodeFactoryV2` 已确认、可长期追踪的正式设计说明。

当前固定采用：

- `00_总纲/`
- `P阶段_中文名/`

两层组织方式，不再使用全局顺序号平铺全部阶段文档。

## 1. 目录规则

### 1.1 `00_总纲/`

只放跨阶段、跨模块的总纲与治理文档，例如：

- 平台总体设计
- 文档治理与协同规则
- 节点合同与验收文种体系设计
- P1-P6 数据互联互通与平台交换层设计
- Orchestrator 基础包壳与注册机制设计

### 1.2 `P阶段_中文名/`

只放与某个阶段直接绑定的正式设计文档。

当前阶段目录包括：

- `P1_业务知识库/`
- `P2_需求分析系统/`
- `P3_软件设计系统/`
- `P4_工具仓库/`
- `P5_软件构建系统/`
- `P6_门户与平台入口/`

### 1.3 命名规则

- 阶段主设计文档：`P阶段-中文标题.md`
- 阶段主设计补充稿：`P阶段-中文标题-YYMMDD-HHMM-补充主题.md`
- 已形成稳定 WBS 子节点的专项设计：`P阶段.子节点-中文标题.md`
- 阶段内专题设计：原则上优先收敛为主设计补充稿；只有已经形成稳定 WBS 子节点且需要长期独立评审时，才使用 `P阶段.子节点-中文标题.md`

补充稿规则用于承接主设计文档之外的阶段性深化设计、专项论证、重构依据和待评审方案。主设计文档保持稳定入口，不在文件名中追加日期时间；除主设计文档外，围绕同一主设计形成的补充稿必须使用对应主设计标题作为前缀，并追加 `YYMMDD-HHMM` 版本时间，确保同一天多次补充时仍能按文件名稳定排序。补充稿中的稳定结论被采纳后，应按需要回并到主设计文档，补充稿继续作为设计演进证据保留。

例如：

- `P5-软件构建系统设计.md`
- `P5-软件构建系统设计-260512-1505-构建任务状态机补充.md`
- `P5.1-最小构建闭环设计.md`
- `P4-工具仓库设计-260419-1000-核心业务循环补充.md`

`P4` 自 2026-05-12 起严格采用与 `P2` 相同的组织方式：`P4-工具仓库设计.md` 作为稳定主软件设计说明，围绕该主设计产生的历史专题和后续深化稿统一作为 `P4-工具仓库设计-YYMMDD-HHMM-补充主题.md` 管理；不得再新增 `P4-10`、`P4-20` 这类阶段内局部号专题作为当前正式入口。
