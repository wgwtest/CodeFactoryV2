# P6.1 首屏观察门户设计

## 1. 设计定位

`P6.1` 是 `P6` 稳定平台层中的首个正式实现对象，负责把 `P1 ~ P5` 的阶段关系、主数据流、阶段入口和运行摘要，以全屏蓝图画布的方式呈现给用户。

它不是普通业务页，也不是“系统首页大卡片”。它承担的是：

- 平台首屏入口
- 阶段关系总览
- 统一观察与跳转
- `P6.2 / P6.3 / P6.4` 的首个承载页面

## 2. 设计目标

- 提供独立路由 `/portal`
- 以全屏、可拖拽、可缩放的蓝图画布呈现 `P1 ~ P5`
- 支持单击高亮、双击进入模块
- 用清晰图形语言区分系统节点、用户节点、数据产物与状态信息
- 支持系统推荐布局与个人覆盖布局
- 以右下角图例表达平台层说明，而不是额外增加大表头

## 3. 设计边界

### 3.1 当前负责

- 平台首屏观察画布
- 阶段主节点与主链路表达
- 门户级投影摘要
- 模块入口跳转
- 画布层交互与布局记忆

### 3.2 当前不负责

- 在门户页直接编辑业务数据
- 弹窗式摘要中心
- 登录与权限流程
- 多人协同编辑布局
- 对 `P1 ~ P5` 反写状态

## 4. 页面结构

`P6.1` 页面采用四层结构：

1. 视口层
   - 负责世界坐标、平移、缩放与边界控制
2. 连线层
   - 负责主链、供给链、设计转化链和构建链的语义连线
3. 节点层
   - 负责系统节点、用户节点、数据产物节点的渲染与交互
4. 图例与摘要层
   - 负责右下角平台图例、当前知识库、交互提示和投影摘要

页面默认不进入普通业务壳层，不承载顶部表头，不再使用遮挡主画布的弹窗。

## 5. 固定节点与元素分层

### 5.1 固定主节点

首版固定展示以下主节点：

- `行业用户`
- `P1 业务知识库`
- `P2 需求分析系统`
- `P3 软件设计系统`
- `P4 工具仓库`
- `P5 软件构建系统`

`P6` 本身不作为并列业务节点出现，而以图例和平台说明的方式存在。

### 5.2 元素分层

门户中允许出现的元素被固定为四类：

- 系统节点
- 用户节点
- 数据/产物节点
- 状态/注释节点

准入规则：

1. 每个元素必须声明所属类别。
2. 每个元素必须声明是否可跳转至稳定页面。
3. 每个元素必须声明是自动投影还是人工配置。

不满足以上三点的元素，不得直接进入门户画布。

## 6. 画布模型

### 6.1 世界坐标

门户采用统一世界坐标系管理节点和连线。

首版约束：

- 推荐世界尺寸按单屏蓝图比例初始化
- 节点拖拽修改的是世界坐标，而不是视口像素
- 视口缩放和平移不得破坏连线对齐

### 6.2 锚点与连线

每个系统主节点至少包含：

- 左侧输入锚点
- 右侧输出锚点

在必要时，可启用：

- 顶部锚点
- 底部锚点

连线必须从锚点出发，而不是从节点中心点出发。这是门户蓝图感和连线正确性的硬约束。

### 6.3 布局模式

`P6.1` 首版固定支持两种布局模式：

- 推荐布局
  - 由系统给出默认画布排布
- 个人布局
  - 用户在本地覆盖节点位置

个人布局的约束：

- 只允许覆盖位置
- 不允许改动节点语义
- 不允许改动关系语义
- 不允许删减系统默认主节点

## 7. 交互模型

### 7.1 单击

- 单击节点只做高亮
- 高亮节点时，联动强调相关连线与相关产物
- 不再打开遮挡主画布的详情弹窗

### 7.2 双击

- 双击系统节点直接进入对应模块页面

首版默认路由约定：

- `P1 -> /graph`
- `P2 -> /requirements`
- `P3 -> /modeling`
- `P4 -> /xx-p4`
- `P5 -> /build`

### 7.3 拖拽与缩放

- 节点可拖拽，但受世界边界与最小间距约束
- 视口支持平移与缩放
- 自动投影节点默认应比人工覆盖节点更受约束，防止语义散架

### 7.4 关系视图

首版允许两种关系表达模式：

- 语义线
  - 显示完整语义连线
- 投影聚合
  - 以节点级摘要和产物聚合降低拥塞

这两种模式都属于读侧视图切换，不改变底层关系语义。

## 8. 门户投影数据模型

`P6.1` 直接消费 `P6.2` 投影层输出，但页面自身也要固定最小投影对象集。

### 8.1 节点对象

每个门户节点至少包含：

- `id`
- `type`
- `stage`
- `title`
- `summary`
- `status`
- `metrics`
- `route`
- `projectionMode`

### 8.2 关系对象

每条关系至少包含：

- `from`
- `to`
- `semanticType`
- `direction`
- `tone`
- `renderStyle`

### 8.3 产物对象

首版至少应支持以下产物节点：

- 需求规格说明
- 软件设计说明
- 工具化描述 / 调用编排

### 8.4 摘要对象

门户摘要至少展示：

- 系统节点数
- 角色节点数
- 产物节点数
- 连线数
- 自动投影数
- 人工配置数
- 当前知识库名称

## 9. 图例要求

右下角图例是 `P6` 平台层在门户页中的唯一显式说明区。

必须包含：

- `P6.1` 当前页面定位
- 当前知识库
- 交互提示
- `P6.2` 数据投影状态入口
- `P6.3` 设计语言基线提示
- `P6.4` 展示实验提示
- `P6.R1 / P6.R2` 后置预留能力说明

图例必须：

- 位于右下角
- 低干扰
- 不遮挡业务主节点
- 不抢占视觉中心

## 10. 验收口径

1. `/portal` 打开后直接进入全屏蓝图画布。
2. 页面不再依赖顶部大表头解释页面身份。
3. 单击节点只高亮，不再弹窗。
4. 双击节点可直接进入对应模块。
5. 连线始终从锚点出发，并在缩放/拖拽后保持对齐。
6. 推荐布局与个人布局的边界清晰，不发生语义混改。
7. 图例固定在右下角，且不与业务主节点争抢视觉中心。
