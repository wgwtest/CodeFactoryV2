# P6 平台门户、观察与前端展示实验层设计

## 1. 设计目标

`P6` 的目标不是替代任何业务子系统，而是在 `P1 ~ P5` 之外形成一个平台层：

- 提供首屏观察门户
- 提供跨阶段只读集成与状态投影
- 承担平台级设计语言统一
- 承担前端展示工具化实验与验证

因此，`P6` 当前不是“登录/权限优先”的阶段，而是“观察、串联、统一和实验优先”的阶段。

## 2. 设计边界

### 2.1 两层结构

`P6` 当前采用“两层结构”。

第一层是稳定平台层：

- `P6.1` 首屏观察门户
- `P6.2` 跨阶段只读集成与状态投影
- `P6.3` 设计语言与前端展示基线

第二层是探索验证层：

- `P6.4` 前端展示工具化实验场

### 2.2 当前负责

- 独立门户路由与全屏观察画布
- `P1 ~ P5` 的只读状态串联与平台观察
- 平台级设计语言、展示基线与前端表达约束
- 页面卡片 / 展示单元的工具化实验

### 2.3 当前不负责

- 真正登录页与完整认证链
- 复杂权限校验执行
- 对 `P1 ~ P5` 的业务写操作
- 跨阶段调度命令中心
- 多人协同编辑门户布局

## 3. 节点结构

### 3.1 `P6.1` 首屏观察门户

首版正式实现对象，负责：

- 独立路由 `/portal`
- 首屏蓝图化表达 `P1 ~ P5` 与用户的关系和主数据流
- 单击高亮、双击进入模块
- 拖拽、缩放、平移和本地记忆布局
- 门户级节点、关系、产物和状态的统一图形语言

### 3.2 `P6.2` 跨阶段只读集成与状态投影

当前主责是：

- 从 `P1 ~ P5` 读取规范化查询 / 订阅接口
- 汇总阶段状态、入口状态、健康指标和摘要信息
- 形成门户页与串行观察页共用的只读投影层

关键边界：

- `P6` 只读
- 不反写
- 不代替任一阶段推进业务
- 不直接读取阶段内部数据库或页面私有状态

### 3.3 `P6.3` 设计语言与前端展示基线

当前主责是：

- 统一平台级命名、状态表达和视觉 token
- 统一总览条、卡片、抽屉、图谱节点、表格和入口按钮的展示语言
- 明确哪些前端展示基元属于平台共性，哪些保留阶段个性

### 3.4 `P6.4` 前端展示工具化实验场

当前主责是：

- 验证页面中的展示卡片能否工具化、模块化、可绑定、可组合
- 在平台首屏和串行观察页上实验前端展示单元的快速配置与替换
- 将实验成果反哺 `P3 / P4 / P5`

这里必须强调：

- `P6.4` 当前是探索性、验证性能力
- 它不是现阶段就要冻结为正式产品能力的模块
- 但它的验证价值很高，因为它直连“前端展示如何工具化”这一关键问题

### 3.5 后置预留能力

以下能力保留在 `P6` 名下，但不作为当前主线：

- `P6.R1` 统一登录接入
- `P6.R2` 权限与角色控制

原因不是它们不重要，而是：

- 对当前原型验证不是主矛盾
- 过早强化权限流会显著增加演示和串联验证阻力

## 4. 门户信息架构

### 4.1 独立路由

门户使用独立路由：

- `/portal`

它不进入普通业务壳层，不再作为 `P1 ~ P5` 页面的附属试验稿。

### 4.2 固定节点集合

首版固定展示以下节点：

- `行业用户`
- `P1 业务知识库`
- `P2 需求分析系统`
- `P3 软件设计系统`
- `P4 工具仓库`
- `P5 软件构建系统`

`P6` 本身不作为并列大节点出现，而通过右下角图例表达其平台层身份。

### 4.3 元素分层

门户元素必须被限定为四类：

- 系统节点
- 用户节点
- 数据/产物节点
- 状态/注释节点

任何新元素在进入门户前，都必须先回答：

1. 它属于哪一类元素
2. 是否可点击进入稳定页面
3. 是自动生成还是人工配置

### 4.4 平台观察页的补充定位

`P6` 不只承载一张门户蓝图，还承载“串行观察页”的设计方向。

串行观察页的定位是：

- 用统一卡片和展示单元，顺序观察 `P1 ~ P5`
- 读取阶段级只读投影
- 做平台级展示与比对
- 不在这一层进入阶段内部编辑

这也正是 `P6.4` 前端展示工具化实验的主要验证场景之一。

## 5. 画布模型与图形语言

### 5.1 技术路线

首版采用“蓝图画布混合实现”路线：

- 视口层：世界坐标、平移、缩放
- 节点层：React/DOM 节点卡片
- 连线层：与视口同坐标系的图形层
- 特效层：流光、脉冲、网格和氛围光

不采用普通页面式门户，也不采用纯 `Canvas/WebGL` 文字承载方案。

### 5.2 锚点 / Pin 模型

每个系统节点至少具备：

- 左侧输入锚点
- 右侧输出锚点

必要时可增加：

- 顶部锚点
- 底部锚点

连线必须从锚点出发，而不是从节点中心点出发。

### 5.3 连线语义

连线不能只表达“有关系”，必须表达语义类型：

- 主生产链连线
- 知识供给连线
- 设计转化连线
- 工具匹配连线
- 构建执行连线

编码规则：

- 颜色表达语义类型
- 粒子或箭头表达方向
- 连线过多时优先采用“主线 + 产物节点”的方式减拥塞

## 6. 跨阶段只读集成契约

### 6.1 各阶段对 P6 的标准读接口要求

`P1 ~ P5` 面向 `P6` 必须逐步收敛出规范化的读接口或订阅接口。

首版优先要求两类：

- 查询接口：概览、详情、入口可用性、阶段摘要、健康状态
- 订阅接口：阶段状态变化、关键指标变化、运行告警

首版允许“先查询、后订阅”，但不允许：

- 直接读取阶段内部数据库
- 直接抓页面私有状态
- 把临时脚本结果当正式接口给 `P6`

### 6.2 P6 的只读边界

`P6` 可以做：

- 读取各阶段的状态、摘要、计数与入口
- 汇总并投影成首屏观察、串行观察和卡片布局
- 在前端层实验不同展示单元组合方式

`P6` 不能做：

- 写入 `P1 ~ P5` 内部事实对象
- 触发阶段命令
- 修改阶段语义
- 反向驱动业务推进

### 6.3 阶段数据消费矩阵

`P6` 当前应重点消费如下数据：

- `P1`：当前知识库、已发布知识规模、知识图谱入口状态
- `P2`：建模任务数、建模阶段状态、需求规格入口状态
- `P3`：设计订单、冻结状态、评审状态、软设入口状态
- `P4`：工具供给、需求单状态、巡检状态、工具仓入口状态
- `P5`：构建单、装配尝试、缺口状态、交付入口状态

首版只要求这些数据能被稳定读出，不要求它们全部以实时流方式刷新。

## 7. 交互与数据投影

### 7.1 交互原则

- 单击节点：只做高亮，不弹窗
- 双击节点：直接进入对应模块
- 拖拽节点：受世界边界、最小间距和碰撞规避约束
- 拖动画布：支持平移与缩放

### 7.2 默认路由映射

首版默认映射如下：

- `P1 -> /graph`
- `P2 -> /requirements`
- `P3 -> /modeling`
- `P4 -> /xx-p4`
- `P5 -> /build`

### 7.3 右下角图例

图例必须是低干扰的信息层，至少包含：

- `P6.1` 首屏观察门户
- 当前知识库
- 交互提示
- `P6.2` 只读集成状态
- `P6.3` 展示语言基线
- `P6.4` 工具化实验提示
- `P6.R1 / P6.R2` 后置预留能力

### 7.4 投影数据模型

门户是平台结构与运行态势的投影视图，而不是自由摆图工具。

输入数据至少包括：

- 节点主数据
- 关系主数据
- 产物主数据
- 布局主数据

自动生成与人工配置分工如下：

- `P1 ~ P5` 主节点、主链路和阶段摘要由系统自动生成
- 当前知识库、入口可用性和运行指标由状态投影生成
- 图例和少量展示开关由人工配置
- 个人布局只覆盖位置，不允许篡改节点语义和链路语义

### 7.5 展示工具化实验对象

`P6.4` 首版建议至少显式建模以下对象：

- `DisplayWidgetTemplate`
- `DisplayWidgetBinding`
- `DisplayWidgetLayout`
- `DisplayWidgetPreset`
- `DisplayExperimentRecord`

它们分别用于表达：

- 卡片模板长什么样
- 卡片绑定哪类阶段数据
- 卡片怎么组合成页面布局
- 哪些组合可以被复用为预设
- 哪次实验产生了什么结论与反馈

这些对象当前可以先停留在设计层，不要求同轮全部实现。

## 8. 设计语言统一职责

### 8.1 P6 为什么要承担这项职责

`P1 ~ P5` 已被定义成五个可独立运行、可单独打开的工具。

这意味着：

- 它们的业务权限和内部结构可以不同
- 它们不必强耦合成一个单体系统

但如果完全没有统一语言，就会导致：

- 状态表达混乱
- 入口行为不一致
- 页面层级和反馈方式割裂
- 用户在跨阶段观察时认知成本过高

因此 `P6.3` 的职责是统一“平台语言”，而不是统一“所有业务实现”。

### 8.2 统一范围

当前统一范围至少包括：

- 平台级阶段命名
- 状态色与状态文案
- 指标卡与总览条
- 抽屉、列表、图谱、工作台容器
- 入口按钮与跳转提示
- 阶段级占位表达

## 9. 视觉原则与验收口径

### 9.1 视觉原则

- 全屏、沉浸式、浅底蓝图
- 用网格、pin、流光、轻量脉冲体现运行感
- 避免大表头、大段说明、遮挡式弹窗和普通后台首页排版

### 9.2 首版验收口径

1. `/portal` 打开后直接进入全屏蓝图画布
2. 单击节点不再出现弹窗
3. 双击节点可直接进入模块
4. 连线从锚点 / pin 出发，并在缩放、拖拽后仍与节点对齐
5. `P6` 对 `P1 ~ P5` 的只读边界在正式设计中已明确固定
6. `P6` 已明确拆成“稳定平台层 + 探索验证层”两层结构
7. 平台级设计语言统一职责已明确归入 `P6.3`
8. 前端展示工具化实验已明确归入 `P6.4`
9. 登录 / 权限已被降为后置预留能力，而不再占据当前主线
