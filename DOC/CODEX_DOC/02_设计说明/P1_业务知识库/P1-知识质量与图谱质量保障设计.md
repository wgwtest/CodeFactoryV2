# P1 知识质量与图谱质量保障设计

## 1. 文档定位

本文回答 `P1` 重构中的关键问题：系统如何保证抽取出来的知识概念质量和图谱质量，如何衡量，使用什么方法持续保障。

本文是 `P1` 重构设计的质量保障专题，关联：

- `DOC/CODEX_DOC/02_设计说明/P1_业务知识库/P1-业务知识库设计.md`
- `DOC/CODEX_DOC/02_设计说明/P1_业务知识库/P1-业务知识库重构设计.md`
- `DOC/CODEX_DOC/03_规范与流程/01_数据规范/02-P1业务知识库重构接口合同.md`

- `docs/superpowers/specs/2026-04-18-knowledge-content-quality-field-dictionary.md`

## 2. 核心结论

知识质量不能只靠“页面看起来完整”判断，也不能只靠最后一个质量门禁阶段兜底。`P1` 必须建立一套贯穿全链路的质量保障体系：

```text
质量字段字典
  -> 策略包质量配置
  -> 抽取过程质量检查
  -> 规则执行记录
  -> 质量门禁决策
  -> 图谱质量评估
  -> 治理确认
  -> 发布态回归评测
```

质量保障的核心原则：

- 所有知识项和关系必须有来源证据。
- 所有质量判断必须可解释、可追溯、可版本化。
- 所有策略变更必须能看到指标变化。
- 所有发布态知识必须经过内容质量、图谱质量和治理边界检查。
- 图谱质量不是布局美观问题，而是结构、证据、关系和可解释性的综合质量。

## 3. 质量保障分层

### 3.1 内容质量

内容质量回答：抽取出的知识对象本身是否可信。

覆盖对象：

- 实体。
- 事件。
- 流程。
- 规则。
- 指标。
- 定义。
- 摘要。
- 关系。

核心判断：

- 名称是否清楚。
- 类型是否正确。
- 定义是否明确。
- 证据是否充分。
- 来源是否可追溯。
- 与同类对象是否重复。
- 是否存在冲突定义或冲突关系。

### 3.2 图谱质量

图谱质量回答：这些知识对象组织成图后是否有参考价值。

覆盖对象：

- 节点。
- 边。
- 节点类型分布。
- 关系类型分布。
- 证据链。
- 连通结构。
- 关系方向。
- 图谱投影。

核心判断：

- 节点是否有明确语义。
- 边是否有证据和动作依据。
- 是否存在大量孤立节点或孤立关系。
- 是否存在重复节点、重复边、自环异常。
- 是否能从文档证据追溯到图谱对象。
- 是否能解释“为什么这两个对象有关系”。

### 3.3 过程质量

过程质量回答：抽取过程是否可靠。

覆盖对象：

- 解析器。
- 分块策略。
- 策略包版本。
- 规则执行记录。
- 模型配置。
- 运行快照。
- Stream / polling 事件。

过程质量不直接等同于内容质量，但它是内容质量可追溯的基础。

### 3.4 发布质量

发布质量回答：本批知识是否可以作为正式资产交给下游系统。

核心判断：

- 批次证据覆盖率是否达标。
- 低置信项比例是否可接受。
- 冲突项是否已处理。
- 图谱结构异常是否可接受。
- 治理确认是否完成。
- `P1 -> P2` 输出是否只包含正式发布知识。

## 4. 质量指标体系

### 4.1 文档结构覆盖指标

| 指标 | 含义 | 用途 |
| --- | --- | --- |
| `structure.block_coverage_ratio` | 被纳入统一文档对象的原文块比例 | 判断是否遗漏大量文档内容 |
| `structure.anchor_coverage_ratio` | 带页码、段落或 chunk 锚点的结构块比例 | 判断证据可定位能力 |
| `structure.table_parse_success_ratio` | 表格解析成功比例 | 判断表格知识是否可靠 |
| `structure.heading_recovery_ratio` | 章节标题恢复比例 | 判断文档结构质量 |
| `structure.unparsed_region_ratio` | 未解析区域比例 | 控制长文档解析缺口 |

### 4.2 知识项质量指标

| 指标 | 含义 | 推荐方向 |
| --- | --- | --- |
| `item.type_valid_ratio` | 知识项类型合法比例 | 越高越好 |
| `item.name_clarity_ratio` | 名称清晰且非空比例 | 越高越好 |
| `item.definition_coverage_ratio` | 有定义或解释的知识项比例 | 越高越好 |
| `item.evidence_coverage_ratio` | 带证据知识项比例 | 越高越好 |
| `item.anchored_evidence_ratio` | 带可定位证据知识项比例 | 越高越好 |
| `item.cross_document_support_ratio` | 被两个及以上文档支撑的高价值知识项比例 | 越高越好 |
| `item.duplicate_ratio` | 重复知识项比例 | 越低越好 |
| `item.conflict_ratio` | 存在冲突定义的知识项比例 | 越低越好 |
| `item.merge_conflict_ratio` | 跨文档归并时出现冲突的知识项比例 | 越低越好 |
| `item.low_confidence_ratio` | 低置信知识项比例 | 越低越好 |

### 4.3 关系质量指标

| 指标 | 含义 | 推荐方向 |
| --- | --- | --- |
| `relation.endpoint_valid_ratio` | 关系两端节点都存在的比例 | 越高越好 |
| `relation.evidence_coverage_ratio` | 带证据关系比例 | 越高越好 |
| `relation.direction_valid_ratio` | 方向符合关系语义的比例 | 越高越好 |
| `relation.duplicate_ratio` | 重复关系比例 | 越低越好 |
| `relation.orphan_ratio` | 孤立关系比例 | 越低越好 |
| `relation.self_loop_error_count` | 非法自环数量 | 越低越好 |
| `relation.low_confidence_ratio` | 低置信关系比例 | 越低越好 |

### 4.4 图谱结构指标

| 指标 | 含义 | 推荐方向 |
| --- | --- | --- |
| `graph.connected_component_count` | 连通分量数量 | 与知识域规模匹配 |
| `graph.giant_component_ratio` | 最大连通分量覆盖节点比例 | 过低说明图谱碎片化 |
| `graph.isolated_node_ratio` | 孤立节点比例 | 越低越好 |
| `graph.average_degree` | 平均度 | 过低稀疏，过高可能乱连 |
| `graph.edge_type_diversity` | 关系类型多样性 | 与策略目标匹配 |
| `graph.semantic_path_coverage_ratio` | 能形成可解释路径的节点比例 | 越高越好 |
| `graph.action_basis_coverage_ratio` | 边或节点能追溯到规则/动作依据的比例 | 越高越好 |

### 4.5 评测集指标

| 指标 | 含义 |
| --- | --- |
| `eval.concept_precision` | 抽出的概念中有多少是正确的 |
| `eval.concept_recall` | 标注概念中有多少被抽出 |
| `eval.concept_f1` | 概念精确率和召回率综合 |
| `eval.relation_precision` | 抽出的关系中有多少是正确的 |
| `eval.relation_recall` | 标注关系中有多少被抽出 |
| `eval.evidence_recall` | 标注证据中有多少被系统命中 |
| `eval.gate_false_block_rate` | 门禁错误阻断比例 |
| `eval.gate_false_pass_rate` | 门禁错误放行比例 |

## 5. 质量保障方法

### 5.1 Schema 约束

所有候选知识、关系、证据和图谱投影必须先通过 schema 校验。

方法：

- Pydantic / JSON Schema 校验字段完整性。
- 类型、枚举、必填字段和版本字段强校验。
- 不合格对象不得进入发布候选。

### 5.2 证据优先

所有知识项和关系必须绑定证据。

方法：

- 每个对象必须有 `source_refs`。
- 每条证据必须指向文档、页码、段落、chunk 或锚点。
- 高价值知识要求多证据或跨文档支撑。
- 证据不足时可以进入候选态，但不能直接进入正式发布态。

### 5.3 规则合同执行

质量规则必须是可配置、可版本化、可执行的合同。

方法：

- 每条质量规则声明 `input_schema`、`output_schema`、`effect_kind`、`trace_fields`。
- 每次规则执行生成 `RuleExecutionRecord`。
- 规则命中必须能解释输入对象、阈值、命中原因和输出动作。
- 策略变更触发影响面计算，而不是静默覆盖旧知识。

### 5.4 跨文档同知识验证

同一知识库内的同一知识可能来自多份文档。质量保障必须把跨文档验证作为库级能力，而不是只在单文档内去重。

方法：

- 为每个文档级候选生成 `KnowledgeIdentityKey`。
- 基于名称、别名、定义、关系邻域、证据锚点和策略版本生成 `CrossDocumentMatchCandidate`。
- 对相似候选执行 `KnowledgeMergeDecision`，区分 `new / same / update / conflict / split / reject`。
- 合并后的规范对象写入 `CanonicalKnowledgeItem`，保留所有来源文档和证据引用。
- 冲突、拆分、修订必须进入质量报告和治理确认，不能静默覆盖正式知识。

质量判断：

- 多文档一致支撑会提高知识可信度。
- 多文档冲突会降低质量分，并生成冲突解释。
- 新文档只补充证据时可以生成 `evidence_append`。
- 新文档改变定义、数值、关系方向或适用范围时必须生成 `revision_candidate`。

### 5.5 多层质量门禁

质量门禁不只存在于最后阶段，而是分层执行。

```text
解析质量门
  -> 证据质量门
  -> 候选质量门
  -> 关系质量门
  -> 图谱结构质量门
  -> 发布批次质量门
```

每层可分为：

- 硬阻断。
- 警告继续。
- 降级为候选。
- 要求治理确认。

### 5.6 基准评测集

必须建立可重复运行的样本文档评测集。

首批样本类型：

- 长文档。
- 结构复杂文档。
- 中英混合文档。
- 证据稀疏文档。
- 存在冲突定义的文档。
- 表格密集文档。
- 关系密集文档。

评测集至少包含：

- 标注概念。
- 标注关系。
- 标注证据锚点。
- 期望质量门禁结果。
- 期望发布态图谱关键路径。

### 5.7 人机结合校验

自动评测不能替代治理确认。

方法：

- 高置信、证据充分、结构稳定对象可自动通过为发布候选。
- 低置信、冲突、证据不足、结构异常对象进入治理队列。
- 人工治理结果反哺评测集和策略版本。
- 每次人工驳回或合并都记录为质量改进样本。

### 5.8 回归评测

每次策略、模型、分块或图谱投影改动都应运行回归评测。

输出：

- 本次指标。
- 上一基线指标。
- 指标变化。
- 变差项原因。
- 是否允许合并。

## 6. 图谱质量保障

### 6.1 图谱生成前检查

图谱投影前检查：

- 所有节点必须有稳定 ID。
- 所有边两端必须存在。
- 所有边必须有关系类型。
- 发布态边必须有证据或治理记录。
- 运行态边必须能追溯到规则执行或阶段输出。

### 6.2 图谱生成中检查

投影过程中检查：

- fan-in / fan-out 超过阈值时生成集合节点。
- 重复边合并为一条聚合边，并保留明细。
- 关系方向由关系类型和阶段动作决定，不由前端布局决定。
- 运行态图谱和发布态图谱使用不同 projection 类型。

### 6.3 图谱生成后检查

投影后检查：

- 孤立节点比例。
- 孤立关系比例。
- 重复边比例。
- 自环异常。
- 最大连通分量比例。
- 证据覆盖率。
- 动作依据覆盖率。
- 观察窗解释覆盖率。

### 6.4 视觉布局质量

视觉布局不是知识质量本身，但影响用户判断。

布局质量要求：

- 节点文字在节点内。
- 主链节点间距稳定。
- 非主链节点围绕相关主链对象聚合。
- 密集区域默认集合化。
- 选中节点/边后高亮输入、规则、输出和证据链。
- 用户拖拽不应破坏语义分层，必要时触发局部重排。

## 7. 质量门禁决策

### 7.1 决策模型

```text
QualityGateDecision
- decision: pass | warn_continue | block | require_governance
- score: number
- metric_results: QualityMetricResult[]
- rule_hits: RuleExecutionRecord[]
- affected_object_ids: string[]
- affected_relation_ids: string[]
- explanation: string
- generated_at: datetime
```

### 7.2 决策含义

| 决策 | 含义 |
| --- | --- |
| `pass` | 满足发布候选质量要求 |
| `warn_continue` | 存在轻微质量风险，可生成发布候选但带警告 |
| `block` | 质量不满足最低要求，不生成发布候选 |
| `require_governance` | 机器无法自动判断，需治理确认 |

### 7.3 不允许的行为

- 不允许把质量门禁失败对象直接写入正式知识。
- 不允许把缺证据对象伪装成高置信对象。
- 不允许质量策略变更后静默覆盖正式知识。
- 不允许只看节点数量增长就判断图谱质量变好。

## 9. 与 P1 模块的关系

建议新增后端模块：

```text
archive_knowledge/quality/
├─ metric_definitions.py
├─ quality_evaluator.py
├─ graph_quality_evaluator.py
├─ evaluation_dataset.py
├─ regression_runner.py
└─ reports.py
```

建议新增前端模块：

```text
features/p1/quality/
├─ QualityDashboardPage.tsx
├─ QualityReportPanel.tsx
├─ GraphQualityPanel.tsx
└─ EvaluationRunHistory.tsx
```

质量模块调用方向：

```text
runtime -> quality
publication -> quality
graph_projection -> quality
quality -> reports
external_exports -> quality reports
```

禁止：

- `quality` 模块直接修改知识对象。
- `quality` 模块绕过治理确认写正式知识。
- 前端页面自行计算正式质量指标作为发布依据。

## 10. 页面呈现

### 10.1 终端用户页

终端用户只看简化质量摘要：

- 当前文档抽取质量：通过 / 警告 / 阻断 / 待治理。
- 主要原因。
- 证据覆盖率。
- 图谱可解释性摘要。
- 是否已形成发布候选。

### 10.2 策略后台页

策略后台显示完整指标：

- 字段级质量配置。
- 阈值。
- 规则命中。
- 版本差异。
- 影响面。
- 回归评测结果。

### 10.3 治理页

治理页显示决策依据：

- 质量问题。
- 证据缺口。
- 冲突对象。
- 重复候选。
- 推荐操作。

## 11. 验收标准

### 11.1 最小可用标准

- 至少有一批固定样本文档可以重复跑。
- 每次抽取生成 `KnowledgeQualityReport`。
- 每次图谱投影生成 `GraphQualityReport`。
- 质量门禁决策能解释至少 3 类原因：证据不足、关系异常、冲突或重复。
- 发布态知识必须带质量报告引用。

### 11.2 指标验收

首批必须具备：

- 结构覆盖率。
- 证据召回率。
- 候选概念准确率。
- 关系归一稳定性。
- 门禁误判率。
- 图谱孤立节点比例。
- 图谱证据覆盖率。
- 图谱动作依据覆盖率。

### 11.3 回归验收

每次以下改动必须运行质量回归：

- 策略包版本变化。
- 规则字段合同变化。
- 分块策略变化。
- 模型配置变化。
- 图谱投影算法变化。
- 发布边界规则变化。

## 12. 下一步落地建议

建议新增一条并行工作线：

```text
I. 知识质量与图谱质量评测
```

第一阶段目标：

1. 建立 `QualityMetricDefinition` 和 `QualityReport` 合同。
2. 建立第一批固定样本文档评测集。
3. 将质量门禁从单一结果扩展为可解释质量报告。
4. 将运行态图谱和发布态图谱接入 `GraphQualityReport`。
5. 在 P1 重构合并门禁中加入质量回归。
