## 1. 背景与问题

`P2 XG 需求分析组织器 Lab` 当前已经包含五个页签：

| 页签 | 当前定位 |
| --- | --- |
| 需求规格说明管理 | 管理 `RequirementSpecWorkItem`，承担需规对象的新建、删除、进入配置、发布 |
| 组织器配置 | 选择组织器、Provider、模板实例、写入策略并创建或恢复分析会话 |
| 会话管理 | 承载 `RequirementAnalysisSession` 下的用户输入、快捷选项、过程产物、保存和另存 |
| 当前 Turn | 展示 `RequirementAnalysisTurn` 的单轮决策审计 |
| 调用日志 | 展示模型 Provider / Runner 调用证据 |

这五个页签在界面上是并列的，但在真实使用流程上不是并列关系。它们存在隐含的对象依赖：

```text
需求规格说明对象
  -> 组织器配置
    -> 分析会话
      -> 当前 Turn
        -> 当前会话相关调用日志
```

如果没有一个统一的作业状态判断模块，用户会在没有选中需规对象、未进入编辑态、未完成配置或未创建会话时直接点击后续页签，从而出现以下问题：

1. 后续页面看起来可以进入，但实际没有可操作对象。
2. 页面内部通过局部错误提示兜底，用户不知道应该先做什么。
3. 部分操作可能提前发起 API 请求，产生 404、409 或上下文缺失类错误。
4. 顶部标题区没有表达当前正在编辑哪份需规、是否已配置、是否已有会话、是否已发布锁定。

因此，Lab 需要补充一个轻量的 `P2 Lab 作业状态管理器`，把当前激活对象、编辑状态、页签准入和阻断提示集中管理。

## 2. 设计判断

### 2.1 不引入完整 BPM 或平台工作流引擎

本问题本质上是 `P2 Lab` 页面内的作业上下文管理，不是跨阶段流程编排，也不是平台交换层能力。因此首版不建议引入 BPMN、状态机引擎或 BasePlatform 级工作流服务。

原因如下：

1. 当前对象依赖链较短，核心只有 `需规对象 -> 配置 -> 会话 -> Turn`。
2. 已有后端对象已经保存主要事实：`RequirementSpecWorkItem.status`、`analysis_session_id`、`published_package_id`、`p3_consumable`。
3. 页签能否进入主要是前端运行态判断，不需要新增平台级持久化表。
4. BasePlatform 后续应负责跨阶段交换、资源发布、消费记录和统一观察，不应把 P2 页面内的编辑态选择下沉为平台职责。

### 2.2 推荐方案：P2 Lab 轻量作业状态管理器

推荐在 Lab 内定义一个轻量的作业状态管理器，设计名为：

```text
P2 Lab 作业状态管理器
```

实现命名可暂定为：

```text
RequirementAnalysisLabWorkspaceState
```

它不新增独立业务对象，而是从现有对象派生当前作业状态：

- 当前选中的 `RequirementSpecWorkItem`
- 需规对象生命周期状态
- 当前组织器、Provider、模板、写入策略选择
- 当前 `RequirementAnalysisSession`
- 当前 `RequirementAnalysisTurn`
- 当前会话的 Provider 调用日志

它负责回答四类问题：

1. 当前激活的是哪份需求规格说明。
2. 当前是否处于可编辑状态。
3. 某个页签或动作现在能不能执行。
4. 如果不能执行，应该给用户什么明确下一步提示。

## 3. 状态模型

### 3.1 持久事实与派生状态分离

本设计区分两类状态。

| 类型 | 来源 | 示例 | 是否需要新增持久化 |
| --- | --- | --- | --- |
| 持久事实状态 | 后端对象和数据库字段 | `RequirementSpecWorkItem.status`、`analysis_session_id`、`published_package_id`、`p3_consumable` | 首版不新增 |
| 前端派生作业状态 | 当前页面选择和已加载对象 | 当前选中需规、当前页签、当前 Turn、当前 Provider 是否可用 | 不持久化，必要时可用本地缓存恢复 |

首版不建议新增“当前激活对象”数据库表。当前激活对象是用户本次页面作业上下文，不是业务事实。它可以由 `selectedSpecItemId`、`session`、`currentTurn` 等前端状态派生。

### 3.2 需求规格说明对象状态

当前代码中 `RequirementSpecWorkItem` 已有以下状态口径：

| 状态 | 含义 | 编辑口径 |
| --- | --- | --- |
| `draft` | 已新建，尚未完成组织器配置或仍处于草稿 | 可编辑 |
| `configured` | 已进入配置并创建或绑定分析会话 | 可编辑 |
| `revision_draft` | 已发布对象的修订草稿 | 可编辑 |
| `published_to_p3` | 已发布到 P3 可接收包 | 默认锁定，不直接编辑 |
| `archived` | 已归档 | 不直接编辑 |

`P2 Lab 作业状态管理器` 不应重新定义一套与后端冲突的生命周期，而应基于这些状态派生编辑态：

```text
可编辑需规 = status in ["draft", "configured", "revision_draft"] 且 p3_consumable 为 false
已发布锁定 = status == "published_to_p3" 或 p3_consumable 为 true
不可操作 = status in ["archived", "deleted"] 或对象不存在
```

### 3.3 Lab 作业层级状态

建议前端派生以下作业层级状态：

| 作业状态 | 判定条件 | 用户含义 |
| --- | --- | --- |
| `no_spec` | 没有选中 `RequirementSpecWorkItem` | 尚未进入任何需规作业 |
| `spec_selected` | 已选中需规，但不是可编辑态 | 只能查看、发布态提示或引导创建修订 |
| `spec_editing` | 已选中且可编辑 | 可以进入组织器配置 |
| `config_ready` | 可编辑需规存在，且已具备模板、组织器、Provider、写入策略上下文 | 可以启动或恢复会话 |
| `session_ready` | 存在当前 `RequirementAnalysisSession`，或需规对象已绑定 `analysis_session_id` 且可恢复 | 可以进入会话管理 |
| `turn_ready` | 当前会话存在至少一个 `RequirementAnalysisTurn` 或页面有 `currentTurn` | 可以查看当前 Turn |
| `published_locked` | 当前需规已发布到 P3 | 默认禁止配置、会话输入、保存过程产物和删除 |

这些状态不是互斥的线性状态，而是从同一个上下文派生出的能力集合。例如，一个对象可能同时满足 `spec_editing`、`config_ready` 和 `session_ready`。

## 4. 页签准入规则

### 4.1 总体规则

页签不建议隐藏。用户应能看到完整工作流，但后续页签在条件不足时应被集中拦截，并给出明确提示。

推荐行为：

1. 页签仍显示在左侧导航。
2. 不满足前置条件时，点击页签不进入目标页签，或进入后只展示阻断说明；首版推荐“不切换页签 + 顶部提示”。
3. 顶部 `Alert` 或轻提示显示下一步动作。
4. 不发起无意义 API 请求，不让后端 404/409 承担流程提示。

### 4.2 准入矩阵

| 页签 | 是否永远可点 | 前置条件 | 阻断提示 |
| --- | --- | --- | --- |
| 需求规格说明管理 | 是 | 无 | 无 |
| 组织器配置 | 否 | 已选中可编辑的需求规格说明对象 | 请先新建或选择一份需求规格说明，并进入编辑状态。 |
| 会话管理 | 否 | 已选中可编辑需规，且已完成组织器配置或已绑定会话 | 请先进入组织器配置，确认模板、组织器和 Provider，并启动或恢复会话。 |
| 当前 Turn | 否 | 已存在当前会话，且会话中已有当前 Turn | 请先在会话管理中发送一轮输入，生成当前 Turn 后再查看审计。 |
| 调用日志 | 可进入但需降级 | 有会话时按当前会话展示日志；无会话时展示空状态或引导 | 当前暂无会话调用日志。选择需规并创建会话后，将按会话展示 Provider 调用证据。 |

调用日志与前三个后续页签不同。它不是业务作业推进的必要步骤，因此可以允许进入空状态。但首版仍应避免展示与当前作业无关的全局日志，除非后续明确增加全局日志筛选能力。

### 4.3 动作准入矩阵

| 动作 | 前置条件 | 不满足时提示 |
| --- | --- | --- |
| 新建需规 | 无 | 无 |
| 删除需规 | 选中未发布需规，且用户二次确认 | 已发布需求规格说明不能删除，请创建修订或归档。 |
| 进入配置 | 选中可编辑需规 | 请先选择一份可编辑的需求规格说明。 |
| 启动验证 / 创建会话 | 已选中可编辑需规，模板和 Provider 可用 | 请先选择可用模板和已启用 Provider。 |
| 会话输入 | 当前会话存在且需规可编辑 | 请先完成组织器配置并启动会话。 |
| 保存会话产物 | 当前会话存在且需规可编辑 | 请先选择需求规格说明并创建会话。 |
| 另存为 | 当前会话存在 | 请先创建会话后再另存过程产物。 |
| 发布 | 需规未发布，冻结包可生成，阻断型缺口已处理 | 当前需求规格说明仍有阻断型缺口，请先进入配置补齐必填内容后再发布。 |
| 发布后编辑 | 已发布对象不可直接编辑 | 已发布版本已锁定，请创建修订草稿后继续编辑。 |

## 5. 顶部作业状态区设计

### 5.1 位置与目的

在当前顶部标题区 `P2 XG 需求分析组织器 Lab` 附近增加一个 `当前作业状态条`。它不是新的功能页，而是全局上下文提示。

状态条需要回答用户进入任意页签时最关心的四个问题：

1. 当前操作的是哪份需求规格说明。
2. 当前是否可编辑，还是已发布锁定。
3. 配置、会话、Turn 分别到哪一步。
4. 下一步应该做什么。

### 5.2 推荐展示内容

状态条建议展示以下信息：

| 内容 | 示例 |
| --- | --- |
| 当前需规 | `空域态势分析系统需求规格说明` / `未选择需规` |
| 版本 | `v1`、`v2 修订草稿` |
| 需规状态 | `草稿`、`已配置`、`已发布到 P3` |
| 编辑状态 | `编辑中`、`发布锁定`、`未激活` |
| 配置状态 | `已配置组织器`、`待配置` |
| 会话状态 | `会话已创建`、`待启动会话` |
| Turn 状态 | `当前 Turn: turn-003`、`暂无 Turn` |
| P3 状态 | `P3 可接收`、`未发布` |

视觉上可以使用一个较明显的主标签表达总状态：

| 主状态标签 | 触发条件 |
| --- | --- |
| `未选择需规` | `no_spec` |
| `需规编辑中` | `spec_editing` 但未配置 |
| `组织器已配置` | `config_ready` 或 `status == configured` |
| `会话进行中` | `session_ready` |
| `Turn 已生成` | `turn_ready` |
| `已发布锁定` | `published_locked` |

### 5.3 顶部状态与页签联动

当用户点击被阻断页签时，顶部状态区应同步强化提示：

```text
请先新建或选择一份需求规格说明，并进入编辑状态。
```

或：

```text
请先进入组织器配置，确认模板、组织器和 Provider，并启动或恢复会话。
```

这类提示应尽量使用业务语言，不直接暴露 `session_id not found`、`409`、`Requirement Analysis session not found` 等技术错误。

## 6. 模块职责设计

### 6.1 前端作业状态管理器

建议在前端定义统一派生模块，承接所有页签和动作的准入判断。

设计职责：

| 职责 | 说明 |
| --- | --- |
| 构建作业状态 | 从 `selectedSpecItem`、配置选择、`session`、`currentTurn`、Provider 状态中派生状态 |
| 计算页签准入 | 为每个页签返回 `allowed`、`reason`、`nextAction` |
| 计算动作准入 | 为发布、删除、保存、另存、会话输入等动作返回统一准入结果 |
| 输出顶部摘要 | 生成顶部状态条所需的状态标签、对象名、版本、下一步提示 |
| 集中阻断处理 | 点击页签或动作前先走统一 guard，避免各子组件散落判断 |

推荐输出形态：

```text
RequirementAnalysisLabWorkspaceState
  activeSpecItem
  activeSpecEditable
  activeSpecLocked
  hasConfigContext
  hasSession
  hasCurrentTurn
  tabAccessMap
  actionAccessMap
  primaryStatusLabel
  nextRecommendedAction
```

### 6.2 后端职责边界

后端首版不需要新增“全局作业状态”表。后端继续负责保存业务事实：

| 后端对象 | 负责事实 |
| --- | --- |
| `RequirementSpecWorkItem` | 需规对象、生命周期状态、模板、工作文档、会话绑定、发布包 |
| `RequirementAnalysisSession` | 组织器会话、Turn、过程产物、Provider 日志 |
| `RequirementAuthoringDocument` | 标准需求规格说明正文、语义状态、冻结包 |
| `PlatformExchangeService` | 发布后形成平台交换层 `ArtifactEnvelope` |

后续若发现前端派生规则在多个页面重复，可以在 `GET /requirement-analysis/spec-items` 或单独上下文接口中增加只读 DTO 字段，例如：

```text
workspace_status
workspace_blockers
recommended_next_action
```

但该 DTO 仍应是派生结果，不应成为新的长期业务事实源。

### 6.3 与 BasePlatform 的边界

本设计不改变 P2 与 BasePlatform 的分工。

| 范围 | 归属 |
| --- | --- |
| 当前 Lab 选中哪份需规、能否进入配置、会话、Turn | P2 前端 / P2 API |
| 需规发布后形成 `ArtifactEnvelope`、记录发布人和发布时间 | BasePlatform / 平台交换层 |
| P3 发现并消费 P2 已发布包 | P3 + BasePlatform 交换接口 |
| P2 页面内的编辑态提示、页签阻断、顶部状态条 | P2 |

因此，本补充不要求新开 BasePlatform 分支，也不要求把页面作业状态下沉到平台交换层。

## 7. 建议交互流程

### 7.1 无需规时

用户进入 Lab 后，如果没有选中需规对象：

1. 默认停留在 `需求规格说明管理`。
2. 顶部状态显示 `未选择需规`。
3. 点击 `组织器配置`、`会话管理`、`当前 Turn` 时，顶部提示：

```text
请先新建或选择一份需求规格说明，并进入编辑状态。
```

4. 主要行动按钮指向 `新建需规`。

### 7.2 新建需规后

用户通过模态窗口新建需规后：

1. 系统创建 `RequirementSpecWorkItem` 和关联工作文档。
2. 当前需规自动设为激活对象。
3. 顶部状态显示 `需规编辑中`。
4. 自动进入 `组织器配置`。
5. 组织器配置页允许继续选择或确认模板、组织器、Provider 和写入策略。

### 7.3 配置完成后

用户进入配置并启动或恢复会话后：

1. 需规对象状态进入 `configured`。
2. `analysis_session_id` 应绑定到当前需规对象。
3. 顶部状态显示 `会话进行中` 或 `组织器已配置`。
4. `会话管理` 页签可进入。
5. `当前 Turn` 在第一轮输入完成前仍提示需要先生成 Turn。

### 7.4 会话进行中

用户在 `会话管理` 中发送输入后：

1. 系统生成 `RequirementAnalysisTurn`。
2. 当前 Turn 自动更新。
3. `当前 Turn` 页签可进入。
4. 调用日志按当前会话展示 Provider / Runner 调用。
5. 保存和另存操作基于当前 `session.session_id`，并在成功后回写当前需规对象的 `analysis_session_id`。

### 7.5 发布后

用户发布成功后：

1. 需规对象状态进入 `published_to_p3`。
2. `p3_consumable` 为 true。
3. `published_requirement_spec_id` 和 `published_package_id` 有值。
4. 顶部状态显示 `已发布锁定` 和 `P3 可接收`。
5. 组织器配置、会话输入、保存过程产物、删除等编辑动作被阻断。
6. 若需要继续修改，应引导用户创建修订草稿，而不是直接修改已发布版本。

## 8. 异常与提示规则

### 8.1 流程阻断优先于接口错误

用户流程不满足前置条件时，应由前端作业状态管理器提前阻断，不应依赖后端接口返回错误。

示例：

| 场景 | 不推荐提示 | 推荐提示 |
| --- | --- | --- |
| 无会话时另存 | `Requirement Analysis session not found` | 请先完成组织器配置并创建会话后再另存。 |
| 已发布对象继续配置 | `409` | 已发布版本已锁定，请创建修订草稿后继续编辑。 |
| 未选需规进入配置 | 空页面或技术异常 | 请先新建或选择一份需求规格说明，并进入编辑状态。 |

### 8.2 顶部提示和页面空状态分工

| 位置 | 用途 |
| --- | --- |
| 顶部 `Alert` | 反馈用户刚才点击或操作为什么被阻断 |
| 页签内容空状态 | 解释当前页面为什么没有内容，并给出下一步动作 |
| 行内按钮禁用提示 | 解释单个动作为什么不可用 |

三类提示应共用同一套阻断原因，不应各写一套文案。

## 9. 后续实现建议

若用户确认本补充合理，建议后续编码按以下顺序推进：

1. 在 `RequirementAnalysisLabPage` 内先抽出统一的作业状态派生函数或 hook。
2. 用该状态替换散落在页签点击、保存、另存、发布、删除、会话输入中的局部判断。
3. 增加顶部 `当前作业状态条`，展示当前需规、编辑态、配置态、会话态、Turn 态和 P3 状态。
4. 改造左侧页签点击逻辑：被阻断时显示统一提示，不进入无上下文页面。
5. 补充前端单元测试：覆盖无选中需规、草稿需规、已配置需规、无会话、有会话、有 Turn、已发布锁定等状态。
6. 仅在前端派生不足时，再考虑给后端 DTO 增加只读状态摘要字段。

## 10. 验收口径

后续实现完成后，至少应满足以下验收项：

1. 未新建或未选择需规时，点击 `组织器配置`、`会话管理`、`当前 Turn` 不会进入无上下文操作态，并提示先新建或选择需规。
2. 只有可编辑需规能够进入组织器配置。
3. 未完成配置或未创建会话时，不能进行会话输入、保存会话产物或另存为。
4. 没有当前 Turn 时，`当前 Turn` 页签给出明确提示，不展示空白审计页。
5. 已发布到 P3 的需规显示 `已发布锁定`，不允许直接配置、会话输入、删除或保存覆盖。
6. 顶部状态条在五个页签中保持一致，始终能看出当前激活需规和作业层级。
7. 调用日志在无会话时展示明确空状态，有会话时按当前会话展示 Provider / Runner 调用证据。
8. 流程阻断提示使用业务语言，不再把 `404`、`409`、`session not found` 作为主要用户提示。

## 11. 本补充不包含的内容

本补充不处理以下事项：

1. 不改造 BasePlatform 平台交换层。
2. 不改变 P2 发布后由 P3 通过交换层发现和消费的模式。
3. 不新增 BPMN、流程引擎或跨阶段工作流编排。
4. 不重写当前 Lab 五个页签的信息架构。
5. 不合并 `需求规格说明管理` 与 `组织器配置` 两个页签。
6. 不直接修改主设计文档，待用户确认后再回写。

## 12. 待确认点

本轮建议用户重点确认以下设计判断：

1. 是否认可作业状态管理器作为 P2 Lab 内部轻量模块，而不是平台级工作流引擎。
2. 是否认可 `组织器配置 / 会话管理 / 当前 Turn` 三个页签按前置条件阻断，`调用日志` 允许空状态降级。
3. 是否认可顶部增加 `当前作业状态条`，把当前需规、编辑态、配置态、会话态、Turn 态和 P3 状态统一展示。
4. 是否认可已发布需规默认锁定，后续修改走修订草稿。
