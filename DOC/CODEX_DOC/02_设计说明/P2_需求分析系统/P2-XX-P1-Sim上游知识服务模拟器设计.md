## 1. 设计定位

`XX-P1-Sim` 是 `P1` 上游知识服务的模拟输入台，命名沿用现有 `XX-Pn-Sim` 体系。

它的存在原因很单一：真实 `P1` 尚不能稳定向 `P2` 输出领域知识，因此首版 `P2` 在联调和验收时需要一个可注册、可查询、可复现的 P1 替身。这个替身只提供 `P1` 本应提供的知识输入，不替代 `P2` 的专家交互、需求规格编写、问答补齐、缺口检查或冻结流程。

`XX-P1-Sim` 的主对象不是软件项目，也不是需求规格样例，而是领域知识。例如：

- `空域规划领域知识`
- `政务服务领域知识`
- `供应链协同领域知识`

这些领域知识可以支撑多个后续目标软件。用户进入 `P2` 后，可以基于 `空域规划领域知识` 编写 `空域运算软件`、`无人机任务规划软件` 或其他需求规格；目标软件名称由 `P2` 专家工作台确认，不由 `XX-P1-Sim` 预设。

## 2. 首版目标

首版只完成 `P1 -> P2` 知识输入链路的模拟：

1. `XX-P1-Sim` 可作为 P1 知识服务注册给 `P2`。
2. `P2` 可发现已注册的 `XX-P1-Sim`。
3. `XX-P1-Sim` 可返回领域知识目录。
4. 用户在 `P2` 主界面选择一个领域知识。
5. `P2` 按领域拉取知识包，获得概念、规则、流程、约束和证据片段。
6. `P2` 编辑器进入普通需求规格编写体验，来源无感。

首版不要求真实 `P1` 接入，不要求真实 LLM 接入，不要求在 `XX-P1-Sim` 中生成任何 P2 文档或专家回答。

## 3. 边界纠正

`XX-P1-Sim` 必须排除以下能力：

| 排除项 | 原因 |
| --- | --- |
| 模拟专家输入 | 专家输入通过 `P2` 主界面真实测试，不属于上游系统输入端口。 |
| 生成需求规格正文 | 需求规格正文是 `P2` 的产物，不能由 P1 模拟器生成。 |
| 生成 `RequirementAuthoringSession` | 会话属于 `P2` 编写过程，`XX-P1-Sim` 只提供知识。 |
| 问答补齐、自动补齐 | 这是 `P2` 的交互和推理能力，不是 P1 输出。 |
| 缺口检查、冻结、P3 可消费包 | 这是 `P2` 输出链路，不能放入 P1 模拟器。 |
| 成型软件目录 | P1 知识库输出领域知识，不输出“空域协同规划软件”这类目标软件。 |

## 4. 真数据与模拟数据边界

| 数据对象 | 首版来源 | 性质 | 说明 |
| --- | --- | --- | --- |
| 需求规格模板 | 本地模板配置 | 真 | 软件级、平台级模板可替换，但不由 `XX-P1-Sim` 生成。 |
| `P2` 专家工作台 | 正式页面与正式流程 | 真 | 问答、表单、正文生成、检查和冻结都属于 `P2`。 |
| P1 服务注册 | `XX-P1-Sim` | 模拟 | 以稳定服务发现对象暴露给 `P2`。 |
| 领域知识目录 | `XX-P1-Sim` | 模拟 | 返回领域知识列表，不返回软件项目或需求样例。 |
| P1 发布态知识包 | `XX-P1-Sim` | 模拟但按真形态造 | 包含概念、规则、流程、约束、证据和来源信息。 |
| 调用日志与固定种子 | `XX-P1-Sim` | 模拟运行证据 | 用于联调复现和机测取证。 |

## 5. 输出对象模型

### 5.1 服务注册

`P1KnowledgeProviderRegistration` 表示一个可被 `P2` 发现的上游知识服务。

关键字段：

- `provider_id`：如 `xx-p1-sim`
- `provider_name`：如 `XX-P1-Sim`
- `provider_kind`：`p1_knowledge_provider`
- `status`：`online` / `offline`
- `capabilities`：至少包含 `domain_catalog`、`knowledge_archive`
- `version`：固定模拟版本，如 `v1.0`

### 5.2 领域知识目录

`P1DomainKnowledgeCatalog` 表示 P1 可提供的领域知识列表。

关键字段：

- `domain_id`
- `domain_name`
- `domain_summary`
- `archive_version`
- `concept_count`
- `rule_count`
- `process_count`
- `evidence_count`

首版默认可包含：

- `airspace-planning`：`空域规划领域知识`
- `government-service`：`政务服务领域知识`
- `supply-chain-collaboration`：`供应链协同领域知识`

### 5.3 发布态知识包

`P1DomainKnowledgeArchive` 表示 `P2` 选择领域后拉取的知识包。

关键字段：

- `provider_id`
- `domain_id`
- `archive_id`
- `archive_version`
- `concepts`
- `entities`
- `rules`
- `processes`
- `constraints`
- `evidence_refs`
- `published_at`

知识包必须保持“领域知识”语义。以 `空域规划领域知识` 为例，可以包含：

- 业务对象：空域单元、冲突窗口、协同任务
- 业务规则：冲突窗口未确认时不得发布规划结果
- 流程知识：任务创建、冲突识别、会签确认、结果发布
- 证据片段：术语说明、规则依据、流程节点描述

### 5.4 调用日志

`P1SimCallLog` 用于证明 `P2` 何时请求了哪个领域知识，便于联调和自测。

关键字段：

- `call_id`
- `called_at`
- `method`
- `path`
- `domain_id`
- `status_code`
- `archive_version`

## 6. API 入口

首版 API 可以采用独立 `XX-P1-Sim` 路由族，避免把它写成 `P2` 文档生成接口：

- `POST /api/xx-p1-sim/register`
- `GET /api/xx-p1-sim/domains`
- `GET /api/xx-p1-sim/domains/{domain_id}/knowledge`
- `POST /api/xx-p1-sim/reset`
- `GET /api/xx-p1-sim/logs`

`P2` 侧只需要接入知识源发现和领域知识绑定：

- `GET /api/requirement-authoring/knowledge-providers`
- `POST /api/requirement-authoring/knowledge-bindings`

不在 `XX-P1-Sim` 中新增以下接口：

- `scenario-turns`
- `auto-complete`
- `freeze`
- `materialize requirement document`

这些接口即使未来存在，也应归属 `P2` 自身的需求规格编写链路。

## 7. 页面与交互边界

### 7.1 `XX-P1-Sim` 页面

目标路由：

- `/xx-p1-sim`

页面职责：

- 显示服务注册状态
- 显示领域知识目录
- 预览发布态知识包
- 固定和重置模拟种子
- 显示调用日志
- 明确输出契约是 P1 知识，不是 P2 文档

### 7.2 `P2` 知识绑定入口

目标位置：

- `P2` 专家需求规格编写工作台的启动或知识绑定区域

页面职责：

- 发现 `XX-P1-Sim` 或真实 `P1`
- 让用户选择领域知识
- 拉取并绑定领域知识包
- 进入普通需求规格编辑器

### 7.3 `P2` 普通编辑器

进入普通编辑器后，界面只能显示来源无感的信息，例如：

- `领域知识已绑定`
- `知识背景已加载`

不得显示：

- `XX-P1-Sim`
- `mock`
- `模拟`
- `发生器`
- fixture id
- 规则引擎名

## 8. 与 LLM / Brainstorming 的关系

`XX-P1-Sim` 不负责 Brainstorming。

后续如果 `P2` 接入大模型，它应在 `P2` 的问答和规格生成链路中消费已绑定的领域知识，并输出经过 `P2` 校验的结构化补丁。`XX-P1-Sim` 只提供知识背景，不能直接写正文、补字段或决定冻结。

## 9. 验收口径

首版验收应覆盖：

1. `/xx-p1-sim` 页面可达。
2. `XX-P1-Sim` 能注册为 P1 知识服务。
3. `P2` 能发现该服务。
4. `XX-P1-Sim` 能返回领域知识目录。
5. 目录中出现 `空域规划领域知识`，不出现 `空域协同规划软件` 这类成型软件。
6. `P2` 能选择 `空域规划领域知识` 并拉取知识包。
7. 知识包包含概念、规则、流程、约束和证据片段。
8. `P2` 普通编辑器可继续由用户确定目标软件名称，例如 `空域运算软件`。
9. `P2` 普通编辑器不暴露 `XX-P1-Sim`、`mock`、`模拟`、`发生器` 等来源概念。
10. `XX-P1-Sim` 能固定版本、重置种子并保留调用日志。

## 10. 设计结论

`XX-P1-Sim` 的核心价值是补齐 `P1` 尚未稳定输出时 `P2` 缺失的上游知识输入端口。

它不是 P2 的样例数据发生器，也不是专家输入模拟器。它向外提供的是“P1 发布态领域知识”，`P2` 消费这些知识后，仍按正常专家工作台流程生成需求规格说明。
