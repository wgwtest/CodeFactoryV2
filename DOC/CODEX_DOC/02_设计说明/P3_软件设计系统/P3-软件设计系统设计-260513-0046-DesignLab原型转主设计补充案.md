## 1. 本补充案目的

当前 `P3 Design Lab` v6 原型已经基本满足使用要求。下一步不能只把原型图片作为附图保留，而应把其中已经收敛的产品结构、对象关系、动作边界和解耦原则补入 `P3 软件设计系统设计.md`。

本补充案用于回答：

1. v6 原型中的七个 Lab 视图分别属于哪个业务模块。
2. 哪些内容应进入主软件设计说明，哪些只应保留在原型包。
3. 软件设计说明正文、结构化设计基线、`P4` 工单投影和回合日志如何保持同源但解耦。
4. 前端 ViewModel、API 映射和关键流程需要补充哪些正式设计。
5. 后续归并主文档时，应该把每一段放到哪个章节。

## 2. 归并原则

### 2.1 原型不是事实源，设计模型才是事实源

v6 原型只能作为界面布局和交互口径的证据，不应成为业务事实源。主文档需要吸收的是以下内容：

- 需规列表与关联软设列表的对象关系。
- 一个需规对象可以关联多份软件设计说明。
- 软件设计说明工作区同时支持文档视图和结构化数据视图。
- `P4` 投影是从设计基线派生出的下游工单组织形态。
- 当前 Turn、检查评审和运行日志是过程观察与治理视图。
- 页面动作应靠近对象，不在顶部堆放重复动作。

主文档不应吸收以下内容：

- v6 原型中的具体像素、颜色、间距和卡片尺寸。
- 截图编号。
- 静态样例文案。
- 只为原型演示服务的装饰性状态。

### 2.2 `Design Lab` 是组合入口，不是第七个业务模块

`P3 Design Lab` 的七个视图必须继续归属于现有六个业务模块：

| Lab 视图 | 主归属模块 | 辅助模块 | 主文档归属 |
| --- | --- | --- | --- |
| 需规输入与关联软设 | 软件设计输入模块 | 软件设计说明编写模块 | `5.5`、`6.4`、`7.3` |
| 软设工作区文档视图 | 软件设计说明编写模块 | 软件设计会话与运算模块、设计评审与冻结模块 | `5.5`、`6.6`、`7.7` |
| 软设工作区结构化数据视图 | 软件设计基线模块 | 设计投影与交换模块 | `5.5`、`6.7`、`7.6` |
| `P4` 工单投影树 | 设计投影与交换模块 | 软件设计基线模块 | `5.5`、`6.8`、`7.8` |
| 当前 Turn 回合列表 | 软件设计会话与运算模块 | 软件设计说明编写模块、软件设计基线模块 | `5.5`、`6.5`、`7.5` |
| 检查评审门禁 | 设计评审与冻结模块 | 软件设计基线模块、设计投影与交换模块 | `5.5`、`6.9`、`7.9` |
| 运行日志审计 | 软件设计会话与运算模块 | 全部模块 | `5.5`、`6.5`、`10.6` |

因此，归并主文档时不新增 `DesignLabService`、`DesignLabDomain` 或独立持久化表。前端可以有 `P3DesignLabPage` 和 `p3DesignLabWorkbenchAdapter`，但它们只能做页面编排和视图模型转换。

### 2.3 同源数据的三种展示形态

主设计需要明确：软设工作区文档视图、软设工作区结构化数据视图、`P4` 工单投影树不是三个互相独立的数据源，而是同一套设计状态的三种展示与消费形态。

```text
SoftwareDesignBaseline v2
  -> 软件设计说明文档视图
  -> 结构化设计数据视图
  -> P4 工单投影树
```

其中：

- 软件设计说明文档视图面向人审阅，强调 A4 正文、章节、版本和正文补丁。
- 结构化设计数据视图面向系统校核，强调模块、接口、数据对象、状态、追溯和投影候选。
- `P4` 工单投影树面向下游交接，强调工具供给任务的组织层级、就绪状态和来源约束。

三者允许展示粒度不同，但不能各自维护独立事实。任一视图触发修改时，都必须进入后端命令并回写或重新派生 `SoftwareDesignBaseline v2`、正文投影或工单投影。

## 3. 建议补入主文档第 5 章的内容

### 3.1 补充 `5.5.2 页面结构`

建议在 `5.5.2 页面结构` 后补充以下设计：

`P3 Design Lab` 的左侧导航不只是视觉 Tab，而是对 `P3` 软件设计过程的任务切片。七个视图按工作顺序构成：

```text
需规输入与关联软设
  -> 软设工作区
    -> P4 工单投影树
      -> 当前 Turn
        -> 检查评审
          -> 运行日志
```

但这个顺序不是强制线性流程。用户可以在不同视图间切换，以观察同一设计会话的不同侧面。工作台必须保持以下规则：

- 默认进入软设工作区。
- 没有选中需规对象时，软设工作区显示正式空态。
- 选中需规对象后，右侧展示该需规已经关联的多份软件设计说明。
- 打开或新建软件设计说明后，软设工作区使用该软设作为当前工作对象。
- 结构化数据视图和 `P4` 工单投影树默认跟随当前软设对象。
- 当前 Turn、检查评审和运行日志默认跟随当前设计会话。

### 3.2 补充 `5.5.4 左侧 Lab 导航`

建议将现有导航项说明细化为以下七项：

| 导航项 | 视图目标 | 主要对象 | 不应出现的内容 |
| --- | --- | --- | --- |
| 需规输入 | 管理可进入 `P3` 的需求规格说明和关联软设 | 需规列表、选中需规、关联软设列表 | 顶部重复的新建、打开按钮 |
| 软设工作区 | 编写、查看和修订当前软件设计说明 | A4 正文、章节对象、结构化数据、章节交互 | 无意义的生成草稿动作 |
| `P4` 投影 | 查看当前软设可派生出的下游工单树 | 投影树、模块节点、任务节点、就绪状态 | 把投影和工单树拆成两个事实源 |
| 当前 Turn | 查看和提交自然语言设计回合 | 回合列表、当前回合、CLI、影响范围 | 把回合隐藏在软设正文下方 |
| 检查评审 | 判断当前设计是否可冻结或可交接 | 阻断项、警告项、通过项、评审结论 | 设计生成动作 |
| 运行日志 | 审计 API、模型、检查器和状态迁移 | 日志事件、调用记录、错误重试 | 正式设计结论 |

说明：v6 原型当前左侧实际保留六个主导航，其中软设工作区内含文档视图和结构化数据视图。主文档可以采用“六个主导航 + 软设工作区二级视图”的表述，避免把结构化数据误认为独立主导航。

### 3.3 补充 `5.5.5 软设工作区视图`

建议把软设工作区明确成双视图工作区：

```text
软设工作区
  -> 文档视图
  -> 结构化数据视图
```

文档视图负责：

- 展示 A4 软件设计说明正文。
- 支持章节选中和章节级交互。
- 支持保存草稿、提交复核。
- 展示当前章节对应的设计对象、追溯来源和检查标记。

结构化数据视图负责：

- 展示架构、模块、接口、数据对象、状态机、部署约束和追溯关系。
- 展示结构化字段是否已从正文或模型结果同步。
- 支持生成 `P4` 投影候选。

文档视图和结构化数据视图的切换应位于软设工作区标题栏，因为它切换的是整个工作区的展示形态，不是左侧章节列表的局部过滤。

软设工作区动作收敛规则：

- 已经存在软设草稿时，不显示“生成草稿”。
- 正文编辑状态下允许“保存草稿”。
- 达到检查条件时允许“提交复核”。
- 结构化数据默认与正文和基线同步，不显示“同步正文”。
- 结构化补全由后端生成或 Turn 承担，不显示无边界的“补全结构”。
- 生成 `P4` 投影候选是结构化数据视图的有效动作。

### 3.4 补充 `5.5.6 当前 Turn 视图`

当前 Turn 视图需要从“当前一个回合”扩展为“回合列表 + 当前回合详情 + CLI”的组合视图。

原因是 `P3` 与 `P2` 不同：`P3` 的主输入是需规文档，软设可以自动生成，回合不是唯一工作对象。但只保留当前回合会让从需规到软设的变化过程不可追踪。因此主设计应要求：

- 左侧或上部展示回合列表。
- 当前回合展示用户输入、系统解释、影响范围、设计基线增量、正文补丁和投影影响。
- CLI 输入框只提交新的设计修订意图。
- 回合列表用于解释软设为何变成当前状态。
- 回合不得直接改写正文或基线，必须通过设计轮次引擎和归并服务。

### 3.5 补充 `5.5.7 P4 工单投影树`

`P4` 投影视图应改称 `P4 工单投影树` 或在正文中明确：

```text
P4 投影 = 从 P3 设计基线派生出的下游工单组织树
```

该视图不是普通列表。它应以树型结构表达：

- 投影包。
- 模块组或设计分支。
- 模块工单。
- 工具供给任务或接口实现任务。
- 每个节点的来源需求、来源设计对象、就绪状态和阻断原因。

主文档应避免同时使用“P4 投影”和“工单树”指代两个对象。正式对象可以命名为 `ModuleWorkorderProjectionTree`，其数据来源仍是 `ModuleWorkorderProjection` 或 `ModuleWorkorderBatchPackage`。

## 4. 建议补入主文档第 6 章的内容

### 4.1 软件设计输入模块补充

`6.4 软件设计输入模块` 应补充需规列表管理职责。

首版输入模块不只提供一个当前输入包，还应支持列出可进入 `P3` 的需求规格说明对象。每个需规对象至少包含：

- 需规标识。
- 需规标题。
- 来源 `P2` 冻结包。
- 创建人。
- 创建时间。
- 最近更新时间。
- 当前状态，例如已创建、待设计、设计中、待复核、已完成、已发布。
- 可设计性状态，例如可设计、待复核、阻断。
- 已关联软件设计数量。

选中一条需规后，输入模块提供该需规的详情和关联软设查询入口，但不负责创建或修改软件设计说明正文。

### 4.2 软件设计说明编写模块补充

`6.6 软件设计说明编写模块` 应补充“一条需规可以关联多份软设”的对象关系。

建议规则：

- 一个需求规格说明可以创建多份软件设计说明。
- 每份软件设计说明拥有独立版本、状态、创建时间、更新时间和设计会话。
- 关联软设列表支持新建、编辑、删除。
- 发布、冻结、提交复核等治理动作不在需规输入视图完成，应进入软设工作区或评审冻结模块。
- 删除软设必须遵循后端状态约束，已冻结或已发布软设不能被普通删除动作直接移除。

### 4.3 软件设计会话与运算模块补充

`6.5 软件设计会话与运算模块` 应补充回合列表作为正式查询对象。

当前 Turn 不是单条临时 UI 状态，而应来源于 `SoftwareDesignTurn` 列表。每条回合至少记录：

- 回合标识。
- 所属设计会话。
- 触发来源：初始生成、CLI 修订、章节交互、检查修复、投影生成。
- 用户输入或系统触发说明。
- 解释出的设计意图。
- 影响范围。
- 基线增量摘要。
- 正文补丁摘要。
- 投影影响摘要。
- 运行状态和错误信息。
- 创建时间。

这样可以解释“需规进入 P3 后，软设如何逐步生成和变化”。

### 4.4 软件设计基线模块补充

`6.7 软件设计基线模块` 应补充结构化数据视图的权威边界。

结构化数据视图展示的模块、接口、数据对象、状态机和追溯关系必须来自 `SoftwareDesignBaseline v2`。前端不允许通过解析 A4 正文自行拼装正式结构化设计对象。

当用户在结构化数据视图中触发 `生成投影候选` 时，后端应：

1. 读取当前设计基线。
2. 校验投影所需字段。
3. 生成或刷新投影候选。
4. 返回投影树预览和缺失项。
5. 记录运行日志。

### 4.5 设计投影与交换模块补充

`6.8 设计投影与交换模块` 应把 `P4` 投影定义为树型投影，而不是扁平工单列表。

树型投影至少包含四类节点：

| 节点类型 | 含义 | 来源 |
| --- | --- | --- |
| `projection_package` | 当前软设派生出的投影包 | 设计会话、设计基线 |
| `module_group` | 模块组、领域分支或设计分支 | 架构设计、模块划分 |
| `module_workorder` | 可交给 `P4` 的模块工单 | 模块职责、接口、数据对象 |
| `supply_task` | 工具供给或实现准备任务 | 工单拆解、接口约束、验收要点 |

每个节点至少包含：

- 节点标识。
- 标题。
- 来源设计对象。
- 来源需求条款。
- 就绪状态。
- 阻断原因。
- 下游目标。

## 7. 建议补入主文档第 9 章的关键流程

### 7.1 从需规列表进入软设工作区

```text
用户进入 P3 Design Lab
  -> 前端读取可消费需规列表
    -> 用户选择一条需规
      -> 前端读取需规详情和关联软设列表
        -> 用户打开既有软设或新建软设
          -> 前端加载软设工作区
            -> 展示文档视图或结构化数据视图
```

流程规则：

- 选择需规不等于创建软设。
- 新建软设只建立软设对象和设计会话，不应自动发布。
- 打开软设后，软设工作区才成为主工作对象。

### 7.2 初始生成过程

```text
新建软设
  -> 建立设计会话
    -> 读取 P2 冻结包和输入快照
      -> 执行初始设计 Turn
        -> 生成 SoftwareDesignBaseline v2 初稿
          -> 渲染软件设计说明 A4 正文草稿
            -> 生成 P4 投影候选或等待人工触发
              -> 写入回合列表和运行日志
```

该流程用于补足原型中“软设为何出现”的过程解释。即使界面默认看到已有草稿，系统设计也必须说明草稿来自初始设计 Turn。

### 7.3 文档视图与结构化数据视图切换

```text
用户在软设工作区切换视图
  -> 前端不重新创建业务对象
  -> 前端读取同一 software_design_id 的正文投影或结构化基线摘要
  -> 保存草稿只影响正文补丁
  -> 生成投影候选只读取设计基线并刷新投影候选
```

该流程保证视图切换不是业务状态切换。

### 7.4 `P4` 工单投影树生成过程

```text
用户在结构化数据视图触发生成投影候选
  -> 后端读取 SoftwareDesignBaseline v2
    -> 校验模块、接口、数据对象、约束和追溯
      -> 生成 P4 工单投影树
        -> 返回投影树和阻断项
          -> 记录运行日志
```

该流程只生成候选或预览，不等于正式推送 `P4`。

## 10. 设计结论

v6 原型应作为 `P3 Design Lab` 的界面基线，但归入主软件设计说明时，应抽取为对象关系、模块边界、ViewModel、API 和运行流程设计。

最关键的主设计结论是：

```text
P3 Design Lab 是同一设计会话的组合观察与操作入口；
需规、软设正文、结构化设计基线、P4 工单投影、回合、评审和日志分别归属现有业务模块；
页面通过 Adapter 和 ViewModel 解耦展示，不能生成新的业务事实源。
```
