# P3 软件设计系统设计 - Inspector 基类与分型展示补充案

## 1. 补充目标

本补充案定义软设工作区右侧 `Inspector` 的目标态组件抽象。`Inspector` 不是普通详情栏，也不是若干固定面板的堆叠，而是 `Canvas` 长卷中所有可选中对象的统一上下文工作区。它负责回答三个问题：

1. 当前选中的是什么对象。
2. 该对象从哪里来、受什么约束、处于什么状态。
3. 用户围绕该对象可以执行哪些局部动作。

`Inspector` 必须支持后续形态节点持续增加和多分支并行开发，因此需要从当前“按 `kind` 条件渲染”的方式升级为“基础壳层 + 分型渲染器 + 展示协议”的结构。

## 2. 设计原则

`Inspector` 设计遵循以下原则：

- 统一外壳：所有对象共用标题、状态、属性、追溯、质量约束和动作区的基础布局。
- 分型展示：不同对象类型通过独立 Renderer 展示专属内容，不在主页面组件里堆叠业务分支。
- 数据先行：`Inspector` 只消费 `InspectorViewModel`，不查询 DOM、不读取 Canvas 私有图元、不反向解析 A4 正文。
- 动作回派：所有按钮、命令和参数提交都回到所属模块命令，不在 `Inspector` 内直接修改业务事实。
- 可扩展：新增形态节点或内部对象时，只新增对象 ViewModel 与 Renderer 注册，不改 `BaseInspectorPanel`。
- 紧凑表达：`Inspector` 是高密度工作面板，标题和属性字号必须克制，不使用夸张标题重复展示关系类型、输入输出等字段。

## 3. 总体组件结构

目标态组件结构如下：

```text
SelectedObjectInspector
  -> InspectorRendererRegistry
    -> BaseInspectorPanel
      -> InspectorHeader
      -> InspectorPropertyGrid
      -> InspectorTracePanel
      -> InspectorQualityPanel
      -> InspectorActionList
      -> type-specific body slot

InspectorRendererRegistry
  -> StageInspectorRenderer
  -> StageRelationInspectorRenderer
  -> DocumentBlockInspectorRenderer
  -> FunctionNodeInspectorRenderer
  -> ArchitectureElementInspectorRenderer
  -> TechnicalImplementationInspectorRenderer
  -> PresentationShapeInspectorRenderer
  -> ProjectionNodeInspectorRenderer
  -> WorkspaceSummaryInspectorRenderer
```

`SelectedObjectInspector` 只负责接收当前选择对象和命令 dispatcher。它不得包含具体业务对象的长 JSX 分支。具体对象展示由 `InspectorRendererRegistry` 根据 `selection.kind` 和 `selection.entityType` 分发。

`BaseInspectorPanel` 是共性基类组件。它不理解 P3 业务，只理解标准检查器区块和标准属性组：

- `header`：对象标题、对象类型、状态、来源阶段。
- `propertyGroups`：按 `Identity`、`LayoutTransform`、`Lifecycle`、`Trace`、`Content`、`Quality`、`Relation`、`Actions` 等分组展示的属性集合。
- `summary`：对象摘要或关键说明。
- `trace`：来源追溯、下游影响、关联节点。
- `quality`：检查项、阻断项、待确认项。
- `actions`：动作列表和主动作。
- `body`：由具体 Renderer 填充的专属内容。

## 4. Inspector ViewModel

`Inspector` 需要从 `DesignMorphSelection` 升级为更明确的 `InspectorViewModel`。`DesignMorphSelection` 仍可作为 Canvas 事件上报协议，但进入 `Inspector` 前应由适配器转换为标准 ViewModel。

```text
InspectorViewModel
  id
  kind
  entityType
  title
  subtitle
  status
  summary
  stageId
  sourceRefs
  qualityRefs
  propertyGroups[]
  traceGroups[]
  qualityGroups[]
  actions[]
  rendererKey
  payload
```

字段说明：

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `id` | 当前选择对象 ID | 前端选择状态 ID，不等于后端主键时必须在 `payload` 中注明映射 |
| `kind` | 选择对象类型 | 例如 `stage`、`stage_relation`、`design_block`、`function_node` |
| `entityType` | 业务实体类型 | 例如 `software_design_document`、`software_function_tree` |
| `rendererKey` | Renderer 注册键 | 优先由适配器给出，避免 Renderer 自行猜测业务类型 |
| `propertyGroups` | 标准属性组 | 按共性属性组组织，类似 UE Inspector 中的 `Name`、`Transform`、`Tags` 等分区 |
| `traceGroups` | 追溯分组 | 上游来源、下游影响、关联形态分组表达 |
| `qualityGroups` | 质量分组 | 待确认、阻断、警告、通过项 |
| `actions` | 可执行动作 | 只描述动作入口，不直接实现业务写入 |
| `payload` | 类型专属负载 | 只能由对应 Renderer 消费，基础壳层不得依赖其内部结构 |

`propertyGroups` 是 Inspector 的核心共性抽象，不应退化成一个无分类的键值列表。`payload` 允许分型，但不得作为无约束垃圾桶。每个 Renderer 必须定义自己的 payload 类型，例如 `StageRelationInspectorPayload`、`DocumentBlockInspectorPayload`、`FunctionNodeInspectorPayload`。

## 5. 共性属性组模型

`Inspector` 需要类似 UE Inspector 的共性属性分组能力。不同 P3 对象虽然业务含义不同，但都应尽量落到统一属性组里，避免每个 Renderer 自行发明字段布局。

`InspectorPropertyGroup` 至少包含：

```text
InspectorPropertyGroup
  groupId
  title
  priority
  collapsedByDefault
  applicability
  fields[]

InspectorPropertyField
  fieldId
  label
  value
  valueType
  readonly
  unit
  source
  editableCommand
  visibility
```

字段规则：

| 字段 | 含义 |
| --- | --- |
| `groupId` | 属性组 ID，例如 `identity`、`layoutTransform`、`relation` |
| `priority` | 展示顺序，`identity` 和 `layoutTransform` 通常靠前 |
| `applicability` | 适用对象类型，例如 `canvas_object`、`stage_relation`、`document_block` |
| `valueType` | `text`、`number`、`enum`、`boolean`、`reference`、`status`、`command` |
| `source` | 属性来源，例如 `canvasViewportState`、`SoftwareDesignPackage`、`DesignMorphSelection` |
| `editableCommand` | 如果允许编辑，必须指向模块命令，不允许直接写 state 或 DTO |
| `visibility` | 是否展示，避免不可适用字段占位 |

### 5.1 Identity 属性组

`Identity` 是所有可选中对象必须具备的属性组，用于表达“它是谁”。

典型字段：

- `name`：显示名称。
- `objectId`：对象 ID。
- `kind`：选择对象类型。
- `entityType`：业务实体类型。
- `stageId`：所属形态节点。
- `ownerModule`：所属业务模块。
- `version`：版本或快照号。

适用对象：

- 阶段节点。
- 阶段关系。
- 文档块。
- 功能节点。
- 架构元素。
- 技术实现对象。
- 展示形态对象。
- `P4` 投影节点。

`name` 和 `objectId` 是基础检查属性，不应只散落在标题里。标题用于快速阅读，`Identity` 属性组用于稳定检查和复制引用。

### 5.2 LayoutTransform 属性组

`LayoutTransform` 对应 UE Inspector 中的 `Transform`。它表达对象在工作区中的展示位置和尺寸，但不表达业务事实。

典型字段：

- `x`
- `y`
- `width`
- `height`
- `scale`
- `zIndex`
- `locked`
- `visible`

适用对象：

- Canvas 上可拖拽和缩放的阶段节点。
- Canvas 上有几何命中区域的阶段关系箭头。
- 后续若内部节点支持自由布局，功能节点、架构节点、展示候选也可具备该属性组。

约束：

- `LayoutTransform` 来源于 `canvasViewportState` 或局部布局状态，不写入 `SoftwareDesignPackage`。
- 修改 `LayoutTransform` 只能改变前端展示布局，不得改变软设正文、设计基线、投影树或冻结判断。
- 如果支持编辑，必须通过 `workspace_layout` 类命令或本地布局偏好命令执行。

阶段关系箭头不一定具备完整矩形变换，但应具备 `RelationGeometry`，可作为 `LayoutTransform` 的专门子型：

```text
RelationGeometry
  fromPoint
  toPoint
  controlPoints
  hitWidth
  visualWidth
```

### 5.3 Lifecycle 属性组

`Lifecycle` 表达对象的生成、确认、冻结和发布状态。

典型字段：

- `status`
- `createdAt`
- `updatedAt`
- `createdBy`
- `confirmedAt`
- `frozenAt`
- `publishedAt`
- `reviewState`

适用对象：

- 软件设计会话。
- 软设文档。
- 设计基线对象。
- 功能节点。
- 技术实现对象。
- 投影节点。
- 阶段关系执行结果。

`Lifecycle` 不等同于 UI 选中态。选中态是前端状态，生命周期是业务或候选对象状态。

### 5.4 Trace 属性组

`Trace` 表达来源和下游影响。

典型字段：

- `sourceRefs`
- `upstreamObjects`
- `downstreamObjects`
- `requirementClauseRefs`
- `designSectionRefs`
- `functionNodeRefs`
- `technicalObjectRefs`
- `projectionNodeRefs`

适用对象：

- 所有从 `P2` 需规或 `SoftwareDesignPackage` 派生的对象。

`Trace` 字段必须尽量使用对象引用，不使用纯文本拼接。需要展示人类可读文本时，由适配器根据引用补充 label。

### 5.5 Content 属性组

`Content` 表达对象自身内容摘要。

典型字段：

- `title`
- `summary`
- `description`
- `bodyExcerpt`
- `sectionTitle`
- `nodeLabel`
- `contractSummary`

适用对象：

- 文档块。
- 功能节点。
- 架构元素。
- 技术实现对象。
- 展示形态对象。
- 投影节点。

`Content` 不应承载整篇文档或长正文。长正文继续由 A4 文档形态或专门编辑器承载。

### 5.6 Quality 属性组

`Quality` 表达检查、覆盖、缺口和阻断。

典型字段：

- `coverageState`
- `blockingIssues`
- `warnings`
- `pendingConfirmations`
- `qualityRefs`
- `reviewGate`
- `lastCheckResult`

适用对象：

- 文档块。
- 功能节点。
- 架构元素。
- 技术实现对象。
- 展示形态对象。
- 投影节点。
- 阶段关系。

`Quality` 字段应保持可追溯，不只显示“通过 / 不通过”，还要能定位对应检查项。

### 5.7 Relation 属性组

`Relation` 专门表达阶段关系、对象关系和映射边。

典型字段：

- `from`
- `to`
- `relationType`
- `inputSummary`
- `outputSummary`
- `strategy`
- `mappingRule`
- `executionState`
- `lastRunAt`

适用对象：

- 阶段关系箭头。
- 需规到软设段落映射。
- 软设段落到功能节点映射。
- 功能节点到架构元素映射。
- 架构元素到技术实现映射。
- 技术实现到展示形态或 `P4` 投影映射。

`Relation` 属性组不替代 `Trace`。`Trace` 关注来源链，`Relation` 关注当前被选中的边或映射本身。

### 5.8 Actions 属性组

`Actions` 表达对象可执行命令。它可以作为面板底部动作区，也可以作为属性组展示。

典型字段：

- `primaryAction`
- `secondaryActions`
- `dangerActions`
- `disabledReason`
- `commandTarget`
- `confirmPolicy`

适用对象：

- 所有可选中对象。

动作展示必须遵守命令回派规则，不在属性组里直接执行业务写入。

### 5.9 属性组适用矩阵

| 对象类型 | Identity | LayoutTransform | Lifecycle | Trace | Content | Quality | Relation | Actions |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 阶段节点 | 必须 | 必须 | 可选 | 必须 | 必须 | 可选 | 不适用 | 必须 |
| 阶段关系箭头 | 必须 | 必须，使用 `RelationGeometry` | 可选 | 必须 | 可选 | 必须 | 必须 | 必须 |
| 需规 / 软设文档块 | 必须 | 不适用 | 可选 | 必须 | 必须 | 必须 | 可选 | 必须 |
| 功能节点 | 必须 | 可选 | 必须 | 必须 | 必须 | 必须 | 可选 | 必须 |
| 架构元素 | 必须 | 可选 | 必须 | 必须 | 必须 | 必须 | 可选 | 必须 |
| 技术实现对象 | 必须 | 可选 | 必须 | 必须 | 必须 | 必须 | 可选 | 必须 |
| 展示形态对象 | 必须 | 可选 | 必须 | 必须 | 必须 | 必须 | 可选 | 必须 |
| `P4` 投影节点 | 必须 | 可选 | 必须 | 必须 | 必须 | 必须 | 可选 | 必须 |

## 6. 基类组件职责

`BaseInspectorPanel` 承担以下职责：

1. 渲染统一的对象抬头。
2. 渲染标准属性组，尤其是 `Identity`、`LayoutTransform`、`Lifecycle`、`Trace`、`Content`、`Quality`、`Relation` 和 `Actions`。
3. 渲染来源追溯与下游影响。
4. 渲染质量约束和待确认项。
5. 渲染动作列表。
6. 接收类型专属内容插槽。
7. 处理空态和不可执行态。

`BaseInspectorPanel` 不承担以下职责：

- 不生成软设草稿。
- 不生成 `P4` 投影。
- 不推导功能树或架构层。
- 不直接读写 `SoftwareDesignPackage`。
- 不读取 Canvas 坐标、DOM 节点或 A4 正文文本。
- 不判断业务动作是否成功。

## 7. 分型 Renderer 设计

### 7.1 阶段节点 Renderer

`StageInspectorRenderer` 用于展示七个形态节点本身，包括 `需规文档`、`软设文档`、`功能树`、`分层架构`、`技术实现`、`展示形态` 和 `P4 投影`。

展示内容：

- `Identity`：形态名称、节点 ID、所属设计包、所属模块。
- `LayoutTransform`：节点在 Canvas 中的 `x`、`y`、`width`、`height`、锁定状态。
- `Lifecycle`：当前状态、最近更新时间。
- `Content`：该形态承担的职责摘要。
- `Trace`：该形态从哪些上游对象派生，会影响哪些后续形态。
- 局部动作：定位、生成候选、重新计算、查看追溯等。

阶段节点 Renderer 不展示节点内部全部列表，内部列表由对应形态画布或专属对象 Renderer 处理。

### 7.2 阶段关系 Renderer

`StageRelationInspectorRenderer` 用于展示形态节点之间的箭头关系。它是基础转换、功能拆解、架构归并、技术映射、展示映射和投影生成的统一入口。

展示内容：

- `Identity`：关系名、关系 ID、所属窗口。
- `LayoutTransform`：箭头几何、命中宽度、视觉宽度。
- `Relation`：关系类型、输入、输出、映射规则。
- `Lifecycle`：执行状态、最近执行时间。
- `Quality`：阻断项、待确认项、检查状态。
- 参数区：转换策略、粒度、覆盖策略、候选范围等。
- 步骤区：只显示步骤序号、短标题和状态高亮。
- 主动作：例如 `执行基础转换`、`生成功能树`、`生成投影候选`。
- 审计提示：动作会产生哪类设计包变更或候选结果。

阶段关系 Renderer 不在箭头上显示文字标签。关系名称只在底部状态、窗口标题和 `Inspector` 中表达。

### 7.3 文档块 Renderer

`DocumentBlockInspectorRenderer` 用于展示 A4 文档内部对象，包括需规条款、软设段落、章节标题、列表块和代码块。

展示内容：

- `Identity`：块 ID、块类型、所属文档。
- `Lifecycle`：章节状态、确认状态。
- `Content`：所属章节、正文摘要。
- `Trace`：需规条款到软设段落、软设段落到功能节点或技术对象。
- `Quality`：缺失来源、待确认、覆盖不足、检查阻断。
- 局部动作：定位章节、生成补丁、标记确认、查看关联对象。

文档块 Renderer 不直接编辑正文。正文修改必须通过正文补丁或模块命令进入软件设计说明编写模块。

### 7.4 功能节点 Renderer

`FunctionNodeInspectorRenderer` 用于展示功能树中的功能项。

展示内容：

- `Identity`：功能名称、节点 ID、层级。
- `Lifecycle`：生成状态、确认状态。
- `Content`：功能说明、父节点、子节点数量。
- `Trace`：来源需规条款、对应软设章节、对应架构层和技术实现对象。
- `Quality`：覆盖状态、缺口、待确认点。
- 局部动作：补充功能描述、生成架构映射、查看下游技术承载。

功能节点 Renderer 不直接修改功能树结构。新增、删除、重排功能节点必须通过软件设计基线模块命令。

### 7.5 架构元素 Renderer

`ArchitectureElementInspectorRenderer` 用于展示分层架构中的层、模块、跨层关系和调用边。

展示内容：

- `Identity`：架构元素名称、元素类型、所属层。
- `Lifecycle`：生成状态、确认状态。
- `Content`：职责摘要、边界说明。
- `Trace`：承载的功能节点、与技术实现对象的映射情况。
- `Relation`：依赖关系、被依赖关系、数据流、调用链、状态流。
- 局部动作：补齐接口、生成技术映射、查看跨层影响。

### 7.6 技术实现 Renderer

`TechnicalImplementationInspectorRenderer` 用于展示真实技术承载对象，例如框架、插件、服务、前端组件、数据表、接口、代码包。

展示内容：

- `Identity`：技术对象名称、技术对象类型、所属框架或插件。
- `Lifecycle`：候选状态、确认状态。
- `Content`：实现职责、接口契约摘要。
- `Trace`：覆盖的理论架构层、承载的功能节点。
- `Relation`：框架边界、插件边界、代码包承载关系。
- `Quality`：对 P4 工单拆分的影响和阻断项。
- 局部动作：生成工单候选、查看代码包边界、补充接口契约。

该 Renderer 必须支持一个真实技术对象横跨多个理论层，例如若依同时承载后台管理界面、权限服务和基础数据表，Cesium 同时承载展示层和部分空间功能能力。

### 7.7 展示形态 Renderer

`PresentationShapeInspectorRenderer` 用于展示可见模块的候选展示方式和交互形态。

展示内容：

- `Identity`：展示对象名称、展示对象类型。
- `LayoutTransform`：如果展示对象在 Canvas 或原型画布中可定位，则展示候选位置与尺寸。
- `Content`：候选交互方式、展示说明。
- `Trace`：关联功能节点和技术实现对象。
- `Quality`：对 P6 展示投影的约束和待确认项。
- 局部动作：添加候选形态、标记推荐形态、查看原型映射。

### 7.8 P4 投影节点 Renderer

`ProjectionNodeInspectorRenderer` 用于展示 `P4` 投影树节点。

展示内容：

- `Identity`：投影节点名称、节点 ID、树路径。
- `Lifecycle`：就绪状态、确认状态。
- `Content`：工具包边界、交接对象摘要。
- `Trace`：对应技术对象、功能节点和展示形态。
- `Quality`：阻断项、待拆分项、交接完整性。
- 局部动作：生成工单、标记待拆分、查看交接包。

`P4` 投影节点 Renderer 不直接调用 P4 服务。它只展示 P3 已生成的投影候选和交接动作入口。

## 8. Renderer 注册机制

Renderer 注册表建议采用显式注册：

```text
InspectorRendererRegistry
  register("stage.requirement_specification", StageInspectorRenderer)
  register("stage.software_design_document", StageInspectorRenderer)
  register("stage_relation.requirement_to_design_document", StageRelationInspectorRenderer)
  register("design_block.standard_document_block", DocumentBlockInspectorRenderer)
  register("function_node.software_function", FunctionNodeInspectorRenderer)
  register("architecture_layer.layer", ArchitectureElementInspectorRenderer)
  register("technical_mapping.implementation_unit", TechnicalImplementationInspectorRenderer)
  register("presentation_shape.presentation_candidate", PresentationShapeInspectorRenderer)
  register("projection_node.p4_workorder_node", ProjectionNodeInspectorRenderer)
```

选择 Renderer 时按以下优先级：

1. `rendererKey`
2. `${kind}.${entityType}`
3. `kind`
4. `WorkspaceSummaryInspectorRenderer`

未注册 Renderer 不应导致页面崩溃，应回退到通用对象 Renderer，并提示“该对象类型尚未配置专属检查器”。

## 9. 动作模型

`InspectorAction` 至少包含：

| 字段 | 含义 |
| --- | --- |
| `actionId` | 动作 ID |
| `label` | 展示文本 |
| `intent` | 动作意图，例如 `primary`、`secondary`、`danger` |
| `disabled` | 是否禁用 |
| `disabledReason` | 禁用原因 |
| `command` | 模块命令名称 |
| `parametersSchema` | 可选参数表单 Schema |
| `confirmPolicy` | 是否需要确认 |
| `auditHint` | 执行后产生的审计或候选结果说明 |

动作必须回派到所属模块命令：

```text
InspectorAction
  -> InspectorCommandDispatcher
    -> software_design_authoring
    -> design_baseline
    -> design_projection_exchange
    -> review_quality_gate
```

`Inspector` 不允许直接调用后端 API。页面编排层或模块命令层负责把命令转换为 API 调用和状态刷新。

## 10. 与 Canvas 的关系

Canvas 与 Inspector 的边界如下：

- Canvas 负责命中检测、选中事件、视口状态和形态节点展示。
- Inspector 负责选中对象的上下文解释、属性展示和动作入口。
- Canvas 上报 `DesignMorphSelection`。
- 适配层把 `DesignMorphSelection` 转换为 `InspectorViewModel`。
- Inspector 不读取 Canvas 内部坐标、渲染缓存或 DOM。
- Inspector 动作执行后，由页面刷新 ViewModel，再由 Canvas 和 Inspector 同步显示最新状态。

该边界保证 Canvas 平台、形态渲染器和 Inspector 可以独立演进。

## 12. 验收标准

本设计落地后应满足：

1. 新增对象类型时不修改 `SelectedObjectInspector` 主组件。
2. `BaseInspectorPanel` 不包含 P3 业务判断。
3. 每类对象有独立 Renderer、明确 payload 类型和明确适用属性组。
4. `Inspector` 对阶段对象、内部对象和阶段关系对象使用同一套标题、属性组、追溯、质量和动作区。
5. `需规文档 -> 软设文档` 的基础转换仍由阶段关系 Renderer 承载。
6. 文档块点击、功能节点点击、架构元素点击、投影节点点击都能进入对应 Renderer。
7. 未注册对象类型能回退到通用对象 Renderer，不导致页面崩溃。
8. 所有动作通过命令 dispatcher 回派，不在 Renderer 内直接调用后端 API。
9. Inspector 不读取 DOM、Canvas 私有状态或 A4 正文文本。
10. 右侧面板排版保持紧凑，属性类字段不得使用过大字号。
11. Canvas 可见对象必须具备 `Identity` 和 `LayoutTransform` 属性组。
12. 阶段关系箭头必须具备 `Identity`、`Relation` 和 `RelationGeometry` 属性。
