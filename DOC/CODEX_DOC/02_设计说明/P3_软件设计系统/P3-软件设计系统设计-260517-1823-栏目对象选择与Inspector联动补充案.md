# P3 软件设计系统设计 260517-1823 栏目对象选择与 Inspector 联动补充案

## 1. 背景

统一软设工作区已经形成 `需规`、`软设文档`、`功能树`、`分层架构`、`技术实现`、`展示形态` 和 `P4 投影` 七个阶段对象的 Canvas 长卷。现有能力已经覆盖主 Canvas 拖拽缩放、顶部滑窗、阶段对象拖拽缩放，以及需规/软设文档的 A4 与编辑区展示。

当前缺口在于：阶段对象内部的数据还没有成为可点击、可选中、可操作的工作对象。用户点击需规条款、软设段落、功能树节点、架构层、技术实现行、展示形态卡片或 P4 投影节点时，右侧 `Inspector` 还不能根据被点击对象显示对应详情和操作。

如果直接为每个框单独写点击逻辑，短期能看到交互效果，但会破坏 P3 后续模块化目标。正确方向是先抽象一套共性的“可选择对象协议”，让不同阶段框只负责把自己的内部数据适配为统一对象，`Inspector` 只消费统一协议。

## 2. 设计目标

1. 阶段对象内部数据必须可选中，选中结果能驱动右侧 `Inspector`。
2. 选择协议必须可扩展到七个阶段对象，不得只为 A4 文档块服务。
3. 每个阶段框保持解耦，只负责本框的数据适配、渲染和命中上报。
4. `Inspector` 不直接理解各阶段框的内部实现，只读取统一选择对象。
5. 后续新增“接口设计图”“数据模型图”等阶段对象时，只要产出统一选择对象，就能复用 `Inspector`。
6. 点击交互不得破坏既有 Canvas 行为：标题栏拖拽、节点缩放、正文滚动和主 Canvas 拖拽缩放需要继续成立。

## 3. 核心抽象

### 3.1 `DesignMorphSelection`

`DesignMorphSelection` 是软设工作区的当前选中对象。它不等同于后端事实源，也不等同于某个 React 组件状态，而是前端工作台在当前视图下的选择上下文。

建议结构：

```ts
type DesignMorphSelection = {
  stageId: string;
  objectId: string;
  kind: DesignMorphSelectableKind;
  title: string;
  summary?: string;
  status?: string;
  sourceRefs: string[];
  qualityRefs?: string[];
  actions: DesignMorphSelectionAction[];
  payload?: Record<string, unknown>;
};
```

### 3.2 `DesignMorphSelectableKind`

`kind` 用于描述被选中对象的业务类型，而不是描述它来自哪个组件。

建议首版枚举：

```ts
type DesignMorphSelectableKind =
  | "stage"
  | "requirement_section"
  | "requirement_clause"
  | "design_section"
  | "design_block"
  | "function_node"
  | "architecture_layer"
  | "architecture_module"
  | "technical_mapping"
  | "presentation_shape"
  | "projection_node";
```

### 3.3 `DesignMorphSelectionAction`

`actions` 描述当前选中对象能执行什么，不由 `Inspector` 硬编码。

建议结构：

```ts
type DesignMorphSelectionAction = {
  actionId: string;
  label: string;
  description?: string;
  disabled?: boolean;
  commandHint?: string;
};
```

示例：

```ts
{
  actionId: "expand_current_block",
  label: "扩写本段",
  description: "围绕当前软设段落补充设计理由、边界和接口说明。",
  commandHint: "扩写当前段落，补充模块边界和设计理由。"
}
```

## 4. 七个阶段对象的适配规则

| 阶段对象 | 可选择对象 | 命中方式 | 典型操作 |
| --- | --- | --- | --- |
| 需规 | 章节、条款 | A4/编辑区 DOM 点击 | 查看来源、定位软设映射、作为生成约束 |
| 软设文档 | 章节、段落、列表、代码块 | A4/编辑区 DOM 点击 | 扩写本段、补充小节、应用补丁、查看追溯 |
| 功能树 | 功能节点 | Canvas hit map 或独立树组件点击 | 拆分子功能、绑定软设章节、生成模块候选 |
| 分层架构 | 架构层、层内模块 | Canvas hit map 或框图组件点击 | 调整层归属、查看依赖、生成技术映射 |
| 技术实现 | 技术映射行、框架模块 | 表格/Canvas hit map 点击 | 绑定框架、检查覆盖层次、生成实现说明 |
| 展示形态 | 展示卡片、布局候选 | 卡片点击 | 设为首选形态、补充交互说明、生成 UI 约束 |
| P4 投影 | 投影树节点、工单节点 | 树节点点击 | 查看来源、检查依赖、生成工单详情 |

七个阶段对象只共享选择协议，不共享具体渲染器。这样可以保证每个框在后续分支中独立深化，不互相污染。

## 5. 分层职责

### 5.1 数据适配层

每个阶段对象拥有自己的 Adapter，把本阶段的业务数据转换为 `DesignMorphSelection` 候选对象。

示例：

- `RequirementSelectionAdapter`：把 P2 冻结需规章节和条款转换为 `requirement_section`、`requirement_clause`。
- `DesignDocumentSelectionAdapter`：把软设章节和正文块转换为 `design_section`、`design_block`。
- `FunctionTreeSelectionAdapter`：把功能树节点转换为 `function_node`。
- `ProjectionSelectionAdapter`：把 P4 投影树节点转换为 `projection_node`。

Adapter 只做映射，不渲染界面，也不执行操作。

### 5.2 渲染命中层

不同展示形态采用不同命中方式：

- DOM 型组件：直接在元素上绑定 `data-selection-id` 和点击事件。
- Canvas 型组件：渲染时生成 hit map，记录对象 ID 与世界坐标矩形。
- 树/表格型组件：节点或行点击后上报对应对象 ID。

无论命中方式如何，最终都向上抛出同一种事件：

```ts
onSelectMorphObject(selection: DesignMorphSelection)
```

### 5.3 选择状态层

`P3DesignLabPage` 或软设工作区容器持有当前选择状态：

```ts
const [selectedMorphObject, setSelectedMorphObject] = useState<DesignMorphSelection | null>(null);
```

状态层只负责保存当前选中对象，并把它传给 Canvas 平台和右侧 `Inspector`。

### 5.4 Inspector 展示层

`Inspector` 只读取 `DesignMorphSelection`。它不关心对象来自 A4 文档、Canvas 框图还是投影树。

首版展示内容：

- 对象标题。
- 对象类型。
- 所属阶段。
- 状态。
- 摘要。
- 来源追溯。
- 质量约束。
- 可执行操作列表。
- CLI 命令提示。

当没有选中内部对象时，`Inspector` 显示阶段对象级信息，例如当前窗口、软设版本、转换策略和整体摘要。

## 6. 与既有交互的关系

### 6.1 与阶段对象拖拽的关系

阶段对象拖拽仍只由标题栏触发。对象正文或内部数据点击只改变 `selectedMorphObject`，不得移动阶段对象。

### 6.2 与对象缩放的关系

右下角缩放把手继续只负责对象尺寸。内部对象点击不得触发缩放逻辑。

### 6.3 与正文滚动的关系

文档区域滚动优先于 Canvas 缩放。点击文档块只更新选择，不改变滚动策略。

### 6.4 与顶部滑窗的关系

顶部滑窗仍表达主 Canvas 视口与阶段对象布局。栏目内对象选择不需要直接反映到顶部滑窗，避免小地图承担过多语义。

### 6.5 与 CLI 的关系

CLI 命令默认作用于当前 `DesignMorphSelection`。例如当前选中软设段落时，用户输入“补充接口说明”，系统应把该命令解释为对当前段落的局部补写，而不是对整份软设文档的全局重写。

## 7. Inspector 操作规则

`Inspector` 的操作按钮应来自选中对象的 `actions`，而不是写死为固定三项。

建议首版动作分类：

| 动作类型 | 适用对象 | 说明 |
| --- | --- | --- |
| 查看来源 | 全部对象 | 展示 `sourceRefs` 对应的上游来源 |
| 定位映射 | 需规条款、软设段落、功能节点 | 在相邻阶段对象中定位映射对象 |
| 扩写 | 软设章节、软设段落 | 生成局部正文补充 |
| 拆分 | 功能节点、架构模块 | 细化为子对象 |
| 绑定 | 架构模块、技术映射、展示形态 | 建立结构化关系 |
| 生成投影 | 模块、技术映射、展示形态 | 派生 P4 投影候选 |
| 检查 | 全部对象 | 对当前对象运行局部质量检查 |

## 8. 选中高亮规则

被选中对象需要在来源框中有明确视觉反馈：

1. DOM 文档块：增加选中边框或浅色背景。
2. Canvas 节点：重绘对应子对象的边框、填充或描边。
3. 树节点：使用 `is-selected` 样式。
4. 表格行：使用选中行背景。

高亮状态由 `selectedMorphObject.objectId` 驱动。组件不应维护与全局选择冲突的私有选中状态。

## 9. 代码落地建议

### 9.1 首批实现范围

首批只要求打通 `需规` 和 `软设文档` 两个文档型阶段对象：

1. 定义 `DesignMorphSelection`、`DesignMorphSelectionAction` 等类型。
2. 扩展 `A4DocumentSurface`，支持块级点击、块级高亮和 `onSelectBlock`。
3. 在 `DesignMorphCanvasPlatform` 中把文档块点击转换为 `DesignMorphSelection`。
4. 在 `P3DesignLabPage` 中持有 `selectedMorphObject`。
5. 改造右侧 `Inspector`，根据选中对象渲染详情和操作。

### 9.2 第二批实现范围

第二批覆盖 Canvas 绘制型对象：

1. 把 `DesignMorphStageViewModel.items: string[]` 升级为结构化对象列表。
2. 各 Canvas renderer 在绘制时生成 hit map。
3. 主 Canvas 点击时优先命中内部对象，其次命中阶段对象。
4. 功能树、分层架构、技术实现、展示形态、P4 投影接入统一选择协议。

### 9.3 不建议首批实现的内容

首批不做以下内容：

- 多选。
- 框选。
- 跨阶段对象连线编辑。
- Inspector 内直接修改后端事实。
- 自动保存选择状态到后端。
- 顶部滑窗中显示内部对象。

这些能力可以后续作为独立扩展，不应阻塞当前“点击对象 -> Inspector 响应”的基础闭环。

## 10. 验收口径

1. 点击需规 A4 文档中的条款，右侧 `Inspector` 显示该条款标题、内容摘要、来源和可执行操作。
2. 点击软设 A4 文档中的段落，右侧 `Inspector` 显示该段落标题、内容摘要、追溯来源和“扩写/补充/应用补丁”等动作。
3. 点击对象标题栏仍能拖拽阶段对象。
4. 点击对象正文不触发阶段对象拖拽。
5. 点击 `A4`、`编辑区`、`更多` 等标题栏按钮不改变内部选中对象。
6. 当前没有选中内部对象时，`Inspector` 回退显示阶段对象级摘要。
7. 选择协议和 `Inspector` 不写死在需规/软设文档，后续功能树、分层架构、技术实现、展示形态、P4 投影可以通过 Adapter 接入。

## 11. 与主设计文档的合并位置建议

后续合入主设计文档时，建议拆入以下位置：

1. “统一软设工作区”章节：补充当前选中对象和 `Inspector` 联动机制。
2. “共性组件与模块解耦”章节：补充 `DesignMorphSelection` 协议、Adapter 分层和渲染命中层。
3. “阶段对象设计”章节：补充七个阶段对象的可选择对象清单。
4. “交互设计”章节：补充点击、选中、高亮、动作列表和 CLI 作用域规则。
5. “代码实现规划”章节：补充首批文档型对象和第二批 Canvas 绘制型对象的分阶段落地路径。
