# P3 软件设计系统设计-260512-1745-Lab 风格工作台重构补充

**日期：** 2026-05-12

**适用范围：** `P3 Design Lab` 新版界面设计、前端组件组织、后续原型实现验收。

## 1. 背景与调整口径

当前 `P3 Design Lab` 已经完成从“旧订单流程面”向“虚规输入 -> 软件设计说明 -> 设计基线 -> P4 投影”的主链路迁移，但界面形态仍偏静态原型页：

- 顶部像页面卡片，而不是阶段 Lab 身份区。
- 左侧拆成“虚规预览 + CLI”上下两块，信息组织较散。
- 右侧虽然有 A4 软件设计说明，但目录、检查、投影仍像附属 Tab。
- 空输入包状态下页面出现大面积空白，产品感弱。

本轮调整明确：`P3` 新界面主要参考 `P2` 的 `/p2-requirement-analysis-lab`，不是参考 `/requirement-authoring`。目标是把 `P3 Design Lab` 重构为“产物中心的 Lab 工作台”。

## 2. 参考对象与继承原则

### 2.1 参考对象

参考页面：

```text
/p2-requirement-analysis-lab
```

该页面更接近当前认可的产品形态，因为它具备：

1. 清晰的顶部阶段身份区。
2. 左侧阶段导航和对象导航。
3. 右侧按任务切换的工作区。
4. 配置、会话、当前 Turn、日志和状态对象的可观测性。
5. Lab 感和产品感兼具，而不是纯文档编辑器。

### 2.2 不参考对象

`/requirement-authoring` 不作为本轮主要视觉基准。它适合 `P2` 正式需求规格说明编写场景，但 `P3` 当前更需要表达：

- 输入包如何被消费。
- 设计生成过程如何被观察。
- 软件设计说明如何和结构化设计基线同源。
- 检查评审如何形成冻结门禁。
- P4 投影如何从设计基线生成。

因此 `P3` 应先继承 `P2 Lab` 的工作台形态，再在其中嵌入 A4 软件设计说明主产物。

## 3. 产品形态定义

新版 `P3 Design Lab` 定义为：

```text
产物中心的 Lab 工作台
```

它同时满足三个目标：

| 目标 | 含义 | 页面体现 |
| --- | --- | --- |
| Lab 导航结构 | 像 `P2 Lab` 一样把复杂工作拆成可切换视图 | 顶部身份区 + 左侧导航 + 右侧工作区 |
| 过程可观测性 | 能看到从虚规到软设、基线、检查、投影的过程 | 当前 Turn、运行日志、状态迁移、生成记录 |
| 正式产物中心 | 默认视图仍围绕 `P3` 正式产物展开 | 软件设计说明、设计基线、检查评审、P4 投影 |

## 4. 页面总体结构

新版页面采用三层结构：

```text
P3 Software Design Lab 顶部身份区
  -> 左侧 Lab 导航
  -> 右侧任务工作区
```

### 4.1 顶部身份区

顶部身份区展示：

- 标识：`P3 Software Design Lab`
- 副标题：`从 P2 需求规格冻结包生成软件设计说明、设计基线和 P4 投影`
- 状态标签：
  - 输入包状态
  - 设计会话状态
  - 设计基线状态
  - 检查评审状态
  - P4 投影状态
- 主动作：
  - 选择 `P2` 冻结包
  - 生成 / 重新生成
  - 运行检查
  - 冻结候选

顶部不再展示“布局：左 38% / 右 62%”这类实现细节。

### 4.2 左侧 Lab 导航

左侧导航项如下：

| 导航项 | 说明 | 默认状态 |
| --- | --- | --- |
| 输入包 | 查看当前 `P2` 冻结包和结构化输入 | 有输入包时可用 |
| 软设工作区 | 默认主视图，展示软件设计说明和产物摘要 | 默认选中 |
| 当前 Turn | 展示自然语言配置、解释结果和影响范围 | 可用 |
| 设计基线 | 展示结构化设计状态 | 生成后可用 |
| 检查评审 | 展示阻断、警告、通过项和证据 | 生成后可用 |
| P4 投影 | 展示下游模块工单投影 | 生成后可用 |
| 运行日志 | 展示 API、生成器、检查器和状态迁移记录 | 始终可用 |

每个导航项应显示：

- 标题。
- 简短说明。
- 当前状态。
- 数量或关键指标，例如模块数、阻断项、投影工单数。

### 4.3 右侧任务工作区

右侧工作区根据左侧导航切换。工作区应保持 `P2 Lab` 的密度和产品感：

- 边界清晰。
- 信息紧凑。
- 操作靠近对象。
- 不使用大面积装饰背景。
- 不把所有对象塞进同一屏。

## 5. 视图设计

### 5.1 输入包视图

输入包视图解释 `P3` 当前消费的 `P2` 冻结包。

内容包括：

- 冻结包标题。
- 来源文档。
- 冻结时间。
- `p3_consumable` 状态。
- 需求规格说明摘要。
- 结构化字段摘要。
- 标注、知识绑定和待确认项。

空态要求：

- 显示“没有可用的 P2 新版冻结包”。
- 保留选择输入包动作。
- 不显示大片无意义 A4 空白。

### 5.2 软设工作区视图

软设工作区是默认视图，承载正式软件设计说明。

布局建议：

```text
当前输入包 / 生成策略 / 会话状态 / 主操作
  -> A4 软件设计说明正文
  -> 设计基线摘要 / 检查状态 / P4 投影状态
```

软件设计说明仍保留 A4 文档质感，但它嵌入 Lab 工作区，而不是让整页都围绕 A4 静态排布。

软设正文的辅助 Tab 建议为：

- 正文
- 目录
- 追溯
- 版本

### 5.3 当前 Turn 视图

当前 Turn 是自然语言配置和生成解释的一等视图，不再挤在左下角。

内容包括：

- 用户输入。
- 系统解释出的设计意图。
- 影响范围。
- 对设计基线的变更摘要。
- 对软件设计说明正文的变更摘要。
- 下一步建议。
- CLI 输入框。

### 5.4 设计基线视图

设计基线是软件设计说明背后的结构化设计状态，不是正文的重复展示。

内容包括：

- 架构模式。
- 模块清单。
- 模块职责。
- 接口草案。
- 数据对象。
- 状态机或关键流程。
- `P2` 需求条款追溯关系。

### 5.5 检查评审视图

检查评审用于判断当前软设是否可冻结、是否能交给后续阶段。

内容包括：

- 阻断项数量。
- 警告项数量。
- 通过项数量。
- 检查规则列表。
- 每条问题的作用范围、证据和建议动作。

该视图回答：

```text
当前软设为什么能或不能进入下一阶段？
```

### 5.6 P4 投影视图

`P4` 投影视图展示 `P3` 成果如何转换为 `P4` 可接收任务包。

内容包括：

- 投影包名称。
- 下游目标阶段。
- 工单列表。
- 每个工单对应的模块、接口、数据对象和需求条款。
- 工单就绪状态。

该视图回答：

```text
这份软设后面怎么变成可执行工作？
```

### 5.7 运行日志视图

运行日志保留 Lab 的可观测性，但不作为默认视图。

内容包括：

- API 调用记录。
- 生成器 / Provider 调用记录。
- 检查器调用记录。
- 状态迁移记录。
- 错误和重试记录。

## 6. 视觉方向

整体视觉参考 `P2 Lab`：

- 浅灰蓝背景。
- 紧凑顶部栏。
- 左侧深浅分明的导航。
- 白色工作区面板。
- 小半径边角，最大 8px。
- 标签、状态、指标紧凑排列。
- 不使用网格背景、装饰渐变和大块静态卡片。

`P3` 可以保留 A4 软件设计说明纸面，但该纸面应是软设工作区内部的主产物，而不是整个页面的唯一组织中心。

## 7. 组件与数据边界

已有以下前端抽象仍然有效：

- `StageDocumentWorkbenchViewModel`
- `StandardDocumentViewModel`
- `StageQualityGateViewModel`
- `StageOutputProjectionViewModel`
- `StageInteractionViewModel`
- `p3DesignLabWorkbenchAdapter`

但页面外壳需要从 `StageDocumentWorkbench` 的三栏文档工作台，调整为 Lab 风格工作台。

建议新增或调整：

| 组件 / 模块 | 职责 |
| --- | --- |
| `StageLabShell` | 顶部身份区 + 左侧导航 + 右侧工作区外壳 |
| `StageLabNavigation` | Lab 风格导航项、状态和指标 |
| `P3InputPackageView` | 输入包视图 |
| `P3SoftwareDesignWorkspaceView` | 软设工作区视图 |
| `P3CurrentTurnView` | 当前 Turn 视图 |
| `P3DesignBaselineView` | 设计基线视图 |
| `P3QualityReviewView` | 检查评审视图 |
| `P3ProjectionView` | `P4` 投影视图 |
| `P3RuntimeLogView` | 运行日志视图 |

边界规则：

- 共性组件只接受 ViewModel，不直接读取 `P3` API DTO。
- `P3` Adapter 继续负责 DTO 到 ViewModel 的转换。
- 页面组件负责加载、选中、命令提交和错误提示。
- 后端 API 不为前端布局返回专用 UI 模型。

## 8. 状态设计

### 8.1 没有输入包

- 顶部显示待输入状态。
- 左侧导航仍可见。
- 除“输入包”和“运行日志”外，其余视图显示不可用或等待状态。
- 右侧默认显示输入包空态和选择动作。

### 8.2 已选择输入包，未生成

- 默认进入软设工作区。
- A4 软设区域显示正式空态。
- 当前 Turn 显示可输入的生成策略。
- 设计基线、检查评审、`P4` 投影显示等待生成。

### 8.3 已生成软设

- 软设工作区显示 A4 正文。
- 设计基线显示模块、接口、数据对象摘要。
- 检查评审可运行。
- `P4` 投影显示工单预览。

### 8.4 检查存在阻断项

- 顶部状态显示阻断。
- 检查评审视图成为建议跳转项。
- 冻结候选动作禁用。

### 8.5 可冻结

- 顶部状态显示候选就绪。
- 软件设计说明、设计基线、`P4` 投影均显示可下发状态。

## 9. 验收口径

1. 页面第一眼像 `P2 Lab` 的同类产品，而不是当前 `P3` 的静态原型页。
2. 左侧导航覆盖输入包、软设工作区、当前 Turn、设计基线、检查评审、`P4` 投影和运行日志。
3. 默认视图突出软件设计说明这一主产物。
4. 当前 Turn 能承载自然语言 CLI、解释结果和影响范围。
5. 设计基线、检查评审、`P4` 投影三个对象有独立视图。
6. 空输入包状态不出现大片无意义空白。
7. 桌面和移动视口不出现文字互相遮挡或按钮不可见。
8. 旧 `/xx-p3` 页面不受影响。

## 10. 本轮不包含

本补充只定义界面重设计，不要求新增后端生成能力。

暂不处理：

- 真正的多轮设计生成算法。
- 冻结版本持久化策略。
- `P4` 真实工单下发。
- `P2` 页面回迁。

这些能力在界面结构稳定后分阶段实现。
