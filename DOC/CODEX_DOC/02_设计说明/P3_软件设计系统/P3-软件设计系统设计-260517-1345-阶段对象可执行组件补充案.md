# P3 软件设计系统设计 260517-1345 阶段对象可执行组件补充案

## 1. 背景

统一软设工作区已经把 `需规`、`软设文档`、`功能树`、`分层架构`、`技术实现`、`展示形态` 和 `P4 投影` 放入同一个 Canvas 长卷。当前 Canvas 已具备视口拖拽、缩放、顶部滑窗、节点拖拽和节点缩放能力，但七个阶段节点的内部仍以摘要绘制为主，用户感受接近“标签”或“概览卡片”，还不是可承载真实工作的对象。

下一阶段需要把阶段节点升级为可执行组件。首批只落 `需规` 和 `软设文档` 两类文档型对象，先解决 A4 文档承载、内部滚动和展示形态切换问题；功能树、分层架构、技术实现、展示形态和 `P4 投影` 保留统一扩展边界，后续分别接入思维导图、框图、映射图、呈现配置和投影树组件。

## 2. 设计目标

1. 七个阶段节点不再只是 Canvas 绘制标签，而是具备统一外壳和独立内容渲染器的可执行对象。
2. `需规` 和 `软设文档` 首先落为文档型阶段对象，支持 A4 形态和编辑区形态。
3. 阶段对象必须保留 Canvas 长卷的空间能力：标题条拖拽对象、右下角缩放对象、空白拖动画布。
4. 文档正文区域必须支持内部滚动，不因长文档膨胀破坏 Canvas 布局。
5. 对象抬头必须压缩，避免多层工具栏挤占真实工作区。
6. 共性框架必须解耦，后续功能树、分层架构等对象可以独立替换内部渲染器。

## 3. 共性组件框架

### 3.1 `StageObjectFrame`

`StageObjectFrame` 是所有阶段对象共享的外壳，负责：

- 对象标题条。
- 对象状态显示。
- 展示形态切换入口。
- 更多操作入口。
- 拖拽命中区。
- 右下角缩放把手。
- 内容插槽。

`StageObjectFrame` 不理解需规、软设、功能树或投影树的业务含义，也不直接读写 `SoftwareDesignPackage`。它只接收标准化的阶段对象模型和渲染器。

建议接口：

```ts
type StageObjectFrameProps = {
  object: StageObjectViewModel;
  activeViewMode: string;
  viewModes: StageObjectViewMode[];
  readonly?: boolean;
  selected?: boolean;
  children: ReactNode;
  onViewModeChange: (mode: string) => void;
};
```

### 3.2 `StageObjectRenderer`

每类阶段对象拥有自己的渲染器：

| 阶段对象 | 首选渲染器 | 首版状态 |
| --- | --- | --- |
| 需规 | `DocumentStageObjectRenderer` | 首批实现 |
| 软设文档 | `DocumentStageObjectRenderer` | 首批实现 |
| 功能树 | `FunctionTreeStageObjectRenderer` | 后续实现 |
| 分层架构 | `LayeredArchitectureStageObjectRenderer` | 后续实现 |
| 技术实现 | `TechnicalImplementationStageObjectRenderer` | 后续实现 |
| 展示形态 | `PresentationShapeStageObjectRenderer` | 后续实现 |
| `P4` 投影 | `ProjectionTreeStageObjectRenderer` | 后续实现 |

Canvas 平台只负责把对象摆到长卷坐标中。对象内容由渲染器负责，避免 Canvas 平台逐步膨胀为业务组件集合。

## 4. 紧凑标题条设计

阶段对象不采用多层抬头。每个对象只保留一行紧凑标题条，高度建议控制在 `32px` 左右。

标题条内容：

```text
对象名 | 状态/版本 | 展示形态切换 | 更多菜单
```

示例：

```text
需规 | 只读 · P2 冻结 | A4 | 编辑区 | 更多
软设文档 | 草稿 · v0.1 | A4 | 编辑区 | 批注 | 更多
```

以下信息不放在对象抬头中：

- 来源包完整信息。
- 创建人和创建时间。
- 追溯摘要。
- 约束说明。
- 质量检查结果。
- 长说明文字。

这些信息放入右侧 `Inspector` 或更多菜单中展示，避免挤占对象内部正文工作区。

## 5. 文档型阶段对象

### 5.1 适用对象

首批文档型阶段对象包括：

- `需规`：读取 `P2` 冻结需求规格说明包，默认只读。
- `软设文档`：读取或生成软件设计说明草稿，允许在受控模式下微调。

二者共享同一套文档型组件，只通过数据、权限和展示形态配置区分。

### 5.2 展示形态

文档型对象首版支持两种展示形态：

| 展示形态 | 用途 | 交互 |
| --- | --- | --- |
| A4 | 模拟正式文档阅读与审阅 | 内部滚动、章节定位、只读或弱编辑 |
| 编辑区 | 面向局部修改和富文本编辑 | 段落编辑、局部补写、插入小节 |

`软设文档` 后续可扩展 `批注` 形态；`需规` 首版不需要批注形态，批注和来源追溯放到 `Inspector`。

### 5.3 A4 形态

A4 形态要满足：

- 页面主体接近 A4 纸张比例。
- 纸张位于对象内容区中央。
- 内容区内部滚动，不改变 Canvas 视口。
- 长文档可继续向下阅读。
- 默认字号、段落间距和页边距接近正式文档。
- `需规` 默认只读；`软设文档` 可以提供受控编辑入口。

### 5.4 编辑区形态

编辑区形态用于后续富文本或结构化段落编辑。首版可以先实现为“段落编辑容器”，不要求一次性接入完整富文本引擎。

编辑区最小能力：

- 按章节或段落展示正文。
- 支持选中段落。
- 支持局部编辑入口。
- 支持从 `Inspector` 或 CLI 对当前段落发起补写。
- 不破坏 A4 形态的阅读体验。

## 6. 交互边界

### 6.1 对象拖拽

对象拖拽只由紧凑标题条触发。正文区域不能默认拖拽对象，避免用户滚动文档或选中文本时误移动节点。

### 6.2 对象缩放

对象缩放只由右下角缩放把手触发。缩放改变对象在 Canvas 长卷中的展示尺寸，不直接改变文档业务内容。

### 6.3 文档滚动

文档正文区域拥有自己的滚动容器。滚轮在正文区域内优先滚动文档；当正文不能继续滚动时，首版不强制向 Canvas 透传滚轮缩放，避免交互混乱。

### 6.4 Canvas 拖拽与缩放

用户在对象外部空白区域拖拽时移动 Canvas 视口。用户在主 Canvas 空白区域滚轮时缩放 Canvas。用户在对象正文中滚轮时默认滚动正文。

### 6.5 右侧 Inspector

右侧 `Inspector` 承载被压缩掉的详细信息：

- 当前对象完整标题。
- 来源与版本。
- 创建与更新时间。
- 追溯来源。
- 约束摘要。
- 当前展示形态。
- 对象级操作。

这样对象内部保持简洁，用户仍能查看完整元数据。

## 7. 数据模型扩展

建议扩展阶段对象模型：

```ts
type StageObjectViewModel = {
  id: string;
  entityType: DesignMorphStageEntityType;
  title: string;
  statusLabel: string;
  summary: string;
  viewModes: StageObjectViewMode[];
  activeViewMode: string;
  document?: DocumentStageObjectModel;
  sourceRefs: string[];
  constraintSummary: string;
};

type StageObjectViewMode = {
  id: string;
  label: string;
  disabled?: boolean;
};

type DocumentStageObjectModel = {
  title: string;
  versionLabel: string;
  readonly: boolean;
  sections: DocumentStageSectionModel[];
};

type DocumentStageSectionModel = {
  sectionId: string;
  title: string;
  paragraphs: string[];
};
```

`StageObjectViewModel` 是前端展示模型，不直接等同后端事实源。后端事实仍以 `P2` 冻结包、软件设计会话和 `SoftwareDesignPackage` 为准。

## 8. 与现有 Canvas 平台的关系

现有 Canvas 平台继续保留：

- 主 Canvas 视口拖拽和缩放。
- 顶部滑窗投影。
- 节点位置和尺寸状态。
- 节点拖拽与缩放命中检测。

但节点内部渲染要从纯 Canvas 绘制摘要，升级为“Canvas 定位 + HTML/React 阶段对象覆盖层”的模式。Canvas 负责坐标系和背景，HTML/React 对象负责真实交互内容。

首版可以采用混合模式：

1. Canvas 继续绘制背景、箭头、滑窗和节点投影。
2. 主工作区增加一个与 Canvas 同步坐标变换的对象层。
3. `StageObjectFrame` 在对象层中按节点坐标绝对定位。
4. 需规和软设文档先由 `DocumentStageObjectRenderer` 渲染。
5. 后续功能树和分层架构再接入各自渲染器。

## 9. 首版实现范围

首版只实现：

1. 共性 `StageObjectFrame`。
2. `DocumentStageObjectRenderer`。
3. 需规 A4 形态。
4. 软设文档 A4 形态。
5. 需规/软设编辑区形态的结构占位。
6. 紧凑标题条。
7. 正文内部滚动。
8. 标题条拖拽对象、右下角缩放对象、对象外拖拽 Canvas 的交互边界。

首版不实现：

- 完整富文本编辑器。
- 功能树真实思维导图编辑。
- 分层架构真实框图编辑。
- 技术实现真实框架映射图。
- 展示形态配置器。
- `P4` 投影树编辑。
- 跨对象自动连线重排。

## 10. 验收口径

1. 需规和软设在 Canvas 中表现为真实文档对象，而不是摘要标签。
2. 文档对象抬头只有一行紧凑标题条，不出现多层说明或重复工具栏。
3. A4 正文区域占据对象主体空间，支持内部滚动。
4. 标题条拖拽对象，正文滚动文档，右下角缩放对象，空白拖动画布。
5. 需规和软设共用文档型组件框架，不写两套重复实现。
6. 右侧 `Inspector` 能承载对象元数据，避免把元数据堆在对象内部。
7. Canvas 平台不直接理解文档业务细节，只负责对象定位、视口和投影。
8. 后续五类对象可通过新增渲染器接入，不需要重写 Canvas 平台。
