# P3 软件设计系统设计 260517-0145 Canvas 节点可编辑布局补充案

## 1. 背景

统一软设工作区已经采用 Canvas 长卷承载“需规、软设文档、功能树、分层架构、技术实现、展示形态、P4 投影”七个形态节点。现有实现支持主 Canvas 视口拖拽、缩放，以及顶部真实滑窗控制视口，但七个形态节点本身仍是固定布局。

随着软设对象进入更真实的设计阶段，功能树、分层架构、技术实现和 P4 投影都会出现内容膨胀。若只能移动整个 Canvas 视口，用户无法对某个形态节点进行局部扩展和布局调整，也不利于后续把每个形态拆成独立插件。

因此，本补充案要求 Canvas 视口平台支持形态节点级别的拖拽和缩放。

## 2. 设计原则

1. Canvas 视口平台负责节点位置、尺寸、命中检测、拖拽缩放和小地图投影，不读取或修改 `SoftwareDesignPackage` 业务事实。
2. 各形态渲染器负责节点内部内容绘制，不直接处理节点在长卷上的绝对位置和外框尺寸。
3. 节点拖拽只通过标题栏或右上角拖拽控制点触发，不允许整块内容区域默认拖拽，避免与内部编辑、选中、展开交互冲突。
4. 节点缩放只通过右下角缩放把手触发，首版不支持旋转、多选、自动避让和吸附。
5. 顶部滑窗必须使用节点真实位置和尺寸进行投影，不得继续使用等距固定节点作为事实来源。

## 3. 交互定义

### 3.1 节点拖拽

- 命中区域：节点标题栏、右上角拖拽控制点。
- 结果：更新该节点的 `x`、`y`。
- 不变：节点内部业务内容、主 Canvas 视口缩放、当前软设数据包。
- 边界：允许节点在长卷中重新排布；首版不做碰撞检测。

### 3.2 节点缩放

- 命中区域：节点右下角缩放把手。
- 结果：更新该节点的 `w`、`h`。
- 限制：必须保留最小宽高，避免节点内容完全塌缩。
- 不变：节点的业务含义和形态类型不变。

### 3.3 主 Canvas 视口拖拽

当指针未命中节点标题栏、拖拽控制点或缩放把手时，主 Canvas 仍按原逻辑拖拽视口。

## 4. 顶部滑窗动态投影

顶部滑窗不再把七个形态节点画成固定等距节点，而是根据当前节点布局实时计算：

- 节点中心位置：由 `x + w / 2` 投影到 track 坐标。
- 节点宽度提示：由 `w` 在当前世界范围中的比例投影为小矩形宽度。
- 真实视口框：继续由主 Canvas 可见世界范围投影。

当用户拖拽或缩放任一形态节点后，顶部滑窗必须同步更新节点相对位置和宽度提示。

## 5. 状态归属

节点布局状态属于 `canvasViewportState` 的前端展示状态，可用于恢复用户工作区偏好，但不属于后端权威设计事实。它不得改变软件设计说明正文、设计基线、功能树、技术实现或 P4 投影的业务内容。

建议扩展的前端状态结构：

```ts
type CanvasStageLayoutState = {
  stageId: string;
  x: number;
  y: number;
  width: number;
  height: number;
};
```

## 6. 首版验收口径

1. 用户按住节点标题栏拖动时，该节点在主 Canvas 中移动。
2. 用户拖动节点右下角缩放把手时，该节点尺寸变化。
3. 未命中节点控制区时，主 Canvas 仍可整体拖拽。
4. 顶部滑窗节点地标使用真实节点位置和宽度动态绘制。
5. 节点拖拽和缩放不影响软设业务数据，不触发保存草稿、生成投影或检查评审。
6. 自动化测试覆盖节点拖拽、节点缩放和顶部滑窗动态投影。
