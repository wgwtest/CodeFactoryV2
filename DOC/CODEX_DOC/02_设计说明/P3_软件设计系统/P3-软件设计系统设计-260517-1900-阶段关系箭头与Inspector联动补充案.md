# P3 软件设计系统设计 260517-1900 阶段关系箭头与 Inspector 联动补充案

## 1. 背景

统一软设工作区已经把 `需规`、`软设文档`、`功能树`、`分层架构`、`技术实现`、`展示形态` 和 `P4 投影` 放在同一个 Canvas 长卷中。七个阶段对象之间通过箭头表达递进关系，但当前箭头主要承担视觉连接作用，尚未成为可选中、可配置、可执行的工作对象。

在真实 P3 工作流中，阶段之间的转换关系本身非常重要。例如 `需规 -> 软设文档` 不是普通连线，而是基础转换关系；它需要承载转换策略、转换参数、执行动作、进度状态、输入输出摘要和追溯关系。后续 `软设文档 -> 功能树`、`功能树 -> 分层架构`、`分层架构 -> 技术实现`、`技术实现 -> 展示形态`、`展示形态 -> P4 投影` 也都具有相似但不相同的转换职责。

因此，箭头应从“装饰性连线”升级为“阶段关系对象”。用户点击箭头后，右侧 `Inspector` 显示该关系的参数、状态和动作。这样可以替代固定占位的转换面板，使工作区更统一，也节约右侧空间。

## 2. 设计目标

1. 阶段对象之间的箭头必须成为可选中对象。
2. 箭头选中后，`Inspector` 显示阶段关系详情、参数和操作。
3. `需规 -> 软设文档` 的基础转换能力应迁移为该关系对象的 Inspector 内容，而不是固定显示在 Inspector 顶部。
4. 所有阶段关系共享统一选择协议，但每条关系拥有独立的参数、状态和动作。
5. 箭头视觉必须比当前更明显，默认态、悬停态、选中态和活动窗口态需要可区分。
6. 箭头命中区域要宽于可见线条，避免用户难以点击。
7. 关系对象只描述阶段之间的数据转换和映射，不直接替代阶段对象内部的编辑能力。

## 3. 核心抽象

### 3.1 `DesignMorphRelationSelection`

阶段关系对象应纳入上一份补充案中的 `DesignMorphSelection` 统一协议。建议新增 `kind = "stage_relation"`。

建议结构：

```ts
type DesignMorphRelationSelection = DesignMorphSelection & {
  kind: "stage_relation";
  relation: DesignMorphStageRelation;
};
```

其中：

```ts
type DesignMorphStageRelation = {
  relationId: string;
  fromStageId: string;
  toStageId: string;
  relationType: DesignMorphStageRelationType;
  title: string;
  description: string;
  status: "idle" | "pending" | "running" | "ready" | "warning" | "blocked";
  parameters: DesignMorphRelationParameter[];
  steps: DesignMorphRelationStep[];
  inputSummary: string;
  outputSummary: string;
  traceabilitySummary?: string;
  actions: DesignMorphSelectionAction[];
};
```

### 3.2 `DesignMorphStageRelationType`

建议首版关系类型：

```ts
type DesignMorphStageRelationType =
  | "requirement_to_design_document"
  | "design_document_to_function_tree"
  | "function_tree_to_layered_architecture"
  | "layered_architecture_to_technical_implementation"
  | "technical_implementation_to_presentation_shape"
  | "presentation_shape_to_p4_projection";
```

每种关系类型拥有自己的参数和动作，但都通过同一套 `Inspector` 展示框架呈现。

## 4. 六条阶段关系定义

| 关系 | 关系类型 | 主要职责 | 主动作 |
| --- | --- | --- | --- |
| 需规 -> 软设文档 | `requirement_to_design_document` | 从 P2 冻结需规生成软件设计说明草稿 | 执行基础转换 |
| 软设文档 -> 功能树 | `design_document_to_function_tree` | 从软设章节拆解功能项和功能层级 | 生成功能树 |
| 功能树 -> 分层架构 | `function_tree_to_layered_architecture` | 把功能节点归入展示层、功能层、服务层、数据层 | 生成分层架构 |
| 分层架构 -> 技术实现 | `layered_architecture_to_technical_implementation` | 把理论架构层映射到框架、模块、服务和数据对象 | 生成技术映射 |
| 技术实现 -> 展示形态 | `technical_implementation_to_presentation_shape` | 把技术模块映射到界面位置、组件形态和交互方式 | 生成展示形态 |
| 展示形态 -> P4 投影 | `presentation_shape_to_p4_projection` | 从设计包派生 P4 工单和工具包树 | 生成投影候选 |

## 5. Inspector 内容结构

选中阶段关系箭头后，`Inspector` 应从“阶段对象摘要”切换为“关系对象面板”。

### 5.1 关系标题区

显示：

- 关系标题，例如 `需规 -> 软设文档`。
- 关系类型，例如 `基础转换关系`。
- 当前状态，例如 `待执行`、`转换完成`、`待复核`。
- 输入阶段和输出阶段。

### 5.2 参数区

参数区由关系对象的 `parameters` 驱动。不同关系显示不同参数。

`需规 -> 软设文档` 首版参数建议：

| 参数 | 控件 | 说明 |
| --- | --- | --- |
| 转换策略 | 下拉框 | 标准软设草稿生成、组件优先拆解、P4 投影优先 |
| 章节生成粒度 | 下拉框 | 按标准章节、按需规功能、按模块候选 |
| 待确认项处理 | 开关 | 是否保留待确认项 |
| 追溯关系生成 | 开关 | 是否同步生成需规到软设的追溯 |
| 结构化事实生成 | 开关 | 是否同步生成结构化设计事实 |

`软设文档 -> 功能树` 参数建议：

- 功能拆解粒度。
- 是否保留章节映射。
- 是否合并相似功能。
- 是否生成待确认功能节点。

`功能树 -> 分层架构` 参数建议：

- 分层策略。
- 模块归属规则。
- 是否允许跨层模块。
- 是否生成依赖提示。

`分层架构 -> 技术实现` 参数建议：

- 技术栈偏好。
- 框架承载策略。
- 数据层映射规则。
- 服务拆分粒度。

`技术实现 -> 展示形态` 参数建议：

- 展示优先级。
- 交互密度。
- 默认布局区域。
- 是否生成替代展示形态。

`展示形态 -> P4 投影` 参数建议：

- 工单粒度。
- 工具包分支策略。
- 验收项生成策略。
- 是否标记阻断依赖。

### 5.3 过程区

过程区用于展示该关系的转换步骤，类似当前基础转换的四步进度，但不应看起来像按钮。

`需规 -> 软设文档` 过程：

1. 读取需规冻结包。
2. 抽取设计对象。
3. 生成软设草稿。
4. 建立追溯映射。

每一步只显示状态：待执行、执行中、已完成、失败。当前步骤高亮。

### 5.4 输入输出区

显示该关系的输入和输出摘要：

- 输入：来源阶段对象、来源版本、关键来源节点。
- 输出：目标阶段对象、生成对象数量、待复核项数量。
- 追溯：输入对象到输出对象的映射摘要。

### 5.5 操作区

操作区由关系对象的 `actions` 驱动。

`需规 -> 软设文档` 首版动作：

- 执行基础转换。
- 查看输入。
- 查看输出。
- 重置本关系。

其他关系动作示例：

- 生成功能树。
- 重新拆解功能。
- 生成分层架构。
- 刷新技术映射。
- 生成展示形态。
- 生成投影候选。

## 6. 箭头视觉设计

### 6.1 默认态

默认箭头应比当前更明确：

- 可见线宽建议 `5px`。
- 箭头颜色使用深青绿或深蓝绿，避免过浅。
- 箭头头部尺寸加大。
- 箭头中段可显示小型关系标签，例如 `基础转换`、`功能拆解`、`技术映射`。

### 6.2 悬停态

鼠标悬停箭头时：

- 线宽增加或外描边加亮。
- 鼠标指针变为 `pointer`。
- 关系标签背景加深。
- 可以在靠近箭头处显示简短提示，例如 `查看转换参数`。

### 6.3 选中态

选中箭头时：

- 线宽进一步加粗。
- 使用高对比描边或轻微光晕。
- 关系标签变为选中色。
- 两端阶段对象可以出现轻量关联高亮，但不能抢占当前选中关系的主视觉。

### 6.4 活动窗口态

当前活动窗口对应的箭头应保持高亮，但弱于选中态。若某条箭头同时是活动窗口和选中对象，以选中态为准。

### 6.5 命中区域

箭头视觉线宽不等于命中宽度。建议：

- 可见线宽：`5px`。
- 命中宽度：`18px` 至 `24px`。
- 箭头标签同样可点击。

命中区域只用于选择关系，不得影响主 Canvas 空白拖拽逻辑。

## 7. 与栏目对象选择协议的关系

阶段关系箭头与栏目内对象使用同一套选择机制：

```ts
onSelectMorphObject(selection: DesignMorphSelection)
```

区别只在 `kind`：

- 栏目对象：`requirement_clause`、`design_block`、`function_node` 等。
- 阶段对象：`stage`。
- 阶段关系：`stage_relation`。

`Inspector` 通过 `kind` 选择渲染分支，但外层状态、选中高亮、动作列表和 CLI 作用域保持统一。

## 8. 与现有转换面板的关系

当前 Inspector 中固定展示的转换策略、执行基础转换按钮和转换进度，应迁移到 `需规 -> 软设文档` 关系对象。

迁移后：

1. 默认未选中关系时，不固定占用 Inspector 顶部空间。
2. 用户点击 `需规 -> 软设文档` 箭头时，Inspector 显示基础转换参数和按钮。
3. 用户点击其他箭头时，Inspector 显示对应关系的参数和动作。
4. 用户点击框内对象时，Inspector 显示栏目对象详情和局部操作。

这样右侧 Inspector 成为真正的上下文工作区，而不是固定堆叠多个面板。

## 9. 状态与数据归属

阶段关系对象属于前端工作台视图模型，但其中某些状态来源于后端会话：

| 数据 | 来源 |
| --- | --- |
| 关系定义、标题、from/to 阶段 | 前端 morph model |
| 基础转换策略和步骤 | P3 software design session conversion |
| 功能树生成状态 | 后续功能树生成服务 |
| 分层架构生成状态 | 后续架构生成服务 |
| 技术映射状态 | 后续技术映射服务 |
| 展示形态状态 | 后续展示形态服务 |
| P4 投影状态 | P3 projection service |

前端关系对象只负责聚合展示，不应伪造后端权威状态。没有后端状态的关系可以显示为 `待生成` 或 `待设计`。

## 10. 代码落地建议

### 10.1 首批范围

首批只落以下内容：

1. 扩展 `DesignMorphSelection`，增加 `kind = "stage_relation"`。
2. 扩展 `DesignMorphWindowViewModel` 或新增 `DesignMorphRelationViewModel`，描述六条阶段关系。
3. Canvas 绘制箭头时使用关系对象，而不是只按相邻 items 画线。
4. 增加箭头 hit test，点击箭头上报 `stage_relation` 选择。
5. 加粗箭头默认视觉，补充 hover 和 selected 状态。
6. 将基础转换策略、执行基础转换按钮、转换步骤迁移为 `需规 -> 软设文档` 关系 Inspector 内容。

### 10.2 第二批范围

第二批再扩展其他关系的参数和操作：

1. `软设文档 -> 功能树`：功能拆解参数和生成动作。
2. `功能树 -> 分层架构`：架构归层参数和生成动作。
3. `分层架构 -> 技术实现`：技术映射参数和生成动作。
4. `技术实现 -> 展示形态`：展示形态参数和生成动作。
5. `展示形态 -> P4 投影`：投影参数和生成动作。

### 10.3 暂不实现内容

首批不实现：

- 箭头拖拽改线。
- 用户自定义新增关系。
- 多条关系并行执行调度。
- 箭头上直接编辑参数。
- 小地图中显示关系参数。

这些能力后续可作为关系编辑器能力扩展。

## 11. 验收口径

1. 主 Canvas 中阶段箭头比当前更粗、更明显。
2. 鼠标悬停箭头时有可点击反馈。
3. 点击 `需规 -> 软设文档` 箭头后，右侧 `Inspector` 显示基础转换策略、转换步骤和“执行基础转换”按钮。
4. 点击其他箭头后，右侧 `Inspector` 显示对应关系标题、说明、输入输出摘要和占位动作。
5. 点击箭头不会移动阶段对象，也不会触发主 Canvas 拖拽。
6. 点击阶段对象内部数据时，`Inspector` 切换到栏目对象详情。
7. 点击阶段对象标题栏时，仍能拖拽阶段对象。
8. 选中箭头后，箭头有明确选中态。
9. 活动窗口高亮和选中态不冲突，选中态优先。
10. 现有“执行基础转换”能力仍可调用原转换接口。

## 12. 与主设计文档的合并位置建议

后续合入主设计文档时，建议拆入以下位置：

1. “统一软设工作区”章节：补充阶段关系对象的概念。
2. “共性选择协议”章节：把 `stage_relation` 纳入 `DesignMorphSelection`。
3. “Inspector 设计”章节：补充关系对象 Inspector 面板。
4. “Canvas 交互设计”章节：补充箭头视觉、命中和选中态。
5. “需规到软设基础转换”章节：说明基础转换面板迁移到 `需规 -> 软设文档` 关系对象。
6. “代码实现计划”章节：补充首批和第二批落地范围。
