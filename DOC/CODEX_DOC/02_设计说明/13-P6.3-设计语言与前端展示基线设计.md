# P6.3 设计语言与前端展示基线设计

## 1. 设计定位

`P6.3` 负责统一平台级设计语言与前端展示基线。

它的职责不是要求 `P1 ~ P5` 做成完全相同的界面，而是解决跨阶段观察时最容易让用户困惑的问题：

- 名称不统一
- 状态表达不统一
- 总览条和信息卡风格不统一
- 列表、图谱、抽屉、筛选条的交互语义不统一

## 2. 统一边界

### 2.1 必须统一的部分

- 阶段命名
- 状态文案与状态色
- 总览条与摘要卡的表达方式
- 平台级入口按钮与跳转提示
- 抽屉、详情页、列表、图谱视图的基础交互语义
- 页面空态、加载态、错误态

### 2.2 允许保留阶段个性的部分

- 阶段特有业务字段
- 专有工作台布局
- 阶段内部图谱/建模/编排细节
- 业务特有按钮和操作链

`P6.3` 统一的是平台语言，不是业务内部实现。

## 3. 统一命名基线

### 3.1 阶段命名

平台正式统一使用：

- `P1 业务知识库`
- `P2 需求分析系统`
- `P3 软件设计系统`
- `P4 工具仓库`
- `P5 软件构建系统`
- `P6 平台门户、观察与前端展示实验层`

不得在平台级页面中混用“工具中台 / 工具仓库”“门户 / 平台入口”等未经说明的别称。

### 3.2 状态文案

平台级状态文案应优先使用：

- `待开始`
- `进行中`
- `已完成`
- `待人工验收`
- `阻塞中`
- `数据暂不可用`

若阶段内部还有更细状态，允许保留，但平台总览必须映射回上述平台级状态集合。

## 4. 视觉与信息层级基线

### 4.1 视觉方向

平台级页面统一采用：

- 浅底工程蓝图方向
- 高信息密度但低视觉噪声
- 强结构感而非“装饰型后台”

避免：

- 大表头
- 大面积无意义留白
- 纯装饰卡片墙
- 依赖弹窗承载关键信息

### 4.2 信息层级

平台级页面的信息层级固定为：

1. 阶段身份
2. 当前状态
3. 核心指标
4. 入口动作
5. 扩展说明

任何页面都不应把“说明性长文”放在“状态与动作”之前。

## 5. 共享展示基元

`P6.3` 首版固定以下共享展示基元：

### 5.1 总览条

用于阶段级数量、状态和摘要展示。

要求：

- 单行表达优先
- 支持多段统计
- 支持状态标签
- 信息密度高，但高度受控

### 5.2 筛选与视图条

用于来源文档筛选、类型筛选、视图切换等操作。

要求：

- 筛选与视图切换应在同一认知层级组织
- 明确区分单选、多选和二选一切换
- 不允许出现“用户不知道当前筛选是否生效”的交互

### 5.3 列表 / 图谱双视图

用于实体、事件、流程等结构数据。

要求：

- 列表视图负责精确查阅
- 图谱视图负责拓扑理解
- 两者使用统一筛选条件
- 节点点击后的详情入口保持一致

### 5.4 详情抽屉

详情优先使用抽屉而不是打断式弹窗。

要求：

- 支持来源、释义、关联关系、投影摘要的分区展示
- 与列表/图谱视图共享详情模型

## 6. 状态与反馈基线

平台级页面必须统一四类反馈：

- 加载中
- 无数据
- 数据暂不可用
- 操作已完成 / 已接收

尤其是“数据暂不可用”必须与“无数据”区分开：

- `无数据`
  - 表示查询成功但结果为空
- `数据暂不可用`
  - 表示查询失败、接口未就绪或投影暂时中断

## 7. 渐进式改造规则

`P6.3` 不要求一次性重写所有页面，而是按以下顺序推广：

1. 先统一 `P6` 平台页
2. 再统一 `P1 ~ P5` 的总览条和平台级入口表达
3. 最后再考虑阶段内部工作台的深层语言收敛

判断标准：

- 只要是跨阶段观察页，就优先用 `P6.3` 基线
- 只要是阶段内部深业务工作台，就允许保留个性

## 8. 与其他阶段的关系

- `P6.1` 消费 `P6.3` 的图形与交互语言
- `P6.2` 提供统一状态对象，支撑 `P6.3` 状态文案映射
- `P6.4` 在实验中探索可复用展示基元，再反哺 `P6.3`

## 9. 验收口径

1. 平台级页面的阶段命名、状态文案和状态色已收敛。
2. 总览条、筛选条、双视图和详情抽屉拥有统一表达基线。
3. “无数据”和“数据暂不可用”有明确区分，不再混用。
4. `P6.3` 的统一不要求抹平各阶段业务个性，边界清晰。
