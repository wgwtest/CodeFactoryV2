# 软件工厂平台总体设计

## 1. 平台定位

`CodeFactoryV2` 的定位是“知识驱动的软件工厂”，不是单独的知识图谱系统，也不是传统表单式低代码平台。

平台的正式主链为：

`P1 业务知识库 -> P2 需求分析系统 -> P3 软件设计系统 -> P4 工具仓库 -> P5 软件构建系统`

`P6 门户与平台入口` 负责统一入口、可视化观察和导航承载。

## 2. 总体设计原则

### 2.1 结构化对象优先

所有关键阶段都优先产出结构化对象，再按需要投影为说明文档、图谱页面或执行描述。

### 2.2 上游只暴露标准成果物

下游模块只允许依赖上游阶段的标准输出，不允许依赖其内部实现细节。

### 2.3 对象优先于流程

需求建模阶段优先从对象出发，再组织流程。原因是：

- 对象建模要素更完整
- 系统需要支持探索新流程，而不只是复现既有流程
- 多对象跨流程应用是重要目标场景

### 2.4 组件/工具闭环发生在生成过程中

组件或工具资产不是应用完成后再回收，而是在应用生成过程中实时发生：

`分析需求 -> 解耦功能 -> 检索工具/组件资产 -> 命中复用 / 未命中开发 -> 形成应用`

## 3. 六个一级模块的职责

### 3.1 P1 业务知识库

输入：

- PDF / DOC / DOCX 等业务资料

输出：

- 已发布知识对象
- 业务元素候选集
- 实体、事件、流程、规则、指标查询能力
- 图谱与证据回溯能力

### 3.2 P2 需求分析系统

输入：

- 用户交互式建模操作
- `P1` 输出的业务元素数据
- 通用应用建模枚举与约束

输出：

- 结构化 `RequirementSpec`
- 可选的人类可读规格说明投影

### 3.3 P3 软件设计系统

输入：

- `RequirementSpec`

输出：

- 结构化 `SoftwareDesignModel`
- “软件设计说明”投影
- 冻结后的模块级/子模块级工具化描述

说明：

- “软件设计说明”与“工具化描述”不是并列终点
- 二者是同一设计对象的顺序化投影

### 3.4 P4 工具仓库

输入：

- `P3` 输出的模块工具化描述
- 已有工具、组件、执行器资产

输出：

- 工具匹配结果
- 可复用资产命中结果
- 新工具/组件登记结果
- 供 `P5` 使用的执行资产

### 3.5 P5 软件构建系统

输入：

- 需求规格
- 软件设计模型
- 工具/组件命中结果

输出：

- 目标软件或元数据应用
- 新沉淀的构建资产

### 3.6 P6 门户与平台入口

输入：

- 平台阶段状态
- 模块入口和观察指标

输出：

- 首页门户
- 模块入口
- 运行态观察视图

## 4. 模块间正式接口

### 4.1 P1 -> P2

输出内容：

- 已发布业务实体、事件、流程、规则、指标
- 检索与筛选能力
- 来源文档与证据回溯

### 4.2 P2 -> P3

输出内容：

- `RequirementSpec`

要求：

- 这是正式结构化输入
- `P3` 不应直接消费 `P2` 内部草稿状态

### 4.3 P3 -> P4

输出内容：

- 模块级工具化描述
- 子模块级工具化描述
- 软件设计说明的冻结投影

### 4.4 P4 -> P5

输出内容：

- 工具/组件匹配结果
- 可执行资产清单
- 校验与约束结果

## 5. 文档表达约束

- 平台总体结构以本文件为正式权威描述
- 任何后续阶段方案都必须与本文件的模块边界保持一致
- 局部实现可以在 `docs/superpowers/` 先起草，但被采纳后必须回写到正式文档层
