# 软件工厂平台总体设计

## 1. 平台定位

`CodeFactoryV2` 的定位是“知识驱动的软件工厂”，不是单独的知识图谱系统，也不是传统表单式低代码平台。

平台的正式主链为：

`P1 业务知识库 -> P2 需求分析系统 -> P3 软件设计系统 -> P4 工具仓库 -> P5 软件构建系统`

`P6 平台门户、观察与前端展示实验层` 负责首屏观察、跨阶段只读集成、平台级设计语言统一以及前端展示工具化验证。

## 2. 总体设计原则

### 2.1 结构化对象优先

所有关键阶段都优先产出结构化对象，再按需要投影为说明文档、图谱页面或执行描述。

### 2.2 上游只暴露标准成果物

下游模块只允许依赖上游阶段的标准输出，不允许依赖其内部实现细节。

### 2.3 对象优先于流程

需求建模阶段优先从对象出发，再组织流程。原因是：

- 对象建模要素更完整
- 系统需要支持探索新流程，而不只是复现既有流程
- 多对象跨流程应用是重要目标场景

### 2.4 组件/工具闭环发生在生成过程中

组件或工具资产不是应用完成后再回收，而是在应用生成过程中实时发生：

`分析需求 -> 解耦功能 -> 检索工具/组件资产 -> 命中复用 / 未命中开发 -> 形成应用`

## 3. 六个一级模块的职责

### 3.1 P1 业务知识库

输入：

- PDF / DOC / DOCX 等业务资料

输出：

- 已发布知识对象
- 业务元素候选集
- 实体、事件、流程、规则、指标查询能力
- 图谱与证据回溯能力

### 3.2 P2 需求分析系统

输入：

- 用户交互式建模操作
- `P1` 输出的业务元素数据
- 通用应用建模枚举与约束

输出：

- 结构化 `RequirementSpec`
- 可选的人类可读规格说明投影

### 3.3 P3 软件设计系统

输入：

- `RequirementSpec`

输出：

- 结构化 `SoftwareDesignModel`
- “软件设计说明”投影
- 冻结后的模块级/子模块级工具化描述

说明：

- “软件设计说明”与“工具化描述”不是并列终点
- 二者是同一设计对象的顺序化投影

### 3.4 P4 工具仓库

输入：

- `P3` 输出的模块工具化描述
- 已有工具、组件、执行器资产

输出：

- 工具匹配结果
- 可复用资产命中结果
- 新工具/组件登记结果
- 供 `P5` 使用的执行资产

补充约束：

- `P4` 中的“工具”默认指**可复用、可组合、可交付的最小资产单元**
- 它不默认等同于完整页面、完整应用或整站脚手架
- 第一优先级工具形态应是：
  - 前端元组件
  - 后端模块
  - 服务接口
  - 模板包
- 页面模板、业务页脚手架、整应用骨架可以作为更高层级资产存在，但不应替代“最小工具”成为 `P4` 的默认定义

因此，`P4 -> P5` 的正式输出不应只回答“有没有命中工具”，而应回答：

- 该工具以什么形态交付
- 宿主系统如何接入
- 运行依赖由谁提供
- 交付产物和版本清单是什么
- 对外暴露的契约是什么

### 3.5 P5 软件构建系统

输入：

- 需求规格
- 软件设计模型
- 工具/组件命中结果

输出：

- 目标软件或元数据应用
- 新沉淀的构建资产

### 3.6 P6 平台门户、观察与前端展示实验层

输入：

- `P1 ~ P5` 的阶段状态投影
- 模块入口和观察指标
- 平台级展示语言约束
- 前端展示实验配置

输出：

- 首屏观察门户
- 串行观察与统一展示页
- 只读状态投影视图
- 平台级设计语言与前端展示基线
- 反哺 `P3 / P4 / P5` 的展示工具化实验结论

## 4. 模块间正式接口

### 4.1 P1 -> P2

输出内容：

- 已发布业务实体、事件、流程、规则、指标
- 检索与筛选能力
- 来源文档与证据回溯

### 4.2 P2 -> P3

输出内容：

- `RequirementSpec`

要求：

- 这是正式结构化输入
- `P3` 不应直接消费 `P2` 内部草稿状态

### 4.3 P3 -> P4

输出内容：

- 模块级工具化描述
- 子模块级工具化描述
- 软件设计说明的冻结投影

### 4.4 P4 -> P5

输出内容：

- 工具/组件匹配结果
- 可执行资产清单
- 校验与约束结果

### 4.4.1 `P4 -> P5` 交付补充约束

补充说明：

- `P4` 提供给 `P5` 的不只是“命中某个名字”，还应包括可消费的 `delivery manifest`
- `delivery manifest` 至少应包含：
  - `tool_form`
  - `packaging_type`
  - `integration_mode`
  - `dependency_policy`
  - `runtime_dependencies`
  - `artifact locator`
  - `contract summary`
- 这样 `P5` 才能判断一个工具究竟是：
  - 直接 `import` 的前端元组件
  - 通过 `include_router` 装配的后端模块
  - 通过 HTTP 调用的服务接口
  - 还是仍需进一步展开的高层模板资产

### 4.5 `P1 ~ P5 -> P6`

输出内容：

- 阶段概览信息
- 入口可用性
- 状态摘要与健康信息
- 可选的阶段状态订阅投影

要求：

- `P6` 只消费规范化查询 / 订阅接口
- 不允许直接依赖阶段内部数据库、私有页面状态或临时脚本结果

### 4.6 `P6 -> P1 ~ P5`

当前约束：

- 不反写
- 不触发业务命令
- 不回写阶段语义

`P6` 当前只承担读侧观察与前端展示验证，不承担跨阶段写协调。
