# 2026-05-10 P2 组织器多轮整改第 3 轮问题与整改说明

## 1. 背景

第 3 轮继续执行受控动态考官测试。对应测试记录为：

```text
DOC/CODEX_DOC/06_测试文档/03_机测记录/2026-05-10-P2-组织器多轮整改第3轮测试记录.md
```

## 2. 问题与根因

### 2.1 决策链状态没有有效沉淀

现象：

- 第 3 轮基线中 `brainstorm-v1` 与 `brainstorm-v1-dify-workflow` 最终 `confirmed_decisions=0`。
- 用户已回答软件定位、主要角色、流程、数据、范围边界、非功能和验收，但这些内容没有形成决策链。

根因：

- `decision_state_delta` 阶段没有明确要求“回答组织器问题时给出的角色、范围、流程、数据、非功能和验收口径”进入 `confirmed_decisions`。
- Dify workflow 的本地节点和远端返回也没有把决策型事实提升为决策项。

归属：

- `brainstorm-v1` Prompt。
- `brainstorm-v1-dify-workflow` 节点与 adapter。

### 2.2 `brainstorm-v1` 收束 JSON 仍可能过长

现象：

- 第 3 轮修复复测中，`brainstorm-v1` 第 11 Turn 收束返回 400。
- 错误为 `Unterminated string starting at...`。

根因：

- 收束成稿阶段仍有一次性输出长 JSON 的倾向。
- JSON 修复重试不足以解决全部长文本截断，需要进一步在 Prompt 中要求控制 `document_patch` 数量和单条内容长度。

归属：

- `brainstorm-v1` Prompt。
- Provider 输出合同稳定性。

## 3. 整改动作

| 问题 | 修改对象 | 处理 |
| --- | --- | --- |
| 决策链不沉淀 | `decision_state_delta.system.md` / `decision_state_delta.user.md` | 明确已回答的软件定位、范围边界、角色、流程、数据接入、非功能和验收应进入 `confirmed_decisions` |
| Dify 决策项缺失 | `document_projection.py` / `adapter.py` | 本地节点生成决策型记录，adapter 对远端旧输出做兼容性提升 |
| 收束 JSON 过长 | `decision_state_delta.system.md` | 要求收束成稿模式控制 provider JSON 尺寸，最多 6 条 patch，每条 500 字以内 |

## 4. 复测结论

第 3 轮完成以下验证：

1. `brainstorm-v1` 收束 JSON 压缩后可完成 11 Turn 动态会话，错误数为 0。
2. Dify 组织器保持 11 Turn 无接口错误。
3. 决策链沉淀问题仍需在第 4 轮用新的动态复测确认，因为第 3 轮最后一次完整双组织器复测中 Dify 仍是旧状态。

## 5. 遗留与第 4 轮入口

第 4 轮应继续验证：

1. 两个组织器最终 `confirmed_decisions` 是否从 0 提升。
2. `brainstorm-v1` 是否仍反复追问软件名称、背景领域或第一阶段纳入范围。
3. Dify 是否过早建议“回看闭合项或直接输出草案”。
4. 草案正文是否还残留用户口语噪声。
