# 2026-05-10 P2 组织器多轮整改第 2 轮问题与整改说明

## 1. 背景

本文件配套第 2 轮受控动态多轮机测记录，用于说明本轮发现的问题、根因判断、整改边界、实际修改和复测结论。对应测试记录为：

```text
DOC/CODEX_DOC/06_测试文档/03_机测记录/2026-05-10-P2-组织器多轮整改第2轮测试记录.md
```

本轮执行原则仍为：当轮测试发现的问题必须尽量在当轮完成分类、整改、复测和归档，不把已明确问题拆到后续轮次慢慢处理。

## 2. 本轮问题与根因

### 2.1 `brainstorm-v1` 交付待确认事项列举未确认领域示例

现象：

- 收束草案的待确认事项中出现“具体业务领域（如军事、应急、城市规划等）”。
- 用户并未确认这些具体领域，且受控动态考官刻意避免把态势分析系统引导到具体军事、应急或城市规划场景。

根因：

`decision_state_delta` 已约束草案正文不得列举未确认领域示例，但 `next_interaction_planning` 交付说明和待确认事项没有同等约束，导致最终展示文本仍可被污染。

归属：

- `brainstorm-v1` Prompt。

### 2.2 `brainstorm-v1` 收束阶段 Provider JSON 截断导致 400

现象：

- 第 11 Turn 输入“强制停止追问，输出完整需求规格说明草案”时，后端返回 400。
- 响应体为：`Unterminated string starting at...`。

根因：

DeepSeek 返回内容不是合法 JSON，平台原先直接 `json.loads(content)`，未做通用 JSON 修复重试。该问题发生在 Provider 输出解析层，尚未进入组织器合同校验。

归属：

- P2 平台通用 Provider 调用稳定性。
- 不属于业务语义判断，修复不应写入章节匹配或态势分析业务规则。

### 2.3 `brainstorm-v1` 把状态回看误判为交付

现象：

- 用户输入“你先回看一下：目前哪些关键决策已经闭合，哪些还没有闭合？先不要急着完整定稿。”
- 组织器返回 `next_interaction.type=deliverable`，测试脚本按交付状态停止。

根因：

`next_interaction_planning` 缺少“状态回看不等同于草案交付”的边界约束。模型把“输出一份回看清单”误当成“交付结果并结束本轮互动”。

归属：

- `brainstorm-v1` Prompt。

### 2.4 Dify 草案补全不足

现象：

- 第 1 轮已修复 Dify 草案重复堆叠，但第 2 轮基线中仍发现收束草案偏薄。
- 结果输出与共享、性能与可靠性、验收准则章节容易只保留空占位或信息不足。

根因：

Dify `document_projection` 草案分支没有把前序事实中的“业务专家复核”“可接受时间”“分析工具使用/成果导出复核/权限日志”等信息稳定投影到 `REQ-3.6`、`REQ-5.1`、`REQ-6.2`。

归属：

- Dify workflow `document_projection` 节点。

### 2.5 Dify 复测环境缺少 `DIFY_API_KEY`

现象：

- 后端重启后 Dify 第 1 Turn 返回 400：`DIFY_API_KEY is not configured for brainstorm-v1-dify-workflow`。

根因：

后端进程第一次重启时未显式加载 `.env.local`，导致真实 Dify workflow API 调用缺少运行时参数。

归属：

- 测试环境启动方式。
- 插件逻辑符合既定规范：缺少 Dify API Key 时直接报错，不本地 fallback。

## 3. 整改边界

| 类别 | 处理方式 |
| --- | --- |
| 未确认领域示例、回看/交付边界 | 放在 `brainstorm-v1` Prompt 中约束 |
| Provider JSON 截断 | 平台通用 JSON 修复重试，不涉及业务语义 |
| Dify 草案补全 | 修改 Dify workflow 节点代码与本地节点源文件 |
| Dify 缺少 API Key | 使用 `.env.local` 启动测试后端，不提交密钥 |

本轮没有把用户意图、章节语义、领域判断、下一问选择等业务判断写入 P2 Python 硬编码。

## 4. 实际修改

### 4.1 `brainstorm-v1` Prompt 约束

修改文件：

```text
orchestrators/xg/brainstorm-v1/prompts/decision_state_delta.system.md
orchestrators/xg/brainstorm-v1/prompts/next_interaction_planning.system.md
apps/api/tests/test_p2_orchestrator_multiturn_probe.py
```

修改内容：

1. 草案正文、交付说明、待确认事项均不得列举未确认具体领域示例。
2. 用户首轮明确提出的功能能力必须保留为已提出/候选范围，不能写成“未在本轮确认”。
3. 状态回看、差距盘点、列出“哪些已闭合/哪些未闭合”不等同于草案交付；除非用户同时明确要求停止追问、输出草案或完整定稿，否则不得使用 `deliverable` 或 `draft_delivery`。

### 4.2 Provider JSON 通用重试

修改文件：

```text
apps/api/app/requirement_analysis/deepseek_client.py
apps/api/tests/test_requirement_analysis_api.py
```

修改内容：

- `DeepSeekRequirementAnalysisClient.run_stage` 在第一次 `json.loads` 失败时，追加通用修复系统提示，要求模型压缩长正文并只返回合法 JSON。
- 第二次仍失败才抛出原始解析错误。
- 该能力只处理通用 JSON 合同稳定性，不做任何业务内容修复。

### 4.3 Dify 草案补全

修改文件：

```text
orchestrators/xg/brainstorm-v1-dify-workflow/nodes/document_projection.py
orchestrators/xg/brainstorm-v1-dify-workflow/workflow.json
orchestrators/xg/brainstorm-v1-dify-workflow/ORCHESTRATOR.md
DOC/CODEX_DOC/03_规范与流程/02_组织器协作流程/02-P2-Brainstorm-v1-Dify工作流搭建规范.md
apps/api/tests/test_orchestrator_plugin_contracts.py
```

修改内容：

1. 收束草案中 `REQ-3.6` 保留成果导出、结果共享或业务专家复核事实。
2. `REQ-5.1` 保留地图流畅性、普通分析可接受时间等性能事实。
3. `REQ-6.2` 保留态势创建编辑、分析工具使用、成果导出复核、结果追溯、权限日志、异常提示等验收链条。
